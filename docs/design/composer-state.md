# Composer 输入身份与同步

产品行为归[输入区](../prd/composer.md#输入与布局)。本契约覆盖 application-api、application、bindings 与平台 app；窗口布局、光标、撤销和阅读位置由平台保存。

## 身份与责任

`InputID` 是一份输入的稳定小写 UUID。正文、持久附件引用、明确的运行时／模型／推理强度／权限选择一起保存。运行时选择包含执行 application 的 `ownerId`；选择记忆按 `(ownerId, runtimeId)` 区分，相同 ID 在两个宿主上也不会互相替代。

`ContextKey = conversation(ownerId, conversationId) | newConversation`，共享目录保存 `ContextKey → InputID`。`ownerId` 消歧执行资源，不标识查看设备。全局新建关联只有一条，项目、运行时、窗口、Tab 与 group 都不增加新建槽位。

平台窗口另存导航上下文、当前 InputID 和当前发送目标。新建的 cwd 等创建目标按 Tab 保存，不使用全局新建输入的 key 分区，也不因为多个新建 Tab 共用正文而合并它们的目标。导航离开时记录恢复关联，再取目标上下文的输入；聚焦已经显示的 group 只改目标；整理布局保持输入。借用其它输入发往新建目标时，普通焦点和离开动作都不覆盖全局新建关联。

## 共享存储与修订

application 在 `ClientState` 之外持有目录，存于 `VELUNE_HOME/composer-inputs.json`；输入更新采用完整内容与输入 revision 的 CAS；恢复关联另有 revision 与 CAS，旧窗口待同步的关联也不能覆盖另一端的新关系。目录 revision 用于条件读取。旧正文／会话选择 API 桥接同一目录。`composer-choices.json` 中的运行时默认选择仍由原配置 owner 管理，不作为输入内容的另一份权威存储。

原子文件提交成功才推进内存状态。客户端保存明确的未同步标记及原修订基线；干净缓存用于显示，不主动回写。旧基线无法覆盖另一端已经消费或修改的内容。冲突内容留在本地，阻止提交并披露原因；不建设多人合并或 CRDT。Mac 的待同步关联与新建交接随窗口恢复点保存，重连后按同一身份完成。

查看同一执行端的本地窗口与配对控制端自然使用同一保存端。bindings 的 `with_composer_authority` 可把输入读写及持久附件放到另一个明确的保存端，同时 `ReadComposerOwner` 仍返回实际执行端身份。不同完整端不会自动合并各自目录；部署时需明确共同保存端。该接线不能通过按查看设备拆分 InputID 代替。

## 新建交接

首次发送捕获实际 InputID 与发送内容。原生创建成功后，继续使用同一输入，并把原生身份记入输入目录的 `ComposerCreation`；其身份是 `(ownerId, conversationId)`，重复交接返回原结果。若全局新建项确实指向这份输入，同一提交为它换入下一份空正文／无附件的输入，保留选择；换入发生在提交消费时而非创建确认时，首发进行中才遇见新建入口的视图拿到的是下一份输入，不会在创建落地时跟随该会话。借用的 X 成功创建时，未消费的全局 N 不变。发送失败时全局新建项换回被消费的输入（其间对新输入的编辑优先）。

交接记录携带真实运行时和目录修订，供正在编辑该新建输入的其它视图接续原生身份，也供重开恢复。客户端保存已经观察的目录修订，区分新发生的交接和旧记录。一般关联替换不冒充创建。删除关联后保留交接身份，迟到重试不能重新绑定已删除的会话，也不能再次消费后来恢复到新建入口的输入。

平台一旦得知原生身份就先保存它和待完成交接，再派发首条消息。首发失败保留于已有会话；恢复已知交接时不会调用原生创建。对结果不明的 Effect 仍遵守[远控调用的交付语义](remote-access.md)，不自动重新创建。

## 附件与提交资格

附件上传后取得持久身份，原内容保存在 `composer-attachments/<id>/<name>`，保留扩展名，单个上限沿用 20 MiB。`composer:<id>` 由执行边界解析；保存端与执行端分离时，bindings 通过实际执行 view 的既有上传通道交付，保留附件的授权边界。本机缓存路径不成为跨设备引用。

一个失效附件不阻断正文与选择恢复。附件留在原位置，可以移除或经原入口重试；恢复内容前禁止提交。尚未取得输入、断连未同步、所选运行时来源或模型不可用时也禁止提交，正文仍可编辑。窗口与编辑器须观察可用性变化，即使内容值未变也更新提交状态。

## 显式迁移

新格式不存在而检测到旧输入文件或旧窗口输入时，application 拒绝静默初始化。退出使用该 HOME 的 Velune 后，按[手动迁移规则](../development.md#破坏性变更与手动迁移)执行：

```sh
python3 scripts/migrations/composer-state.py --home /absolute/VELUNE_HOME
python3 scripts/migrations/composer-state.py --home /absolute/VELUNE_HOME --apply
```

脚本使用运行时排他锁，保留原文件和原附件，将旧窗口身份、关联、选择及附件导入一个目录；多份旧新建输入只选一份作为全局项，其余保留。缺失附件保留引用并报告。目标已存在时视为已迁移并跳过，不覆盖。iOS 的旧本机输入保留在原窗口记录中，通过“恢复本机旧输入”显式接入，不用旧缓存覆盖共享输入。
