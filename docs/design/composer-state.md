# Composer 输入身份与同步

产品行为归[输入区](../prd/composer.md#输入与布局)。本契约覆盖 application-api、application、bindings 与平台 app；窗口布局、光标、撤销和阅读位置由平台保存。

## 身份与责任

`InputID` 是正文与持久附件的稳定小写 UUID。执行选择独立按 `ContextKey = conversation(ownerId, conversationId) | newConversation` 保存，包括运行时、各运行时上的模型／推理／权限及明确选择标记。运行时选择中的 `ownerId` 消歧执行 application，不标识查看设备；相同 runtimeId 在两个宿主上不会互相替代。

共享目录的 `ContextKey → InputID` 只负责找回内容；同一 ContextKey 的 `ComposerTarget` 负责找回配置。新建只有一条全局内容关联及一套目标选择，项目、运行时、窗口、Tab 与 group 不增加新建槽位。

平台窗口另存导航上下文、当前 InputID 和发送目标。三种动作分别处理：

- 同 group 导航换 Tab：记录当前内容关联，恢复目标的内容与配置。
- 跨 group 只移动焦点：保留当前 InputID，仅恢复新目标的执行配置。
- 整理布局：延续内容；目标不变时选择也不变。

新建的 cwd／项目等创建目标按 Tab 保存；多个新建 Tab 共用内容与选择，不合并它们各自的创建目标。借用其它输入发往新建目标时，普通焦点和离开动作不覆盖全局新建关联。

目标尚未加载时不能从旧会话的 nextTurn 播种选择，发送暂不可用；加载的目标身份与请求一致后才初始化它自己的选择。外观、额度及菜单均以当时的目标配置解析，不能持有创建视图时的旧输入选择快照。

## 选择依据与边界

把正文、附件和执行选择继续放在同一全局输入里，会使跨group移焦点把原会话的模型带到新目标；全部改为per-session则会在移焦点时替换正在写的内容。当前拆分来自两种操作的不同含义：换Tab是在找回另一份工作，移焦点是在为手头内容选择接收方。布局位置因此不属于内容或配置的持久身份，调用方需要说明导航动作，不能从bottom drawer外观猜测。

这个边界也约束迟到结果：从Codex打开Pi尚未完成时，旧画面的配置不能初始化Pi；首次创建尚未返回时，新建页后来选择的模型不能改写已提交会话。共享层负责各自修订与提交身份，窗口负责导航，运行时负责已开始执行的配置快照。侧聊继续使用其专属会话store的执行选择与能力限制，不把主会话目录中不存在的侧聊身份当作可写目标。

## 共享存储与修订

application 在 `ClientState` 之外持有 `VELUNE_HOME/composer-inputs.json`（schema 2）。`inputs` 保存正文／附件和内容 revision；`bindings` 保存恢复关联及其 revision；`targets` 保存 ContextKey、选择及独立 revision。内容、关联与目标配置分别 CAS，目录 revision 用于条件读取；编辑正文不会覆盖刚在另一端改变的模型。旧正文／会话选择 API 分别桥接对应记录。`composer-choices.json` 只管理运行时默认选择，不成为目标选择的另一份权威存储。

原子文件提交成功才推进内存状态。客户端分别保存内容与目标的未同步标记和原修订基线；干净缓存只用于显示。旧基线不能覆盖另一端已消费的内容或更新的选择；冲突留在本地并阻止提交，不建设多人合并或 CRDT。后台读取只记录最新修订，不替待同步编辑重设基线；用户明确重新选择（包括同值重选）才表示采用当前整套本地执行配置，并以最近观察的目标修订重新提交。此动作不触碰正文／附件，后续并发变化仍受CAS保护，提示必须说明如何恢复，不能只要求不可操作的“接续”。导航、光标、撤销和窗口安排不跟随目录跨设备同步。

查看同一执行端的本地窗口与配对控制端自然使用同一保存端。bindings 的 `with_composer_authority` 可把目录与持久附件放到另一个明确保存端，而 `ReadComposerOwner` 仍返回实际执行端身份。不同完整端不会自动合并各自目录，部署需明确共同保存端；不能按查看设备拆分 InputID 代替。

## 新建交接

首次发送捕获实际 InputID、内容和目标选择快照。原生创建成功后继续使用同一内容，并以提交时的选择初始化新会话的目标记录，再执行 `Promote`；迟到的创建回包不能把此后修改的全局新建选择复制到已创建会话。`ComposerCreation` 以 `(ownerId, conversationId)` 记录原生交接身份，重复交接返回原结果。

若全局新建关联确实指向被消费的内容，同一提交为其换入下一份空正文／无附件的内容；全局新建目标的选择不随内容轮换。首发进行中才进入新建页的视图拿到下一份内容，不会在创建落地时跟随旧会话。借用 X 成功创建时，未消费的全局 N 不变。失败恢复只针对被消费的内容，并尊重其间新编辑。

交接身份与目录修订供正在编辑这份内容的其它视图接续，也供重开恢复。一般关联替换不冒充创建；删除关联后保留交接身份，迟到重试不能重新绑定已删除的会话或再次消费后来恢复的新建内容。平台得知原生身份后先保存它与待完成交接，再派发首条消息；首发失败留在已有会话。结果不明的 Effect 遵守[远控交付语义](remote-access.md)，不自动重新创建。

## 附件与提交资格

附件上传后取得持久身份，原内容保存在 `composer-attachments/<id>/<name>`，保留扩展名，单个上限沿用 20 MiB。`composer:<id>` 由执行边界解析；保存端与执行端分离时，bindings 通过实际执行 view 的既有上传通道交付，保留附件的授权边界。本机缓存路径不成为跨设备引用。

一个失效附件不阻断正文与选择恢复。附件留在原位置，可以移除或经原入口重试；恢复内容前禁止提交。尚未取得输入、断连未同步、所选运行时来源或模型不可用时也禁止提交，正文仍可编辑。窗口与编辑器须观察可用性变化，即使内容值未变也更新提交状态。

## 显式迁移

旧输入目录或旧窗口格式必须在升级前显式迁移。schema 1 中同一输入携带的选择转换为每个已绑定 ContextKey 的目标选择；正文／附件和内容身份保持，原文件及孤立输入的旧资料保存在备份中。旧文字／窗口输入先由原迁移接入目录，再拆分内容与目标。应用不自动转换或用空输入覆盖旧文件。

退出使用该 HOME 的 Velune 后，按[手动迁移规则](../development.md#破坏性变更与手动迁移)预览并执行：

```sh
python3 scripts/run-migrations.py --home /absolute/VELUNE_HOME
python3 scripts/run-migrations.py --home /absolute/VELUNE_HOME --apply
```

脚本获取运行时排他锁，保留原数据并幂等；缺失附件保留引用并报告。各平台窗口缓存中的旧选择需显式接入目标记录，不能用迟到旧缓存重写新的共享目录。真实 HOME 的迁移是否执行由任务包单独记录，合成验证不代表已迁移用户数据。
