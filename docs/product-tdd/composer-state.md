# Composer 输入身份与同步

产品行为归[输入区](../prd/composer-input.md#内容与目标的归属)。本契约覆盖 application-api、application、bindings 与平台 app；窗口布局、光标、撤销和阅读位置由平台保存。

## 身份与责任

`InputID` 是正文与持久附件的稳定小写 UUID。执行选择独立按 `ContextKey` 保存，包括运行时、各运行时上的模型／推理／权限及明确选择标记。已创建会话使用 `conversation(ownerId, conversationId)`；Mac 未发送 Tab 使用该执行 owner 下的 `conversation(ownerId, "draft:<Tab UUID>")`。旧 `newConversation` 记录保留用于兼容和恢复，不再作为 Mac 新建 Tab 的共享槽位。查看设备不参与执行 owner 身份。

共享目录的 `ContextKey → InputID` 找回内容，`ComposerTarget` 找回配置。Tab 导航与跨 group 聚焦都恢复目的上下文的完整状态；布局整理保持当前输入身份。新建的 cwd／项目按 Tab 保存，恢复或移动 Tab 保留其 UUID。

Mac 的停靠／独立窗口共享 composer 只是呈现宿主。按 Tab 查询输入、队列操作或配置时始终使用该 Tab 的上下文，不能返回焦点所在 Tab 的输入。焦点游标记录当前呈现输入的实际来源，不能用旧保存点中另一个发送目标来回写输入关联或采集撤销配置。

恢复旧共享输入留下的跨会话多重绑定时，Mac 为目的上下文复制正文和附件引用，通过现有内容保存与关联 CAS 建立独立输入；原输入及其他上下文保留，执行配置仍由各自的目标记录拥有。不改目录格式，不把关联冲突当作成功。同一上下文的跨窗口接续保持 InputID；原生创建记录或待完成 Promote 所指的草稿到原生身份交接属于同一生命周期，不作为跨会话共用拆分。迟到的 ensure 结果不得覆盖已经改选的关联。

窗口拥有原生撤销历史。切换可见输入时，在目的输入的撤销栈记录上一份正文、附件与目标选择；撤销把该副本写入当前上下文，来源内容及关联不变。执行选择仍由共享目录的目标记录保存，不能额外放进内容记录建立第二个权威来源。正文、配置各自的 CAS 继续独立。

目标尚未加载时不能从旧会话的 nextTurn 播种选择，发送暂不可用。迟到准备与创建结果按目标身份拒收；首次创建提交时捕获的选择不受之后新建 Tab 改选影响。侧聊使用专属 store 和临时输入，不注册共享输入或目标记录。普通输入只有共享目录这一条持久写入通道。

## 目标准备用例

共享记录保存用户明确意图。未手选的运行时、模型、推理与权限继续沿用当前会话或运行时默认，手选后才固定。选择某一字段只修改该字段，解析后的其他有效值不随同写成明确选择。当前轮使用提交时捕获的有效配置。

`VeluneApplication.prepare_composer_target` 是普通输入目标的完整准备入口。请求说明读取来源运行时及会话。`draft:` 身份在核心作为尚未创建的目标处理，跳过原生历史读取并使用新会话默认；空会话只为旧调用方保留全局目标。application 确定规范目标身份、默认依据与解析规则，bindings 在既有 execution／composer authority 边界组合读取和初始化，返回执行 owner、实际保存记录及 revision、核心解析依据和有效 NextTurn。

首次记录采用空明确意图，已有记录优先。执行端与保存端可以分离，结果以保存端实际返回的记录为准。初始化已提交而后续解析失败时，记录保留，下一次读取继续；重试复用幂等 ensure 和既有 CAS。准备过程复用会话事实，原生目录按既有缓存和加载寿命到达后，用共享 `resolve_composer_target` 重解。

平台会话模型拥有准备请求和观察寿命，按目标身份拒收迟到结果。本地未同步明确选择作为只读 overlay 参与解析，保存仍使用原修订基线。`change_composer_target` 从 raw intent 更新被选择的字段。窗口拥有内容与目标的配对，视图、菜单及补全消费投影并表达操作，读取资格不承担准备或编辑器绑定。正文恢复与目标准备分别推进，目标失效时正文继续可编辑。

历史消息编辑使用独立正文、附件和执行选择。`EditMessage` 成功后，由提交编辑的平台把捕获的选择保存到返回会话的 `ComposerTarget`，不修改或重新绑定普通 `InputID`。原地替换使用发送前捕获的目标修订，分叉新目标使用不存在基线；发送期间并发改选仍经原有 CAS 显示冲突，不静默重基线。配置写回与已成功的原生发送分别报告，配置失败保留待同步选择，不把编辑重新标记为发送失败，也不自动重发。取消和发送失败不发布编辑选择。

编辑历史基线与目标配置修订分别拥有。`EditableMessage.revision` 是核心的不透明内容／活动基线；已结束活动的保留或释放不改变内容基线，新活动与实际内容变更仍须核验。确认变化时读取最新资格与版本，仅在用户明确再次提交后采用新基线，命令端与原生写入前继续检查；后端发现变化时客户端先同步状态并保留副本，不强制跳过 CAS。旧编辑入口保持其既有调用语义，新运行时／版本入口使用显式基线。

冲突后重读的完成由回执拥有，不依赖视图是否采用该次投影；确认准备持续到可靠历史版本与当前编辑资格就绪，不能因为初查尚未完成而丢失。等待时保留编辑内容并阻止提交，重读失败保留真实错误并结束等待，不自动接受新基线或重发。

Pi 编辑专用接口在来源历史完成同步、或回退的原生结果确认后返回；Core 在回退后另行等待同源新投影安装，再发送替换消息。普通刷新仍可异步，受理请求不能冒充同步完成。回退后同步失败时弃用未经核验的投影，并明确替换消息尚未发送。

历史模型的稳定 `ModelSelection` 与显示名分开保存。Pi 网关别名可可靠映射到 managed 记录时，命名投影同时保留该身份；编辑器只以目标消息所属轮次准备选择，目录尚未就绪不判为不可用，不从显示字符串伪造 provider 为空的原生选择。

队列收录待执行的完整指令。队列投影给出该项修订和已受理的执行配置，简版 composer 使用独立编辑副本。替换命令在 Core 按会话与队列项校验原修订，并原子替换正文、附件和执行配置，保留队列项身份、提交编号、位置和暂停决定。保留附件通过原修订的附件下标引用，新增文件经过当前连接的附件交付。Core 校验下标及新输入。失败回执保留编辑副本供核对。

## 共享存储与修订

application 在 `ClientState` 之外持有 `VELUNE_HOME/composer-inputs.json`（schema 2）。`inputs` 保存正文／附件和内容 revision；`bindings` 保存恢复关联及其 revision；`targets` 保存 ContextKey、选择及独立 revision。内容、关联与目标配置分别 CAS，目录 revision 用于条件读取；编辑正文不会覆盖刚在另一端改变的模型。旧正文／会话选择 API 分别桥接对应记录。实例的新会话策略归 `generic-config.json` 的 `settings.newConversation`，由 typed codec 与执行环境、ACP launch 一次提交。`composer-choices.json`（schema 2）只管理带 Adapter Type 的 `lastChosen`，不成为目标选择的另一份权威存储；类型不匹配的记录不参与默认。改变新会话策略不使已准备的执行或原生历史失效。

原子文件提交成功才推进内存状态。客户端分别保存内容与目标的未同步标记和原修订基线；干净缓存只用于显示。旧基线不能覆盖另一端已消费的内容或更新的选择；冲突留在本地并阻止提交，不建设多人合并或 CRDT。后台读取只记录最新修订，不替待同步编辑重设基线；用户明确重新选择（包括同值重选）才表示采用当前整套本地执行配置，并以最近观察的目标修订重新提交。此动作不触碰正文／附件，后续并发变化仍受CAS保护，提示必须说明如何恢复，不能只要求不可操作的“接续”。导航、光标、撤销和窗口安排不跟随目录跨设备同步。

查看同一执行端的本地窗口与配对控制端自然使用同一保存端。bindings 的 `with_composer_authority` 可把目录与持久附件放到另一个明确保存端，而 `ReadComposerOwner` 仍返回实际执行端身份。不同完整端不会自动合并各自目录，部署需明确共同保存端；不能按查看设备拆分 InputID 代替。

## 提交受理与展示

提交意图与核心实际受理去向分开。`SendTurn` 与 `EditSendQueue` 可携带本次逻辑请求的 `submissionId`；它只用于衔接客户端提交与队列，不进入模型输入、执行配置或内容指纹。`SnapshotResult.submissionReceipt` 明确返回 `queued(queueId)` 或 `sending`；后者确认派发交付，不表示已有原生消息或执行完成。普通 Codex、Claude Code 和 Pi 发送等待所提交输入的原生回执。Claude Code 的输入开始后才能向该输入发出中断。明确未写入或被拒绝时返回可恢复的错误。没有回执或队列中没有该项，都不能推断为正在发送。有受理回执但 `snapshot` 为空时，仅表示本次没有附带投影；保留已加载会话并等待后续同步，不把它解释为会话消失。

显式排队请求受理前由 composer 保留输入与提交反馈，不先在转录或队列中制造另一份已受理消息。权威队列通过 `QueuedMessage.submissionId` 与本地请求关联；普通发送立即显示暂态行。运行时确认接收后撤下「发送中」，原生记录接替暂态行。提交回执带有 `submittedMessageId` 时使用该身份关联。若核心实际将其入队，转交确切队列项并移除暂态行。暂态行不写入历史，不提供编辑、删除或大纲条目。正文相同不构成受理证据，原生历史中的真实用户消息不得为消除暂态行而过滤。

命令回执与独立轮询没有平台回调顺序保证。处理回执使用回执携带的事实，不读取尚未安装新投影的旧快照；先观察到确切队列项也构成已受理证据。后到的旧回执不能复活已经派发或移除的队列项，已确认受理后的传输／展示失败不能恢复为可重复发送的草稿。切换或关闭展示宿主不撤销仍待结算的提交归属。取消已转入队列的发送，只删除回执指明的队列项；成功后按原输入身份与修订恢复，不停止无关的当前执行，不覆盖随后编辑。

撤回按队列项身份和编辑修订仲裁。执行端在一个 Composer 目录提交中保存撤回的输入、绑定及目标选择，提交后移除原队列项。已派发、修订冲突或附件无法保存时拒绝撤回。原 InputID 作为独立草稿保留，同一保存端的客户端通过共享目录观察结果。

## 新建交接

首次发送捕获实际 InputID、内容和目标选择快照。原生创建成功后，`promote_composer_input` 让保存端一次提交输入关联、初始目标选择与原生交接记录。已有目标选择遵循原有修订和默认值规则。保存端若未声明原子交接能力，绑定层使用旧主机支持的准备及交接流程。`ComposerCreation` 以 `(ownerId, conversationId)` 记录原生交接身份，重复交接返回原结果。客户端只让持有该 InputID 的未发送 Tab 接续原生身份。

草稿身份随工作区标签创建、恢复和移动。本地草稿身份的编码、识别与共享目录映射统一由 application-api 提供。Windows 将标签 UUID 保存在布局中，旧布局的设备级全局草稿从一个恢复入口复制，备份原始布局并保留旧输入资料。提交到原生会话后，工作区先保存原生身份再退休本机草稿缓存。

旧全局新建关联仅在仍指向被消费输入时换入空内容，以兼容旧调用方；独立 Tab 不消费该关联。失败恢复只针对提交时的内容，并尊重其间新编辑。

交接身份与目录修订供正在编辑这份内容的其它视图接续，也供重开恢复。一般关联替换不冒充创建；删除关联后保留交接身份，迟到重试不能重新绑定已删除的会话或再次消费后来恢复的新建内容。平台得知原生身份后先保存它与待完成交接，再派发首条消息；首发失败留在已有会话。结果不明的 Effect 遵守[远控交付语义](remote-access.md)，不自动重新创建。

## 附件与提交资格

附件上传后取得持久身份，原内容保存在 `composer-attachments/<id>/<name>`，保留扩展名，单个上限沿用 20 MiB。`composer:<id>` 由执行边界解析；保存端与执行端分离时，bindings 通过实际执行 view 的既有上传通道交付，保留附件的授权边界。本机缓存路径不成为跨设备引用。

一个失效附件不阻断正文与选择恢复。附件留在原位置，可以移除或经原入口重试；恢复内容前禁止提交。尚未取得输入、断连未同步、所选运行时来源或模型不可用时也禁止提交，正文仍可编辑。窗口与编辑器须观察可用性变化，即使内容值未变也更新提交状态。

`ConversationActions.input_access` 随原生目标投影，用于限制提交。平台按草稿上下文是否属于普通会话决定正文与附件的编辑权限。普通会话收到 `ReadOnly` 时保留相同的输入身份和编辑控件；原生子会话的输入由父会话负责。

## 显式迁移

旧输入目录或旧窗口格式必须在升级前显式迁移。schema 1 中同一输入携带的选择转换为每个已绑定 ContextKey 的目标选择；正文／附件和内容身份保持，原文件及孤立输入的旧资料保存在备份中。旧文字／窗口输入先由原迁移接入目录，再拆分内容与目标。应用不自动转换或用空输入覆盖旧文件。

旧开发格式的预览与执行步骤归[迁移说明](../development/migrations.md#composer-未手选默认)。迁移获取运行时排他锁，保留原数据并幂等；缺失附件保留引用并报告。各平台窗口缓存中的旧选择需显式接入目标记录，不能用迟到旧缓存重写新的共享目录。

旧 `choiceEdited=false` 记录可能包含平台自动固化的值。显式 `target-intent.py` 迁移把它们归为空意图，推进修改记录的修订并完整备份，同时移出平台缓存中的自动初始化待写项。`choiceEdited=true` 保留，历史上被顺带固定的字段无法可靠反推。
