## 设备与状态归属

用户始终选择同一台设备。局域网地址、公网地址、relay 和查询这些地址的服务都属于连通信息，不产生另一类设备、业务接口或授权。Direct 既可能发生在局域网，也可能跨公网。默认使用 iroh 公共设施，连接设置可替换为兼容设施；正常添加设备不要求理解网络配置。

| 状态 | 权威与寿命 | 网络变化后的行为 |
| --- | --- | --- |
| 本设备私钥、公钥身份 | 应用私有设备存储 | 不因换网、换 relay 或端点重建而改变 |
| 已核验的目的设备身份 | 本机设备联系人记录 | 公钥固定；名称只是显示信息 |
| 本机授予对端的控制权 | 执行设备的入站授权记录 | 只有明确批准、撤销才能改变 |
| 会话、任务、审批 | 唯一 ApplicationService／Harness | 连接关闭不取消或重开业务 |
| 调用世代、去重账本、结果完成记账 | 与业务 owner 同寿命的远控服务 | 网络端点重建后仍能查询原请求 |
| 连接地址与来源、近期路径 | 可刷新缓存和连接状态 | 失败后重新发现；不作为身份依据 |
| QUIC 连接与监听资源 | 可替换的网络端点 | 路径迁移或受控重连 |

“记住这是我的 Mac”与“允许这个 Mac 控制本机”分别表达。手机扫码 Mac 时，手机保存 Mac 的身份，Mac 明确授权手机控制自己；不隐式授权反向控制。两台执行设备也沿用同一添加流程，每个方向由被控制设备确认，不引入账户或角色权限框架。

`RemoteAccessService` 继续放在 `remote` 包，通过 Handler 引用唯一业务 owner，不依赖 application 实现、不建立新进程或请求数据库。服务根保有有界账本、执行世代和已接纳任务；bindings 装配的业务异步 runtime 与稳定服务同寿命，不因 Endpoint 换代而重建。已接纳任务只持服务状态与 Handler，完成记账不依赖旧网络对象。mDNS 另有每网络代际最多一份的单 worker 私有 IO runtime，所有 Controller 共享；它仅容纳 lookup actor、swarm 与其孙任务，不承载业务。这个额外 worker 是完整关闭发现资源的代价：锁定 swarm 的 DropGuard 及 acto 只发出 abort，没有保留可等待的全部子句柄，外层 actor join 不能证明退出。controller-only 装配没有 Handler，同样持有设备身份、联系人及连接生命周期，不因此链接执行栈。

bindings 持有这份稳定服务，显式区分停止本机被控入口、替换网络资源与关闭整个服务。“停止接入”关闭本机作为执行端的邀请、未确认候选及入站控制，不能误关本机正在控制其他设备的出站连接，也不能释放记账 runtime。没有出站需求时可以释放网络资源；宿主按已有退出规则真正结束时才关闭服务。设施替换串行进行，同一身份保持一个主动发布的网络代际，避免两个独立 Endpoint 用同一密钥竞争发布位置。

请求接纳、撤销和代际封闭共享一个串行裁决点。旧代际已读完但尚未进入账本的请求再次核对代际和授权；已进入账本的请求继续执行并完成记账。撤销先原子持久化，再拒绝后续接纳并关闭该方向的访问；已接纳的工作不因此取消，撤销设备也不能继续查询结果。其他已授权设备通过业务快照和真实审批继续操作，不冒用原设备的请求命名空间。真正更换业务 owner 才产生新的调用世代，网络启停不得伪造宿主重启。

## 共享接口与持久化

下表固定接口职责和可观察语义；导出使用 UniFFI 具名类型，最终语言拼写随生成器约束确定。平台不持有 Endpoint，也不直接组织配对网络消息。现有 `VeluneApplication` 保持业务代理入口，网络连接可在代理内部替换。

| 接口组 | 契约与消费者 |
| --- | --- |
| `open_service`、`set_control_ingress`、服务关闭 | 平台进程持有稳定服务；执行端附加现有唯一 Handler，控制端为 None。关闭服务只归应用最终生命周期，不作为界面断开操作 |
| `read_state`、`observe_state` | 返回带递增版本的完整快照；取消观察不关闭服务，事件落后重读快照。回调不在状态锁内调用平台代码 |
| `controller(peer_id)`、活动事实、`connect` | 每个目的公钥一份恢复状态；窗口／视图共享，平台只报告选中、活动与网络事实。Rust 的 Controller 保留持久暂停状态，但平台暂无主动断开入口 |
| `decode_offer`、`begin_pairing`、`cancel_pairing`、事务查询 | 有界离线解析后才建连；准备完成由 Rust 在原子保存后发送。重复相机帧或 Activity 重建不重复兑换邀请。执行端不回调，控制端 Rust 在发起后及冷启时跟进未确认事务（每 2 秒，最长 10 分钟），结果经状态观察送达 |
| 本地邀请、批准／拒绝、`revoke_control` | 仅执行端本地可信管理入口可用，不进入远程业务 Command。取消与批准竞争时返回实际已提交状态，不伪造撤销 |
| `application_for_device(peer_id, view_id)`、未决请求观察 | 保留完整业务 SDK，平台界面与本地使用同一组方法；远程副作用统一经过写前记录，结果确定后自动确认。确认只结束本机跟踪，不取消远端任务、不删除服务端去重信息 |
| 网络设置（Rust 内 `apply_network`／`retry_network`，平台暂无编辑入口） | 语法校验和持久化后串行应用网络代际；装配失败返回保留已保存目标的 Failed 状态，语法／持久化／冲突失败才返回调用错误 |

为使各平台只编写一份界面，普通远程代理直接调用具名方法即可执行副作用：Rust 自动分配完整请求 ID，原子记录 pending 后才发送；方法返回成功或确定的业务失败时自动确认，传输中断、结果不明、过期或执行端重启时保留 pending，由界面显示为未解决，不自动重发。释放或关闭代理不关闭共享连接或视图。未决请求只由 Controller 恢复连接后查询原结果，平台没有手动查询或确认入口。

Rust 是身份、联系人 pin、入站 grant、配对事务、未决请求、网络设置及主动暂停意图的唯一权威。复用 remote 内现有原子文件适配，平台显式传应用私有目录，不读取全局应用配置。Kotlin 只保存选中设备、阅读位置等 UI 偏好，删除 `DeviceStore` 对 descriptor 和 pending 的重复持久化；邀请、相机帧和显示码不进入 Bundle、SavedStateHandle 或备份。

执行端本地保存的呈现偏好只在配置实际写入成功后成为新视图的默认值；已有远端视图保留自己的浏览、显示和打开偏好。远端写配置时保留执行端已提交的默认值，不能把自身视图的旧偏好写回磁盘。默认值不包含会话、草稿或执行选择；持久化失败不推进默认值，持久化成功后的响应失败也不撤销已经提交的值。local-runtime 与 portable 使用同一规则。

副作用交付分类与修订冲突分类分开。`Command::changes_shared_state()` 用于业务修订，不能直接作为是否写 pending 的条件；在中立 API 中用穷尽匹配明确观察与副作用，覆盖上传、认证控制、运行时动作及配置／会话写入，新增命令必须明确交付分类。发送前固定目的公钥、调用世代、完整请求 ID 和执行上下文，原子保存 ID、操作种类、视图及必要定位元数据，成功后才发送。文件不保存消息、附件、秘密或可重放命令正文；容量满或写入失败时在发送前拒绝。

未决记录保留至平台处理结果并明确确认；确认落盘失败则保留。网络或控制进程恢复只查询原 ID；新进程可为新操作使用新 ClientSession，但旧记录的世代、client 和 sequence 不改。Unknown、ResultExpired、ServerRestarted 均不触发自动重发，先刷新业务快照；安全的观察请求可以重新发起。执行世代只采用认证 Hello 返回值，不使用联系人缓存中的 incarnation。

普通接入状态当前为 schema 4（[`store.rs`](../../packages/remote/src/store.rs)）；首次公开 beta 对已知 schema 3 在写入前保留逐字节私有备份，迁移联系人、pins、控制 grants、pending 操作、重置通知与历史标记；schema 4 新增 profile grants 与 pending pairings，初始为空。未来或未知格式报错并保留原文件，不初始化空状态覆盖。identity 继续 schema 1，wire／邀请当前为 v3（[`protocol.rs`](../../packages/remote/src/protocol.rs)），三者是独立的版本边界。网络设置及每代凭据存于独立原子私有文件，普通状态只保留安全摘要；公开快照不返回 token。独立身份损坏时阻止启动，不重新生成私钥；打开文件前检查身份、普通状态和派生网络私有文件的路径冲突，含身份秘密标记的文件不能当作旧普通 schema 重置。用户显式重置仍产生可确认且跨冷启保留的通知：“远控配置已更新，请重新添加设备。此前任务或结果未知的操作仍可能在执行，请检查会话；应用不会自动重发。”这项显式重置不作用于 Harness 文件、真实会话或平台秘密。

schema 3→4 的 beta 转换由应用 owner 自动备份并迁移；更早格式或未知格式必须保留原件并按迁移说明恢复，不以重置代替迁移。

## 遥测分享与 wire v3

远控 wire 与 ALPN 为 v3。Submit/Query 的 W3C carrier 是有界的独立字段，不参与 Command fingerprint、RequestId 或授权。受信的关联只在鉴权后建立；原请求查询继续使用同一 RequestId。

`TelemetryProfileRead` 有独立的邀请用途、TLS 核对上下文及 grant。端点在控制或分享需要入站时接纳连接，具体 RPC 各自检查权限。配置读取直接访问本机 telemetry owner，不进入业务账本、结果缓存或持久重试；响应上限 32 KiB。新增分享配对的 pending attempt 与既有已确认联系人分开保存，失败不能破坏原控制关系。

设备存储及升级边界见[共享接口与持久化](#共享接口与持久化)。协议不兼容要求对端升级，不能通过重置身份或重试突变命令补偿。双 SDK 装配与配置导入契约见[遥测设计](telemetry.md)。
