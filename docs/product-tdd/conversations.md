# 会话投影、接续与协作

本页维护 conversation、agent-runtime、application、bindings 与平台之间的会话契约。包职责见[架构](architecture.md)，进程寿命见[运行时执行](runtime-execution.md)，输入内容与目标配置见[Composer 状态](composer-state.md)。

## 会话

### 会话权威与展示投影

`conversation` 是运行时中立的会话投影契约，Harness 是持久化权威。adapter 把原生历史与执行事件映射到同一类型：角色区分用户、assistant、工具与系统，内容区分正文、推理、工具与通知；工具调用与完成分开表达，保留原生关联 ID 与已有输出。原生消息身份优先，缺失时由 adapter 分配投影内稳定的身份。

`agent-runtime::transcript` 统一产生顺序投影：application 输入消息、身份确认与执行状态，输出同一 typed snapshot 中的有序展示项、工作区间、大纲锚点与展示身份。`Message.completed` 只表示内容完整，不代表执行成功。工作区间以用户消息为锚，覆盖到下一条用户消息之前的全部响应；区间末条 assistant 消息末尾的正文块外露为回复；该消息中先前的思考、工具块与其他中间消息归入工作过程。末条不以正文结尾时整段归入工作过程，不向前寻找旧答复。执行结束与工作时长依据 Harness 生命周期；历史没有完整证据时不虚构耗时。展示身份在当前投影内稳定，live→native 确认只修改 canonical 引用；映射不持久化。原生历史可以替换、分支、压缩与重排，投影不是永久追加日志。

标题区分原生名称、Velune 生成兜底与首消息派生等来源；原生名称优先，生成规则见[自动命名兜底](#自动命名兜底)，平台消费核心提供的显示名称。时间在 adapter 边界规范为可选 Unix 毫秒，缺失保持缺失，平台负责时区与格式。snapshot 的 revision 只在当前投影生命周期内有意义，平台以请求 generation 与会话身份丢弃过期回调。

内部完整快照的 `Executions` 关联原生执行范围与消息成员；每次明确发送／继续／主动压缩建立独立活动身份，steer 和自动恢复留在当前活动。用户显式继续可复用原展示范围，但重置本次配置捕获、恢复预算和终态消费。adapter 解释明确的结束证据，application 按活动一次性处理通知、队列与遥测；闲置、消息完成和取消意图不能替代成功／取消确认。关联只随内存快照保留，不新增会话日志或公开远控协议。

续接装饰同时转换消息 ID、执行范围／成员和身份确认，保留活动身份与原生分支点。转录投影原子消费消息和执行关联，各 steer 展示段共享结果；独立维护始终独立呈现，轮次内压缩完成后进入工作过程。原生历史没有结果证据时保持未知。

### 浏览与执行准备

列表合并全部启用实例，不按当前执行实例过滤；禁用实例保留配置与原生数据，但不读取其历史，也不出现在可执行选择中。每个实例的读取失败独立报告，不解释为其他来源没有会话。历史读取 helper 是只读适配步骤，不是执行进程：读取不要求模型、认证或工作目录仍可执行，详情 ID 必须属于所选实例的列表，不接受任意路径。分组、筛选与排序是展示投影，与会话打开和执行归属分开。

新建会话给出运行时、工作目录与模型，首次发送时自动准备并由 Harness 建立会话。准备失败保留内容与选择，修正后可重试，不自动重发已被接受的消息；配置变化只使执行装配失效。Pi 可从原生记录恢复有效的模型选择；Codex 与 DSH 的历史只有 API model ID，不能证明提供商，继续前要求选择。

原生索引、Codex 项目与归档／按身份查找的回退投影使用同一个读取来源身份。客户端上次列表的条目与来源共同保存在 `ListedProjection`，所有读取入口先校验来源，覆盖跨客户端视图恢复后的查找、管理和关联会话信息。`RuntimeSourceKey` 包含实例及 Adapter Type，直接复用实际 Pi history、native `HistoryConfig` 或 ACP launch 配置。缓存身份检查只进行纯解析，进程与资源准备由读取入口负责。实例名称、新会话策略及 Velune 网关／提供商变化可以复用已读摘要和项目。归档按来源分组，每个来源验证一次，共享来源标记减少重复存储。

写入缓存前核对捕获的来源仍为当前来源，拒绝迟到的旧来源结果。真实来源改变、实例停用／删除或当前来源读取失败时，统一清理索引、项目及回退投影。恢复旧客户端视图同样经过来源校验。当前来源解析失败时清空该实例缓存。当前来源有效时，旧请求的失败只能清理与它相同的来源。

读取来源与执行配置分别表达依赖。Pi 的 `sdkHelper` override 只供执行装配使用，历史读取使用自己的 helper。因此修改它使执行配置失效，同时保留历史缓存。执行配置由 `execution_configuration` 及已捕获的 gateway／backends 管理，提供商内容变化走网关执行失效路径。

### 下一轮选择与跨 Harness 接续

下一轮的运行时与模型是发送意图，不随浏览的历史来源变化。历史的原生来源负责读取、重命名与删除；已开始的轮次保留自己的实例、会话与模型，用于轮询、取消与交互回复。`send_turn` 显式接收来源会话、目标运行时与选择，同来源时恢复原生会话。

不同 Harness 的原生会话 ID 不能互相恢复。跨 Harness 接续为线性逻辑会话：每次切换（包括切回）创建目标原生会话。Claude Code、Codex 与 Pi 之间以**原生上下文翻译**接续：来源 adapter 导出 compact 和分支选择后的有效模型上下文，经过独立的中性上下文类型，目标 adapter 写入自己的原生会话记录，再以普通新消息发送本轮请求。摘要、保留消息、工具参数与结果保持配对；不重新执行历史工具、审批或签名推理，不用固定预算删除旧轮次。无法可靠解释的原生格式在改变会话归属前明确失败。

模型上下文与展示转录分开：界面仍读取各来源段的完整历史；导入目标的上下文前缀只供模型恢复，不在界面重复展示。`VELUNE_HOME/conversation-links.json` 只保存有序原生引用、封闭段截止位置和导入前缀边界及摘要校验，不保存正文。消息 ID 以段命名空间区分。准备目标前核对来源历史与空闲状态；取得目标身份后先保存关联再发送，结果不明时不重发或删除目标。逻辑标题沿用首段原生名称；逻辑删除逐段执行原生删除，全部成功才移除关联。

旧式引用交接仍只读还原；含旧 `<velune-context>` 载荷的来源不能当作可靠上下文再次导入，需先显式处理。ACP、DeepSeek 目标尚无原生写入契约，仍保留既有引用式路径；从它们向上述原生目标的有效上下文导出尚不支持。这些路径不宣称具备完整的 compact 翻译能力。

某些 Harness 的新会话在首条消息前没有持久记录。application 记录本次创建且尚未提交 prompt 的草稿身份；首发前改变模型来源或 Harness 时可以重建目标并保持公开会话身份。一旦尝试发送就撤销重建资格；尚未落盘的 Harness 原生草稿身份不保证跨重启保留；用户正文、附件与下一轮选择仍按[Composer 状态](composer-state.md)持久保存。

### 原生会话管理

重命名与删除由 agent-runtime 的原生操作执行，application 负责实例身份校验、执行状态与投影同步；平台不写运行时文件，也不维护标题覆盖或隐藏列表。能力由版本化描述声明，缺失的能力不以本地隐藏代替。删除前必须结束会话工作；重命名按原生元数据接口能力独立判定，不以执行中统一禁用，见[会话管理](../prd/conversations.md#会话管理)。Pi 首条消息前的未落盘会话仍由活动 SessionManager 拥有，只有身份精确匹配且确认文件不存在时，才经活动 RPC 改名或关闭空草稿。

### 会话数据通路

- **列表**：application 按实例保留最近一次列表，以同一原生读取来源校验索引、项目及回退投影，打开列表中的会话复用来源范围校验。Claude Code 与 Pi 的列表先建索引：只取文件状态与文件头的工作目录、开始时间，用于分组、计数与决定先读哪些；只解析列表窗口显示到的会话，未变化的文件复用已读摘要。搜索、协作工具与按 ID 查找按需读取所需会话。索引是进程内缓存。
- **交付**：core 为每个展示视图（上下文运行时＋会话，最近 8 个）记录已交付内容，以 generation／sequence 游标表示交付位置。快照中超过 2 KB 的推理与工具输出只携带字节数，由 `message_payloads` 按消息读取完整内容；`snapshot_update(since)` 只返回变化的消息与完整顺序。
- **平台**：轮询只传游标并按身份合并变化；展开延迟内容时按需读取。滚动条与大纲代表完整会话，不做界面分页。

## 协作

### Agent 间协作

跨 Harness 协作是会话之间的对等交流（A2A），参与方都是普通会话（[PRD](../prd/collaboration.md)）。application 持有一个 loopback MCP 服务，注入 Velune 执行的每个会话，每个会话一张随机票据；票据由 HTTP 层校验并决定调用方，工具参数不能自报身份，也不能传程序、环境或认证。MCP 线程只把调用放进收件箱，由唯一执行 owner 推进会话并处理；`ApplicationService` 在没有客户端请求时也定时推进，协作不依赖界面持续轮询。被联系的会话与用户打开的会话是同一个执行对象。工具与参数见 [application](../../packages/application/README.md)。

协作消息带出处包装，作为对方的普通下一轮提交；对方忙碌、待审批或在 Velune 外运行时拒绝，不排队。等待以“调用方尚未读到的非运行状态”判定。取消不跨会话传播，不设联系上限，循环联系由忙碌拒绝自然阻断。SSH 运行时经反向转发访问服务；只支持 stdio MCP 的 ACP Agent 使用内嵌的 Python relay。服务、转发或 relay 不可用时会话照常运行，只是没有协作工具。

### 原生子 Agent

原生子 Agent 是 Harness 自己的子会话，属于会话体验。会话模型以两个通用字段表达，平台不按运行时分支：`ConversationSummary.parent_conversation_id` 标出子会话及其父会话，`MessageBlock::Tool.conversation_id` 记录调用启动或指向的子会话。快照的 `collaborators` 另列 A2A 参与方及方向，平台把子 Agent、父会话与协作方一起呈现为关联 Agent。

- **Codex**：`collabAgentToolCall` 在恰有一个 receiver 线程时链接该线程，`subAgentActivity` 的 `started` 链接其 `agentThreadId`；线程列表按 `parentThreadId` 或 `source.subAgent.thread_spawn.parent_thread_id` 标父会话。Codex 在子 Agent 结束后归档其线程，按身份查找时只用 `thread/read` 读这一个线程，不扫描整个归档。子线程上的审批请求作为父会话的交互出现，标题前缀“子 Agent：”。
- **Claude Code**：以工具结果的 `agentId` 与任务通知链接 `<session>/agent-<id>`，历史读取父会话旁的 `subagents/agent-<id>.jsonl`；`Agent` 调用与其结果合并为一个工具块。

子会话进入 application 列表但平台不在侧栏列出；它们只读，`send_turn` 明确拒绝，A2A 的 `list_conversations` 也不提供。子 Agent 的审批、继续与取消归启动它的会话。

## 会话输入准入与调度

`ConversationActions.input_access` 独立于 `RunState`。适配器报告原生控制权，application 以执行位置、运行时目录与原生会话身份管理后台观察；首次检查、外部控制、检查不可用、外部执行与只读原因分别投影。未提供排他报告的适配器不伪装为已证明可写；原生写入仍是最终仲裁。平台只消费语义状态，不扫描锁路径、不解析原生错误。锁定保留草稿、允许复制；恢复可编辑不自动发送。发送、恢复、压缩、编辑、steer、队列启动和定时任务共用准入。

application 从原生能力、会话执行事实和本次控制权观察统一计算提交准入，再投影为 `actions.can_send`、`follow_up.can_queue`、`can_steer`、`can_resume` 与 `can_compact`。普通发送消费这次最终投影，队列受理与原生插入消费同一政策；平台不再组合父会话、待答交互或压缩状态重算业务规则。本地输入法、内容与附件准备、请求在途、尚未加载目标及早于详情到达的活动信息仍可限制本地操作。下一轮目标配置独立于会话准入：恢复和压缩只能作用于当前上下文运行时，模型、推理与权限仍由核心按实际目标校验；侧聊仅使用自己的发送路径，不取得普通会话的队列、插入或恢复资格。

`follow_up.can_queue` 表示当前输入区可以提供“排队”，只在正常会话运行中为真。它不表示已发出的排队请求只能在运行中受理：正常结束后迟到的请求可以立即派发，停止或失败后迟到的请求必须保留并暂停。这两种资格由同一政策分别计算，平台不得用当前按钮可用性拒绝已在途的请求，也不得把空闲时的新“发送”改成暂停队列。

本地调度 owner 与 `ApplicationService` 执行 owner 同寿命，复用应用 HOME 的排他锁；窗口、MCP 与远端通过同一命令管理，不能另起一份。定义 revision 与运行账本在 `scheduled-tasks.sqlite3` 保存，事务领取先于派发；重开跳过错过触发，对跨崩溃接纳结果不明的调用不自动重发。既有任务的来源与交接约束见 [定时任务 PRD](../prd/scheduled-tasks.md)。

## 自动命名兜底

application 负责实例开关、模型选择、生成时机与持久名称；ai-provider 的文本操作负责三种原生协议的请求／响应边界。调用直接消费 AI 服务，不启动 Harness 或本地网关；后台任务有取消与超时，不占核心调度线程。响应只生成标题，不带工具能力。native／generated／firstMessage 保留不同来源，原生名称优先；无原生标题的摘要在列表与 snapshot 同一处应用 generated 元数据。

生成结果写入既有会话组织记录，不修改 Harness 源文件。原生／用户命名、配置关闭或模型选择改变后，迟到结果被丢弃。平台只呈现配置与核心给出的名称，不各自发起命名请求。
