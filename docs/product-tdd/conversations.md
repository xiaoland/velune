# 会话投影、接续与协作

本页维护 conversation、agent-runtime、application、bindings 与平台之间的会话契约。包职责见[架构](architecture.md)，进程寿命见[运行时执行](runtime-execution.md)，输入内容与目标配置见[Composer 状态](composer-state.md)。

## 会话

### 会话权威与展示投影

`conversation` 是运行时中立的会话投影契约，Harness 是持久化权威。adapter 把原生历史与执行事件映射到同一类型：角色区分用户、assistant、工具与系统，内容区分正文、推理、工具与通知；工具调用与完成分开表达，保留原生关联 ID 与已有输出。原生消息身份优先，缺失时由 adapter 分配投影内稳定的身份。

Claude Code 普通发送使用一份写入原生历史的用户消息 UUID，供实时展示和冷读取共同寻址。编辑提交仍按原生分支核对。实时流合并或拆分回复导致投影和已落盘记录不一致时，读取权威历史并为同一编辑器提供新的确认基线。展示专用的接续和执行准备提示不参与源历史比对。

Claude Code 普通分叉和消息编辑在改变会话前，按当前原生回放链和压缩明确保留的记录校验分支点。若编辑点无法回放，或位于一次后来压缩之前，就导出所选用户消息之前的上下文，重建目标后发送替换消息。即使压缩保留了编辑点，后来的摘要也不能带入替换后的请求。原地替换保留逻辑会话 ID，编辑后分叉保留原会话。尚未落盘的普通原生分支若在写入首条消息前启动失败，保留分支身份、起点与输入资格，报告实际错误，等待用户决定是否重试。

Mac 可按已启用运行时的限定身份直接打开列表之外的原生会话。历史读取仍校验来源和会话身份，无需先刷新会话索引。Codex、Claude Code 与 Pi 的无缓存冷读从同一次原生读取取得摘要和消息。Pi 的路径准入沿用会话目录、子会话布局与原生父身份约束。

Pi 的原生消息与来源身份必须取自同一已固定的 SDK 投影快照，再原子安装到展示投影；不能把独立查询的身份数组与内存消息按位置合并，数量相等也不代表来源一致。同步期间的新事件按快照读取边界继续消费，不能被较旧快照覆盖；校验失败保留既有历史，不截断消息或补造身份来通过检查。

Pi 展示投影遍历 SDK 当前原生分支，复用 SDK entry 转换并应用该分支最后生效的 `context_edit` 替换／删除；来源身份沿用原 entry ID 与消息 ordinal。压缩和分支摘要作为维护事件保留，压缩前历史不因模型上下文裁剪而消失，弃置分支不重新出现。冷读与实时快照共用此投影。SDK 的 compaction-aware `buildSessionProjection`／`buildSessionContext` 继续只服务有效模型上下文，不能用其裁剪结果验证完整展示历史的导入前缀。

恢复已打开的原生 Pi 会话时，实时投影从该会话已显示的历史开始接收新事件。此显示数据不代表已同步当前原生分支，既有原生快照校验与编辑准入继续生效。创建新会话及内存侧聊沿用各自的初始化路径。连接启动诊断继续显示在历史之前，原生分支回退不会把它当作被撤销的消息。连接生成的压缩进度与结果提示只用于显示。编辑版本和来源校验使用原生压缩摘要及原生消息。

`agent-runtime::transcript` 统一产生顺序投影：application 输入消息、身份确认与执行状态，输出同一 typed snapshot 中的有序展示项、工作区间、大纲锚点与展示身份。`Message.completed` 只表示内容完整，不代表执行成功。工作区间以用户消息为锚，覆盖到下一条用户消息之前的全部响应；区间末条 assistant 消息末尾的正文块外露为回复；该消息中先前的思考、工具块与其他中间消息归入工作过程。末条不以正文结尾时整段归入工作过程，不向前寻找旧答复。执行结束与工作时长依据 Harness 生命周期；历史没有完整证据时不虚构耗时。展示身份在当前投影内稳定，live→native 确认只修改 canonical 引用；映射不持久化。原生历史可以替换、分支、压缩与重排，投影不是永久追加日志。

独立客户端通知、独立上下文维护项与外露回复的相对顺序遵守原生记录；closing 回复在遍历到该原生消息时输出，位于回复之前的独立通知仍先于回复，真正晚到的通知仍在回复之后。工作过程仍使用用户锚点下的单个分组，内部成员顺序不变；尚无外露回复时，独立通知可以显示在该分组下方，这不表示它比组内全部工作都晚。混合思考／工具与正文的 closing 消息维持原有 work 与 reply 拆分身份。

工作通知由内部 `ConversationSnapshot.work_notification_ids` 显式分类。Pi adapter 将原生 custom（含 legacy hookMessage）中的 `background-task-notification` 与 `subagent-`／`subagent_` 通知命名空间统一归组，包括 supervisor 请求、控制提醒及所有等待 outcome；不按待答、成功或需要关注状态排除，也不由正文、消息 ID 前缀或 `Client + Notice` 组合推断。原生隐藏标记仍生效，其它扩展／管理输出保留各自角色。交付层复用同一分类，把对应的 `Client` 消息以 `Tool` 角色交付，保留原有内容块与状态。原生角色仍用于历史身份、接续前缀校验和模型上下文，交付角色不合成工具调用或成功状态。`TranscriptEvent::ReplaceSnapshot` 原子消费消息、执行关联与分类；通知早于外露回复或本轮尚无回复时，按原生顺序进入 work 成员，不参与 closing 判定，真正晚到的通知仍独立位于回复之后。压缩后无用户锚点的通知保留原位；身份确认、续接命名空间、侧聊拼接与截断／分支过滤同步转换或裁剪分类 ID。平台继续只消费既有的有序展示项和 work 成员，不新增通知容器或公开 ABI。

`ContextCompaction.text` 的首行承载运行时状态；可读原生摘要附在空行后的详情中，由客户端默认折叠。Adapter依据原生结构化边界关联摘要，不生成用户消息或新的执行范围，后续只含状态的事件不擦除已有详情。客户端只拆分呈现首行与详情，不解释原生 synthetic／meta 字段。

Pi 的 `compactionSummary` 与 `branchSummary` 从原生 `summary` 字段恢复全文，分别使用“上下文已压缩”和“分支摘要”标题，复用上述折叠维护项。`bashExecution` 独立投影为客户端本地执行记录，保留命令、输出与已知状态，不伪造 assistant 调用、工具关联或新的用户轮次。custom 消息与原生状态 entry 保持区别：历史请求的存在不证明仍待答，缺少答复 entry 或失败回执也不证明尚未送达。

标题区分原生名称、Velune 生成兜底与首消息派生等来源；原生名称优先，生成规则见[自动命名兜底](#自动命名兜底)，平台消费核心提供的显示名称。时间在 adapter 边界规范为可选 Unix 毫秒，缺失保持缺失，平台负责时区与格式。snapshot 的 revision 只在当前投影生命周期内有意义，平台以请求 generation 与会话身份丢弃过期回调。

转录游标按执行上下文、会话与交付世代定序。平台通过共享的 `classify_transcript_delivery` 判定回包，再按交付的完整 ID 顺序安装增量。增量须从当前游标出发，并能解析出全部成员。过期回包丢弃，基线无法衔接或增量缺少成员时保留当前投影并读取完整快照。只有当前请求能切换完整投影的执行上下文或交付世代。延迟内容与该交付世代下的消息 stamp 一同核对。

内部完整快照的 `Executions` 关联原生执行范围与消息成员；每次明确发送／继续／主动压缩建立独立活动身份，steer 和自动恢复留在当前活动。用户显式继续可复用原展示范围，但重置本次配置捕获、恢复预算和终态消费。adapter 解释明确的结束证据，application 按活动一次性处理通知、队列与遥测；闲置、消息完成和取消意图不能替代成功／取消确认。关联只随内存快照保留，不新增会话日志或公开远控协议。

原生插入使用寻址的原会话与当前活动。目标运行时和模型是指令的意图，须与现有执行匹配。未指定的选项沿用当前执行。明确指定的推理和权限由适配器确认能否应用。Claude Code 的权限更新须收到原生控制回执，再写入同轮用户消息。控制已成功但正文未发送时按两项事实报告；正文交付不明时保留输入，暂停队列的自动发送。

续接装饰同时转换消息 ID、执行范围／成员和身份确认，保留活动身份与原生分支点。转录投影原子消费消息和执行关联，各 steer 展示段共享结果；独立维护始终独立呈现，轮次内压缩完成后进入工作过程。原生历史没有结果证据时保持未知。

### 浏览与执行准备

已归档会话工具窗口从既有application owner派生独立client view，不重复打开同一个本地home。归档开关、筛选、分页、原生归档缓存和列表投影属于该view；本地派生视图的呈现隔离与远程执行权限分别表达，持久化配置保留主视图的呈现默认值。Trace／composer装饰保留view身份，释放或关闭派生视图不关闭共享owner或停止工作。平台持有独立归档列表投影，不将归档快照写回共享设备的主列表；会话管理仍使用所属设备的操作与删除通知，成功后重读各自视图。

归档窗口刷新时读取各实例的原生归档。需要解析 Velune 归档标记时，才更新其会话和关联段所属实例的普通索引。归档标题搜索复用索引，仅补读这些标记及关联段的摘要，并覆盖未显示的分页。原生归档读取失败时按实例报告，其他来源仍可浏览。

本地 Codex 归档优先使用原生索引分页。核对已有归档文件的身份和更新时间，遇到旧格式、索引遗漏或状态不一致时使用 Codex 自己的完整读取和修复。对未被原生列表收录且没有预览的归档子会话，按原生身份确认其状态。Mac 归档窗口首次激活复用同一次首屏读取。

列表合并全部启用实例，不按当前执行实例过滤；禁用实例保留配置与原生数据，但不读取其历史，也不出现在可执行选择中。每个实例的读取失败独立报告，不解释为其他来源没有会话。历史读取 helper 是只读适配步骤，不是执行进程：读取不要求模型、认证或工作目录仍可执行，详情 ID 必须属于所选实例的列表，不接受任意路径。分组、筛选与排序是展示投影，与会话打开和执行归属分开。

新建会话给出运行时、工作目录与模型，首次发送时自动准备并由 Harness 建立会话。准备失败保留内容与选择，修正后可重试，不自动重发已被接受的消息；配置变化只使执行装配失效。Pi 可从原生记录恢复有效的模型选择；Codex 与 DSH 的历史只有 API model ID，不能证明提供商，继续前要求选择。

Pi 启动时由原生 SessionManager 为新草稿预留会话文件。Core 用该文件身份发布草稿并派发首条输入，首轮写入仍由同一个 SessionManager 完成。

原生索引、Codex 项目与归档／按身份查找的回退投影使用同一个读取来源身份。客户端上次列表的条目与来源共同保存在 `ListedProjection`，所有读取入口先校验来源，覆盖跨客户端视图恢复后的查找、管理和关联会话信息。`RuntimeSourceKey` 包含实例及 Adapter Type，直接复用实际 Pi history、native `HistoryConfig` 或 ACP launch 配置。缓存身份检查只进行纯解析，进程与资源准备由读取入口负责。实例名称、新会话策略及 Velune 网关／提供商变化可以复用已读摘要和项目。归档按来源分组，每个来源验证一次，共享来源标记减少重复存储。

逻辑会话的首段来源与当前末段上下文是不同地址。只读快照与冷历史读取接受首段或当前末段运行时，并归一化到同一逻辑投影；不接受中间段或无关运行时。composer 请求仍以首段来源寻址，下一轮运行时保存在独立选择中；只读地址归一化不能修改发送目标或放宽原生写入的来源校验。

写入缓存前核对捕获的来源仍为当前来源，拒绝迟到的旧来源结果。真实来源改变、实例停用／删除或当前来源读取失败时，统一清理索引、项目及回退投影。恢复旧客户端视图同样经过来源校验。当前来源解析失败时清空该实例缓存。当前来源有效时，旧请求的失败只能清理与它相同的来源。

读取来源与执行配置分别表达依赖。Pi 的 `sdkHelper` override 只供执行装配使用，历史读取使用自己的 helper。因此修改它使执行配置失效，同时保留历史缓存。执行配置由 `execution_configuration` 及已捕获的 gateway／backends 管理，提供商内容变化走网关执行失效路径。

### 下一轮选择与跨 Harness 接续

下一轮的运行时与模型是发送意图，不随浏览的历史来源变化。历史的原生来源负责读取、重命名与删除；已开始的轮次保留自己的实例、会话与模型，用于轮询、取消与交互回复。`send_turn` 显式接收来源会话、目标运行时与选择，同来源时恢复原生会话。

不同 Harness 的原生会话 ID 不能互相恢复。跨 Harness 接续为线性逻辑会话：每次切换（包括切回）创建目标原生会话。Claude Code、Codex 与 Pi 之间以**原生上下文翻译**接续：来源 adapter 导出 compact 和分支选择后的有效模型上下文，经过独立的中性上下文类型，目标 adapter 写入自己的原生会话记录，再以普通新消息发送本轮请求。摘要、保留消息、工具参数与结果保持配对；不重新执行历史工具、审批或签名推理，不用固定预算删除旧轮次。无法可靠解释的原生格式在改变会话归属前明确失败。

模型上下文与展示转录分开：界面仍读取各来源段的完整历史；导入目标的上下文前缀只供模型恢复，不在界面重复展示。`VELUNE_HOME/conversation-links.json` 只保存有序原生引用、封闭段截止位置和导入前缀边界及摘要校验，不保存正文。消息 ID 以段命名空间区分。准备目标前核对来源历史与空闲状态；取得目标身份后先保存关联再发送，结果不明时不重发或删除目标。逻辑标题沿用首段原生名称；逻辑删除逐段执行原生删除，全部成功才移除关联。

保留段和导入前缀的摘要兼容已发布的错误展示格式：将原通知升级为 `RuntimeFailure` 时，可按旧通知编码重新计算并精确匹配原摘要，不能仅因显示类型变化拒绝编辑。此兼容不清空或重写旧摘要，不忽略角色、正文或工具结果变化。失败诊断记录逻辑会话与原生来源的安全身份、运行时、段索引、前缀种类，以及长度不足或摘要不符的具体原因。

旧式引用交接仍只读还原；含旧 `<velune-context>` 载荷的来源不能当作可靠上下文再次导入，需先显式处理。ACP、DeepSeek 目标尚无原生写入契约，仍保留既有引用式路径；从它们向上述原生目标的有效上下文导出尚不支持。这些路径不宣称具备完整的 compact 翻译能力。

某些 Harness 的新会话在首条消息前没有持久记录。application 记录本次创建且尚未提交 prompt 的草稿身份；首发前改变模型来源或 Harness 时可以重建目标并保持公开会话身份。一旦尝试发送就撤销重建资格；尚未落盘的 Harness 原生草稿身份不保证跨重启保留；用户正文、附件与下一轮选择仍按[Composer 状态](composer-state.md)持久保存。

### 原生会话管理

重命名与删除由 agent-runtime 的原生操作执行，application 负责实例身份校验、执行状态与投影同步；平台不写运行时文件，也不维护标题覆盖或隐藏列表。能力由版本化描述声明，缺失的能力不以本地隐藏代替。删除前必须结束会话工作；重命名按原生元数据接口能力独立判定，不以执行中统一禁用，见[会话管理](../prd/conversations.md#会话管理)。Pi 首条消息前的未落盘会话仍由活动 SessionManager 拥有，只有身份精确匹配且确认文件不存在时，才经活动 RPC 改名或关闭空草稿。

Codex 的 `inter_agent_communication_metadata` 只记录投递／唤醒信息，按原生 replay 跳过；对应 `response_item.agent_message` 的明文正文仍保留，带作者与接收方归属转换为 assistant 上下文，不成为用户输入。未知记录、未知内容或加密 Agent 正文不能静默丢弃，须在提交目标关联前明确失败。

Codex 的 `configuration_update` 型推理强度记录由原生 backend 解释，便携上下文保留对话内容并使用目标这次发送的执行配置。若 Agent 投递包含加密正文，投递抬头不足以还原正文。跨提供商导出返回明确的摘要前置条件；只有使用源模型生成并核验的可移植摘要，才会把有效历史概括为目标输入。普通的同提供商原生接续仍直接使用原生历史。

Codex 摘要在带标记的临时副本中通过原生本地压缩生成，沿用来源提供商与认证，压缩模型请求不执行工具。`thread/compact/start` 的回执只确认启动，adapter 等待同一副本的原生压缩终态，按该轮追加记录核验新助手文本和压缩检查点。application 保留活动作业与关联队列直到终态、取消或连接失败，结果缓存的回收只在交接完成或无人持有时生效。

### 会话数据通路

`ClientViewId` 分别保存各组的初始容量和追加页数。组重排复用容量。折叠释放的容量分给尚未获配的展开组。来源刷新重分初始容量，保留追加页。重置分页或修改限额会清除容量。

分页与浏览偏好修改复用索引，只补读当前窗口缺少的摘要。部分失败时，`ConfigurationSnapshot` 同时交付可用列表和 `historyFailures`，`loaded` 只计显示的条目。Mac 分页先展开来源组并合并同组请求。可见条目数未增加且回包报告相关来源失败时，在该组显示错误。

- **列表**：application 按实例保留最近一次列表，以同一原生读取来源校验索引、项目及回退投影，打开列表中的会话复用来源范围校验。Claude Code 与 Pi 的列表先建索引：只取文件状态与文件头的工作目录、开始时间，用于分组、计数与决定先读哪些；只解析列表窗口显示到的会话，未变化的文件复用已读摘要。搜索、协作工具与按 ID 查找按需读取所需会话。索引是进程内缓存。
- **交付**：core 为每个展示视图（上下文运行时＋会话，最近 8 个）记录已交付内容，以 generation／sequence 游标表示交付位置。快照中超过 2 KB 的推理与工具输出只携带字节数，由 `message_payloads` 按消息读取完整内容；`snapshot_update(since)` 只返回变化的消息与完整顺序。
- **平台**：轮询只传游标并按身份合并变化；展开延迟内容时按需读取。滚动条与大纲代表完整会话，不做界面分页。

## 协作

### Agent 间协作

跨 Harness 协作是会话之间的对等交流（A2A），参与方都是普通会话（[PRD](../prd/collaboration.md)）。application 持有一个 loopback MCP 服务，注入 Velune 执行的每个会话，每个会话一张随机票据；票据由 HTTP 层校验并决定调用方，工具参数不能自报身份，也不能传程序、环境或认证。MCP 线程只把调用放进收件箱，由唯一执行 owner 推进会话并处理；`ApplicationService` 在没有客户端请求时也定时推进，协作不依赖界面持续轮询。被联系的会话与用户打开的会话是同一个执行对象。工具与参数见 [application](../../packages/application/README.md)。

协作消息带出处包装，作为对方的普通下一轮提交；对方忙碌、待审批或在 Velune 外运行时拒绝，不排队。等待以“调用方尚未读到的非运行状态”判定。取消不跨会话传播，不设联系上限，循环联系由忙碌拒绝自然阻断。SSH 运行时经反向转发访问服务；只支持 stdio MCP 的 ACP Agent 使用内嵌的 Python relay。服务、转发或 relay 不可用时会话照常运行，只是没有协作工具。

### 原生子 Agent

Pi的原生描述由adapter填入snapshot.sub_agents，application合并关联，不从普通后台任务推断原生子关系。描述来自append-only父记录中的调用、结构化结果及通知，冷inspect和热metadata使用同一验证器；SessionManager的name和有效消息保持原义。run身份与原生session路径分别建模，resume依据原生调用关系映射旧session，不以新run ID猜目录。活动children只来自当前完整RPC观察，停止只指向已验证单子项的当前run；描述保留不表示活动。

内部metadata帧带父session身份，JS缓存及异步发布按父作用域和读取序号隔离；Rust以SDK当前投影的原生路径校验，不能以可能过期的启动配置覆盖当前owner。SDK换父时清除旧描述；缺字段的旧get_messages响应不擦除同父已知描述。新资源模块须随完整端bundle与SSH执行资源一起部署。


原生子 Agent 是 Harness 自己的子会话，属于会话体验。会话模型以两个通用字段表达，平台不按运行时分支：`ConversationSummary.parent_conversation_id` 标出子会话及其父会话，`MessageBlock::Tool.conversation_id` 记录调用启动或指向的子会话。快照的 `collaborators` 另列 A2A 参与方及方向，平台把子 Agent、父会话与协作方一起呈现为关联 Agent。

- **Codex**：`collabAgentToolCall` 在恰有一个 receiver 线程时链接该线程，`subAgentActivity` 的 `started` 链接其 `agentThreadId`；线程列表按 `parentThreadId` 或 `source.subAgent.thread_spawn.parent_thread_id` 标父会话。Codex 在子 Agent 结束后归档其线程，按身份查找时只用 `thread/read` 读这一个线程，不扫描整个归档。子线程上的审批请求作为父会话的交互出现，标题前缀“子 Agent：”。
- **Claude Code**：以工具结果的 `agentId` 与任务通知链接 `<session>/agent-<id>`，历史读取父会话旁的 `subagents/agent-<id>.jsonl`；`Agent` 调用与其结果合并为一个工具块。

子会话进入 application 列表但平台不在侧栏列出；它们只读，`send_turn` 明确拒绝，A2A 的 `list_conversations` 也不提供。子 Agent 的审批、继续与取消归启动它的会话。

### 后台任务观察与控制

Mac 按会话与请求代际接收任务读取和停止回执，切换目标时撤下旧任务和操作。输出按任务身份保存，刷新或重试失败时仍可读上次成功的同任务输出。关闭详情停止输出轮询。

`ReadBackgroundTasks` 从当前或停放的执行连接读取 `BackgroundTaskInfo`。无实时宿主返回 `live: false`，故障填 `issue`。`ReadBackgroundTaskOutput` 发起有界读取，后续按任务和请求 ID 查询。每连接保留至多 8 个结果，每个至多 64 KiB，10 秒超时。详情可见且结果为 `Checking` 时每秒查询一次。

`ReadBackgroundTasks.manual` 默认为 `false`。手动刷新与自动查询重叠时，Mac 在当前查询结束后补发一次。Codex 跳过查询冷却期，Pi 向桥接请求完整快照，Claude Code 在 stream-json 连接上请求重发活动任务。后续轮询取回结果。读取和刷新限于已有连接，Core 无需等待运行时回包。

会话活动只投影前台轮次、待答交互及已观察到的后台执行。后台状态检查和完成通知交付可以保留宿主连接，活动列表在这些阶段保持原生执行状态。

Pi 桥保留 Host v1 的 task ID、kind、描述、状态和操作能力；`stop` 只发送精确 task ID，`logs` 请求最多 64 KiB，delegate/fusion 优先读取 Host 校验的 `result`。命令只写 RPC，Host EventBus 在原生侧异步执行，普通 poll 收取按请求归属的状态帧，application owner 不等待 Host 或日志 IO。delegate 仅从该任务的 artifact/child-session 路径检查 manifest 的 task／nonce／seed／child ID、当前父 session 和子文件头，缺失或不符时保持普通任务。

Pi 后台通知的宿主保留期由原生交付或取消证据结束。原生清队列成功响应携带该次实际移除的通知 ID，按当前连接和会话代际结算。清队列之后到达的通知继续等待原生交付；已写入历史的通知仍可按历史回执确认。

Claude 使用结构化 task events 与 `background_tasks_changed` 的完整活动集合，不以通知文本解析 live 状态。任务按进程 epoch、native task ID 与 run ID 隔离，旧 run 和迟到停止 ACK 不能覆盖新 run 或终态。`stop_task` 能力保守限定为已证实的 CLI 2.1.292 及之后版本，复用原有启动版本结果；旧版仍可观察，不额外探测或回退到父 `interrupt`。ACK 仅确认请求，任务保持 Stopping 直到终态或完整活动集合证明结束；控制超时不释放仍活动的进程。任务描述不成为结果，仅结构化 summary/output 可读。任务缓存以 128 项为回收目标，活动工作不驱逐；回收非活动项时同步移除其输出。

Codex 通过已有 app-server 连接的 `thread/backgroundTerminals/list` 观察原生后台终端。后台终端与协作线程分别投影。单项停止以线程和已观察的 `processId` 寻址，终态使用匹配的原生命令事件。任务从清单消失只证明它已离开活动清单。终端运行期间使用面板单独停止。处理协作线程的批量停止既有回执不代表终端已停止。终端输出继续由消息中的原生命令记录呈现。

## 会话输入准入与调度

`ConversationActions.input_access` 独立于 `RunState`。适配器报告原生控制权，application 的共享观察服务按完整物理来源去重，并在视图之外推进刷新与截止时间。Session 查询只读缓存；同一来源的已排队或执行中任务未实际结束前，不因超时、失效或历史驱逐而另起探测。首次等待和缓存新鲜度均有界，饱和或失效不能无限保持“正在检查”或沿用过期可写事实。首次检查、外部控制、检查不可用、外部执行与只读原因分别投影。未提供排他报告的适配器不伪装为已证明可写；原生写入仍是最终仲裁，原生拒绝使旧观察失效。平台只消费语义状态，不扫描锁路径、不解析原生错误。锁定保留草稿、允许复制；恢复可编辑不自动发送。发送、恢复、压缩、编辑、steer、队列启动和定时任务共用准入。

主动释放通过同一执行 owner 记录交接，先阻止队列和定时任务再次派发，再等工作与交互结束并释放执行。已释放、正在释放和允许释放由 `FollowUp.control_handoff` 投影。平台用当前原生上下文身份发起操作。恢复派发由用户明确发起，之后仍须通过原生准入。外部能否接续取决于适配器的原生恢复能力、HOME 和 provider。

application 从原生能力、会话执行事实和本次控制权观察统一计算提交准入，再投影为 `actions.can_send`、`follow_up.can_queue`、`can_steer`、`can_resume` 与 `can_compact`。普通发送消费这次最终投影，队列受理与原生插入消费同一政策；平台不再组合父会话、待答交互或压缩状态重算业务规则。本地输入法、内容与附件准备、请求在途、尚未加载目标及早于详情到达的活动信息仍可限制本地操作。下一轮目标配置独立于会话准入：恢复和压缩只能作用于当前上下文运行时，模型、推理与权限仍由核心按实际目标校验；侧聊仅使用自己的发送路径，不取得普通会话的队列、插入或恢复资格。

原生插入以正在执行的轮次为模型和推理强度来源，适配器只接收正文、附件和适用的明确权限变更。平台的下一轮模型目录、草稿同步与其他队列项独立于插入已有队列项。排队另起一轮仍使用该项保存的配置。

`follow_up.can_queue` 表示当前输入区可以提供“排队”，只在正常会话运行中为真。它不表示已发出的排队请求只能在运行中受理：正常结束后迟到的请求可以立即派发，停止或失败后迟到的请求必须保留并暂停。这两种资格由同一政策分别计算，平台不得用当前按钮可用性拒绝已在途的请求，也不得把空闲时的新“发送”改成暂停队列。

本地调度 owner 与 `ApplicationService` 执行 owner 同寿命，复用应用 HOME 的排他锁；窗口、MCP 与远端通过同一命令管理，不能另起一份。定义 revision 与运行账本在 `scheduled-tasks.sqlite3` 保存，事务领取先于派发。已确认的轮次结果按运行 ID 交给调度账本，临时写入失败由当前调度器在标记结果不明前重试。会话关闭或应用重开时，按账本已保存的轮次终态结算，缺失终态标为结果待核查。重开跳过错过触发，对跨崩溃接纳结果不明的调用不自动重发。既有任务的来源与交接约束见 [定时任务 PRD](../prd/scheduled-tasks.md)。

## 自动命名兜底

application 负责实例开关、模型、提示词、生成时机与持久名称；ai-provider 的文本操作负责三种原生协议的请求／响应边界。调用直接消费 AI 服务，不启动 Harness 或本地网关；后台任务有取消与超时，不占核心调度线程。响应只生成标题，不带工具能力。native／generated／firstMessage 保留不同来源，原生名称优先；无原生标题的摘要在列表与 snapshot 同一处应用 generated 元数据。Claude Code 的实时事件不包含标题，Core 在正常完成后通过原生历史读取器检查已持久化的命名记录，刷新实时投影后再决定是否需要生成。

生成结果写入既有会话组织记录，不修改 Harness 源文件。原生／用户命名、配置关闭、模型或提示词改变后，迟到结果被丢弃。平台只呈现配置与核心给出的名称，不各自发起命名请求。
