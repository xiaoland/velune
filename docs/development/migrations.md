## 破坏性变更与手动迁移

允许 hard-reset／hard-cutoff，但涉及已有数据或配置时，必须在切换到新格式的版本前完成显式手动迁移并核验结果，不能用“旧数据会被重置”代替迁移交付。原 Harness 会话与认证的处理边界保持不变。

迁移可以由 Agent 手工完成，也可以编写并显式执行一次性脚本。脚本自动处理转换仍属于手动发起的迁移；应用运行时不自动检测并转换旧格式，不引入长期维护的自动迁移框架、兼容层或多版本迁移链。

一次性迁移脚本归 `scripts/migrations/`，文件名顺序即执行顺序，接口统一为 `--home <VELUNE_HOME>`（必填）与 `--apply`（写入，缺省为预览）。脚本自行获取 `runtime.lock` 排他锁，不改动正在运行的核心；自检适用性并幂等，无事可迁移时以 0 退出，前置条件不满足（如需人工核对的实例）以非 0 退出并说明手工步骤。`scripts/run-migrations.py --home <dir>` 先探测目录锁占用并列出占用进程，再顺序执行全部迁移，任一失败即中止。Mac 重装在安装后、启动新版前对本机状态目录调用该入口（见[开发环境](environment.md#mac-重装)）；这是用户显式发起重装的一部分，不属于应用运行时自动迁移。

当前显式升级步骤包含普通配置 schema 10→11 的查询凭据类型转换、旧 composer 输入接入及内容／目标选择拆分、Codex 实例类型调整和 Mac 输入区宽度比例转换。宽度以 1280pt 为固定参考，将旧值除以 1280 并钳制到 50%–100%；保留原外观文件备份。完整 runner 在各步拒绝不认识的数据后停止，不能以直接启动新版绕过。

对应任务记录迁移的来源与目标格式、执行方式和验证结果；未完成的迁移明确保留为升级前的待办。真实数据与凭据操作仍遵守[隔离验证与敏感数据](../development.md#隔离验证与敏感数据)。本约定修订此前“不写迁移、直接清空旧普通配置”的规则，来源见 [S63](../sources/development.md#s63)。

## Codex 0.166 实例迁移

0.166 改变了 provider 准入，采用独立的 `codex-0.166` 类型。先安装包含新适配器的构建，再正常退出使用该状态目录的所有 Velune 进程。保留实例 ID 与 CODEX_HOME；本机先预览 `python3 scripts/migrations/codex-166.py --home <VELUNE_HOME>`（可加 `--runtime <实例ID>` 限定单个实例），确认范围后加 `--apply` 显式迁移。脚本验证所配置 CLI 为 0.166.x，同时修改实例的 `typeId` 与 `conversation-links.json` 中该实例的旧 `runtimeTypeId`，原文件以私有权限保存在状态目录下的一次性备份中；不访问原生会话正文或认证存储，不修改 Harness 配置。中断可重跑，已经迁移的实例仍会修复剩余关联段。SSH 实例先在执行机器核实 CLI，再手动完成同样的两处类型修改。应用不自动迁移，不要仅改实例类型而遗漏已有会话关联。
