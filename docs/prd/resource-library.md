# 资源库

Agent 运行时的用户指令、MCP、技能与子 Agent 定义的管理：以资源为中心，启用于若干运行时并保存即同步。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 范围

2026-10-11 用户进一步要求将 Agent runtime 管理从会话、模型扩展到 user instruction、MCP、agent skills 与 sub-agent 定义。各运行时允许缺少相应能力或资源；宿主须能区分不支持、尚未配置和读取失败，不能把缺失伪装成统一支持。管理保留原生资源归属与运行时差异，sub-agent 定义不等同于执行中的子会话。App 管理界面的组织见下文“资源库”段落。实施与验收归 [运行时资源管理任务](../../tasks/runtime-management/packet.md)。

## 组织

2026-10-11 用户要求 Mac App 接入 Agent 运行时的用户指令、MCP、Agent skills 与子 Agent 定义的管理，并要求在 UI／UX 上投入。设置窗口保持紧凑的固定尺寸，Agent 运行时页只保留实例列表与配置；资源管理放在独立、可缩放的“资源库”窗口。

同日经多轮讨论后用户重新梳理，确定以资源为中心（取代“运行时为主、模板为辅”的两条导航轴与分组／梯级覆盖设想）：

- **概念只有资源与运行时**。资源是 Velune 资源库中的一份定义（指令、技能、MCP 服务器、子 Agent），采用 Velune 的 canonical 格式，按各运行时的原生格式写入；运行时不支持的类别或字段跳过并说明原因，不伪造。资源“启用于”若干运行时实例：勾选即写入并持续同步，批量就是多勾选几个运行时；“全局”指资源库本身，不是默认作用于全部运行时的一层。
- **窗口结构**：侧栏为四个类别；中间栏列出该类别的资源，以及“运行时中的其他内容”（不在资源库的原生条目）；详情为资源编辑器与“启用于”运行时列表及各自状态。
- **保存即同步**：保存资源立即写入所有已启用且处于同步状态的运行时；运行时忙（有任务运行或协作 scope）时显示“待同步”，可稍后重试。
- **原生被改或被删**：不静默覆盖，在该运行时一行由用户选择“用资源库覆盖”或“不再同步（保留原生）”。2026-10-13 用户改为需要回填（[S21](../sources.md#s21)）：原生被改时还可以“用原生内容更新资源库”，资源随之更新并按保存即同步写入其他已启用的运行时；无法带入的原生字段先列出再由用户确认。停用（取消勾选）时由用户选择删除原生内容或保留原生内容。
- **原生内容只在资源库编辑**：不在资源库的原生条目只读显示，唯一操作是“加入资源库”，加入后自动启用于来源运行时；无法带入的原生字段先列出再由用户确认。启用到已有同名原生条目的运行时需确认覆盖。
- 指令整文件写入，每个运行时最多启用一份指令资源；不同资源的内容不拼接。
- MCP 等资源中的秘密与 AI 提供商一致：保存在 Velune 私有文件，可显式查看编辑，默认遮盖，公开描述、日志与 Debug 不含秘密。
- 首轮只管理用户范围，项目范围另行设计。Velune 只对资源库写入的条目负责，其余原生内容仍归运行时所有。

## MVP

2026-10-11 用户认可此组织后要求推进到 MVP，并确定范围：

- **从运行时批量导入**：选一个运行时，列出其所有不在资源库的内容，多选后一次加入资源库（各自启用于该运行时）；逐条“加入资源库”保留。资源库表达不了的原生字段维持现状：列出后丢弃。暂不做从磁盘导入。
- **原生被改时可看差异**：覆盖前对比原生内容与资源库版本。
- **待同步自动补写**：轮次结束、运行时空闲后自动写入待同步的运行时。
- **未保存修改保护**：草稿在应用运行期间保留，关闭窗口不丢失；退出应用时提醒未保存的修改。
- **生效说明**：同步后说明修改何时被运行时加载，不替用户重启会话。
- **真实 Harness 加载验证**：在隔离环境确认 Claude Code、Codex、Pi 能识别写入的内容，不调用模型、不读取真实配置。
- **MCP 完善**：原始 JSON 视图（可粘贴文档中的声明），补常用字段（工作目录、超时）。不另设启用开关：是否启用即“启用于”的勾选，且 Claude Code 的条目本身无法表达停用。
- **批量与便捷**：启用于所有运行时、新增运行时后提示可启用已有资源、列表搜索、复制资源。
- 技能编辑器增强（目录树、附件、头部校验）不在本轮。

实施与验收归 [运行时资源管理任务](../../tasks/runtime-management/packet.md)。

## 子 Agent 资源

2026-10-14 用户要求补全子 Agent 资源（[S23](../sources.md#s23)）：描述与指令一样用多行文本编辑；可配置推理强度；可选择资源库中的技能；Codex 子 Agent 的模型与推理强度要写入，加入资源库时也要带入，不再丢弃。各运行时按原生格式写入能表达的字段，表达不了的照常跳过并说明。同日用户进一步要求子 Agent 既能用 Velune 托管模型也能用原生模型，同一运行时可随时在经 Velune 网关的轮次与原生轮次之间切换，并且选 Velune 模型的子 Agent 在原生轮次中不会被运行时用到：子 Agent 的模型为“沿用父会话”“原生 model ID”或“Velune 模型”之一；原生 ID 写入原生定义，经网关的轮次中改由 Velune 中唯一同 ID 的模型提供；Velune 模型的子 Agent 不写入原生定义，只提供给经网关的轮次。Pi 的子 Agent 由扩展提供，用户计划之后单独支持，届时需处理扩展的版本兼容，不在本轮。实施归 [子 Agent 字段任务](../../tasks/resource-subagent-fields/packet.md)。
