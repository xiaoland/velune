# 会话与会话列表

会话的权威与投影、运行状态、会话列表的浏览、分组、项目与管理，以及侧聊。

本页维护当前规则；来源链接用于追溯决定，历史表述不单独构成当前要求。产品入口见[产品定义](index.md)。

## 会话权威与投影

Harness 拥有原生会话历史和持久化，Velune 投影其会话与运行状态，不另存一份消息正文。早期 Pi 切片确立这一边界（[S15](../sources/first-loop.md#s15)），后续适配器沿用；会话关联与列表组织元数据的例外分别见[跨 Harness 接续](collaboration.md#跨-harness-接续)和下文。开发验证与真实数据边界统一见[开发说明](../development.md)。

2026-10-06 用户要求内部具有权威的会话／消息模型，UI 展示可按内容拆分为多个条目，不必逐个照搬领域消息。Harness 仍拥有持久化，Velune 的内部权威是运行时中立的会话投影，展示层不建立另一份会话存储。

2026-10-11 用户明确会话的唯一权威（SSoT）始终在 Agent 运行时侧：会话可能在 Velune 之外变化或仍在运行（包括不是从 Velune 发出的 turn），状态漂移无法完全排除，追求完全一致的投入不值得，采用 best-effort。正在运行的会话应在会话列表中有指示，消息列表流式显示实时进展；理论上外部发起的进行中 turn 也应尽量识别；同时提供手动“重新读取”，从运行时重新读取会话列表与当前会话。2026-10-12 用户澄清：“是否在 Velune 之外运行”不重要，重要的是“正在运行”；这是 Velune 作为 shell 对齐原生运行状态的问题，本质仍是会话 SSoT，各适配器按所属 Harness 的原生机制分别判断。界面对 Velune 发起与外部发起的运行使用同一“正在运行”表达，不再区分“可能在 Velune 之外运行”。下一轮默认与明确选择的解析统一见[输入区](composer-choices.md#选择器与下一轮选择)。消息布局与阅读操作归[消息展示](conversation-view.md)。

2026-10-06 用户进一步明确：主界面 Agent 运行时与模型选择表示下一轮发送时的执行目标，不表示正在浏览的原生历史来源。浏览、导航与目标选择的切换规则见[输入区](composer-input.md#内容与目标的归属)。历史读取和原生重命名／删除按会话来源执行；已经发出的轮次由固定执行实例负责轮询、取消和交互回复，不跟随之后编辑的目标。

## 会话管理

2026-10-23 用户要求接入 Xuanwo/xurl 的 `agents://` 会话地址（[S47](../sources/conversations.md#s47)）。Mac、Windows 和 Android 支持点击 `agents://` 深链直接打开会话，无需复制地址、粘贴或手动查找。会话正文内的链接使用该会话所在设备；系统外部链接在 Windows 默认指向本机，Mac 使用接收链接的窗口所控制的设备，Android 只有一台已配对设备时自动使用它，否则先选择设备。地址本身不含设备或 Velune 实例身份，定位在当前控制的设备已配置实例中进行；只有全部相关实例读取成功且唯一匹配时直接打开，多匹配由用户选择，局部失败明确显示。复合会话没有一个能代表全部原生段的 xURL 地址，继续使用 Velune 深链；原生子 Agent 打开后仍只读。

2026-10-26 用户要求恢复复制 xURL，并将会话菜单中的拷贝操作合并为二级菜单。Mac 与 Windows 的单会话右键菜单提供“拷贝”，内含“会话 ID”“Velune 链接”，仅在核心提供有效原生地址时增加“xURL”。复制地址用于交给 Agent、终端或其他工具，不恢复手动输入或查找页面；复合会话不提供 xURL。地址不包含正文，也不授予对原生会话数据的访问权限。

会话管理提供重命名与删除，操作真实作用于所属 Agent 运行时的会话数据，不建立 Velune 标题覆盖。归档与已读优先采用可用原生能力；普通项目、Codex 原生项目及显式列表组织记录的规则见[会话列表](#会话列表)，不是标题覆盖或删除替代。缺少原生名称时的生成名称另见[自动命名兜底](#自动命名兜底)。切换会话时立即表达目标选中与加载状态，已加载内容与待加载目标分别管理；旧轮询或迟到结果不得将选中态恢复为原会话。加载失败应明确反馈并保持可理解的选中和内容关系。

2026-11-02 用户指出运行中会话无法重命名的统一限制（[S61](../sources/dogfood.md#s61)）：原生标题修改与删除分别判断，轮次或子 Agent 运行不构成统一禁用重命名的理由。使用运行时的元数据接口修改真实标题，保留当前执行、审批与队列，不启动新轮次；跨 Harness 会话仍修改原生来源标题并保留执行中的尾段。没有原生重命名接口或原生操作实际失败时明确说明，删除仍需先停止该会话的工作。

会话加载不禁用列表的上下文菜单或原生重命名／删除操作。用户可在加载中打开并提交管理操作；实现负责正确安排加载与原生修改的先后顺序，不能因笼统 loading 标志静默忽略操作。执行、关闭或确实不支持的能力仍具有各自边界。

2026-10-29 用户要求（[S56](../sources/conversations.md#s56)）会话的右键菜单能停止与继续会话，并能在 sheet 中打开输入区发送一次消息；首个 beta 前只做 Mac。单会话菜单按会话当前状态提供：本轮运行中提供“停止”，与输入区的停止相同，同时停止该轮及其子 Agent；轮次已结束、只剩子 Agent 运行时提供“停止子 Agent”；具备继续资格时提供“继续”，资格、原生恢复或文本兜底方式与输入区的[继续](composer-actions.md#发送队列与-steer)一致，沿用该会话保存的下一轮选择；“发送消息…”在 sheet 中打开该会话的输入区（见[在 sheet 中发送](composer-actions.md#在-sheet-中发送)）。多选时只提供“停止”，作用于所选会话中正在运行的那些。这些操作不要求先打开会话，也不改变列表选中与当前显示的会话；动作执行时由核心重新判定资格，状态已变化时明确显示原因。

## 会话列表

2026-11-02 用户明确会话列表的点击分工（[S60](../sources/dogfood.md#s60)）：双击只触发重命名，不触发切换或打开；单击才切换或打开。双击的首击不能先产生导航副作用；列表选择与正在显示的会话须能分别表达，键盘导航、多选管理和拖拽继续保持平台原生行为。

2026-11-03（[S67](../sources/dogfood.md#s67)）：已读／未读有可用原生接口时以运行时记录为准，没有时保留 Velune 的列表组织状态。打开已有列表中的会话不先刷新全部运行时；本地已读标记等列表组织操作不等待无关运行时扫描。单击导航仍须保留“双击只重命名”的语义。

2026-11-03（[S68](../sources/dogfood.md#s68)）：已打开且闲置的会话可以归档，当前内容继续可读；正在执行的会话仍须先停止。归档、重命名和删除由设备接收并排队，用户可以继续处理其他会话；按目标展示等待或执行，失败不吞后项，完成结果独立于发起操作的标签页及其后续导航。原生已读接口使用用户实际看到的列表或正文版本；版本冲突只刷新和说明，不盲目重试覆盖后来出现的结果。

会话浏览使用统一列表，纳入所有启用 Agent 运行时的会话。当前执行运行时不作为隐式列表筛选条件；运行时、CWD／project、label／section 可用于显式分组或筛选，创建时间和更新时间可用于排序。不同来源的会话仍保持所属实例身份；浏览分组不改变执行归属。懒加载或分页是可采用的实现方式，不能变成按运行时切换后才看见该来源的入口。用户随后澄清 label／section 仅为示例，不要求本轮接入。若增加自定义 tag／label／section，应独立持久化 Velune 的列表组织记录，不能混同各 Harness 的原生概念；Codex section 用于聚合 project，不是通用会话标签。当前切片先完成运行时／项目分组筛选和时间排序。

会话列表记住用户选择的分组、运行时与项目筛选、时间排序及方向，应用重启后恢复。浏览偏好属于 Velune 配置，不修改原生会话数据，也不选择下一轮执行运行时；临时搜索文字不作为持久偏好。

2026-10-14 会话列表管理（[S24](../sources/conversations.md#s24)）：分组可折叠，折叠状态与其他浏览偏好一同记住；组按最近活动排序。

### 按需加载

会话列表支持平台原生多选，默认每次加载 20 条，可在应用设置修改加载条数。批量管理仍执行原生会话操作，保留每项所属运行时身份。

整个列表设总数上限，各组按需展开，组内只提供“加载更多”，不提供“显示全部”。运行时若有按项目组织的原生存放或注册信息，应借此分组与计数，只按需读取每组的前 N 个会话，不为分组而读出全部原生会话。项目组织见下文多文件夹项目与 [Codex 原生项目](#codex-原生项目)。

### 组织与状态

会话可以置顶、标记已读／未读、移到另一项目，以及拷贝会话 ID 与 Velune 深链。归档原生优先：运行时有原生归档（Codex）时使用原生操作，其余由 Velune 记录、不修改原生会话；已归档会话默认隐藏，可切换查看并取消归档。置顶、显式移动后的项目归属、普通项目名称与文件夹是 Velune 列表组织记录；已读／未读按上述原生优先规则处理。“移到项目”只改变 Velune 列表的归属，不改变会话的原生工作目录或下一轮的执行位置。运行时自行安排的无工作区目录与主目录归入“无项目”，不自动创建普通项目；新建无工作区的目录规则见[运行时](agent-runtimes.md#会话模型与工作目录)。

未读表示上次查看之后有轮次结束（无论正常还是异常）：会话运行中不显示未读，轮次结束后才显示；上一轮异常结束的未读会话以感叹号代替未读圆点。

2026-10-16（[S29](../sources/conversations.md#s29)）：会话条目只显示会话标题与状态（未读、上一轮失败、正在运行），不显示最后更新日期与 Agent 运行时等信息；组标题不因单击而展开或收起。

### 组排序

2026-10-18（[S37](../sources/conversations.md#s37)）：组可手动排序，作为与“最近活动”并列的显式组排序方式：手动时组只按用户的顺序排列，不随创建或更新时间跳动，之后新出现的组排在末尾；置顶组始终在最前。顺序随浏览偏好保存，项目分组与运行时分组各有各的顺序；转回最近活动时手动顺序保留。会话排序（创建／更新时间及方向）只排组内的会话。

### 多文件夹项目

2026-10-17 多文件夹项目（[S35](../sources/conversations.md#s35)）：项目与单个文件夹解耦，一个项目可有多个文件夹，其中一个为主文件夹；工作目录属于任一文件夹的会话都归入该项目，新会话的工作目录建议使用主文件夹。Git worktree 中的会话归入其所属仓库的项目，例如 Claude Code 在 `.claude/worktrees/<名称>` 中运行的会话不再成为独立项目。项目的名称与文件夹仍是 Velune 列表组织记录，不改变文件夹、会话的原生工作目录或下一轮的执行位置。

### 从组新建

2026-11-03（[S66](../sources/dogfood.md#s66)）：Mac 会话列表的组右键菜单提供“新建会话”，沿用普通新建的未首发草稿界面。Agent 运行时组预选该运行时；项目组预填项目主文件夹，原生项目同时预选所属运行时；无主文件夹时保留为空，用户仍可调整。其他组沿用普通新建默认值。共享输入区继续保留草稿，组显式指定的运行时成为下一轮目标；只有首次发送才创建原生会话，模型等其他选择继续遵守新会话规则。2026-11-04 起（[S74](../sources/workspace-keyboard.md#s74)）与普通新建一致：在新标签页中打开，当前标签已是未发送的新会话时原地改目标。

## Codex 原生项目

2026-10-26：读取 Codex 原生项目的名称、按顺序保存的全部文件夹和线程项目归属；项目身份由运行时实例与 Codex 项目 ID 共同确定。两个项目即使共享首个文件夹也分别显示，没有文件夹的项目仍可识别。原生线程按 Codex 的项目归属分组，其工作目录可以在第二个文件夹或项目根之外；没有原生归属时继续按 Velune 文件夹与 worktree 规则组织。Velune 显式“移到项目”仍只改变列表组织，优先于原生归属，不修改 Codex 成员关系。

Mac 与 Windows 的“显示 → 编辑项目”可进入所有项目，包括还没有会话的项目。“编辑 Codex 项目”直接保存名称和文件夹到 Codex，并保留其他原生项目元数据。名称不能为空，文件夹可为空；首个文件夹表示原生根的顺序，不作为身份。普通 Velune 项目仍遵循原有主文件夹规则。编辑项目不会替换已有线程的工作目录或执行权限范围；继续已有线程保留 Codex 自身记录的工作区。

## 侧聊

2026-10-29 用户要求（[S56](../sources/conversations.md#s56)）提供侧聊，即 Claude Code 的 `/btw`：不打断、不改变会话，就该会话的上下文另外提问。侧聊是多轮的，可以继续追问；关闭即丢弃，不保存，不进入会话列表，不改变原会话的历史、下一轮选择或发送队列。原会话运行中也可以打开侧聊并提问，两者互不等待。

上下文优先使用 Agent 运行时自己的侧聊能力；运行时没有时，在运行时内把会话原生 fork 成不保存的临时副本，在副本上对话。侧聊中能做什么（工具、审批、是否只读）由运行时自身决定，Velune 默认不另加限制。侧聊使用会话当前的模型与认证；尚未首发的新会话没有上下文，不提供侧聊。首个 beta 前只做 Mac。

| 运行时 | 侧聊方式 |
| --- | --- |
| Claude Code | 原生侧问（`/btw` 所用的 side question），带上本次侧聊之前的问答；按其原生行为不使用工具 |
| Codex | 与 Codex 自身的 `/side` 相同：不保存的临时 fork，附“此前历史仅作参考、不是当前任务”的说明 |
| Pi | 不保存的临时 fork |
| DSH、通用 ACP | 没有原生侧聊或 fork，不提供 |

Mac 上侧聊是普通 editor 中的会话，使用同一套标签页、消息列表、输入区、运行状态与审批交互；只以“侧聊 · 原会话标题”的名称区分，不另设标题栏、临时说明或背景。展示方式可在设置中选择：在原会话的 editor 旁拆分（默认，可调整宽度），或使用普通会话的 sheet。拆分发生在 editor 层，两个 editor 各有自己的标签栏。切换展示方式保留同一个侧聊的问答、未发送文字和阅读状态；重新打开应用只恢复展示偏好，不恢复侧聊及其空拆分。

入口为“会话”菜单、命令面板、输入区 `/side`（或 `/btw`）与会话列表的右键菜单。列表右键默认在 sheet 中打开目标会话的侧聊，不切换当前标签页，也不改变列表选择；其他入口沿用展示偏好。发送键、输入法、消息查找、工作过程与工具输出的显示沿用普通会话；停止与审批作用于正在操作的会话。关闭侧聊（包括关闭 sheet）即丢弃侧聊。从当前 editor 打开的侧聊还会随父标签页关闭或改看其他会话而关闭；列表直接打开的侧聊由其 sheet 独立持有。侧聊最初沿用打开时的下一轮选择。本次调整来源见 [S57](../sources/conversations.md#s57) 与 [S58](../sources/conversations.md#s58)。

2026-11-02（[S62](../sources/composer.md#s62)）：侧聊标签显示“侧聊 · 来源会话名称”，不以临时原生会话的未命名状态覆盖。侧聊可调整下一轮运行时、模型、推理强度与权限，运行时限于具备临时侧聊能力的类型；改选保留未发送输入，发送按此次选择执行。执行配置改变后仍保留来源参考上下文和已有侧聊问答，不修改来源会话，不把侧聊转成普通持久会话。异构运行时使用引用式上下文，过去的指令、工具调用和审批仅供参考，不重新执行。

## 原生自动命名

2026-11-02（[S64](../sources/dogfood.md#s64)）：Velune 创建的 Codex 会话首次发送文字后异步自动命名，结果写回原生会话名称，不创建 Velune 标题覆盖；使用这一轮选定的运行时和模型连接，命名过程不阻塞编辑和下一轮发送、不显示为用户轮次或子 Agent。手动名称优先，失败保留首条消息派生标题，不自动反复生成。原生标题变更实时更新；子 Agent 显示原生名称或昵称，缺少这些值时再使用首条消息／原生角色，列表、标签与关联 Agent 入口共享同一投影。

## 自动命名兜底

2026-11-03（[S69](../sources/dogfood.md#s69)）：运行时没有提供自动名称时，Velune 可为没有原生标题的会话生成名称。按运行时实例开关、选择 Velune 中的模型，默认关闭；开启时说明所选模型会读取首轮用户消息与回复。仅在观察到一轮正常结束后后台调用一次，不向原会话追加提示、不改变其模型或执行状态。

原生名称和用户重命名始终优先，迟到结果不能覆盖它们。关闭影响后续生成，不删除已有名称；失败保留原显示名并记录诊断，不阻止会话使用。Velune 生成的名称作为列表组织元数据持久保存，来源与原生标题、首消息截取分别表达；这是对早先“不建立标题覆盖”规则的限定补充，只为缺少原生名称提供兜底，不接管原生命名。Pi 1.4 的公开 SDK 提供显式设置名称，但没有自动生成名称的配置开关；由本机制服务。Codex 已有的自动命名路径继续工作，不叠加一次生成。
