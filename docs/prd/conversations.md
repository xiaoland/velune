# 会话与会话列表

会话的权威与投影、运行状态、会话列表的浏览、分组、项目与管理。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 会话权威与投影

此切片中，Pi 拥有会话历史和持久化，Velune 只投影其会话与运行状态，不新增自己的会话持久化。资源在应用中配置；本轮不把三家资源的例子固定为产品模型或预设可用性。真实操作与验收由用户完成，开发方负责实现、构建及隔离验证，不替用户登录或调用真实模型。此边界限定当前 Pi 切片，不将既有模拟数据库当作真实会话权威。来源见 [S15](../sources.md#s15)，执行状态见 [任务](../../tasks/pi-mac-first-loop/packet.md)。

2026-10-06 用户要求内部具有权威的会话／消息模型，UI 展示可按内容拆分为多个条目，不必逐个照搬领域消息。Harness 仍拥有持久化，Velune 的内部权威是运行时中立的会话投影，展示层不建立另一份会话存储。

2026-10-11 用户明确会话的唯一权威（SSoT）始终在 Agent 运行时侧：会话可能在 Velune 之外变化或仍在运行（包括不是从 Velune 发出的 turn），状态漂移无法完全排除，追求完全一致的投入不值得，采用 best-effort。正在运行的会话应在会话列表中有指示，消息列表流式显示实时进展；理论上外部发起的进行中 turn 也应尽量识别；同时提供手动“重新读取”，从运行时重新读取会话列表与当前会话。2026-10-12 用户澄清：“是否在 Velune 之外运行”不重要，重要的是“正在运行”；这是 Velune 作为 shell 对齐原生运行状态的问题，本质仍是会话 SSoT，各适配器按所属 Harness 的原生机制分别判断。界面对 Velune 发起与外部发起的运行使用同一“正在运行”表达，不再区分“可能在 Velune 之外运行”。新会话与未记录可用模型的会话，composer 默认选择一个与运行时兼容的模型（优先最近选择），不留空。消息列表的“回到底部”按钮采用与整体一致的标准矩形按钮，不用圆形，并与滚动条保持间距。

2026-10-06 用户进一步明确：主界面 Agent 运行时与模型选择表示下一轮发送时的执行目标，不表示正在浏览的原生历史来源。打开历史详情不得覆盖已选择的下一轮目标。历史读取和原生重命名／删除按会话来源执行；已经发出的轮次由固定执行实例负责轮询、取消和交互回复，不跟随之后编辑的目标。

## 会话管理

会话管理提供重命名与删除，操作真实作用于所属 Agent 运行时的会话数据，不建立 Velune 标题覆盖。归档、置顶、已读／未读、项目归属与项目的名称和文件夹属于 Velune 的列表组织记录（见下文 2026-10-14 段落），不是标题覆盖或删除替代。切换会话时立即表达目标选中与加载状态，已加载内容与待加载目标分别管理；旧轮询或迟到结果不得将选中态恢复为原会话。加载失败应明确反馈并保持可理解的选中和内容关系。

会话加载不禁用列表的上下文菜单或原生重命名／删除操作。用户可在加载中打开并提交管理操作；实现负责正确安排加载与原生修改的先后顺序，不能因笼统 loading 标志静默忽略操作。执行、关闭或确实不支持的能力仍具有各自边界。

## 会话列表

会话浏览使用统一列表，纳入所有启用 Agent 运行时的会话。当前执行运行时不作为隐式列表筛选条件；运行时、CWD／project、label／section 可用于显式分组或筛选，创建时间和更新时间可用于排序。不同来源的会话仍保持所属实例身份；浏览分组不改变执行归属。懒加载或分页是可采用的实现方式，不能变成按运行时切换后才看见该来源的入口。用户随后澄清 label／section 仅为示例，不要求本轮接入。若增加自定义 tag／label／section，应独立持久化 Velune 的列表组织记录，不能混同各 Harness 的原生概念；Codex section 用于聚合 project，不是通用会话标签。当前切片先完成运行时／项目分组筛选和时间排序。

会话列表记住用户选择的分组、运行时与项目筛选、时间排序及方向，应用重启后恢复。浏览偏好属于 Velune 配置，不修改原生会话数据，也不选择下一轮执行运行时；临时搜索文字不作为持久偏好。

2026-10-14 会话列表管理（[S24](../sources.md#s24)）：分组可折叠，折叠状态与其他浏览偏好一同记住；组按最近活动排序。整个列表设总数上限，各组按需展开，组内只提供“加载更多”，不提供“显示全部”。运行时若有按项目组织的原生存放或注册信息，应借此分组与计数，只按需读取每组的前 N 个会话，不为分组而读出全部原生会话。项目以工作目录识别，可设自定义别名（2026-10-17 起见下文多文件夹项目）。会话可以置顶、标记已读／未读、移到另一项目，以及拷贝会话 ID 与 Velune 深链。归档原生优先：运行时有原生归档（Codex）时使用原生操作，其余由 Velune 记录、不修改原生会话；已归档会话默认隐藏，可切换查看并取消归档。置顶、已读／未读、项目归属与别名都是 Velune 列表组织记录，不写入原生会话；“移到项目”只改变 Velune 列表的归属，不改变会话的原生工作目录或下一轮的执行位置。不指定工作目录时运行时自行安排的位置不是项目：如 Codex 的无项目聊天在 Codex 管理的目录（默认 `~/Documents/Codex`）中创建，这类会话与主目录下的会话都归入“无项目”组，其他运行时的类似位置同样处理。未读表示上次查看之后有轮次结束（无论正常还是异常）：会话运行中不显示未读，轮次结束后才显示；上一轮异常结束的未读会话以感叹号代替未读圆点。2026-10-16（[S29](../sources.md#s29)）：会话条目只显示会话标题与状态（未读、上一轮失败、正在运行），不显示最后更新日期与 Agent 运行时等信息；组标题不因单击而展开或收起。2026-10-18（[S37](../sources.md#s37)）：组可手动排序，作为与“最近活动”并列的显式组排序方式：手动时组只按用户的顺序排列，不随创建或更新时间跳动，之后新出现的组排在末尾；置顶组始终在最前。顺序随浏览偏好保存，项目分组与运行时分组各有各的顺序；转回最近活动时手动顺序保留。会话排序（创建／更新时间及方向）只排组内的会话。

2026-10-17 多文件夹项目（[S35](../sources.md#s35)）：项目与单个文件夹解耦，一个项目可有多个文件夹，其中一个为主文件夹；工作目录属于任一文件夹的会话都归入该项目，新会话的工作目录建议使用主文件夹。Git worktree 中的会话归入其所属仓库的项目，例如 Claude Code 在 `.claude/worktrees/<名称>` 中运行的会话不再成为独立项目。项目的名称与文件夹仍是 Velune 列表组织记录，不改变文件夹、会话的原生工作目录或下一轮的执行位置。

2026-10-06 后续验收要求：AI 提供商及运行时列表双击编辑；模板使用原生多选批量添加，提供商模型表单将“添加新模型”和“从模板中选取”分开，模板选择使用独立 sheet。会话列表支持平台原生多选和按组首批加载20条、应用设置可修改数量（2026-10-14 起改为每次加载条数，另有整个列表的总数上限）。批量管理仍执行原生会话操作，保留每项所属运行时身份。
