# 本地定时任务

来源：[S60](../sources/dogfood.md#s60)。任务由执行设备的 application 调度，随 Velune 启停；窗口和远控客户端不各自运行调度器。Mac 在“显示 → 本机定时任务…”管理定义、启停、运行一次、删除、最近运行记录和来源导入；Agent 使用 Velune 的 `scheduled_tasks` MCP 工具。其他端可调用同一业务 API，管理界面尚待跟进。

任务详情默认呈现已保存的概览、执行资格与最近运行，编辑具有明确的保存／取消；启用和暂停独立即时生效，暂停不要求先修复失效的模型或执行目标。后台刷新不打断输入，不清除尚未处理的操作错误。新建任务保持暂停。

普通创建支持每天、每周选星期和按小时间隔；自定义规则保留高级编辑。简单控件由核心无损识别／构造，界面显示核心计算的未来三次触发与明确时区。修改时区按当地墙上时间同步规则锚点，夏令时仍由日历库计算。无法无损表达的规则保持自定义，不近似转换。

每个任务保存指令、显式 IANA 时区与 RFC 5545 规则、运行时／模型／推理强度／权限模式。可以每次新建会话（一个或多个工作目录，可用独立 Git 工作树），或继续一个已有会话。执行使用现有会话池、模型网关、原生审批及共享会话控制权准入；不会自动批准请求、换账户或夺取控制权。任务需要的运行时被删除或不可用时转为待配置，不阻止删除运行时。

退出后不再派发，重新打开从未来的触发恢复，错过的触发和上次尚未发送的等待项不补跑。运行期间遇到同任务尚在执行、会话忙、等待审批或外部占用，保留一份待执行触发，后续 tick 不积压重复指令。可以手动运行一次；不会因为关闭任务窗口而停止调度。

定义与运行账本在执行设备本地事务保存。领取触发及进入派发阶段先持久化，再调用运行时；更新定义需要当前 revision。跨崩溃不能承诺任意 Harness 的 exactly-once：接纳结果不明的运行标为“结果待核查”，保留会话引用，不自动重发。运行记录关联原生会话，关闭所有会话窗口后仍可从结果入口重新打开；不在调度库复制会话正文。删除计划不取消已开始的执行，不删除会话或运行记录。

## 接管已有任务

用户选择 Codex HOME 或 automations 目录，并明确来源时区和对应运行时。仅解析必要的任务定义，不导入登录或历史正文。支持 cron 新会话和 heartbeat 既有会话；预览并列显示来源配置和 Velune 实际使用的配置，明确来源模型不会自动映射到执行模型；规则、目录／工作树、目标与通知方式可核对，可查看已识别的来源配置与来源文件路径。来源的本地环境脚本和自动归档选项保留在来源元数据，需要用户另外配置，不自动执行来源脚本。

以来源文件身份和内容指纹幂等导入，首次和再次导入都保持暂停；重导入更新同一项，先展示指令、日程、目标、模型等配置差异，并明确重置交接和暂停后才确认覆盖。裸 model 名称不代表 Velune 的提供商身份，由用户核对模型和账户。用户须在原应用中暂停任务、处理在途运行，再通过明确交接确认解锁启用；单改 TOML 不等于原宿主确认停派发。确认后仍保持暂停，核对配置后才启用。

启用及每次派发检查来源仍停用且内容未冲突变更。若来源 HOME 下存在已知桌面任务数据库，还会以只读方式按所选任务 ID 核对原宿主状态与在途运行；TOML 已暂停而数据库仍启用或仍有 IN_PROGRESS 运行时，不能交接。来源重新启用、删除或改变时，暂停 Velune 这一份并显示原因。两应用没有共享原子租约，因此不承诺用户在原宿主重新启用任务时仍能无条件避免所有竞争；不偷偷修改原应用的调度状态。开发验收只用合成任务，不启用或运行真实任务。
