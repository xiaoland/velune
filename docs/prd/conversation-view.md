# 消息展示

会话详情中的消息布局、Markdown 与链接、工作过程折叠与大纲。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 布局与渲染

会话通过布局区分消息类别：用户在右侧、LLM 在左侧、系统与 Harness 状态在中间。不显示用户或 LLM 的头像、昵称等身份标签，也不将 LLM 消息标记为 Velune 发出。Velune 品牌不作为 LLM 的身份。来源见 [S15](../sources.md#s15)。

会话标题采用可读内容而非 transcript 文件名，时间按平台本地格式呈现。打开会话来到底部，发送和流式追加跟随最新内容，同时允许用户阅读历史。长会话采用懒加载或复用列表，避免每次更新重建全部消息视图。用户内容显示为右侧气泡；LLM content 与工具在左侧左对齐，系统／Harness状态保持独立。LLM content 按完整 Markdown 渲染，复用成熟 Swift 组件并遵守其开源许可。消息中的网页和本地文件链接可交给系统打开，相对文件地址以该会话工作目录解析；无法打开时显示原始链接并允许复制。大纲跳转应对齐实际目标消息，不因懒布局估算停在相邻消息。

## 工作过程与大纲

消息展示支持工作过程折叠与用户消息 outline。工作过程折叠块与内容列内的LLM／工具消息左边缘对齐，不按系统状态居中。2026-10-11 用户纠正折叠区间：消息列表呈现为“用户消息 – 工作过程 – Agent 回复”：回复只指区间最后一条 assistant 消息末尾的正文文本，不含思考；该消息中位于回复之前的思考、工具等块与其他中间消息一并归入工作过程，末条不以正文结尾（例如以工具调用或工具结果收尾）时整段为工作过程、没有回复。大纲以用户消息为条目，有两种呈现，由设置中的“大纲按钮”选项决定点击详情右侧工具栏大纲按钮的行为（2026-10-10 用户纠正：此设置不是消息列表的默认显示模式）：“弹出面板”在按钮处弹出原生 popover，大纲项单击选择，双击直接前往，并保留显式前往按钮；“就地折叠”把消息列表以动画原地缩起为只剩用户消息，按钮呈选中状态，再次点击或点击某条用户消息即恢复完整列表并停在该消息，所在位置在动画中保持稳定。折叠只是临时阅读状态，切换会话或发送消息后恢复完整列表。回到底部保留在消息列表浮动操作区并只使用向下箭头，与滚动条保持合适间距。工作过程以用户消息为锚，完整覆盖下一条用户消息之前的响应；单条正文完成不能截断后续工具及答复的折叠归属。纯正文可流式外露，执行结束由Agent运行时的生命周期确定。时长仅来自实际观察到的执行区间，缺失时显示“工作过程”，不能伪造耗时。2026-10-12 用户要求：未结束的 turn 默认展开工作过程；运行中的表达参考 Claude Code／Codex App（如最新思考摘要的 shimmer），但优先贴合原生常见模式；“可能正在 Velune 之外运行”的说明文字多余，只保留进度指示即可；composer 并列的弹出按钮不用强调色指示器，改用中性色。同日用户补充：运行中 turn 的思考块不自动展开；有思考摘要时以摘要作为思考块的标题，没有摘要时不显示思考块，不出现通用的“思考过程”折叠项。
