# Velune 产品定义

状态：核心产品设计、Rust／SQLite 与原生 UI 方向已获用户认可，具体契约仍待验证；2026-10-02 已授权无凭据 Rust 核心原型。本文只记录产品“做什么、为什么”。

## 目的与动因

Velune 是 coding agent 的 control surface：提供统一控制界面与协调层，让多个订阅、多个 AI 提供商和多个 coding agent harness 能在完整、稳定、可恢复的体验里使用和协作，降低对单一提供商或 Harness 的依赖。执行 Agent 由 Harness 承载，Velune 本身不充当 Agent。

当前使用背景：用户有两个 ChatGPT 账户，希望更好利用已有订阅。账户身份和凭据不进入仓库；这不证明不同账户权益可以合并，也不证明可移用于任意工具。

Velune 是新的独立产品，已经停止继续推进 Factory26。Beluna 是另一个独立的、非 Coding 的通用 Agent / Digital Life 姐妹项目；两者不共享本仓库的产品范围。见[方向切换来源](../sources.md#s1)。

## 已确认的优先级

### 第一优先级：AI 提供商、模型与多 Harness 协作

下列项同属核心优先级，尚未在它们之间排定实现顺序：

- 多订阅支持
- 多 LLM 供应商支持
- 自动 LLM 路由
- 多 coding agent harness 支持
- 不同 harness 的会话能够互相发现／感知、观察、交流和协作

这里的自动路由仅指 LLM 请求如何选择模型及其提供商。它不自动包含设备调度或 harness 调度。用户已要求以首批三个 harness 均可接管为设计目标，调查具体路径与边界，而非按现成功能重新筛选 harness。优先级依据[用户纠正](../sources.md#s2)。

### 后续扩展：分布式能力

在上述基础上，通过分布式架构实现远程控制、多设备和多平台使用。此处确认的是产品方向与相对优先级，不是已批准的分布式实现方案。不得以“手机优先”或“远程控制优先”替代核心目标。

## 已确认的产品结构与质量方向

- 持久化的任务—会话模型：任务与会话应可持续保留和恢复；具体身份、状态机、存储和重连语义见架构中的细化契约
- 任务树视图：以任务及其关系提供理解、观察和操作工作的入口；树节点与交互细节由方案继续收敛
- 完整、稳定、可恢复的体验：不把仅能跑通单一路径的演示视为产品完成
- 避免供应商锁定：应能清楚辨认对具体供应商与 harness 的依赖；具体适配器边界和替代验证见架构中的细化契约
- 平台原生体验：各平台尽可能遵循所属平台的原生视觉与交互习惯，包括导航、窗口、控件、字体、材质、颜色和系统行为。品牌及软件特点在图标、内容与少量细节中体现，不覆盖平台的整体视觉风格。此原则适用于整个项目，见 [S15](../sources.md#s15)。

Apple app 使用 UIKit／AppKit／SwiftUI 的原生组件与真实系统视觉，采用系统语义颜色和样式，不模拟平台皮肤。原生控件的深色模式由系统适配，不设完整的独立深色验收流程；Core Graphics、自定义 logo、固定色位图、阴影、渐变和边框等自绘内容仍须按所在背景处理颜色与可见性。应用内 logo 浅色背景使用 graphite，暗色背景使用品牌素材提供的中性反色版本。此验收决定见 [S15](../sources.md#s15)。

任务—会话模型和任务树来自[已确认讨论](../sources.md#s3)。这些是目标，不是当前仓库已实现的能力。

- Codex
- Claude Code

### 订阅、模型与认证

- 需要辨清订阅账户、API 账户、模型供应商及 harness 原生认证之间的边界
- “支持多订阅”不意味着订阅额度可合并、可无限使用、免 token 计费，或可合法用于任意第三方工具
- 支持能力和限制必须按具体供应商、账户类型、地区／计划与官方规则验证；身份切换、配额处理和失败恢复见架构中的细化契约
- 接管路由不自动授权接管凭据；具体认证与数据路径由设计说明、官方依据和原型验证约束

- 先前“原生 runtime＋官方登录＋隔离配置”的 Claude Code 方案只是待验证想法，没有成为已批准架构决定
- 跨 harness 会话通信可以研究 lexoliu/acphub，也允许提出其他方案；参考项目不构成强制技术依赖

## 稳定术语

- **LLM 供应商**：提供可调用模型服务的一方；不等同于 harness
- **订阅／账户**：某供应商下的访问权益和身份边界；不推定可跨工具通用
- **Harness**：承载 coding agent 执行、工具和会话的运行载体，例如 Codex、Claude Code、Pi
- **LLM 路由**：为模型请求选择有权使用的 AI 提供商的产品能力；控制点与策略见架构中的细化契约
- **任务**：需要持续跟踪目标和进展的工作单元；具体状态模型见架构中的细化契约
- **会话**：与某个 harness 执行交互的工作上下文；跨 harness 统一表示见架构中的细化契约
- **跨会话协作**：会话间的感知、交流与共同推进工作；通信协议、共享程度与权限见架构中的细化契约

## 已确认的架构与技术方向

2026-10-01 11:28 UTC，用户认可上一轮四项产品设计，并确认以下方向，见[复核来源](../sources.md#s10)：

- 保持三 Harness、统一 LLM 路由、独立资源身份、持久逻辑会话与安全续作的产品设计；先核心闭环，后分布式扩展
- MCP 暴露协作工具，ACP 作为可替换接入方式
- Rust 为产品核心实现语言，SQLite 为存储；替换先前 TypeScript／Node.js 主核心建议
- UI 原生实现：Apple 方向为 Swift／UIKit，Android 为 Kotlin／Jetpack Compose；不采用 Web 前端，用户接受实验性项目的跨平台开发不便
- “Apple-universal”具体平台边界、Mac Catalyst／AppKit 落点属于待收敛技术细节，不推定用户要求或已批准全部 Apple OS

跨 Harness 协作指实际的发现、会话消息接入、委派、结果回传、并发与失败协调；保存任务树、消息、权限和恢复状态是支撑设施，不能单凭持久化说明协作已经实现。此区分来自用户本次复核。

## AI service 的有界实施方向

2026-10-03 用户确认 AI service 为独立 lib、领域不限 LLM，sampling 是其中一项操作。service 拥有对调用方和 provider 的权威契约；provider 即 adapter，转换外部协议，协议库／SDK 只作为 provider 内部可替换依赖。provider 基本配置为协议配置、凭据引用、模型列表，不再新增账户／渠道实体。

Harness 与 AI 服务保持独立；读取 Harness 提供商配置属于装配边界的导入适配，不让 AI 服务理解 Harness 的配置、运行或推理级别。AI 服务也不以大语言模型作为整个领域的基础假设；模型、token、对话和推理参数只归相应操作及协议契约。当前只实现 sampling 与原生 Responses 不代表 AI 服务仅限 LLM。

2026-10-05 用户进一步明确：当前 gateway 仅为 LLM Gateway，是 AI 模块的一种应用模式，不代表整个 AI 服务。应用可以直接消费 AI 能力，不要求全部经过 gateway。此前本页“AI 网关”在当前实现范围内均指 LLM Gateway；非 LLM 能力及其接入模式按具体需求另行设计。

提供商拥有认证配置，不要求独立中央认证建档。API key 可在 application 私有文件保存并显式查看编辑，公开摘要与日志不含秘密；OAuth 保留来源登录／刷新，不复制 refresh credential。Pi 等运行时只是来源，不是认证方式。解析与目标校验归 application，gateway 仅消费中立异步解析接口；解析失败不回退环境或其它认证。

统一配置中心持久化，app main 装配；AI lib 不自行读全局配置／环境／文件或保存配置；一次已开始调用保持运行配置稳定。具体归属见 [AI service 设计](../design/ai-service.md)，决定来源见 [S13](../sources.md#s13)。本步只实现契约与校验，不改旧宿主；验收方案、真实接入与 fixture 准备独立记录，不把静态检查等同运行验收。

## Pi 与 Mac 首循环

2026-10-04 用户要求以 Pi agent 与 Mac app 建立第一个可交互循环，资源包括后续自行配置的 ChatGPT 订阅、Tokenflux 与 ARK Coding Plan。应用必须提供 Chatbot 会话界面与会话列表，不能用硬编码资源和固定任务代替配置及真实交互。

此切片中，Pi 拥有会话历史和持久化，Velune 只投影其会话与运行状态，不新增自己的会话持久化。资源在应用中配置；本轮不把三家资源的例子固定为产品模型或预设可用性。真实操作与验收由用户完成，开发方负责实现、构建及隔离验证，不替用户登录或调用真实模型。此边界限定当前 Pi 切片，不将既有模拟数据库当作真实会话权威。来源见 [S15](../sources.md#s15)，执行状态见 [任务](../../tasks/pi-mac-first-loop/packet.md)。

共享领域能力与平台 app 分离。Rust lib 提供跨平台一致行为；平台 app 在进程内消费语言绑定，管理库的生命周期。外部 Harness 子进程与本机 AI 网关具有独立职责，不构成 App 与共享库的常驻 Host 通信。

2026-10-05 用户决定全面采用 UniFFI，并授权独立 package 拆分，避免把全部共享能力集中到巨大 core。共享领域、应用装配和语言绑定各自保持契约；各平台消费生成的类型接口，不保留手写 JSON／C ABI 产品入口。移动端可按需只选择远程接入，不被迫携带本地 Harness；直接 AI 能力是独立选择。remote 尚未实现，拆分不提升其交付状态。边界见 [架构](../design/architecture.md#独立-package-与平台装配)，来源见 [S17](../sources.md#s17)。

每个独立 package、每个平台 app 都是一个 unit，分别拥有明确契约、依赖与知识维护归属。内部模块不必须成为独立 unit；unit、语言 SDK 与二进制产物不要求一一对应。配置持久化为共享 application unit 的内部模块，不建立通用存储框架或独立 persist package；出现真实独立消费者后再复核。目标覆盖 Swift、Kotlin、C# 消费 Rust，具体语言工具的兼容性须有生成与编译证据。

Mac 开发交付安装到 `/Applications/Velune.app`，每次修改后重新构建、安装并关联源码版本。用户已授权开发方随时退出或强制退出正在运行的 Velune，以完成更新。当前产品显示版本为 `0.1 beta.1`，与 ABI、投影契约、配置 schema 和构建版本独立维护。来源见 [S15](../sources.md#s15)。

用户随后要求完全重写 Mac app，并明确避免与任何提供商或 Agent Harness 耦合。Mac 界面消费共享 application 的通用会话、消息、运行状态和设置描述；具体 Harness 协议、消息映射和配置转换由适配器封装。运行时或资源名称可作为数据展示，不能成为 UI 的专用命令、字段分支或协议解析。视觉使用用户提供的 Velune 光学校准 SVG logo，默认选择 graphite 配色而非 theme，真实资源验收仍由用户执行。

应用数据与配置通过文件系统持久化，根目录由 `VELUNE_HOME` 指定，默认 `~/.velune`。AI provider 资源和 Harness 配置可采用 JSON／TOML 或 SQLite；当前切片采用 JSON。此要求归属应用配置，不改变 Harness 拥有会话历史的边界；API key 可在本机应用配置中保存，并在提供商表单查看、修改；订阅认证保留其必要的来源与刷新能力。开发方不读取、输出或提交真实秘密。来源见 [S15](../sources.md#s15)。

## AI 网关与 Agent 运行时配置

2026-10-04 用户纠正首循环配置模型：产品使用“AI 提供商”，废弃“模型资源”实体。模型独立于提供商存在，同一个模型可以由多个提供商提供，一个提供商也可以提供多个模型。模型具有提供商规定的 model ID，以及昵称、图标及能力参数；最大输出 token 数、支持的推理级别是示例，不要求所有提供商支持这些参数。字段与编码以提供商协议为权威；提供商配置包含可调用模型、可编辑的协议与端点，以及其认证配置；不要求用户另行建立认证资源。model ID 是提供商 API 接受的模型标识，不是由用户另填的 Velune 内部记录键；内部引用和显式网关路由别名须与它分别命名。跨提供商的模型关联不能凭同名自动推断等价。 用户可从公开模型目录显式拉取、搜索并挑选条目作为模板快填。目录给出来源声明，不决定实际提供商的协议、端点或可用性；填入后成为独立可编辑快照，不能自动覆盖已保存模型或因 reasoning 支持标记猜测具体级别。

协议使用有限选项，首先实现 OpenAI ChatCompletions v1；2026-10-04 用户进一步要求支持 OpenAI Responses v1，当时暂不进行协议翻译；此阶段限制已由2026-10-06三协议互转授权修订。不使用任意字符串输入来代表协议。AI 提供商只是 Velune AI 服务网关配置的一部分；模型路由与 fail-over 策略同属网关配置，不属于提供商实体。Harness 使用 Velune 注入的 AI 服务网关配置，不能以“工作环境已有的认证”绕过 Velune AI 服务直连上游。认证由 Velune 提供商适配边界处理；认证来源可以研究对用户指定 Harness 配置的明确委托，并不要求所有登录流程由 Velune 重写。

界面使用“Agent 运行时”表示 Harness 类型及其配置实例。Pi Agent 是一种运行时类型；同类型下不同的配置／状态目录等设置形成独立实例，而非一份全局运行时表单。实例身份、配置和会话投影必须区分，具体外部环境变量由适配器转换。此决定不自动要求所有实例并发运行。来源见 [S15](../sources.md#s15)。

2026-10-06 用户授权增加 Codex（app-server）与 deepseek-harness 接入，并直接消费 huihua 发行包读取会话，不复制其源码；交付须保留对应开源声明与许可证。同一运行时家族的 breaking-change 版本分别作为独立运行时类型，绑定各自适配器与版本正则，允许多种 Pi 版本同时配置。实际版本匹配用于确认所选类型，不是用一个全局版本闸门替代多版本支持。huihua 是只读会话证据库，不代替原生运行控制接口。实施与证据见 [多运行时任务](../../tasks/multi-runtime/packet.md)。

Velune 不随应用分发任何 Agent 运行时，运行时由用户安装、配置或从本机发现；未来的安装运行时功能尚未实施。辅助 adapter 与只读解析依赖可以随应用交付，但不能以 SDK 名义隐含捆绑完整运行时。支持范围必须根据公开版本和实际协议证据决定，公开版本读取失败与已识别但不受支持的版本应明确区分。

双击进入编辑是项目级 UI/UX 范式，适用于所有可编辑列表，包括模型模板、提供商模型与会话标题；会话标题仍写入原生运行时，不建立本地覆盖。双击不能破坏单击选择及系统多选，选择列表或只读目录不伪装成编辑入口。

工作目录属于具体会话，不属于 Agent 运行时实例。一个实例可在不同项目目录创建和恢复会话；新建时选择目录，恢复时沿用 Harness 保存的目录。运行时目录是该实例的配置／状态根目录，具体环境变量由适配器转换，不等同于项目目录。

会话通过布局区分消息类别：用户在右侧、LLM 在左侧、系统与 Harness 状态在中间。不显示用户或 LLM 的头像、昵称等身份标签，也不将 LLM 消息标记为 Velune 发出。Velune 品牌不作为 LLM 的身份。来源见 [S15](../sources.md#s15)。

## 会话内容展示
