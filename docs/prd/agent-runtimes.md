# Agent 运行时

运行时类型与实例、接入方式（专用 adapter、ACP）、执行位置与 HOME、版本、发现与导入，以及运行时与会话模型、工作目录的关系。

## 类型与实例

界面使用“Agent 运行时”表示 Harness 类型及其配置实例。Pi Agent 是一种运行时类型；同类型下不同的配置／状态目录等设置形成独立实例，而非一份全局运行时表单。实例身份、配置和会话投影必须区分，具体外部环境变量由适配器转换。此决定不自动要求所有实例并发运行。来源见 [S15](../sources.md#s15)。

2026-10-06 用户授权增加 Codex（app-server）与 deepseek-harness 接入，并直接消费 huihua 发行包读取会话，不复制其源码；交付须保留对应开源声明与许可证。同一运行时家族的 breaking-change 版本分别作为独立运行时类型，绑定各自适配器与版本正则，允许多种 Pi 版本同时配置。实际版本匹配用于确认所选类型，不是用一个全局版本闸门替代多版本支持。huihua 是只读会话证据库，不代替原生运行控制接口。实施与证据见 [多运行时任务](../../tasks/multi-runtime/packet.md)。

Velune 不随应用分发任何 Agent 运行时，运行时由用户安装、配置或从本机发现；未来的安装运行时功能尚未实施。辅助 adapter 与只读解析依赖可以随应用交付，但不能以 SDK 名义隐含捆绑完整运行时。支持范围必须根据公开版本和实际协议证据决定，公开版本读取失败与已识别但不受支持的版本应明确区分。

运行时设置提供快速导入，检测本机已有可执行入口、实际版本与非秘密实例目录，预览选择后保存；可接续原生提供商／模型导入预览，不把检测当成自动读取登录或调用模型的授权。

## ACP

2026-10-10 用户进一步授权通用 ACP Adapter，继续限定 Rust packages。用户随后澄清，目标是尽可能覆盖更多 Agent Harness，同时避免为每个 Harness 分别开发适配；ACP 是服务该目标的技术方案，不是不可推敲的产品约束。它作为已有专用 Harness adapter 之外的接入方式，使用 Agent 公布的协议能力；配置、模型／会话选项与能力展示已于 2026-10-12 接入 Mac（见 [Mac 接入任务](../../tasks/mac-runtime-integration/packet.md)）。指定参考为 [lexoliu/acpsub](https://github.com/lexoliu/acpsub)，不引入其独立 daemon。实现与验收归 [ACP 任务](../../tasks/acp-adapter/packet.md)。

## 原生提供商、网关轮次与执行位置

2026-10-10 用户授权推进 Claude Code、SSH 远程运行时及 Velune 管理的运行时 HOME，并明确本轮仅实现 Rust packages。运行时不必同时注册多个提供商：保留它已有的提供商，允许会话下一轮选择其原生模型；选择 Velune 管理的模型时，仅该 turn 临时使用 Velune Gateway，结束后恢复原生提供商。成功、失败及取消都必须结束临时覆盖，不修改或删除原 Harness 的持久提供商配置。运行时原生模型的身份属于其具体实例，不能按裸 model ID 当成 Velune 提供商或另一 Harness 的模型。

2026-10-16 用户确认（[S32](../sources.md#s32)）：上述“turn 结束”指该轮的工作全部结束，即轮次本身及其启动、仍在运行的原生子 Agent／后台任务都结束、失败或被用户停止；此前运行时进程与临时覆盖保持，子 Agent 不因父轮次结束被终止。工作未结束时，下一轮若不需要重启运行时照常发送；需要重启（例如换成原生模型、Claude Code 换推理强度）时，先等待子 Agent 结束，或由用户确认停止子 Agent 后发送。父会话的停止同时停止该轮及其子 Agent；轮次已结束、只剩子 Agent 运行时，父会话提供停止子 Agent。

使用原生提供商不阻止跨 Harness 接续。会话的历史来源、下一轮目标运行时和下一轮模型分别表达；切换 Harness 后仍按现有目标原生会话与文本上下文交接机制继续，不能重放原生工具或审批状态。SSH 是运行时执行位置，HOME 是实例环境归属；两者都不改变 Harness 拥有会话历史的边界。Velune 管理 HOME 时不复制用户原有凭据或会话，也不把 HOME 隔离描述成安全沙箱。

**本轮不修改 app（前端已于 2026-10-12 接入，见下文）：** composer 展示并选择目标实例的既有提供商模型与 Velune 管理模型；运行时设置提供 SSH 连接与 HOME 归属配置；按远端文件系统解释会话工作目录。平台应消费共享核心的模型身份、能力和失败信息，不自行解析 Harness 配置。Rust 契约与隔离验收完成不表示这些交互已交付。实施状态见 [运行时扩展任务](../../tasks/runtime-provider-ssh/packet.md)。

2026-10-12 用户要求把 Velune 管理的运行时 HOME 接入 Mac 运行时设置：编辑运行时实例时可选继承当前用户 HOME、指定目录或由 Velune 管理。SSH 连接配置已于同日接入（见下段任务）。

## 会话模型与工作目录

Pi 模型的上下文窗口与输出上限可以未知；未知时由 SDK 使用其原生默认行为，不以强制用户填写能力参数作为执行门槛。实际参数仍以提供商协议为准。Velune 决定当前对话的逻辑模型及 LLM 路由，Harness 应获得执行该模型所需的身份与能力信息。2026-10-06 用户修订运行时默认模型决定：模型选择属于会话，不再要求运行时配置初始模型，也不要求手动连接。已添加运行时即可被选择和浏览其会话；应用按需自动准备执行，浏览历史不依赖模型、凭据或网关准备成功。已有会话的可识别模型选择由 Harness 保存，Velune 恢复并投影；无法识别或已删除的目标须在继续执行前明确选择，不按裸模型 ID 猜提供商，不建立第二份会话存储。运行时启用／禁用可作为额外管理能力，不把它变成手动连接的替代门槛。

工作目录属于具体会话，不属于 Agent 运行时实例。一个实例可在不同项目目录创建和恢复会话；新建时目录可选，留空交给运行时使用默认值；仅没有默认值且协议要求目录的运行时提示必填。恢复时沿用 Harness 保存的目录。运行时目录是该实例的配置／状态根目录，具体环境变量由适配器转换，不等同于项目目录。
