# 输入区（composer）

会话详情底部的输入区：文本编辑、下一轮的运行时／模型／推理强度／权限选择、附件、status line、发送队列、steer、继续与编辑消息。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 输入与布局

消息输入区指会话详情底部整个面板，以编辑文本为主，下一轮运行时／模型和发送／停止作为少量必要操作。运行时和模型使用紧凑、直接的选择器并提供设置入口，不各占半个面板宽度；设置入口直接打开设置窗口中对应的页（运行时对应 Agent 运行时，模型对应 AI 提供商），其他入口同理，不让用户在打开设置后重新寻找上下文（2026-10-11 用户指出“上下文断裂”）。Mac 的新建会话与筛选／分组位于侧栏工具栏（⌘N），大纲入口位于详情右侧工具栏。2026-10-11 用户决定新建会话不使用 sheet：直接进入空消息列表与空 composer，运行时、模型沿用当前选择并可在 composer 调整，尚未首发的新会话还可在 composer 选择工作目录。占位提示与输入文字保持一致的排版，采用平台输入控件的原生文本行为；不通过重复边框、永久说明行或独立占位文字增加视觉层级。Mac 保持 Return 换行、⌘Return 发送，输入法确认不能触发发送。2026-10-10 用户确认 composer 状态按会话保存：草稿文字、下一轮运行时与模型属于各自会话，切换会话不带走另一个会话的输入或选择；草稿在应用重启后保留，删除会话时一并删除。尚未首发的新建会话草稿随该草稿会话存在，不承诺跨重启。随后用户要求 composer 尽量保持 macOS 原生风格，同时满足多行输入这一不同于聊天软件的需求：输入区是随内容增高的标准多行文本框（系统文本框外观与焦点环），运行时／模型的弹出按钮与发送／停止按钮位于框外下方一行，不采用聊天式卡片或图标按钮；编辑为可靠的纯文本多行编辑，不做 Markdown 高亮或富文本格式，粘贴与输入不被自动替换、纠错或智能空格改写。composer 是 Velune 与 Agent 运行时的交界处（下一轮意图与运行时公布的能力在此汇合），核心按会话维护下一轮意图及运行时能力选项的方案另行对齐，当前不实施。

## 附件、推理强度与权限模式

2026-10-11 用户确认日常主力 MVP 的推进顺序：多会话并行执行 → 会话实时状态（含外部进行中识别）→ 完成与待审批通知 → 变更审阅（按会话工作目录的 git 改动与差异）→ composer 增强（附件、@ 文件、推理强度、技能／命令入口）。目标是逐步解除对 Codex App 的依赖并增强软件开发能力。git worktree 隔离暂缓：关键待定决策是 Velune 是否管理 git worktree。同日用户澄清尚未打算加入变更审阅（文件变更）功能；已实现的部分保留代码但关闭产品入口，是否启用另行决定。composer 增强本轮只做图片／文件附件与推理强度（@ 文件引用与技能／命令入口不在本轮）。图片以各 Harness 原生图片输入交付；非图片文件以绝对路径引用附在消息中，由 Agent 用自身工具读取，不内联内容。消息列表中用户消息的附件显示为缩略图（图片，按需加载）与文件名，可用默认应用打开；从原生历史读回的图片同样显示。推理强度取所选模型声明的级别并经 Harness 原生通道设置，按会话记住；未选择时的语义见下文 [S21](../sources.md#s21) 段落。2026-10-13 用户指出 composer 还缺少权限模式选择器：可选模式由运行时类型声明（Claude Code 的原生权限模式、Codex 的预设），经 Harness 原生通道作用于下一轮。所选模式按会话记住。2026-10-13 用户确认权限模式是会话状态（[S20](../sources.md#s20)）：不选时沿用会话当前的模式，新会话为运行时自己的默认；选择器显示当前模式（取自最近一轮的记录），要换模式就明确选择一个。Velune 不读取 Harness 的配置文件来推断默认。不提供模式的运行时不显示该选择器。ACP Agent 自报的模式仍属会话选项。

## 选择器与下一轮选择

2026-10-13 用户确认 composer 的选择器按语义收为两个原生下拉（[S20](../sources.md#s20)）。第一个回答“谁来回答”，按钮显示“运行时 · 模型 · 推理强度”。同日用户指出菜单过长、过杂，菜单因此只有运行时、模型、推理强度三个子菜单，子菜单标题带当前选择，相关的设置入口放在对应子菜单内。第二个回答“允许做什么”，包含权限模式；ACP 会话选项也归入这里。两者都使用系统原生下拉样式，不覆盖系统颜色，须随深色模式等系统外观变化。点击发送后，用户消息立即出现在消息列表中，在运行时确认收到之前标为“发送中”，而不是只显示运行指示。每个 turn 实际使用的配置（运行时、模型、推理强度、权限）可在消息列表中查阅：工作过程行右侧平时只显示一个次要图标，悬停该行时展开摘要，点击图标显示完整配置。配置以 Harness 原生记录为准，best-effort：原生记录没有的项，用 Velune 本次执行实际发送的选择补充；两者都没有时不显示，不猜测。

2026-10-13 用户继续要求（[S21](../sources.md#s21)）：composer 的模型、推理强度与权限模式按会话内的每个运行时分别保存（应用运行期间），切回某个运行时即恢复它在此会话中未发送的选择。下一轮运行时只是临时选择：切换后未发送，离开会话再回来时回到会话当前（最近一轮）的运行时，其他运行时保存的选择仍在；尚未首发的新会话保留所选运行时。某运行时在此会话中还没有选择时，模型默认跟随该运行时在此会话中最近一轮使用的模型。推理强度不做本地化，按实际发给运行时的值显示。推理强度与权限模式一样是会话状态：不选时沿用会话当前的级别（最近一轮在同一运行时上的记录），不知道时不发送，由运行时决定；Velune 从不发送“默认”之类的值。轮次配置悬停时只显示运行时与模型；点击后的详情另列该轮的 token 用量，包括推理 token，来源以 Harness 原生记录为准，原生不单独记录的项注明未记录，不推算。

2026-10-18 用户发现 Claude Code 会话的“沿用”显示模型为默认、推理强度为 medium，要求整理运行时、模型、推理强度与权限的行为（[S42](../sources.md#s42)）。模型、推理强度与权限模式各分两层：会话当前（以 Harness 原生记录为准，没有时取 Velune 为该轮记录的发送请求）与下一轮的选择（用户明确选的）。未选的项沿用会话当前；会话当前未知时不发送该项，由运行时使用自己的默认值。模型同样如此，不再因不认识当前模型而改用目录中的第一项；记录里的模型 ID 不在目录中时，作为“沿用当前（ID）”列出并原样发送。“运行时默认”在 Velune 内部就是未指定（空），不以 unknown、native 之类的取值表示。推理强度仍是单一维度。composer 的选择持久化，取代上文“应用运行期间”的约定：各运行时上的模型、推理强度与权限模式按会话保存，应用重启后保留，同一会话在多个标签页中共享一份；下一轮运行时仍按上文回到会话当前的运行时。Velune 记录的发送请求同样持久化，重启后仍作为会话当前。尚未首发的新会话的选择随草稿存在，不承诺跨重启。新会话默认使用用户上次在该运行时上的选择；运行时实例设置中可改为“运行时默认”（三项都不指定），或指定模型、推理强度与权限模式，其中各项也可为运行时默认。会话中仍可随时更改。

## status line 与用量显示

2026-10-14 用户要求在会话详情的 composer 中增加 status line（[S22](../sources.md#s22)）。它以紧凑方式放在操作行右侧、发送按钮之前，原则是不造成信息过载、界面干净，同时不损害信息披露：默认只显示上下文用量（占模型上下文窗口的比例，窗口未知时只显示 token 数）；悬停给出说明，点按打开完整状态，列出全部可用项。本会话累计 token、工作目录与 git 分支、Codex 账户额度、Harness 报告的费用估算默认不放进 status line，用户在设置的“通用”页中选择要常驻显示的项。数据以 Harness 原生记录为准（上下文窗口例外：managed 模型以 Velune 中配置的窗口为准，因为 Harness 对它不认识的模型只给出猜测），没有记录的项不显示、不推算；费用只是 Harness 按其价格表的估算，经网关或订阅时不代表实际计费。

2026-10-18 用户要求（[S39](../sources.md#s39)）：额度可显示为“剩余多少”，上下文窗口同样如此。一项“用量显示”设置在已用与剩余之间切换，作用于提供商额度窗口、账户用量限额与会话上下文；只改变呈现，额度的使用上限仍按已用比例生效，显示剩余时表现为至少保留的比例。该设置放在设置窗口新的首页“通用”，原“会话”与“快捷键”页并入其中。

## 发送队列、steer、继续与编辑

2026-10-15 用户要求（[S27](../sources.md#s27)）：

- 发送队列：turn 运行中再次发送时，消息默认进入 Velune 的发送队列，显示在 composer 上方，可编辑、删除、调整顺序；当前 turn 结束后按顺序逐条发出，每条是一个独立 turn。队列属于会话，同一会话在不同窗口／分屏看到的是同一个队列。
- Steering：队列项可改为 steer，另有快捷键直接 steer：消息经 Harness 原生通道立即注入正在运行的 turn，不另起 turn。运行时不提供原生 steer 时只能排队，不模拟。
- 中断与继续：中断沿用“停止生成”（Esc）；停止或失败的 turn 之后提供“继续”，作为一条真实的用户消息发出，不伪造历史，也不重放旧的工具执行。
- 编辑用户消息：可以编辑任意一条用户消息。编辑最后一条直接原地继续；编辑更早的一条时询问从该处 fork 出新会话继续，还是原地继续——原地继续会舍弃该消息及之后的内容，fork 保留原会话不变。编辑与 fork 经各 Harness 的原生机制执行，Velune 不重写原生会话文件；运行时不支持的情况下不提供该操作。
