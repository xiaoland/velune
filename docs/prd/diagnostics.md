# 问题与诊断

操作失败的集中展示与本地诊断内容。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 问题面板与诊断

2026-10-06 用户要求统一问题展示：会话列表不混入“历史读取”等内部操作错误分组，composer 与设置页底部不持续堆放操作错误。提供集中“问题”面板，便于查看失败及相关诊断；入口与布局遵循平台原生习惯。字段校验、运行进度和成功提示与操作问题区分，不把问题面板变成会话消息或原始日志展示。2026-10-11 用户指出 sheet／弹窗右上角不应出现打开问题面板的按钮，主窗口工具栏在有问题时保留入口；操作失败时如何提醒用户查看问题仍需进一步设计。

Velune 采用分布式架构，各设备的执行与数据由用户控制。本地问题详情与诊断应保留实际可获得的错误原因、上下文和底层错误链，不以安全或隐私为由替换为泛化提示、过滤用户所需的诊断内容。数据采集范围与向外发送是独立决定：完整展示一次失败不等于默认记录全部请求、会话或认证数据，更不授权开发工具读取真实秘密和会话。用户可查看、复制和清除自己的问题记录。 运行时失败还应能定位具体配置实例：保留实例标识、名称、类型及操作实际使用的非秘密入口路径；安装解析失败说明实际解析目标和底层文件系统原因，不要求用户手动抄配置才能判断失败来源。

## 客户端遥测

2026-10-27 用户确认：Velune 采用分布式架构，可观测性与开发可诊断性主要服务于 agent。四个平台客户端分别控制自己的遥测；选中的远端、窗口或会话不改变本机设置。使用各生态成熟的 OpenTelemetry SDK，通过 OTLP/gRPC 接入用户指定的接收端。

普通安装与 Debug 构建均默认无配置、不启用。设置区分“未设置”“关闭”“开启”；显式开发入口可以为未设置的隔离客户端临时提供配置，明确关闭始终优先。临时开发配置不成为保存的连接配置，普通重启不会自动沿用。接收端故障或启用失败不得成为业务启动与执行的依赖。

用户可单独设置地址、认证 metadata 与 trace 采样率，查看配置是否已由原生与 Rust 两侧应用、最近导出结果，并显式发送三信号测试。接收端回执不等于后台已可查询。关闭或换配置先撤销旧出口，旧队列不能在新目的地恢复发送；已发送的数据可能在关闭后到达。

采样率控制本机发起的新链路，已有父上下文时沿用其决定，以保持分布式因果。0% 仍可能记录已采样链路的子 span，日志和指标也不随之关闭；需要停止遥测时使用“关闭”。

从设备复制仅传递来源保存的连接、认证与采样参数，保留目的端自己的开关、身份和修订；后续没有持续同步。读取配置需要独立的 `TelemetryProfileRead` 授权，控制授权不包含它。来源可以是前台运行的手机；生成邀请、核对与批准明确说明“遥测配置（含认证）”。撤销阻止之后受理的读取，不能收回已经复制的凭据。回环地址原样复制并提醒调整，不猜测来源的可访问地址。

向外发送限定操作类别、阶段、结果、时长、随机操作标识与必要的分布式关联，不包含会话正文、代码、文件路径、原始 URL、设备名、认证或底层错误链。完整本地问题详情仍可由用户查看。指标不使用请求或会话 ID 作为标签；计数与时长不依赖 trace 抽样。无法确定父节点、结果未知、旧代际结束和外部 Harness 内部不可见的情况需要明确保留缺口。

agent 使用本地无秘密状态与接收端机器 API 判断故障，必须注明时间范围、参与实例、采样率和查询限制。SDK 未提供的队列深度、丢弃计数为未知，不能解释为零；官方 SDK 的已知丢弃汇总另外保留原代际的本地诊断记录。具体契约见[遥测装配与关联](../design/telemetry.md)。
