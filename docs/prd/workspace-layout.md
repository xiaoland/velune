# 多窗口、标签与布局

窗口、分屏标签组、停靠区与工具窗口，以及布局的恢复。下文以 Mac 表述；Windows 按[平台与界面](platforms.md)的跨端一致性要求取得同样结构。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 窗口与 Tab

Mac 每个原生窗口／Tab 独立保存当前会话、加载状态、下一轮选择、输入草稿和阅读位置。配置与执行核心保持共享，打开历史不改变其它Tab的执行上下文；发送明确绑定来源会话。关闭一个Tab不停止其它Tab中的任务。应用仍只允许一个活跃执行，不将多Tab提升为多个运行器。未发送的新会话先作为工作区草稿，首次发送才创建原生会话；创建成功后若发送失败保留其原生身份，结果不明确时不自动重建或重发。

## 窗口系统

2026-10-14 窗口系统（[S25](../sources.md#s25)）：目标是让用户由浅入深地高效工作，界面能承担高工作负载与高信息负载，参照 JetBrains IDE 等专业软件。默认形态保持简单，进阶能力按需出现；不追求任意内容都可停靠、组合，优先做好最常用的部分。

- 窗口内分屏：一个窗口可左右／上下拆分出多个会话面板，每个面板有自己的会话、输入区与运行状态；面板可拖出成独立窗口，也可拖回。多窗口、原生 Tab 与系统窗口平铺继续可用。
- 工具窗口限于会话列表、会话大纲与输入区（composer），可停靠、浮动或隐藏。浮动面板贴近主窗口边缘或彼此时吸附，吸附后随主窗口移动；拖入主窗口的停靠区即恢复停靠。
- 布局（拆分、面板与工具窗口状态）自动恢复，不提供命名布局。2026-10-16 细化（[S33](../sources.md#s33)）：工具窗口的位置、显示、停靠区与尺寸总是记住，任何没有自己布局的窗口（含退出后重开与新建窗口）沿用最近一次的安排；重开哪些窗口及其分屏、标签与会话跟随系统的窗口恢复设置。
- 变更审阅暂缓，跨会话活动面板不做；后续由“任务”层级承担跨会话的工作组织。

2026-10-15 复核（[S26](../sources.md#s26)）：首轮实现偏重模仿浮动、吸附等表面能力，未建立专业软件的布局机制。窗口系统按统一布局模型重建：

- 窗口由编辑区与左／右／底停靠区组成；工具窗口共用同一套状态（所在停靠区、模式、是否显示、尺寸）与操作，可放任一停靠区、同区并排。模式为停靠、浮动、独立窗口（可进 Mission Control、放到另一块屏幕或全屏）与隐藏。
- 编辑区的每个分屏是会话标签组（类似 VS Code 的 editor group），可同时打开多个会话，标签可在分屏与窗口之间移动，外观与交互仿照系统 Tab Bar。会话窗口不使用系统窗口 Tab：系统 Tab Bar 无法放进窗口内的各个分屏（没有公开接口），与分屏标签叠放又角色重复；标签只有分屏内一层，多个工作区就是多个窗口。其余尽可能复用平台机制。
- 工具窗口的快速开关、聚焦与其他进阶入口由开发方按 macOS 习惯选择，默认形态保持简单。2026-10-18（[S38](../sources.md#s38)）：右侧区与底部区沿用 VS Code 的 ⌥⌘B、⌘J，标签页切换沿用 Chrome 的 ⌥⌘←／→；收起底部区时停靠其中的输入区一起隐藏。Velune 自己的命令快捷键可在设置中更改、移除或恢复默认，发送消息保持 ⌘Return。

2026-10-16 补充（[S28](../sources.md#s28)）：

- 会话独立窗口：会话可移到只含编辑区的窗口（仿 VS Code 的移到新窗口），其中只有标签、分屏与各自的输入区，没有会话列表等停靠区；标签可在它与其他窗口之间拖动，需要时可恢复停靠区。
- 窗口与分屏的创建不依赖菜单栏：拖动标签到分屏边缘即拆分、拖到窗口外即成为会话独立窗口；标签的右键菜单提供同样的操作。标签栏始终显示，外观与系统默认的 Tab Bar 一致，不另加强调色的激活条。
- 面板尺寸参照 VS Code：分屏、停靠区与区内工具之间的分隔都可拖动调整，双击分隔恢复均分或默认尺寸。
- 窗口可保持在最前面（pin to top）。
- 标签栏已显示会话标题，工具栏不再重复显示。
- 布局（工具窗口的位置、底部区域、只显示编辑区、保持在最前面）同样不依赖菜单栏：在标签与各工具自身的右键菜单中切换；会话列表的位置在它的“显示”（筛选）菜单中调整。
