# Composer 提交、队列与恢复

本页拥有发送、steer、继续、编辑、压缩、失败恢复及控制权的行为。内容归属见[内容与导航](composer-input.md)，执行选择见[下一轮选择](composer-choices.md)。返回[产品能力索引](index.md#能力)。

## 提交主按钮与即时反馈

输入区只有一个提交主按钮，“停止”独立。正文与附件共同决定是否有输入；仅附件仍是发送，不能被“继续”忽略。来源：[S54](../sources/composer.md#s54)、[S73](../sources/dogfood.md#s73)。

| 状态 | 正文或附件 | 提交主按钮 |
| --- | --- | --- |
| 空闲，可发送 | 有 | 发送 |
| 空闲，同一上下文可继续 | 无 | 继续 |
| 空闲，没有恢复资格 | 无 | 发送，禁用 |
| 运行中，可排队 | 有 | 排队 |
| 运行中 | 无 | 不显示，保留停止 |
| 正在停止、发送或恢复 | 任意 | 显示对应进度，禁用 |
| 异地运行、未载入、只读子会话或其他提交受限状态 | 任意 | 发送，禁用；控制权锁定使用下文的原因状态 |

按钮、菜单、命令面板与快捷键读取同一份实时正文、附件、输入法和执行状态，动作入口重新判定，不等待草稿保存。输入法组词期间不提交；发送快捷键只发送或排队实际输入，空输入不恢复。继续使用明确按钮、菜单或专门配置的快捷键。默认键位归[键盘操作](keyboard.md)。

发送／恢复在途时禁止重复提交；停止请求本地发出后立即禁止重复停止和新提交，编辑器仍可输入。运行活动早于详情快照到达时先撤销空闲资格；核心也独立拒绝异地运行中的发送与恢复。

普通发送、排队和插入本轮在本地操作后立即可见，并表达提交状态；运行时确认前显示“发送中”。受理后由权威队列或原生消息接替占位，避免重复与空白等待。失败保留未发送输入，迟到回包不得清掉后续编辑。来源：[S20](../sources/composer.md#s20)、[S73](../sources/dogfood.md#s73)。

## 发送队列与 steer

运行中的会话再次提交默认进入发送队列，可编辑、删除、排序；当前 turn 结束后按顺序逐条发出，每条形成独立 turn。队列属于会话，在不同窗口和分屏共享，始终放在所属会话详情，切换共享 composer 的目标不带走队列。正常只显示“排队 N 条”，不常驻解释顺序。来源：[S27](../sources/composer.md#s27)、[S69](../sources/dogfood.md#s69)。

队列项可改为 steer，也可用快捷键直接插入本轮：经原生通道立即注入正在运行的 turn，不另起一轮；运行时没有原生 steer 时只能排队，不模拟。

停止、失败或消息未发出后，就地说明原因并提供“继续发送”。停止／失败完成后才到达的排队请求也保留并暂停，不自动新开一轮；已有队列保留用户的暂停或恢复决定。短暂控制权检查和连接交接属于等待，检查后继续调度，不锁存为发送失败。

“继续发送队列”与恢复当前上下文的“继续”独立。恢复本轮不解除停止／失败造成的队列暂停，用户停止后不能擅自启动下一条。只有后台子 Agent 工作时，沿用发送等待规则及停止子 Agent 操作，不提供原生恢复。

## 停止与继续

停止沿用“停止生成”（Esc）。停止、失败或原生历史标记提供恢复候选，但仍须空闲、无待审批、无子 Agent 工作、有原用户输入等资格；下一轮选择另一运行时时不提供继续。待审批由交互卡处理，是否可排队／插入本轮由核心能力决定。

Codex／Claude Code 支持在同一原生上下文以空输入开启新轮次，也可重开中断的原生会话后恢复。不重放工具或重答审批；可采用 composer 当前模型、推理与权限，但不修改原消息的发送配置。普通发送仍拒绝空消息，恢复失败明确显示。

运行时不支持无输入恢复时可声明文本兜底；Pi 使用 `continue`，作为普通用户消息保留，仍提供“继续”入口。策略派发前确定，原生恢复失败后不另发文字。来源：[S54](../sources/composer.md#s54)，文本兜底由 [S73](../sources/dogfood.md#s73) 修订。

## 编辑用户消息

用户消息可编辑；最后一条可原地继续，较早消息询问从该处 fork 新会话或原地继续。原地继续舍弃该消息及以后内容，fork 保留原会话。操作通过 Harness 原生机制执行，不重写原生会话文件；没有可靠能力时不提供。来源：[S27](../sources/composer.md#s27)。

单目标会话关联不构成禁止编辑的理由，composer 暂选另一运行时也不隐藏历史编辑入口。重发使用会话当前上下文的运行时，编辑窗口明示目标，失败保留编辑。只读子 Agent、执行中、待审批及无可靠继续机制的消息仍受操作限制。来源：[S65](../sources/dogfood.md#s65)。

Codex 普通用户消息按原生轮次回退／分叉。同轮追加的 steer 消息、跨运行时关联的前段消息不能精确原地回退时，仅提供“在新会话中继续”：在当前 Codex 上下文的运行时创建独立持久线程，以所选消息之前可读取的内容作参考，再发送编辑后的消息。参考不含所选消息及之后内容，不重放工具、审批或请求，不改写原会话或共享原生所有权。

## 在 sheet 中发送

Mac 会话列表右键菜单可在 sheet 打开目标的完整输入区，发送一次而不切换当前显示会话。使用该会话同一份草稿、下一轮选择及发送／排队／继续规则；运行中提交即排队。受理后关闭 sheet，失败保留输入并说明原因；取消只关闭 sheet，不删除草稿。

sheet 不含消息列表，不改变列表选中和当前会话。目标有待处理审批／请求时不能提交，说明原因并可转到会话。首个 beta 前只做 Mac。来源：[S56](../sources/conversations.md#s56)。

## 主动压缩上下文

支持原生压缩的运行时，在会话空闲、有历史、无待答交互和运行中子 Agent 时提供“压缩上下文”。使用同一运行时当前模型，不切 Harness，不作为普通消息发送；来源拒绝或无可压缩内容时如实显示，不改发摘要提示词。

压缩可停止，期间禁止并发发送、插入消息及修改队列。已有队列和暂停状态保留，结束不自动推进队列。主动压缩不重开上一用户轮次，不改变回复归属与计时；运行时自动压缩显示原生状态，仍属于原用户轮次。

这是可配置快捷键的桌面命令；Mac 命令面板可搜“压缩”或 `compact`，`/compact` 执行同一操作。菜单、按钮和命令共用可用性，不能执行时保留输入。以上为 2026-10-27 的要求。

## 失败恢复

优先由原生运行时重试。Codex app-server 明确终止为 `serverOverloaded`、`rateLimitExceeded` 或原生错误携带 HTTP 429，且未报告正在自动重试时，Velune 按 2、4、8、16、32 秒退避，最多五次。账户额度耗尽等独立错误不视为临时频率限制。恢复通过同线程、同模型／推理／权限的空输入继续，不重发原用户消息或已完成工具。其他失败、断连后派发结果不明时不自动重发。来源：[S59](../sources/dogfood.md#s59)、[S62](../sources/composer.md#s62)。

等待仍属于同一用户 turn，保持运行状态、允许停止、队列不推进。原生已报告重试时只展示其状态，不叠加循环；尚无可靠错误类型与恢复契约的运行时不猜测重试。

恢复状态在工作过程折叠时仍可见，集中显示错误种类、实际详情、恢复进度与操作。Mac 在转录区底部显示状态条，不改变 composer 高度：等待给出倒计时和次数，尝试给出进度与停止，成功／停止／耗尽分别显示结果。只有原生重试事实时不伪造时间或次数；历史错误可展开，但不重复活动进度，后续输入或已完成历史轮次不留过时提示。来源：[S65](../sources/dogfood.md#s65)。

## 会话控制权与输入锁定

控制权与是否正在生成分开表达，空闲不代表有写入权。Velune 按运行时机制提前观察占用、投影状态并限制操作，不等发送失败才告知；平台不自行猜锁文件或错误，不自动夺取其他客户端控制权。原生运行时仍拥有会话与排他机制。来源：[S60](../sources/dogfood.md#s60)。

控制权锁定只限制提交。已有正文与附件保留，普通未发送文字仍可编辑、粘贴、添加或移除附件，无须先保存或进入草稿模式；原生子会话等实际只读内容仍受编辑限制。说明原因与恢复方式，解锁不自动发送。Mac 用既有操作行中的“会话已锁定”等状态替代提交按钮，点按查看原因，不新增说明带；占位提示不能发送，焦点环仍反映本地编辑焦点。来源：[S62](../sources/composer.md#s62)。

编辑区高度与附件查看分别见[布局](composer-input.md#编辑与响应式布局)及[附件](composer-input.md#附件)。跨会话归档／重命名等管理进度属于窗口工具栏，不占 composer 内容或状态行。来源：[S69](../sources/dogfood.md#s69)。
