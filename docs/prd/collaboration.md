# Agent 协作与跨 Harness 接续

原生 sub-agent、Agent 间协作（A2A）、关联 Agent，以及会话换到另一个 Harness 继续。

本页维护当前规则；来源链接用于追溯决定，历史表述不单独构成当前要求。产品入口见[产品定义](index.md)。

## 原生 sub-agent 与 A2A

2026-10-11 用户要求 Harness 互联互通：运行中的 Agent 能发现其他运行时与会话、与之交流并委派具体工作，取得可关联的进度与结果后继续自己的工作；仅能从 Velune 启动不同 runtime 或切换会话不满足此目标。通用协作工具与现有 ACP／原生 adapter 分工，避免按每一对 Harness 开发连接。2026-10-12 用户纠正此前另一会话将其记为“把另一 runtime 当作 sub-agent”的表述，Velune 区分两种关系：

- **原生 sub-agent**：Harness 自身创建和拥有的子会话（例如 Claude Code、Codex 的子 Agent），属于会话体验。Velune 不创建它们；消息列表显示其发生，关联 Agent 面板汇总其状态，并可单独打开该子 Agent 的会话；子 Agent 会话不进入侧栏会话列表，只读，由启动它的会话继续。
- **Agent 间协作（A2A）**：Velune 提供的、不同会话之间的对等交流，可跨运行时与 Harness。参与方都是普通会话：出现在会话列表，可由用户单独打开、继续和处理审批；Agent 可以新建会话，也可以联系已有会话。Velune 不另设父子任务树、协作 scope 或“子任务”视图。

两者本质是否相同不由 Velune 这个 shell 判断，产品上按上述归属分别呈现。A2A 默认不设联系限制：Velune 执行的任一会话都可联系所有已启用运行时及其会话；以后若需要限制，设置归运行时设置，不在 composer 中逐会话授权。协作消息带出处、不授予额外权限；接收会话的待审批仍按其自身流程交给用户，忙碌、取消、失败和未知结果须明确。2026-10-13 用户确认收到的协作消息留在用户侧，标出来源会话即可，不改为居中的系统状态。原生 sub-agent 需要的审批交给启动它的会话处理（来源 [S19](../sources/runtime-collaboration.md#s19)）。

## 子 Agent 与关联 Agent

Pi 子 Agent 在关联 Agent 面板中的名称使用原生角色和任务摘要，冷读或上下文压缩后仍可恢复；不改写子会话自己的原生名称。关联身份与活动分开：续作产生的新 run ID 可继续使用原子会话，活动和停止须关联当前执行；父会话仍在工作不表示其子 Agent 仍在运行，普通后台任务仍在独立面板呈现。读取活动信息失败时保留已确认的关系和观察缺失语义，不把未知当成已结束。

打开执行中的子 Agent 会话时，消息列表底部显示当前活动，即使首条消息还未写入。指示器随该子 Agent 的执行启动和结束更新。


2026-10-16 用户要求优先补齐原生 sub-agent 的界面短板，并指出概念上可都视为 A2A，但多数运行时另有一套并行的原生 sub-agent 机制（[S31](../sources/runtime-collaboration.md#s31)）。本轮范围：会话页可看到该会话的子 Agent 概览（标题、运行中／结束／失败，可直接打开），不必展开工作过程逐个查找；会话列表中父会话行反映其子 Agent 仍在运行或有待处理的审批，即使父会话自身的轮次已结束；从父会话打开子会话后能返回原处。父会话轮次结束后才到达的子 Agent 审批也交给父会话处理，不再拒绝。概览后来统一为下述“关联 Agent”；不保留早期 Velune 父子委派或独立子任务视图。

2026-10-18 子 Agent 概览升级为“关联 Agent”（[S36](../sources/runtime-collaboration.md#s36)）：一个会话的父会话（它是原生子 Agent 时）、原生子 Agent，以及与它经 Velune 协作的会话（它联系了对方、对方联系了它，或互相联系）在同一面板分组列出，体现子 Agent 与 A2A 同为“与其他 Agent 的关系”；两种机制仍按上文归属分别运作。关联会话的打开方式是一项应用设置：当前标签页（默认，可后退返回）、新标签页、浮层（盖在窗口上，可转到标签页或独立窗口）或新窗口；面板中双击、消息列表中的“打开会话”、来源链接与“打开父会话”都按它打开，面板的右键菜单可选其他方式。已由某个标签页显示的会话改为切换到该标签页。

## 后台任务

后台 shell、delegate 等工作具有独立的任务身份，不要求存在可打开的会话。Mac 以独立的“后台任务”工具列出运行时报告的任务，可查看状态和运行时已提供的有界输出。它与“关联 Agent”各有入口、选择和布局，可分别弹出、停靠、浮动或放入独立窗口；数量、空态与运行状态各自表达。关联 Agent 只列会话关系，普通 shell 不冒充子 Agent。只有原生任务元数据、父关系和子记录一致时，才提供打开子会话。来源：[S91](../sources/conversations.md#s91)。

单项停止只作用于选中的任务，不中断父回复或兄弟任务；“正在停止”表示请求在途，控制请求的 ACK 不等于任务已结束。完整活动集合可证明任务不再运行，但没有终态回执时结果仍为未知。运行时不支持精确控制、旧版能力未经证实或失去连接时，不提供该操作，也不改为停止父轮次。描述与进度文字不冒充任务结果；未知、失败和无法读取输出均保留事实并就近说明。

查看后台任务不启动原生 Agent 或抢占会话控制权。当前入口复用已连接宿主的结构化观察；未连接的冷历史通知仍保留在消息中，任务面板明确不可查询，不能由旧启动回执推断现在仍在运行。Windows 和移动端暂不提供任务专属面板。

## 跨 Harness 接续

2026-10-23 用户要求 Agent 能用 xURL 查询、读取和继续各 Harness 会话，同时吸纳有助于效率、稳定性与支持范围的实现思路（[S47](../sources/conversations.md#s47)）。Mac 与 Windows 随包提供固定版本的官方 CLI，Agent 通过现有 MCP 发现调用路径、目标实例环境与指引。Velune 的协作工具也接受支持的 `agents://` 地址，补充查询与分页历史读取，续聊仍遵守原有忙碌、审批和子会话限制。官方 CLI 的直接写入是独立原生执行，不承诺 Velune 的模型路由、审批与取消；不以其替换现有运行时适配器。当前应用地址入口支持 Codex、Claude Code 与 Pi，其他上游查询形式使用官方 CLI。

用户已接受跨 Harness 接续采用“目标原生会话＋上下文交接＋只持久化关联元数据”：保留来源原生会话，在目标运行时创建原生会话，由 adapter 交接可携带的上下文，不重放旧工具执行或审批状态。Velune 保存原生会话引用与切换位置，使重启后仍能恢复同一条逻辑会话；消息持久化继续由各 Harness 拥有，不保存消息副本。这是对只做 projection 的关联元数据边界补充，不将不同运行时的 native session ID 视为可以互相 resume，也不承诺无损迁移。

## 后台任务通知

工作进行中的后台任务通知，以及子 Agent 发给 parent 的结果、决策请求、控制提醒和各种等待状态，统一归入“工作过程”，按原生顺序与工具执行记录一起展开；不因消息需要答复或关注而把它排在整段工作之后。它们不是用户输入，也不产生新的用户轮次。真正晚于该轮最终回复的通知仍显示在回复之后；压缩等原因造成没有可归属轮次的历史通知时，保留其原位置。

消息遵守原生显示标记并保留正文；归入工作过程不表示请求已回答或任务已完成。原生用户指令、独立管理输出及其它扩展消息保留各自身份，父 Agent 发给子 Agent 的指令保留原来的工具调用关系。后台任务面板的状态与操作继续独立于关联 Agent。
