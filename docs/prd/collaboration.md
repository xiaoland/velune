# Agent 协作与跨 Harness 接续

原生 sub-agent、Agent 间协作（A2A）、关联 Agent，以及会话换到另一个 Harness 继续。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## 原生 sub-agent 与 A2A

2026-10-11 用户要求 Harness 互联互通：运行中的 Agent 能发现其他运行时与会话、与之交流并委派具体工作，取得可关联的进度与结果后继续自己的工作；仅能从 Velune 启动不同 runtime 或切换会话不满足此目标。通用协作工具与现有 ACP／原生 adapter 分工，避免按每一对 Harness 开发连接。2026-10-12 用户纠正此前另一会话将其记为“把另一 runtime 当作 sub-agent”的表述，Velune 区分两种关系：

- **原生 sub-agent**：Harness 自身创建和拥有的子会话（例如 Claude Code、Codex 的子 Agent），属于会话体验。Velune 不创建它们；当前只在消息列表中显示其发生，并可单独打开该子 Agent 的会话（2026-10-12 已实现 Codex 与 Claude Code；子 Agent 会话不进入会话列表，只读，由启动它的会话继续）。
- **Agent 间协作（A2A）**：Velune 提供的、不同会话之间的对等交流，可跨运行时与 Harness。参与方都是普通会话：出现在会话列表，可由用户单独打开、继续和处理审批；Agent 可以新建会话，也可以联系已有会话。Velune 不另设父子任务树、协作 scope 或“子任务”视图。

两者本质是否相同不由 Velune 这个 shell 判断，产品上按上述归属分别呈现。A2A 默认不设联系限制：Velune 执行的任一会话都可联系所有已启用运行时及其会话；以后若需要限制，设置归运行时设置，不在 composer 中逐会话授权。协作消息带出处、不授予额外权限；接收会话的待审批仍按其自身流程交给用户，忙碌、取消、失败和未知结果须明确。2026-10-13 用户确认收到的协作消息留在用户侧，标出来源会话即可，不改为居中的系统状态。原生 sub-agent 需要的审批交给启动它的会话处理（来源 [S19](../sources.md#s19)）。

## 子 Agent 与关联 Agent

2026-10-16 用户要求优先补齐原生 sub-agent 的界面短板，并指出概念上可都视为 A2A，但多数运行时另有一套并行的原生 sub-agent 机制（[S31](../sources.md#s31)）。本轮范围：会话页可看到该会话的子 Agent 概览（标题、运行中／结束／失败，可直接打开），不必展开工作过程逐个查找；会话列表中父会话行反映其子 Agent 仍在运行或有待处理的审批，即使父会话自身的轮次已结束；从父会话打开子会话后能返回原处。父会话轮次结束后才到达的子 Agent 审批也交给父会话处理，不再拒绝。概览按中立的“关联会话”组织，以后 A2A 参与方可并入同一呈现，但本轮不改变 A2A 的呈现。运行时之间的互相调用是后续方向，不在本轮。实施归 [Agent 间协作任务](../../tasks/agent-collaboration/packet.md)；2026-10-11 的父子委派实现及其证据见 [Harness 协作任务](../../tasks/harness-interoperation/packet.md)，其父子 scope 模型已被取代。

2026-10-18 子 Agent 概览升级为“关联 Agent”（[S36](../sources.md#s36)）：一个会话的父会话（它是原生子 Agent 时）、原生子 Agent，以及与它经 Velune 协作的会话（它联系了对方、对方联系了它，或互相联系）在同一面板分组列出，体现子 Agent 与 A2A 同为“与其他 Agent 的关系”；两种机制仍按上文归属分别运作。关联会话的打开方式是一项应用设置：当前标签页（默认，可后退返回）、新标签页、浮层（盖在窗口上，可转到标签页或独立窗口）或新窗口；面板中双击、消息列表中的“打开会话”、来源链接与“打开父会话”都按它打开，面板的右键菜单可选其他方式。已由某个标签页显示的会话改为切换到该标签页。

## 跨 Harness 接续

用户已接受跨 Harness 接续采用“目标原生会话＋上下文交接＋只持久化关联元数据”：保留来源原生会话，在目标运行时创建原生会话，由 adapter 交接可携带的上下文，不重放旧工具执行或审批状态。Velune 保存原生会话引用与切换位置，使重启后仍能恢复同一条逻辑会话；消息持久化继续由各 Harness 拥有，不保存消息副本。这是对只做 projection 的关联元数据边界补充，不将不同运行时的 native session ID 视为可以互相 resume，也不承诺无损迁移。具体实现与隔离验收归 [跨 Harness 接续任务](../../tasks/cross-harness-continuation/packet.md)。
