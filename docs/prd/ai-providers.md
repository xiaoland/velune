# AI 服务、提供商与模型

AI 服务与 LLM 网关的职责，提供商、模型与模板，协议及转换，提供商导入与来源。技术契约见 [AI 服务设计](../design/ai-service.md)。

各段保留用户决定的原话与日期；同一主题下后来的决定修订先前的表述，以日期较晚者为准。来源见各段标注，产品入口见[产品定义](index.md)。

## AI 服务与网关

2026-10-03 用户确认 AI service 为独立 lib、领域不限 LLM，sampling 是其中一项操作。service 拥有对调用方和 provider 的权威契约；provider 即 adapter，转换外部协议，协议库／SDK 只作为 provider 内部可替换依赖。provider 基本配置为协议配置、凭据引用、模型列表，不再新增账户／渠道实体。

Harness 与 AI 服务保持独立；读取 Harness 提供商配置属于装配边界的导入适配，不让 AI 服务理解 Harness 的配置、运行或推理级别。AI 服务也不以大语言模型作为整个领域的基础假设；模型、token、对话和推理参数只归相应操作及协议契约。当前只实现 sampling 与原生 Responses 不代表 AI 服务仅限 LLM。

2026-10-05 用户进一步明确：当前 gateway 仅为 LLM Gateway，是 AI 模块的一种应用模式，不代表整个 AI 服务。应用可以直接消费 AI 能力，不要求全部经过 gateway。此前本页“AI 网关”在当前实现范围内均指 LLM Gateway；非 LLM 能力及其接入模式按具体需求另行设计。

提供商拥有认证配置，不要求独立中央认证建档。API key 可在 application 私有文件保存并显式查看编辑，公开摘要与日志不含秘密；OAuth 保留来源登录／刷新，不复制 refresh credential。Pi 等运行时只是来源，不是认证方式。解析与目标校验归 application，gateway 仅消费中立异步解析接口；解析失败不回退环境或其它认证。

统一配置中心持久化，app main 装配；AI lib 不自行读全局配置／环境／文件或保存配置；一次已开始调用保持运行配置稳定。具体归属见 [AI service 设计](../design/ai-service.md)，决定来源见 [S13](../sources.md#s13)。本步只实现契约与校验，不改旧宿主；验收方案、真实接入与 fixture 准备独立记录，不把静态检查等同运行验收。

2026-10-04 用户进一步提出统一网关接管方向：保留 Harness 原有提供商配置，研究读取并接入它的配置与认证来源；例如由 Velune 触发 Pi 的订阅登录，用户完成后供网关使用。Velune 创建的会话希望默认保持 `velune/auto` 或按 Harness 区分的稳定入口，由网关负责实际模型与提供商选择。用户随后明确授权调整实现；稳定入口和认证委托的具体适配仍需隔离验证。授权不包括开发方读取真实秘密、执行真实登录或调用模型，真实验收由用户进行。

## 提供商与模型

2026-10-04 用户纠正首循环配置模型：产品使用“AI 提供商”，废弃“模型资源”实体。模型独立于提供商存在，同一个模型可以由多个提供商提供，一个提供商也可以提供多个模型。模型具有提供商规定的 model ID，以及昵称、图标及能力参数；最大输出 token 数、支持的推理级别是示例，不要求所有提供商支持这些参数。字段与编码以提供商协议为权威；提供商配置包含可调用模型、可编辑的协议与端点，以及其认证配置；不要求用户另行建立认证资源。model ID 是提供商 API 接受的模型标识，不是由用户另填的 Velune 内部记录键；内部引用和显式网关路由别名须与它分别命名。跨提供商的模型关联不能凭同名自动推断等价。 用户可从公开模型目录显式拉取、搜索并挑选条目作为模板快填。目录给出来源声明，不决定实际提供商的协议、端点或可用性；填入后成为独立可编辑快照，不能自动覆盖已保存模型或因 reasoning 支持标记猜测具体级别。

协议使用有限选项，首先实现 OpenAI ChatCompletions v1；2026-10-04 用户进一步要求支持 OpenAI Responses v1，当时暂不进行协议翻译；此阶段限制已由2026-10-06三协议互转授权修订。不使用任意字符串输入来代表协议。AI 提供商只是 Velune AI 服务网关配置的一部分；模型路由与 fail-over 策略同属网关配置，不属于提供商实体。Harness 通过 Velune 注册的网关提供商共享模型、聚合订阅与提供商；网关是新增入口，不是唯一允许的入口。用户于 2026-10-08 明确纠正：不得拦截运行时原有提供商注册、模型选择或派发，不以“防绕过”为由限制原生能力。认证由 Velune 提供商适配边界处理；认证来源可以研究对用户指定 Harness 配置的明确委托，并不要求所有登录流程由 Velune 重写。

2026-10-05 用户要求立即实施模型业务重构，并明确早期阶段所有重构为 hard-cutoff：不保留旧接口、字段兼容或配置迁移。旧配置无需保留，遇到旧 schema 直接初始化当前配置，不备份、不迁移；原 Harness 文件、会话与 Keychain 秘密不删除。模型 ID、内部记录键和网关别名分别建模，提供商绑定保留实际能力与限制，详情面板遵守原生对齐习惯。

2026-10-05 后续产品修订：用户指出独立模型与中央认证管理增加多处建档，要求先厘清参数归属再实施。提供商的协议、服务地址应允许修改；API model ID 应在模型表单显示并可编辑，API key 应可直接查看和修改，Keychain 不再是产品要求。独立“认证”管理入口不再是目标体验。当前配置结构待按“提供商及其模型”复核，不能继续把跨提供商存在同一真实型号推导成必须建立独立全局模型配置实体；本次先完成需求与结构讨论。

跨提供商存在同一模型的产品价值，是复用型号参数作为模板，避免用户每次手填。提供商下的模型配置可从模板快速填入，并按该提供商实际支持编辑 model ID 和参数；模板不证明不同提供商的能力完全相同，也不要求先创建全局模型调用实体。本轮用户已认可参数归属并授权实施；模板作为填写起点，实际模型配置可独立修改。当前请求的 reasoning effort 与模型支持的 effort 集合分别表达。

## 提供商编辑器

提供商编辑器需先整理功能与内容，再按平台原生方式重新设计布局和交互；不能把接入、认证与全部模型字段不断追加到一张表单。提供商及其模型可以在同一编辑流程完成配置，单目标调用不要求先配置全局模型、独立认证资源或路由。模板管理服务快速填写，不承担运行时模型身份或认证职责。

提供商编辑器的复杂度优先通过主次层级与渐进披露处理。隐藏次要内容或在上下文中展开，当前任务的主要字段直接可见；放大窗口不是默认解决方式。信息组织变化不能让 model ID 或可用 reasoning effort 再次难以发现。

## 提供商模板与来源

2026-10-17 用户指出在提供商表单中逐个罗列“使用某订阅”的入口无法随订阅增加扩展，并提出订阅锁定协议与地址，可理解为一种 AI 提供商模板。添加提供商因此先选择模板：每个订阅是一个固定连接方式的模板，API 提供商是可编辑协议与地址的模板；之后增加订阅只增加模板，不改变表单结构。模板只决定新提供商的初始组合，与模型模板一样不形成独立的全局实体。

2026-10-17 用户随后决定提供商来源范围：Codex 订阅维持在 Velune 中逐个账户登录，不导入或粘贴 auth.json；Claude Code 订阅可沿用本机已有登录（本人默认登录或某个本机 Claude Code 运行时实例的登录），以引用方式由官方 CLI 继续保存与续期，Velune 不复制凭据，也不提供退出该登录的操作；“从 Agent 运行时导入”扩展到 Codex 与 Claude Code，首批导入 Claude Code 登录及两者已配置的 API 提供商，ACP 暂不做。

Harness 提供商配置导入是一项完整功能，包含提供商定义、协议与端点、模型及能力参数、对应认证来源。导入来源选择已经配置的 Agent 运行时实例，复用该实例的目录与执行配置，不要求用户再次填写来源目录或 Node 路径。读取配置不以运行时连接成功、已有默认模型或模型路由为前提。预览按提供商、模型与详情组织内容，模型参数和不可导入原因渐进披露；用户显式选择导入项，读取本身不默认全选。不能把仅接入认证来源描述为导入完成；原 Harness 配置保留，Velune 接管其模型请求路由；API key 的本机保存与编辑遵循提供商配置要求，预览不输出秘密。

## 协议

AI 服务增加原生 Anthropic Messages 协议，与既有原生 OpenAI 协议并列；同协议保持原生路径，异协议按后续授权采用best-effort转换；运行时是否支持由具体版本适配器的真实能力决定。

2026-10-06 用户授权为跨 Harness 对话增加 OpenAI ChatCompletions v1、Responses v1 与 Anthropic Messages 的全部双向转换，修订此前仅同协议透传的阶段限制。同协议调用继续保留原生请求、响应与流式事件；异协议转换采用 best-effort，不采用 fail-closed。尽量映射消息、工具与参数，不可等价的协议特性允许降级或省略，并通过不含正文的诊断说明转换情况；不能伪造缺失历史、工具执行结果或上游成功。Anthropic 必须的输出上限优先取请求，未提供时采用所选模型配置的最大输出；两者均无值时说明必要配置缺失。
