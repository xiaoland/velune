# AI 服务、提供商与模型

AI 服务与 LLM 网关的职责，提供商、模型与模板，协议及转换，提供商导入与来源。技术契约见 [AI 服务设计](../product-tdd/ai-service.md)。

本页维护当前规则；来源链接用于追溯决定，历史表述不单独构成当前要求。产品入口见[产品定义](index.md)。

## AI 服务与网关

2026-10-03 用户确认 AI service 为独立 lib、领域不限 LLM，sampling 是其中一项操作。service 拥有对调用方和 provider 的权威契约；provider 即 adapter，转换外部协议，协议库／SDK 只作为 provider 内部可替换依赖。provider 基本配置为协议配置、凭据引用、模型列表，不再新增账户／渠道实体。

Harness 与 AI 服务保持独立；读取 Harness 提供商配置属于装配边界的导入适配，不让 AI 服务理解 Harness 的配置、运行或推理级别。AI 服务也不以大语言模型作为整个领域的基础假设；模型、token、对话和推理参数只归相应操作及协议契约。当前操作与协议的实现范围不将 AI 服务限定为 LLM。

2026-10-05 用户进一步明确：当前 gateway 仅为 LLM Gateway，是 AI 模块的一种应用模式，不代表整个 AI 服务。应用可以直接消费 AI 能力，不要求全部经过 gateway。此前本页“AI 网关”在当前实现范围内均指 LLM Gateway；非 LLM 能力及其接入模式按具体需求另行设计。

提供商拥有认证配置，不要求独立中央认证建档。API key 可在 application 私有文件保存并显式查看编辑，公开摘要与日志不含秘密；OAuth 保留来源登录／刷新，不复制 refresh credential。Pi 等运行时只是来源，不是认证方式。解析与目标校验归 application，gateway 仅消费中立异步解析接口；解析失败不回退环境或其它认证。

统一配置中心持久化，app main 装配；AI lib 不自行读全局配置／环境／文件或保存配置；一次已开始调用保持运行配置稳定。具体归属见 [AI service 设计](../product-tdd/ai-service.md)，决定来源见 [S13](../sources/first-loop.md#s13)。验收方案、真实接入与 fixture 证据归对应任务记录，不把静态检查等同运行验收。

网关接管只作用于选择 Velune 模型的轮次，保留 Harness 原生提供商与模型能力。稳定模型入口和认证委托由各适配器实现；读取既有提供商配置的范围见[提供商模板与来源](#提供商模板与来源)，执行边界见[Agent 运行时](agent-runtimes.md#原生提供商网关轮次与执行位置)。开发验证遵守[真实数据边界](../development.md)。

## 提供商与模型

产品使用“AI 提供商”，不保留“模型资源”实体。一个提供商可配置多个模型；同一真实型号可由多个提供商提供，但各自配置独立。模型具有提供商规定的 model ID，以及昵称、图标及能力参数；最大输出 token 数、支持的推理级别是示例，不要求所有提供商支持这些参数。字段与编码以提供商协议为权威；提供商配置包含可调用模型、可编辑的协议与端点，以及其认证配置；不要求用户另行建立认证资源。model ID 是提供商 API 接受的模型标识，不是由用户另填的 Velune 内部记录键；内部引用和显式网关路由别名须与它分别命名。跨提供商的模型关联不能凭同名自动推断等价。

用户可从公开模型目录显式拉取、搜索并挑选条目作为模板快填。目录给出来源声明，不决定实际提供商的协议、端点或可用性；填入后成为独立可编辑快照，不能自动覆盖已保存模型或因 reasoning 支持标记猜测具体级别。

协议使用有限选项：OpenAI ChatCompletions v1、Responses v1 与 Anthropic Messages；不使用任意字符串输入来代表协议。透传与转换规则见[协议](#协议)。AI 提供商只是 Velune AI 服务网关配置的一部分；模型路由与 fail-over 策略同属网关配置，不属于提供商实体。Harness 通过 Velune 注册的网关提供商共享模型、聚合订阅与提供商；网关是新增入口，不是唯一允许的入口。用户于 2026-10-08 明确纠正：不得拦截运行时原有提供商注册、模型选择或派发，不以“防绕过”为由限制原生能力。认证由 Velune 提供商适配边界处理；认证来源可以研究对用户指定 Harness 配置的明确委托，并不要求所有登录流程由 Velune 重写。

配置变更允许 hard-reset／hard-cutoff，但已有数据或配置必须在版本切换前完成显式手动迁移，不建立应用自动迁移机制；原 Harness 文件、会话与平台秘密不在重置范围内。当前执行约定归[破坏性变更与手动迁移](../development/migrations.md)，来源为 [S63](../sources/development.md#s63)。

提供商的协议、服务地址可修改；API model ID 在模型表单显示并可编辑，API key 可直接查看和修改，不要求 Keychain。配置围绕“提供商及其模型”组织，不要求独立的中央认证入口或全局模型调用实体（2026-10-05 修订）。

跨提供商存在同一模型的产品价值，是复用型号参数作为模板，避免用户每次手填。提供商下的模型配置可从模板快速填入，并按该提供商实际支持编辑 model ID 和参数；模板不证明不同提供商的能力完全相同，也不要求先创建全局模型调用实体。模板作为填写起点，实际模型配置可独立修改。当前请求的 reasoning effort 与模型支持的 effort 集合分别表达。

## 提供商编辑器

提供商编辑器需先整理功能与内容，再按平台原生方式重新设计布局和交互；不能把接入、认证与全部模型字段不断追加到一张表单。提供商及其模型可以在同一编辑流程完成配置，单目标调用不要求先配置全局模型、独立认证资源或路由。模板管理服务快速填写，不承担运行时模型身份或认证职责。

提供商及运行时列表双击进入编辑；模型模板支持原生多选批量添加，提供商模型表单将“添加新模型”与“从模板中选取”分开，模板选择使用独立 sheet。

提供商编辑器的复杂度优先通过主次层级与渐进披露处理。隐藏次要内容或在上下文中展开，当前任务的主要字段直接可见；放大窗口不是默认解决方式。信息组织变化不能让 model ID 或可用 reasoning effort 再次难以发现。

## 提供商模板与来源

2026-10-17 用户指出在提供商表单中逐个罗列“使用某订阅”的入口无法随订阅增加扩展，并提出订阅锁定协议与地址，可理解为一种 AI 提供商模板。添加提供商因此先选择模板：每个订阅是一个固定连接方式的模板，API 提供商是可编辑协议与地址的模板；之后增加订阅只增加模板，不改变表单结构。模板只决定新提供商的初始组合，与模型模板一样不形成独立的全局实体。

官方 API 模板包括 OpenAI Platform（默认 Responses）、Anthropic API（默认 Messages），以及 DeepSeek、Moonshot、OpenRouter；均允许编辑协议与地址，额度读取按实际支持单独配置。OpenAI Platform 与 Codex 订阅、Anthropic API 与 Claude Code 订阅、Moonshot 开放平台 API 与 Kimi Code 订阅分别配置，各自使用对应服务的凭据与计费额度。不能仅凭品牌、模型名称、协议或 API key 认证方式推断为同一种接入产品。

2026-10-17 用户随后决定提供商来源范围：Codex 订阅维持在 Velune 中逐个账户登录，不导入或粘贴 auth.json；Claude Code 订阅可沿用本机已有登录（本人默认登录或某个本机 Claude Code 运行时实例的登录），以引用方式由官方 CLI 继续保存与续期，Velune 不复制凭据，也不提供退出该登录的操作；“从 Agent 运行时导入”扩展到 Codex 与 Claude Code，首批导入 Claude Code 登录及两者已配置的 API 提供商，ACP 暂不做。

Harness 提供商配置导入是一项完整功能，包含提供商定义、协议与端点、模型及能力参数、对应认证来源。导入来源选择已经配置的 Agent 运行时实例，复用该实例的目录与执行配置，不要求用户再次填写来源目录或 Node 路径。读取配置不以运行时连接成功、已有默认模型或模型路由为前提。预览按提供商、模型与详情组织内容，模型参数和不可导入原因渐进披露；用户显式选择导入项，读取本身不默认全选。不能把仅接入认证来源描述为导入完成；原 Harness 配置保留，Velune 接管其模型请求路由；API key 的本机保存与编辑遵循提供商配置要求，预览不输出秘密。

## 账户额度、历史与提醒

2026-10-27 用户同意借鉴 quotio 的金额额度、官方账户额度、额度历史与提醒（[S55](../sources/ai-routing.md#s55)）。

额度除按比例的窗口外，还可报告余额等金额，带数额与单位。金额只显示与记录，不换算成比例，也不参与智能排序；提供商表示账户不可用（如余额不足）时暂停新请求。

额度页逐项显示全部已报告的窗口；重置时间使用本地日期及精确到分钟的时刻。来源未报告时间戳时明确显示未知，不用“下周”等相对文案代替已知时刻。composer 中对应模型或路由的额度详情遵守[同一展示约定](composer-choices.md#status-line-与用量显示)。

API key 提供商直连官方地址时可读取账户额度：DeepSeek（`api.deepseek.com`）、Moonshot（`api.moonshot.cn`，以及 `api.moonshot.ai`）与 OpenRouter（`openrouter.ai`）。Key 只发往同一官方主机，不跟随重定向，中转或其他地址不提供此项；对应模板默认开启，编辑器可关闭。DeepSeek 与 Moonshot 报告余额；OpenRouter 报告这个 Key 的花费上限（作为可设使用上限的窗口）与剩余额度，未设上限的 Key 不报告额度。其他供应商的充值余额查询若无公开官方接口则不接入；组织报表与余额分别处理，见下节。

额度历史只记录 Velune 成功读取到的观测，不补点，没有观测的时段留空而不连线；不为记录历史而增加后台读取。更换认证后从新的记录开始；保留 30 天，可在额度页清除，删除提供商时一并删除。

达到使用上限、窗口用尽或提供商表示账户不可用时，以系统通知提醒一次；条件解除后再次出现才再提醒。提醒沿用已有的使用上限，不另设阈值。

## 组织用量与账单

OpenAI Platform 与 Anthropic API 提供可选的“用量与账单”入口，位于已保存的官方 API 提供商下，查询配置独立保存。模型认证与组织查询认证分别管理，不自动将模型 Key 用作 Admin Key，也不要求另建账户实体。查询组织与模型认证的关联由用户确认，不能称为服务端核验。更换模型认证后暂停查询，重新确认后恢复；关闭查询、删除提供商或改为不支持的连接时清除查询凭据。保存查询配置不打断正在执行的模型请求。

首期读取本月 UTC 范围的官方用量与费用，明确显示组织与统计范围、统计区间、本地抓取时刻和官方数据刷新时刻。OpenAI 可选整个组织、Project 或 API key ID；Anthropic 可选整个组织、Workspace 或 API key ID。Key ID 是筛选标识，与查询密钥分别填写。同一范围涵盖其他客户端消费，多个提供商引用时不能把组织总额重复相加。

用量、费用、余额、月度支出限额和配置速率上限分别展示：OpenAI 读取组织／Project 月度支出限额，Anthropic 读取组织／Workspace 速率配置；API key 范围不套用整个组织的限额。这些报表只读展示，不推算充值余额或剩余百分比，不进入网关准入、路由排序、额度历史与提醒。充值余额仍需在官方控制台查看。

查询需要相应组织权限。Anthropic Analytics 当前为 beta，普通 workspace 模型 Key 不适用，个人账户不支持 Admin API；统计通常延迟 4 小时，最长 24 小时，费用为折扣后、credits 抵扣前金额。其区间按 UTC 小时截断，官方刷新时间未知时保持未知。OpenAI 的文本生成用量与 Costs 覆盖的服务可能不同。空记录显示“此范围暂无记录”，不推断账户有余额，范围 ID 不匹配也可能返回空集合。

读取立即返回缓存状态，按需采集，可手动刷新；查询失败时保留上次报表并标记过期。某一项分页失败，不把已取到的页面当作完整总额；独立成功项仍可展示，同时说明失败项。查询 Key 只向固定官方 HTTPS 目标发送，不跟随重定向，无读取明文入口。

## 协议

AI 服务增加原生 Anthropic Messages 协议，与既有原生 OpenAI 协议并列；同协议保持原生路径，异协议按后续授权采用best-effort转换；运行时是否支持由具体版本适配器的真实能力决定。

2026-10-06 用户授权为跨 Harness 对话增加 OpenAI ChatCompletions v1、Responses v1 与 Anthropic Messages 的全部双向转换，修订此前仅同协议透传的阶段限制。同协议调用继续保留原生请求、响应与流式事件；异协议转换采用 best-effort，不采用 fail-closed。尽量映射消息、工具与参数，不可等价的协议特性允许降级或省略，并通过不含正文的诊断说明转换情况；不能伪造缺失历史、工具执行结果或上游成功。Anthropic 必须的输出上限优先取请求，未提供时采用所选模型配置的最大输出；两者均无值时说明必要配置缺失。
