# Composer 下一轮选择与状态

本页定义目标会话的执行选择、轮次配置披露与额度显示。正文和附件的归属见[内容与导航](composer-input.md)，提交资格见[提交与恢复](composer-actions.md)。返回[输入区入口](composer.md)。

## 选择器与下一轮选择

选择器按两个问题组织为系统原生下拉，沿用系统颜色与深色模式：

- “谁来回答”：按钮显示“运行时 · 模型 · 推理强度”，菜单内只设这三个子菜单，子菜单标题含当前选择，设置入口置于对应子菜单内。
- “允许做什么”：权限模式与 ACP 会话选项。权限模式由运行时类型声明，通过原生通道作用于下一轮；不提供模式的运行时不显示该选择器。

模型、推理强度与权限各分为“会话当前”和“下一轮明确选择”。会话当前优先取 Harness 原生记录，缺失时取 Velune 为该轮保存的实际发送请求；未明确选择的项沿用会话当前，仍未知就不发送，由运行时决定。Velune 不读取 Harness 配置猜默认值，不把 `unknown`、`native` 或“默认”作为参数发送，也不因不认识当前模型而改用目录第一项。记录中的模型不在目录时显示“沿用当前（ID）”，原样发送。来源：[S20](../sources/composer.md#s20)、[S21](../sources/composer.md#s21)、[S42](../sources/composer.md#s42)。

推理强度取模型声明的级别，经 Harness 原生通道设置，仍为单一维度；按实际传值显示，不做本地化。未选时沿用同一运行时最近一轮的记录，未知则不发送。权限模式遵守同样规则；新会话未指定时使用运行时默认。

每个目标会话按运行时分别保存模型、推理与权限，重启后保留，同一会话的多个 Tab 共享；切回运行时恢复其尚未发送的选择。下一轮运行时同样按目标保存；离开后回来或跨 group 聚焦时恢复该目标尚未发送的运行时选择，各运行时的模型／推理／权限选择也保留。这是 [S78](../sources/dogfood.md#s78) 对早先“离开后恢复会话当前运行时”规则的修订；尚未首发的新会话恢复全局新建选择。Velune 实际发送请求同样持久化，用于补充原生记录。

新会话默认使用用户上次在该运行时上的选择；实例设置可改为“运行时默认”（三项都未指定），或逐项指定模型、推理与权限，之后仍可在会话中修改。新建内容和选择也跨重启保留，导航和跨 group 聚焦时的恢复规则见[内容与目标归属](composer-input.md#内容与目标的归属)。

实例的新会话策略与该实例配置共同保存；保存成功后，两者同时生效。上次选择带有 Adapter Type 归属，更换类型后不将旧类型的模型／推理／权限用作默认。已有会话目标的明确选择仍保留，不由普通实例编辑清空。

## 轮次配置与模型速度

实际使用的运行时、模型、推理与权限可在消息列表中查阅：工作过程行右侧平时只显示次要图标，悬停展开运行时与模型摘要，点按显示完整配置和该轮 token 用量（含推理 token）。Harness 原生记录优先，没有的配置项以实际发送选择补充，两者皆无则不显示、不猜测；原生未单列的用量注明未记录，不推算。来源：[S20](../sources/composer.md#s20)、[S21](../sources/composer.md#s21)。

速度是模型的服务档位，表达为模型目录中的独立条目，不是另一个按轮选项。managed 模型可为相同模型 ID 声明携带额外请求参数（如 `service_tier=priority`）的独立记录，参数随每次上游请求发送；原生目录报告的档位由 adapter 展平为模型变体。选择随模型保存、排队和记录，“当前速度”就是当前模型，不需要特殊继承规则。此决定以 [S77](../sources/ai-routing.md#s77) 为准，取代 S73 的独立速度选项；服务参数契约见 [AI 服务](../design/ai-service.md)。

## status line 与用量显示

status line 紧凑放在操作行右侧、提交按钮之前。默认只显示上下文用量：窗口已知时为占比，未知时只显示记录的 token 数。悬停说明，点按查看全部可用项。累计 token、工作目录及 git 分支、账户额度、Harness 费用估算默认不常驻，用户在设置“通用”选择。即使没有固定项，只要有额度待显示也保留“状态”入口。来源：[S22](../sources/composer.md#s22)。

会话用量来自 Harness 原生记录，无记录不显示、不推算。managed 模型的上下文窗口使用 Velune 配置，因为 Harness 对未知模型只给出猜测；费用是 Harness 按其价格表的估算，经网关或订阅时不代表实际计费。

“通用 → 用量显示”分别保存额度和上下文的“占用／剩余”偏好，旧统一偏好只作为两项初始值。额度偏好作用于提供商窗口、账户额度和详情；上下文偏好作用于会话状态栏、圆环和详情。上限判定与警示颜色仍按已用量，剩余显示下的额度上限表现为至少保留比例。设置“通用”是首页，原“会话”和“快捷键”并入其中。来源：[S39](../sources/composer.md#s39) 及 2026-10-26 细化。

## 账户额度来源

详情逐项显示提供商报告的窗口（如 5 小时、7 天）与余额。重置时间使用查看设备本地日期、时和分；没有时间戳则显示未知，不从相对文案推算。

| 当前选择 | 额度来源与展示 |
| --- | --- |
| Velune managed 模型 | 所选提供商，与提供商编辑器一致 |
| 路由 | 按提供商分组，同一账户去重，显示适用于任一成员模型的窗口 |
| 原生 Codex | 运行时记录的账户限额 |
| Claude Code 原生模型、沿用当前或运行时默认 | 所选运行时自身 CLI 登录额度，无须先导入或选择 Velune 提供商 |

managed／路由额度不混入历史轮次另一账户的原生限额。Claude Code 与提供商编辑器共用采集规则，但独立提供商不能替代原生登录来源；分组为“运行时名称 · 登录额度”。CLI 可能采用其他 API 认证，不能据登录额度推断本轮一定订阅计费。该采集阶段支持本机继承 HOME 的 Claude Code，其他 HOME 或 SSH 明示不支持，不回退到本机默认登录；加载中或读取失败仍保留入口并说明原因。以上来源为 2026-10-27／28 细化。

额度随当前目标选择更新，保留提供商的加载中、未知或失败状态；切换模型／提供商后不继续使用旧输入快照解析出的账户。来源：[S78](../sources/dogfood.md#s78)。
