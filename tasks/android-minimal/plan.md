# Rust 远控库的线性实现计划

2026-10-18 用户明确本轮仅限 Rust Library。完整产品目标保留在 [技术方案](../../docs/design/remote-access.md)；本计划只安排库实现、UniFFI 契约和库级验证。Mac／Android 页面、扫码、系统权限交互及 App 安装退出当前范围。库内切片和本轮交付检查已完成，真实网络能力仍按外部条件保持未验证。已有结果见 [verification](verification.md)，完整产品判据继续保留在 [acceptance](acceptance.md)，不会因范围收回而变成已通过。

## 顺序与责任

继续使用独立 `feat/android-minimal` worktree；原 main 不改，允许本地提交，不发布远端。共享 Rust／API 由 remote_application 唯一负责，主执行者集成和维护知识。平台 App 不再参与本任务的实现或出口。生成 Kotlin／Swift 与编译平台目标库可检查 ABI，不能等价为 App 可用。

| 顺序 | 库产出 | 出口与状态 |
| --- | --- | --- |
| S1 传输判别 | 网络事实输入、路径观察、mDNS 依赖及接口生命周期 | 当前同网源码和三轮判别已完成；E2／E3 未验证，不推导公网或非默认双网能力 |
| S2 稳定服务 | 业务 owner、调用世代、账本、完成任务及 runtime 独立于 Endpoint | 已有真实 Handler 的丢回执、网络替换、原 ID 查询及 owner 重启证据，库出口完成 |
| S3 v2 契约 | 方向授权、配对事务、Rust 普通状态／pending、具名操作作用域与 UniFFI | 静态检查、目标库构建、真实 ABI 与库级合成驱动通过；不等待批准界面 |
| S4 统一连接与设置 | locator、生产 mDNS、Rust Controller 恢复、设施代际及状态投影 | 完成库拥有的机制和隔离证据；真实 E2／E3 未取得时单独列为能力未验证，不能宣称自动选优已被整机证明 |
| S6 库交付 | 匹配的源码、生成契约、目标库、影响清单与验收状态 | 库内硬不变量与可做判别通过；外部条件、未适配 App 和网络能力缺口明确列出 |

原 S5 完整 Mac／Android 用户流程属于平台接入，已移出本任务，不创建对应页面或借用其作为库验证夹具。原方案的产品矩阵仍供未来平台集成使用；库交付不等于整项产品验收完成。

## S3：保存库检查点

S3 将邀请、ALPN 与 wire envelope 硬切为 v2，普通状态当时为 schema 2；S4 因 locator／设置形状改为 schema 3，独立身份始终为 schema 1。pin 与入站 grant 分离；本地批准只接受 Ready 的准确 peer／attempt，不能由远端自批或旧事务复活授权。原子失败不得发布成功状态。

穷尽分类 Command 的观察与 Effect，副作用发送前保存准确 ID 和安全摘要；每个 RemoteOperation 只执行一次 Effect，结果由调用方处理后准确确认。未知、过期或 owner 重启只查询，不自动重发。保存普通状态不含消息、秘密或完整结果。

已有证据覆盖未批准／反方向拒绝、挑战并发、存储失败、批准／断线竞争、提交后丢回执、撤销、写前门禁、并发 scope、真正进程冷启及 schema 截断。Rust 库出口已具备；平台调用方与人工 Android 脚本未适配 v2，应明确记录，不恢复旧接口来掩盖。

## S4：统一寻址、设施和自动恢复

先判别公网设施不可达是否错误阻断 LAN：配置 relay／lookup，故意使设施不可达，通过正式库入口完成 LAN 发现、认证和一次真实 Handler 往返。区分配置已保存、网络代际已应用和设施可达；不能因 online 等待失败销毁仍能提供 LAN 的 Endpoint。

联系人只固定公钥，locator 保留来源并刷新。初连／重连装配 LAN 与所配公网查找，活动连接沿原生地址变化／QNT 选路；生产 mDNS 复用已有窄补丁和显式接口事实，不能把诊断用的空 registry 限制带进产品。

每个目的设备由同一 Rust Controller 管理选择、前后台、主动暂停和配置代际，平台只报告事实。保持一个有界退避循环，网络变化唤醒；旧异步结果不安装到新意图。无效身份、撤销或协议不兼容进入 Blocked；前台不撤销主动断开。

实现公共默认与兼容自定义 relay／lookup、按规范目的地装配的每网络代际私有认证、设施保存／应用／可达状态。严格移除、换 token 或启用未装配 transport 使用唯一串行关闭屏障后重建网络。移除后不得偷偷回落公共预设；离线端缺新 locator 时明确要求带外更新同一公钥的联系资料，不重新授信。

库内判别使用合成身份、真实 iroh、真实 Handler 和可控本地设施，覆盖陈旧地址、恢复意图、旧结果竞争、主动断开、设施交接、原请求连续性及资源退出。不能用 map 修改返回或缓存候选代替业务往返。

E2 WAN→LAN→WAN 可在有独立公网出口时验证，未必依赖蜂窝。E3 蜂窝默认而 Wi-Fi LAN 同时存在需相应真实环境。当前缺这些条件，完成独立库工作并保留未验证结论，不伪造整机路径通过，也不据此继续修改 App。

## S6：库验证与交付

按仓库要求执行 fmt、locked workspace check、全 feature 严格 clippy、remote-only 依赖与目标编译。采用已冻结且源码摘要匹配的成功证据；只有受影响的改动、失败或新疑点才补验。不新增或运行自动化测试；临时人工驱动用于非平凡状态与信任边界，不接入 CI，不调用真实模型或读取真实资料。

交付记录源码与生成绑定／目标库摘要、已经观察的硬不变量、尚未验证的网络能力、删除 API 与新接口对应、未适配平台调用方。无需生成或安装 Mac／Android App。保留 hard-cutoff，不引入 v1 兼容层。最终核对文档链接、diff 与改动归属，关闭本轮合成资源，再本地提交。

## 收敛条件

库拥有的实现、静态检查和可行判别完成后形成有明确边界的库交付。跨公网选优、非默认网络、长时后台与完整产品流程只有取得相应环境证据才标为通过；它们不被悄悄删除，也不扩大本任务的源码责任。需要重造传输栈或降低已确认体验目标时，停止相关分支并提出有证据的架构修订。
