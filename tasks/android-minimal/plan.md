# 统一远控的线性实现计划

2026-10-18，技术方案、人工验收方案和本计划收敛后，用户明确恢复实施。S1 平台传输切片进行中，S2—S6 尚未开始。产品意图归 [PRD](../../docs/prd/index.md#后续扩展分布式能力)，技术契约归 [remote-access](../../docs/design/remote-access.md)，判据归 [acceptance](acceptance.md)，已有结果归 [verification](verification.md)。计划收敛表示执行路径、责任和失败分支明确，不表示真实网络已经验证。

实施继续使用当前独立 worktree 的 `feat/android-minimal`，不在原 main 目录工作，不 push、创建 PR 或部署公网服务。开始前核对分支、源码与现有产物；保留尚未提交的 Android 邀请 UI／合成宿主改动，由所属 owner 在相关切片吸收或按新契约替换，不混入无关修改。若 main 已前进，先评估与本任务的实际交集，再在独立分支完成必要集成；不按旧 bundle 清单覆盖更新的安装。

## 顺序与责任

只有当前切片达到出口，才推进下一切片的实现。每个切片同时完成相关调用方、静态检查、必要人工判别与文档，不把修复和验证留给无人负责的尾项。共享契约只由一个集成 owner 修改；平台 owner 顺序消费已确定契约，不跨阶段并行改同一份 API。

| 顺序 | 完整产出 | 集成责任 | 出口 |
| --- | --- | --- | --- |
| S1 平台传输判别 | 有证据的网络事件／QNT／Android 路由接线及 mDNS 依赖选择 | android_native；android_verification 提供证据采集 | 三个高风险边界已通过，或其局部修补已编译并复验；不存在未定位的架构阻塞 |
| S2 稳定服务 | 业务 owner、调用世代、账本、完成任务和 runtime 独立于网络代际 | remote_application，配合 Mac 生命周期 owner | 网络资源完整替换后，原合成写入仍只执行一次且可查询 |
| S3 v2 契约同切 | 方向授权、配对事务、Rust 存储／pending 门禁、具名 UniFFI 及两端必要调用方 | remote_application 统筹；android_app／android_mac_host 消费 | 新协议与存储的硬不变量通过，两端生成绑定与构建匹配，无 v1 分支 |
| S4 统一连接与设置 | locator、设施代际、Rust Controller 恢复及平台事件的产品装配 | remote_application 统筹，android_native 接网络边界 | 首版路径策略、自动恢复、严格设施移除和请求连续性通过 |
| S5 两端完整交互 | Mac 二维码／批准／设备管理；Android 离线扫码与统一设备、恢复、业务页面 | android_app／android_mac_host 各自贯通本平台，主执行者集成 | 最终产品入口完成同网真实界面闭环，无调试入口替代正常流程 |
| S6 端到端验收与交付 | 同批产物、正式矩阵、文档与安装状态 | android_verification 贯通，主执行者采纳与收尾 | 所有必需项通过，环境缺失显式阻塞，不把未执行算通过 |

S1 前必须具备现有同 Wi-Fi 设备之外的受控条件：可用蜂窝／独立公网出口、可让手机保留 Wi-Fi LAN 同时以蜂窝为默认网络的拓扑。S4／S6 还需要两套可控 relay／lookup 与认证样例；可用隔离本地设施，不以此计划授权公网部署。只掌握当前同 Wi-Fi 设备不等于这些条件已具备。缺失时留在当前切片，完成可独立取得的证据并报告最小缺失条件，不能静默删掉要求。

## S1：先判别可能改变接入方式的边界

先补最薄的观察通路，保持现有 selector 和传输装配：Android 的默认网络、可用 Wi-Fi、链路属性及能力变化进入 Rust；路径事件经 UniFFI 带进程内连接编号、连接内 path ID 和安全统计，必要的受控地址只进入私有诊断。现有 `PathObserver` 可复用，事件落后重读快照。改动范围为 `packages/remote/src/paths.rs`、bindings 的 remote／Android 装配、Android 网络回调和临时合成驱动，不先做完整扫码或新配对。

按以下顺序隔离变量，每项都使用合成身份和低流量已知载荷，不调用模型：

1. 手机从异网连入保持在目标 LAN 的宿主，记录真实起始路径；加入和离开 LAN 时保留原客户端，观察地址变化、QNT、新路径和实际流量。此探针禁止自动重连以区分原连接迁移与关闭；关闭后的恢复另行记录，最终产品仍需自动重连。
2. 使蜂窝成为默认网络而 Wi-Fi LAN 保留，分别观察普通 UDP 与显式 Network 绑定。普通可达则不新增 socket 适配；仅绑定可达才贯通 UDP 创建／每次 rebind 与 Network 生命周期。两者都失败先核验 AP 隔离、权限和路由。不得以进程级绑网或新建第二条业务连接规避。
3. 独立验证 mDNS 初连、既有 peer 地址更新及过期，核对两平台本地网络／多播权限及资源释放；确认修复的兼容上游版本，或固定最小缓存更新补丁。mDNS 不承担活动连接的直接候选注入，订阅事件不替代实际探测。

计时与故障点采用验收方案的固定预算及 180 秒诊断窗口，不能等待原生 60 秒周期后宣称 10 秒 LAN 升级通过。出口需要一份实际装配选择、可编译依赖清单、对应路径证据和已定位的失败分支。若必须修补 iroh／netwatch，只接受覆盖明确边界、固定版本且有来源记录的局部修补；需要重造传输栈或放弃统一体验时停止依赖实施，重开架构决定，不无限等待上游。

## S2：拆开服务与网络寿命

在 `packages/remote` 内提取稳定服务状态和私有网络代际；在 `packages/bindings/src/remote.rs` 移动现有 runtime 的归属，保留同一业务 Handler。先内部重构，暂不改变当前公开协议签名，不新增用于旧协议兼容的适配层。调用世代、Ledger、已接纳任务不能再被新 bind 初始化；任务完成不持旧 Endpoint。

入站启停与整份网络替换分开；停止本机接入不能误停出站控制。旧代际封闭与请求接纳串行，旧代完整关闭后才创建下一代，同身份只保留一份主动发布位置。保留 Ledger 的有界结果和接纳水位；不新增持久请求数据库，不宣称跨宿主崩溃 exactly-once。

人工判别使用真实 Handler 的延迟写入：丢回执、停入站、重建 Endpoint、释放旧网络引用，再用原 ID 查询同一次完成。另做真正 owner 重启，旧 ID 必须不执行；两个场景不能共用同一种“断开”替代。通过后形成 Rust／两端可编译检查点，再进入协议同切。

## S3：一次切换协议、存储和调用方

先建立 Rust 的 pin、入站 grant、配对事务、联系人和未决请求存储。配对按已固定的 exporter context、挑战预算、Ready、原子提交与结果查询实现；批准只来自执行端本地可信 API。邀请、ALPN、wire envelope 和普通状态 schema 一次切到 v2；独立设备身份不重建。旧 schema 原子重置并留下可确认通知，旧双向 trust 不推导新 grant，旧 pending 不迁移或重发。

在中立 Command 上建立穷尽的交付副作用分类，与修订冲突分类分开。所有副作用发送前由 Rust 保存完整请求 ID 和安全元数据，失败则不发送；未知结果恢复只查询。Controller 的恢复状态和业务代理归稳定服务，窗口、Kotlin 和 Swift 不各建一套重连器。此切片验证恢复资料和显式查询，自动恢复调度在 S4 接完。保留现有修订与视图隔离语义。

契约修改顺序固定为 Rust 状态／协议与 API → 生成 Swift／Kotlin → 同步 Mac／Android 直接调用方 → 两端构建。新配对的最简状态和本地批准页面随本切片接上，完整相机入口留给 S5；不保留可自动授信的旧产品入口。删除 Android `DeviceStore` 的设备／pending 权威存储，只留 UI 偏好。不手改 generated；已验证的 JNI 初始化、Android Cleaner 和 UniFFI 命名约束保持。

出口按验收方案覆盖未批准拒绝、方向不对称、挑战并发、存储失败、批准／断线竞争、提交后丢回执、撤销后旧事务、写前零发送和 cold-start 原 ID 查询。两端 Handler 的合成场景证明无隐式反向授权，不能仅依靠 Android 没有 Handler。此切片内不签中间的混合版本交付。

## S4：统一寻址、设施和自动恢复

将 S1 已验证的网络接线装入稳定服务。联系人只固定公钥与联系信息，locator 带来源并可刷新；初连／重连同时使用局域网与配置的公网查找，活动连接沿原生地址变化／QNT 选路。Controller 按选中、前后台、主动暂停和配置代际维护唯一连接意图；旧异步结果不能安装到新意图。网络回调只报告事实，不等同恢复完成。

实现默认公共设施与兼容自定义 relay／lookup 设置、按规范目的地装配的私有认证、保存／应用／可达三种结果。严格移除、换 token 或启用原先未装配的 transport 使用串行网络代际切换；移除后不回退未配置的公共预设。先传播新 lookup 线索再撤旧入口；未获新线索的离线端允许按原公钥带外更新 locator，不重新授信。

出口需要同网离线寻址、陈旧联系人、WAN→LAN→WAN、UDP 故障回落、控制进程恢复、主动断开不被前台覆盖，以及自定义／认证设施交接的真实往返。网络前提可达时必须满足固定预算；不能用 map 修改返回、缓存中的候选或同一 Direct 标签替代流量证据。出现直连策略导致不可接受控制延迟时，先定位并作有证据的局部修复，不静默把用户目标改成“库就是这样”。

## S5：完成正常用户流程

Mac 接入设置提供单码、限期候选、八位数字核对和本地批准／撤销；保留唯一应用 owner。Android 使用已固定并编译验证的 CameraX／ZXing 离线解码，扫码、系统选择二维码图片、显式粘贴进入同一解析器。重复帧只产生一个事务；邀请只在内存持有，相机随页面释放，权限失败有明确可用的辅助入口。两端不要求选择 LAN／公网模式。

设备目录、连接状态、未决请求和配置重置通知均消费 Rust 快照。消息、会话、已有运行时／模型选择、停止、审批和问题回答构成本次最小 UI；完整业务能力继续由 SDK 覆盖，不为本次扩展成全部配置编辑器或通用终端。主动断开、忘记联系人、撤销入站授权分别表达，不能用一个“删除”动作声称完成三者。

通过最终包的同网真实界面闭环、相机生命周期、键盘及可访问性观察后，冻结本轮候选产物。扫码容量合规不替代实际手机识别；原邀请粘贴页面和临时探针不作为完成正常流程的证据。

## S6：用匹配产物完成验收

对照 [验收矩阵](acceptance.md) 逐项记录通过、失败、阻塞、未执行及证据。完整业务 SDK 以 Command／具名导出清单逐项对应合成 fixture；有真实平台语义的项目经 Mac／Android 界面验收。至少覆盖实际异网、进入／离开 LAN、UDP 回落、非默认双网、自定义设施、控制进程重启与撤销；未具备的外部条件不能被同网结果替代。

代码静态验证按 [开发说明](../../docs/development.md) 执行 fmt、locked workspace check／严格 clippy、remote-only 与 Android target 检查；`scripts/build-android.sh` 生成匹配 so／Kotlin 并运行 assemble／lint。Mac 中间阶段使用 `scripts/build-macos.sh --build-only`，最终安装前核对已安装版本，避免覆盖无关更新；按用户既有授权重建安装到标准位置，先在隔离配置下验收。无自动化测试、CI 测试入口或真实模型调用；人工脚本只服务当前可识别行为边界。

记录提交、生成绑定和二进制摘要，安装后以新鲜 UI 证据验证，不能套用旧包或诊断包结果。修复留在原 owner，按影响范围重验，不机械重复全部历史场景。完成后关闭合成宿主，撤去本轮网络规则并只清理本轮合成资料；更新 unit README、开发说明、技术方案和已有 verification，核对链接与 diff。允许本任务本地提交，不自动发布远端。

## 收敛与停止条件

本轮设计已固定状态归属、授权方向、配对提交点、写前记录、选路策略、验收预算和唯一实施顺序。仅保留实施可判别的局部选择：Android socket 钩子、QNT 通知修补、mDNS 版本／窄补丁、相机兼容性；每项都有触发证据、责任层和退出条件。它们不要求先由用户选择库内部 API。

实施完成要求六个切片出口及正式验收必需项全部满足；没有新反例就停止追加机制。环境缺失仍是未完成，架构前提被证据推翻则暂停相关依赖并给出具体替代方案。研究文档、loopback 机制实验或子任务“完成”都不替代该门槛。
