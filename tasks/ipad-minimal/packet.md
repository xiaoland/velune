本轮授权范围：

- 问题面板：应用内集中查看问题，显示设备、会话或操作上下文，保留诊断详情，支持复制与清除。主界面用问题数量入口和明确失败提示，不将长错误插入会话列表或持续占据输入区。
- 原生多窗口：每窗独立设备、会话、导航、阅读位置、草稿、模型选择及面板状态；列表可在新窗口打开会话。共享单一 endpoint、配对身份与网络监视，不复制远控服务。每窗使用独立稳定 viewID，同窗列表与正文用同一核心视图。
- 工作连续性：已加载且在活动窗口显示的会话显式标已读，后台轮询不消除未读；保留手动标记入口，其他窗口同步核心状态。接入核心搜索；切会话保留编辑与阅读状态，已存在会话的本地草稿按窗口和会话保存。原生子 Agent 只读限制由核心决定。
- 大纲：消费核心 transcriptOutline，以用户消息定位，点击后跳到实际消息，关闭面板后继续阅读。
- 关联 Agent：同一面板分组显示父会话、原生子 Agent 与 A2A 协作会话，呈现运行、结束、失败及待回复；从面板、工具链接和消息来源打开，保留返回原会话入口；可在新窗口打开。继续复用核心的协作执行，不建立另一套调度器或任务树。
- 键盘工作：Return 换行，⌘Return 发送并保留焦点；点击发送收起屏幕键盘。新建会话／窗口、查找并切换会话、聚焦输入、大纲、关联 Agent、问题面板、返回与 Escape 关闭都有可发现的键盘入口。普通文本编辑和输入法行为交给原生控件。

布局采用左侧会话列表、中间会话与输入区、按需打开的右侧大纲／关联 Agent 检查器；窄窗口使用系统自适应面板。问题独立集中呈现。MVP 的验收是“并行工作、找回上下文、恢复编辑、处理失败”的主要旅程；MLP 的要求落实在每次切换的流畅性、焦点与阅读保持、键盘发现性、横竖屏及双窗视觉上，不以继续添加功能数量定义。Mac 式任意停靠、浮动吸附、窗口内多分屏不列入本轮范围。

技术核实：核心 ClientState 已按 view 隔离草稿和呈现，但远控草稿不落盘；释放 view、远端重启或视图淘汰会丢失，因此不能把它当成重启恢复承诺。本地草稿若持久化应为该窗口草稿的唯一写入权威。Controller 活动要按同设备各窗口取并集，不能由任一后台窗口暂停其他前台窗口。关闭窗口释放该 view，不关闭共享 endpoint；后台与普通 onDisappear 不等于窗口关闭。已读水位由核心按该 view 最近列表的活动时间确认；客户端只在活动窗口加载并显示正文后调用，不直接改蓝点。列表活动时间与转录时间没有等价契约，不能在客户端比较它们或用转录 cursor 缓存自动已读。
