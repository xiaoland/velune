# Composer 状态归属：产品方案

状态：2026-11-03 方案已确认并授权落地，源码实施完成。正文／附件／执行选择、恢复关联、全局新建及原生身份交接的现行契约归 [Composer 输入身份与同步](../../docs/design/composer-state.md)；下文保留方案形成时的推导与候选解释，不将历史提问当作当前待办；实施事实、部署边界与证据归 [任务入口](packet.md)。

## 本轮：先确定操作的含义

新的观察修订旧版本中“多面板共用 composer 时切换标签也只改目标”的规则。分屏数量不是导航与聚焦的边界：同一 group 中选另一会话 Tab，是主动换处理上下文；聚焦另一 group 已经显示的会话，是在并置内容之间换操作目标。

推荐用以下三句话统一，而不是继续为不同布局增加例外：

1. **导航到另一个会话，存好当前输入，恢复目标上下文上次留下的输入。** 同 group 换会话 Tab 是已明确的例子；明确执行“新建会话”进入全局唯一的新建输入。建议列表打开、Tab 内前进／后退、在当前 Tab 打开另一个会话遵守导航语义。这会修订旧版“分屏里把 B 换成 C 仍保留输入”的决定，不能假称用户已经确认这项扩展。
2. **只把焦点移到另一 group 已经显示的会话，继续手头输入，发送目标跟随焦点。** 不调出目的会话的另一份输入，不重置正文／附件／明确选择。
3. **整理布局，延续手头输入。** 拆分、合并、重排、移动 group／工具窗口及收起输入区本身不选另一份输入。bottom drawer、左右停靠、浮动和独立工具窗口采用相同的导航规则；位置不再决定归属。

上述共享规则用于一个 composer 服务多个会话的情况。每个面板都有自身 composer 时，移动焦点不会让一个面板的输入覆盖另一面板；本来同时显示的两份输入继续各自存在。固定目标的发送 sheet／侧聊继续使用其自身上下文，不因主窗口的焦点改变目标。

## 本轮：输入身份与恢复 key

不能用一个 key 同时表示输入身份、导航位置和当前发送对象。用户已认可三层模型；其中“输入状态”指正文、附件、暂选运行时及各运行时上的模型／推理强度／权限选择，不把光标、撤销或窗口布局扩大成跨设备同步范围。

| 信息 | 建议身份／索引 | 负责什么 |
| --- | --- | --- |
| 一份正在写的输入 | 跨设备稳定的 `InputID` | 正文、附件、明确选择和编辑修订一起同步；改变目标或布局不改 ID |
| 导航回来恢复哪份输入 | 全局 `ContextKey → InputID`；窗口另存本地的当前导航上下文与输入指针 | 会话恢复关联也同步；新建入口始终解析全局新建项；WorkspaceID 只标识本地窗口的导航位置和历史 |
| 当前发送目标 | 窗口单独持有的 `target` | 聚焦只改 target；导航可以同时改上下文与目标；另一设备的焦点不替本窗口换目标 |

全局 `ContextKey` 是两类之一：`conversation(ConversationRef)` 或唯一的 `newConversation`。`ConversationRef` 指同一个逻辑会话，不能随查看设备变化；原生 ID 需要用执行宿主身份消歧时，那是资源来源，不是按客户端设备另存一份输入。侧聊使用租约身份，不与来源会话混为一项，也不因此延长侧聊租约。

`ContextKey → InputID` 关联在同一用户的同步范围内共享，固定目标 sheet 与各会话内置输入复用它。不再额外保留一套窗口私有的同会话恢复覆盖：在设备一离开 B 时把 B 关联到 X，设备二后来导航到 B，也应该找到 X。窗口中的“现在正编辑 X、暂时发往 B”仍由本地输入指针与 target 表达，不能仅因 B 的关联更新就换掉正在处理的另一个上下文。

内容记录与关联分开：修改同一个 InputID 时同步完整正文、附件、明确选择；导航可以改共享恢复关联；仅聚焦不发布正文替换、不改关联。会话关联从 Y 改指 X 时，直接跟随该会话上下文的编辑器接续 X；Y 的真实未完成工作仍保留原 ID，可从既有入口恢复。临时聚焦 B、实际仍在编辑 A 输入的窗口不受这次 B 关联变化影响。原生编辑器对象仍可分别持有，不要求多个 NSTextView 共用同一个 `ComposerModel.textView`。

**不把 `groupID`、Tab 的排列／索引、分屏数量、工具位置、focus、运行时或模型放进输入 key。** group 与 Tab 是承载和触发导航的入口；Tab 内可以换会话，同一会话也可有多个入口。延续已有“同一会话常规输入共享”的承诺，不因为多开一个 Tab 就默默分叉输入；若以后需要同一会话的独立输入，那是显式创建另一份工作。

WorkspaceID 只区分窗口的导航位置、历史、当前输入指针与布局，不能隔离输入内容或为同一会话另建恢复 key。相同 InputID 在另一台设备上仍代表同一份输入。共享输入可以临时发往另一会话；焦点改变不重写那个会话的正文，也不改其恢复关联。只有随后确实离开该上下文的导航，才按已收敛的恢复规则更新关联。

现有 `ComposerModel.id` 与窗口 `conversations`、`shared`、`retained` 提供本地原型的基础；跨 view 共享内容和关联仍须由核心承担。`.shared` 应表达“这个窗口当前使用哪份输入”，不再是一份由分屏条件永久选中的内容桶。

## 本轮：全局唯一的新建输入

用户已明确新建会话有独立状态，全局只有一份。这里的全局包含同一用户参与同步的设备与窗口；不按查看设备、执行宿主、项目、group、Tab、运行时或模型拆成多个新建项。这不要求全应用只允许一个“新建会话”Tab；多个入口查看的是同一个全局新建输入。

推荐用一个稳定的 `ContextKey.newConversation` 指向当前新建 InputID。A 留有 X，新建页留有 N 时，明确执行“新建会话”总是恢复 N，不拿 A 的 X 当作新建页正文，也不因为再次按 ⌘N 就清空 N。无记录时才初始化空输入和既有的新会话配置默认值；已有 N 时恢复其附件及明确选择。cwd／project 属于创建目标上下文，不扩充本轮输入状态范围，也不产生多个新建槽位。

该交点已随“同意这个判断，可以落地”确认：只聚焦另一 group **已经显示**的新建页时，是否仍保留当前 X？推荐延续聚焦规则，只换创建目标；真正执行新建命令才取 N。另一可选解释是新建页具有更高优先级，聚焦它就切 N。已按前一种行为实施。

无论上述聚焦交点如何决定，窗口都不能把借用的 X 写成另一个私有 `newConversation` 记录，也不能在离开新建页时用 X 覆盖全局 N；借用的 X 仍由原上下文持有。唯一新建入口没有窗口私有的恢复覆盖；它总是指向全局项。若用户明确将另一份输入恢复到新建入口，才是全局项的显式变更，原 N 仍按既有未完成工作保留机制处理。

首发的推荐交接规则：

1. 从全局 N 发起首发时捕获 InputID、修订和创建目标。原生会话身份确认后，这份工作继续归新会话；正在编辑它的视图接续该身份，不把编辑内容复制成另一份。
2. 在同一次状态变更中，让全局 `newConversation` 指向下一份空正文／无附件的输入；新建配置沿用刚才的新建选择，独立于后续对已创建会话的改选。下一次执行新建命令使用这份新的空输入。
3. 未创建成功时 N 保留；已创建会话但首条发送失败时，未发送内容保留在已创建会话，继续发送不能另建第二个原生会话。创建结果未知时查询原操作，不自动重复创建。
4. 首发后又编辑的内容由原 InputID 和修订保护，不能被迟到清空吞掉。另一设备收到“已消费／新建项已交接”后，旧缓存不能把 N 复活。
5. 若按聚焦规则临时拿其他输入 X 发往创建目标，提交消费实际的 X；全局 N 没有被消费，就不能清空或替换它。

单用户假设用于简化同步：不做多人协作、CRDT 或多份冲突合并界面；按已确认修订传递完整输入，正常依序接续。保留防止旧设备缓存回写和重复创建的最小版本／操作身份，这两件事也会发生在一个人先后使用两台设备时。

## 本轮：跨设备的可用内容

正文与明确选择同步同一份结构化记录，不再分别作为客户端私有草稿／选择。运行时选择引用真实的运行时实例及其执行来源，查看设备变化不改选；新目标暂不可用时显示原因，保留选择，不按运行时名称猜一个本机替代项。

附件同步须包含可读取的文件内容或持久内容引用，不能只把 Mac 的本地 URL 发给手机。复用现有附件上传／读取通道，把持久附件身份与某个 client view 的短期上传引用区分；发送时由实际执行端解析为可用输入。图片与普通文件仍使用各运行时已有的发送机制，不为同步另建一种正文表达或查看路径。附件未同步完成时就地表达状态，正文继续可编辑。

窗口恢复、光标、文本选择、编辑区滚动和撤销仍按本地需要保存；跨设备接续这份输入不要求同步布局或把另一台设备切到同一个 Tab。跨设备输入同步也不改变会话实际执行 owner。

## 本轮：往返恢复的推荐解释

一个决定仍在向用户核对：A 写 X → 聚焦 B，仍 X → B 切 C，写 Y → 再切回 B。

推荐恢复 **X**，因为它是离开 B 时实际使用的输入。B 如原先还有另一份输入，仍可恢复，不能覆盖丢失。这个推荐不等于用户已确认。

据此推荐的转换是：

- 聚焦已显示的 B：只改目标，当前仍是同一个 InputID；不向全局会话草稿存储发布一次伪编辑。
- 从当前 B 导航到 C：把当前 InputID 记为 B 的共享恢复引用，再载入 C 的恢复引用；C 没有记录时初始化输入。全局新建项按上一节处理，不能被借用输入覆盖。
- 再回 B：通过引用恢复 X。A、B 可以引用同一个 InputID，内容只存在一份；发送 X 后，两处都不能重新冒出未发送的 X。
- 当前输入原有的会话来源不决定发送目标，也不能决定删除范围。引用可以改变，内容身份不变。

这保留“上次离开这个上下文时的工作”，而非记住一个原始会话来源。代价是恢复关系可以多对一；它是稳定输入的引用图，不是每次换目标复制正文，也不需要用户先使用“另存草稿”。若旧引用被替换，另一份确有未完成内容且不再可达时，沿用已有就地恢复机制保留它；空输入不制造保留项。

## 本轮：关键操作推演

以下为推荐方案的设计推演，尚未作为运行结果验收。

| 操作 | 输入 | 目标／恢复关系 |
| --- | --- | --- |
| 当前 group：A1 写 X，切 A2 写 Y，再回 A1 | 恢复 X | A2 保留 Y；是否分屏不影响结果 |
| A1 当前输入 X，聚焦另一 group 已显示的 B1 | 仍 X，同一 ID | 目标改 B1；B1 已有的其他输入不丢 |
| 承上，B1 切 B2 写 Z，再切回 B1 | 恢复 X（待确认推荐） | 离开 B1 时关联 X，B2 保留 Z |
| A1 留 X 后切 A2；另一 group 又从 B1 切 B2；最后当前 group 从 A2 回 A1 | 恢复 X | 不因 B1／B2 的选择不同生成另一份 A1 输入 |
| 直接点击未聚焦 group 中尚未选中的 B2 | 按一次导航恢复 B2 输入 | 出发上下文是操作前实际在用的上下文，不把未曾聚焦的 B1 伪记成出发处 |
| 再点已经选中的当前 Tab | 保留当前输入 | 不是导航，不做重新恢复 |
| 打开已在另一 group 显示的会话 | 保留当前输入 | 实际只发生聚焦；若必须选那个 group 的另一 Tab，才是导航 |
| 隐藏 drawer，从命令面板改模型，再展开 | 同一输入与明确选择 | 不依赖视图挂载；target 状态仍实时更新 |
| 当前目标受外部控制，或恢复引用指向空输入 | 继续编辑；空输入保持空 | 禁止提交；不能为找非空内容跳到另一份输入 |
| 当前输入从 X 导航到 Y 后，X 的发送失败回包到达 | Y 不受影响 | 按捕获的 InputID 与修订恢复 X；已有新编辑时不覆盖 |
| 重启共享 composer 窗口 | 恢复退出前的输入与导航位置，再核对同步记录 | 本地快照不覆写别的设备已更新的内容／关联；不从焦点或分屏数量重新推导输入 |

不能使用各 group 当前选中 Tab 的组合做 key。例如 `A1+B1` 写 X，切 `A2+B1` 后再切 `A2+B2`，最后回 `A1+B2`；用户是在回 A1，应该找到 X，组合 key 却会进入未见过的新组合。输入规模应随实际未完成工作与导航上下文增长，不随各 group 的排列组合增长。

## 本轮：布局、关闭和非会话内容

布局变化沿用已确认的连续性：有未完成输入时延续同一个 ID；目的处原有另一份输入保留；空输入可以使用目的处已有输入。发出或清空后的空状态也保存，不能再根据“是否有内容”自动选择旧输入。

从共享输入切回各面板内置输入时，当前 target 面板接住同一个 InputID；其他面板恢复各自另一份真实输入，没有则显示空输入。此前因共享操作形成的引用不能让多个不同会话面板自动各摆出一份当前工作；在该布局转换中转移相应关联，未完成内容仍只有原来的 ID。不通过复制或清空全局正文强制修整界面，其他设备得到同一份有效关联。

建议区分操作意图，而不是最终几个 group：关闭当前**会话 Tab**是离开上下文，保存其输入并恢复接替会话的输入；关闭后台 Tab 不改变当前输入。明确**关闭／合并 group**是整理布局，当前输入继续随共享 composer 留在眼前。关闭最后一个 Tab 导致 group 消失，也按最初的关闭 Tab 意图处理，不能让 group 数量偷偷改变规则。关闭整个窗口先保存当前输入与引用，再交给既有窗口恢复范围。

查看 Artifact 不创建一份会话输入，不将原文或来源会话当作发送目标。打开／查看／关闭 Artifact 延续当前输入；焦点在不能发送的 Artifact 上时禁用提交。回到其原会话是结束查看；主动选另一会话才按导航处理。需要从操作入口区分这两种意图，不能以任意 `selectedID` 改变推断用户换了会话。

Tab 在同一窗口换 group／重排保留会话恢复引用，不以目的 group 创建新 key。跨窗口沿用已有承诺：Tab 自身的会话输入和阅读状态可携带；源窗口共享 composer 的当前指针不因发送目标 Tab 被移走而变化。内容记录本来就可以共享，不必再把内容搬到一个窗口私有副本中。目的窗口有另一份未完成输入时继续保留两份；后续技术设计必须明确传递的是哪个 InputID，不能从 `tab.composer` 猜共享输入。

## 本轮：状态字段归属

| 状态 | 归属 |
| --- | --- |
| 正文、附件、用户明确选的运行时／模型／推理强度／权限、每运行时的明确选择记忆 | InputID；导航时一起恢复，聚焦时一起保留 |
| 光标、选择、正文内部滚动、撤销 | 本地编辑器按 InputID 保留；布局整理携带原编辑状态，不向其他窗口同步光标／撤销，不新增跨重启撤销承诺 |
| 未明确选择的“沿用当前”值、提交资格、控制权、审批、运行状态、用量、队列、cwd | target 会话；焦点改变立即重解，不纳入输入 key |
| 工具位置、drawer 高度、窗口和 group 尺寸 | 窗口布局；状态／内容／target 改变不重算 |
| 菜单展开、补全候选、当前焦点等临时界面状态 | 呈现；不能驱动输入身份或写入持久草稿 |
| 已受理提交 | 捕获的目标、配置、InputID 与修订；独立于后续焦点和导航 |

明确选择在新目标不可用时保留并解释原因，不自动换成另一模型。所有引用同一输入的上下文观察同一次清空；其他真实输入继续存在，发送后不自动选出其中一份。

运行时不是输入身份的一部分，但同一输入内的选择记忆仍以 RuntimeID 索引，即 `(InputID, RuntimeID)` 对应一组明确模型／推理／权限选择；当前暂选运行时也属于输入。这与“target 会话在某运行时上的最近值”是不同信息，解析时才组合。

## 本轮：实现边界与后续验证

产品源码尚未修改。行为收敛后，由窗口导航入口把操作表达成聚焦、导航、布局整理、查看 Artifact、恢复等明确转换；核心输入 owner 管理共享内容与关联，`ComposerDrafts` 适配本地编辑器及当前导航指针；`ComposerContext` 仅组合所选输入和实时 target。不能让 `Pane.select`、SwiftUI 挂载、`tools.didSet` 和会话加载回调各自再猜一次归属。一次操作同时产生 focus 与 selection 改变时作为一个完整转换落盘，恢复时不重放导航。

持久化需要保存输入内容、共享 ContextKey 关联、本地导航上下文／当前指针；窗口快照只是本地恢复与缓存，不是另一份内容权威。现有 `persistConversation` 只取第一个匹配会话、`associations` 每输入只记一个会话，不能原样承担多引用含义。仅聚焦不写正文或共享关联；导航可改共享关联；真正编辑／消费某个 InputID 才同步该内容。不能继续使用“当前指向哪个会话”作为正文同步目的地。

核实的实现缺口：`ClientState` 会交换 `drafts` 和 `choices`，跨 view 的这些状态实际隔离；Mac 的完整编辑状态及附件主要由 `ComposerDrafts`／窗口 journal 持有；`createConversation` 每次生成一个 `draft:` UUID；附件上传引用与 `ClientViewId` 绑定，映射只在 service 内存里，既有 `ReadAttachment` 又面向已发送消息。这些机制还不能兑现本轮同步／唯一新建要求，不能把改 Swift 字典 key 作为完整实现。后续技术方案需要把共享输入／关联移到跨 view 的核心 owner，建立持久输入附件引用，并在既有设备通道上同步同一目录；会话执行 owner 不变，不为单用户引入多人协作服务。具体权威记录的存放与跨执行宿主接线仍属后续技术方案，不宣称现有远控已自动提供这些能力。

旧数据的当前 shared 输入必须作为眼前工作保留；既有会话输入和 retained 输入不能丢弃或复制成多个独立内容。若调整持久格式，按仓库规则提供显式一次性手动转换，不在启动路径自动迁移；用合成旧快照先验证，不读取真实会话。本设计阶段不做真实数据转换。

分层验证只覆盖本次受影响路径：先以表中往返反例判断规则是否成立；实现时用状态转换／引用与序列化检查验证不串写、不重复消费；用实际窗口动作和合成数据核对 Tab／group 的不同含义及隐藏 composer 命令；仅补一次退出重开验证当前指针恢复。没有新增布局时不重复全套视觉、运行时或其他平台验收，不用 computer-use，不占用户前台与鼠标。当前表格是方案推演，不是已通过的应用证据。

本次新增的关键验收条件：两个独立客户端从同一会话读到同一输入及关联；一端修改正文、附件及明确选择，另一端可完整接续且不会被旧缓存覆盖；设备／窗口多次执行新建均回到同一 N；首次创建成功后进入新会话、下一次新建为空，创建失败与“创建成功但首发失败”保留内容的位置正确；附件在另一端实际可读取并可交给执行端，不能只断言元数据相同。先在共享核心／协议组合取得这些依据，再补必要的端侧路径，不因本次纯设计文档重跑 UI。

## 2026-11-02 已实施版本（历史）

下文为原获批方案的设计推演。它记录旧决定及其理由；其中共享区“切标签／替换会话只改目标”等行为正在被本轮 dogfood 修订，不能继续作为新实现的依据。

## “自然”的依据

Composer 中的输入是一件尚未完成的工作。用户希望操作后的连续性符合自己对这件工作的理解：换了对话，就能找到那个对话未完成的输入；仍在同一个共用工作空间里，就继续手头的输入；整理布局，也继续手头的输入。

用户已明确的三个例子：

1. 单栏中切换会话，即使输入区在 bottom drawer，也应具有按会话切换的直观感受。
2. 多会话分屏共用底部输入区时，点击另一侧已有会话，保留草稿，发送目标跟随焦点。
3. 在这个共用工作空间内把 B 换成 C，也保留共享草稿；拆出／关闭分屏或移动输入区时，当前文字、附件和明确选择继续留在眼前。

据此形成三个判断：**导航可以更换对话上下文，焦点可以更换操作目标，布局整理延续正在写的输入。** “停靠在底部”与“分屏数量”分别提供线索，但都不能单独决定当前草稿的生命周期。

## 默认的使用关系

| 使用情境 | 导航或聚焦的含义 | 默认输入行为 |
| --- | --- | --- |
| 一个会话面板，输入区内置或停靠在左／右／底部 | 在这个面板中切换对话上下文 | 切到目标会话自己的草稿和选择 |
| 一个面板有多个标签，但一次只显示一个 | 仍在替换当前对话上下文 | 与单栏相同；多个标签不构成共享工作空间 |
| 多面板分屏，输入区内置于每个面板 | 每个面板分别处理自己的对话 | 每个输入区仍跟随自己的会话 |
| 多面板分屏，只有一个停靠输入区 | 多个会话共用一个操作区 | 保留当前输入；聚焦面板、切换其标签或替换其会话只更换目标 |
| 浮动或独立工具窗口中的输入区 | 作为独立的操作区使用 | 延续既有共享语义，即使主窗口只有一个面板也保留输入，只更换目标 |
| 从列表打开某会话的发送 sheet | 明确向指定会话操作 | 固定目标，使用该会话草稿；取消仍保留 |

上述“默认”决定进入一个上下文时选择哪份输入，不允许布局回调直接替换当前输入。

单栏中，列表打开、前进／后退、标签切换、打开已有会话使用同一规则；新建会话进入独立的空输入，选择按既有新会话默认规则初始化。共用输入区中，这些操作只更换目标，包括把目标换成新会话；需要另起一份输入时使用“新建草稿”，原输入保存。

## 布局变化时，继续同一份输入

布局操作前捕获实际在用的输入。拆出首个分屏、关闭最后一个分屏、移动输入区、收起与展开 drawer、在停靠／浮动／内置之间移动，都延续这份未完成输入。多份内置输入区合并为一个时，延续操作来源面板的当前输入；其余输入保留。共用输入区放回多个面板时，当前目标面板继续这份输入，其余面板展示各自的输入。

“未完成”包括原始正文、附件、这次尚未发送的明确选择改动，或仍可撤销的编辑；不把加载来的会话选择记忆、运行时默认值算成一次新编辑。如果当前没有未完成输入，转换后可直接使用目的上下文的草稿，不用为了保住空输入而藏起已有内容。单纯隐藏／展开保持当前激活项。

这是一份工作的连续呈现，不是把正文复制到另一个缓冲后留下一个稍后会重新出现的副本。正文、附件、撤销、光标和明确选择一起延续；输入法组合不能被布局变化当成发送。

布局变化后，下一次导航按新的使用关系处理。例如共享输入 X 随关闭分屏留在 A 面板，之后单栏导航到 B，才切到 B 的草稿；再次回到 A 能找回留在 A 的 X。重新拆分时，延续此刻眼前的输入，不突然调出某次历史分屏留下的旧草稿。

## 两份未发送输入相遇时

当前共享输入 X 回到单栏 A，而 A 原有草稿 Y 时，继续展示 X，并保留 Y。两份不拼接、不覆盖，也不要求每次布局调整都先经过对话框。

在既有操作行提供条件出现的“草稿”菜单：只有存在其他可恢复输入时才需要常驻入口。菜单标明当前输入及其他草稿的来源会话／共享工作空间，并以正文首行或附件摘要帮助辨认。用户可切换到 Y；切换保存 X。不增加框外提示带或改变 drawer 高度。这里管理实际存在的未完成输入，不提供无关的历史版本或命名布局。

每份输入保持同一身份：从会话带入共用输入区、再带回某面板，转移其当前关联，不产生多个会重新冒出的副本。来源处如仍有恢复引用，指向同一份输入；它发出后，相应引用也不再声称还有一份未发送正文。目的会话原有的另一份草稿不受影响。会话记住的选择仍按既有规则保留，不因移动正文而抹掉其选择记忆。

例如 A 的 X 经共用输入区转到单栏 B，X 是带到 B 的同一份工作；A 不额外生成另一份独立的 X。B 原有的 Y 留作可恢复项。这个关联变化随布局转换保存，之后单栏往返仍能在 B 找回 X 和 Y。删除某会话清理仅属于它的草稿，已经明确转入其他上下文的当前输入不因其历史来源被删除。

发送／排队受理后仅清空提交的那份输入，保持空编辑器，不自动切出 Y。其他保留草稿仍由用户主动恢复。删除正文、发送完成、运行状态改变或一次后台刷新，也不能偷偷切换草稿。

代价：出现真实草稿冲突时需要一个小型切换入口和保留记录。相比静默覆盖或每次转换弹窗，这个代价用于同时满足“布局时继续当前输入”和“原有输入能够找回”。

## 状态分别跟随什么

| 状态 | 归属与变化 |
| --- | --- |
| 正文、附件、用户明确的下一轮运行时／模型／推理强度／权限选择 | 跟随正在写的输入；切换草稿才切换整组。各运行时上已选的值仍分别记住 |
| 撤销、光标、文本选择、编辑区内部滚动位置 | 跟随这份输入，在当前进程内保留；重启不承诺恢复撤销历史 |
| 未明确选择的值 | 按当前目标会话解析“沿用当前”；实际值随目标变化，明确选择保持 |
| 工作目录、发送队列、审批、运行／停止、上下文用量、控制权与可用能力 | 属于目标会话；目标改变立即更新，不能夹进共享草稿里带走 |
| drawer 高度、工具位置、窗口尺寸 | 属于窗口布局；会话、草稿和执行状态变化不重算 |
| 已受理的发送及失败恢复 | 捕获提交时的目标、输入身份和修订；后续导航与布局不改变它，不覆盖新编辑 |

明确选择在新目标不可用时保留并显示原因，不能自动改成另一个模型或权限。用户随后明确修正：目标受外部控制时保留输入并允许继续编辑，禁止提交；保留以“已锁定”替代提交按钮的呈现，解锁不自动发送。

## 恢复与独立性

保存正文、附件引用、明确选择、当前激活的输入及其他保留草稿的关系。重开同一恢复窗口时，眼前应是关闭前正在写的那份，不能仅根据当时的分屏数量重新挑选。附件失效时标明失效，不吞掉整份草稿或擅自移除引用。

会话草稿继续按既有会话持久化规则恢复；共享输入和因布局转换保留的窗口输入随窗口恢复。新建工作区有自己的共享输入，不能拿另一窗口的共享输入当默认。不同设备的会话与草稿不混用。关闭窗口恢复与未首发会话跨重启的范围沿用既有约定，本轮不另外引入后台恢复服务。

## 分层验收

产品判断先用下列场景确认，不用构建成功替代：

1. 单面板 drawer 中 A 写 X，B 写 Y，往返与新建：分别找到自己的输入；两个标签但无分屏也一样。
2. 共用 drawer 中 A／B 分屏：焦点切换、B 换成 C、切到新会话均保持同一输入，目标提示与目标状态同步。
3. X 仍未发送时反复拆分／关闭分屏、内置／停靠／浮动移动：文字、附件与明确选择持续可见；高度不跳；撤销还属于原输入。
4. A 已有 Y，当前 X 随布局回到 A：眼前仍为 X，Y 可通过就地入口恢复；切换往返不丢失，发送 X 后不自动冒出 Y，也无 X 的重复副本。
5. 共享目标切到受外部控制的会话：同一输入保留且仍可编辑，只锁定提交；回到可提交目标后恢复发送资格，选择能力与“沿用”值按目标解析。
6. 隐藏输入区时通过菜单修改选择，再展开：写入的仍是同一输入，不能因视图缺席落到别的归属。
7. 发出后立即换目标、改输入或换布局，再收到失败：恢复只影响原输入的合适修订；不会把已提交消息发给新目标。
8. 实际退出并重开隔离窗口：当前输入、保留草稿、附件引用、明确选择与目标关系恢复；第二窗口、另一设备不串状态。

后续技术验收分别取得状态转换／持久化的局部依据、真实应用组合路径的依据、合成数据下的原生操作与截图依据。实现前需细化故障与删除的原子边界；这些技术选择不能放宽上述用户可见承诺。
