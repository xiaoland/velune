# Composer 用例边界收敛

## 要纠正的架构问题

这次从状态权威和用例完成责任审查。内容目录与目标选择已有共享存储，下一轮规则已有共享 resolver，但公开入口仍把目录操作、执行事实和完成准备的责任分给客户端。Mac 的 Context、Window、View、Store 和 Client 各推进一段，菜单和补全等消费者也可能发起绑定、初始化与刷新。

这条职责缺口在三个真实用例中表现出来。补全查询经编辑器绑定回到补全，产生递归。执行身份或模型事实迟到时，初始化要等待下一次视图读取。跨 group 移焦点时，正文身份保持而执行目标变化，因此一个输入模型绑定一个 Store 不能表达产品关系。

跨端核对还发现持久语义分叉。Mac 首次保存完整 nextTurn.choice，Windows 及移动端按各自路径选择运行时和空 choices，目录保留先写入的目标。先使用哪个平台会影响共享记录。完整准备责任需要进入共享用例边界，平台自己的生命周期也需要明确所有者。

## 已确定的产品规则

用户确认，模型、推理和权限等未手选项继续沿用会话／运行时默认，手选后才固定。共享存储保存明确意图，解析后的有效值供展示及执行。选择某一字段只更新该字段的明确意图。已开始的轮次仍使用提交时捕获的有效执行配置。

InputID 与目标保持独立。同组切 Tab 找回内容与配置，跨组移焦点保留内容并更换目标，布局整理延续当前输入。新建仍是全局唯一内容关联和目标，创建工作目录归各 Tab。这些导航语义继续归平台。

## 责任和接口

| 层 | 完整责任 |
| --- | --- |
| application／application-api | 目标身份、首次初始化、继承与明确选择、已有记录优先级、有效下一轮解析及 CAS 规则 |
| bindings facade | 在现有 execution 与 composer authority 路由边界组合完整准备操作，返回实际保存记录及有效投影 |
| 平台会话模型 | 请求和观察寿命、重试触发、身份核对、迟到结果拒收、接合本地待同步明确选择与已缓存目录 |
| 窗口及内容目录 | Tab／group 导航，InputID 与目标的本地配对，编辑对象的呈现寿命 |
| 视图、菜单、补全 | 消费目标投影并表达操作，维护本地光标、输入法和原生编辑交互 |

共享 facade 以 ComposerTargetRequest 表达读取来源，conversationId 为空表示唯一新建目标。prepare_composer_target 返回 execution owner、规范 ContextKey、authority 实际 ComposerTarget／revision、核心解析依据与有效 NextTurn。客户端本地 overlay 只参与解析，提交明确选择仍走原有 CAS。

原生目录有平台缓存和加载寿命。准备不强制启动 Harness 读取目录。目录到达后，调用共享纯 resolver 重新解析 prepared 事实。改变选择的共享 helper 从 raw intent 更新被选字段，避免将有效默认值写回为全部明确选择。

保存端和执行端可以是不同设备。保存成功、后续解析失败时保留已写记录，返回失败，再次操作读取实际保存结果继续。复用既有身份、修订及幂等 ensure。就绪是当前事实的投影，不增加持久 ready、跨服务总修订号或另一份选择缓存。

## 迁移与退出旧路径

四端普通首次打开不再自行挑选 seed，改用同一 facade。Mac 目标准备从 View、菜单、Context 构造及 Window 的补监听迁到会话模型的正常刷新寿命。内容模型解析、编辑器绑定和补全刷新分离，查询不推进编辑行为。

旧 choiceEdited=false 记录中被固化的 runtime、owner、choices 通过显式迁移归为空意图。目标 revision 与目录 revision 按修改推进，完整私有备份先于写入。choiceEdited=true 全部保留，历史上哪些默认值曾被顺带固定无法可靠反推。客户端对未手选值使用共享规范化语义比较，避免旧缓存与空意图形成永久待同步。

## 验收依据

先验证共享公开用例，随后复用现有平台入口。证据应证明相同目标不因先使用的平台而改变初始化结果，手选一项后其他项仍继承，执行端与保存端分离时采用保存端实际记录，部分失败后能重读恢复，未同步明确选择遵守 CAS。

Mac 沿正常输入和命令消费检查：输入命令、菜单、切 Tab、移焦点、收起／展开输入区，内容与目标遵守产品规则且界面持续响应。迟到目标事实不可播种旧目标。类型／绑定变化按实际受影响平台编译。采用既有设施与临时公开接口验证，避免继续扩张应用内专项检查入口。

实现已完成。共享公开 facade 的 7 组验证覆盖普通历史会话、双执行端与独立保存端、逐字段继承、只读 overlay、foreign owner 拒绝、部分失败恢复、CAS 及保存端重开。既有 resolver 12 项和严格 Clippy 通过，显式迁移的合成验证通过。四端原生库、生成绑定与应用构建通过。

Mac 复用既有 controls 6 组及 content-target 8 组，验证原生输入、同组 Tab／跨组焦点、布局连续性、撤销、跨窗口移动、迟到失败和实际双 client 冲突恢复。旧 CAS 段用不存在的普通会话模拟新建，严格规范身份暴露了夹具错误；现改用真实全局新建身份及实际修订基线，未绕过共享准备或增加专项入口。

这些原生检查使用未显示的窗口和合成数据，没有前台激活或全局输入。未执行已安装应用中完整的可视菜单／补全旅程，也未验证真实跨网络中断；职责链的源码核对与公开用例证据不代替这两项。部署及旧两组七 Tab 的实际恢复按用户稍后统一重启的决定等待。
