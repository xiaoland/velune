# Mac 多分屏渲染性能

2026-10-16 用户反馈：多会话分屏时应用性能明显下降、动画掉帧，要求优化消息列表渲染或整体性能。属于已授权的 Mac 持续迭代，没有新的产品决定。

## 方法

开发版在临时 `VELUNE_HOME` 中后台启动：回环合成上游，12 个合成会话，每个会话 12 轮较长的 Markdown（列表、表格、代码块）。临时启动参数按 2×2 拆分窗口（1240×780），可选每面板再开两个后台标签。由进程内计时器驱动根分隔条往返拖动 240 步，每步布局并绘制一帧，统计步间耗时；同时用 `sample` 采样主线程。这些参数与计数器只在测量期间存在，已删除，不进入提交。数字只用于本机前后比较，真实拖动与动画是否流畅由用户验收。

## 发现

- 拖动分隔条时每一步都把比例写进窗口模型，窗口内所有观察者（各面板、标签栏、输入区）都重新求值。
- 每次宽度变化，每个转录都会按新宽度把可见带重新排版一遍；四个面板每帧各排一次。
- 隐藏的后台标签页仍然参与布局。宽度变化时它们也重排；而且隐藏是 if/else 分支，每次切换标签都会重建转录视图，6 次切换重建了 10 个。
- 输入区用 `@State` 记录可用宽度，每一步都重新求值整个输入区。

## 改动

- 拖动分屏分隔条时，比例只是该分屏视图的局部状态，松开才写入布局。
- 转录宽度连续变化时，最多每 0.1 秒重排一次；宽度停下 0.15 秒后补一次重排，并在后台测量其余行。
- 面板只为显示中的标签页建立视图。转录控制器与原生列表视图由标签页持有（`TranscriptReading`），切回时放回原处，跟随、回到底部与大纲锚点也随标签页保存。视图移除后控制器丢弃 SwiftUI 输入，以免闭包与标签页成环。
- 输入区只在单行／两行的选择改变时更新视图状态。
- 输入区只在标签页首次显示时取得焦点；切换标签时，焦点转移等新输入区进入窗口后再进行。

## 结果

分隔条拖动，每步耗时中位数 / p90：

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 四面板，每面板一个标签页 | 37 ms / — | 1.3–1.4 ms / 7–8 ms |
| 四面板，每面板三个标签页 | 15.7 ms（已含节流与局部拖动） | 1.9–2.0 ms / 9–10 ms |

窗口边缘调整大小（`setFrame` 驱动；其中包含系统每次保存窗口位置的开销）：一个标签页 8.1 ms，三个标签页 12.7 ms。

正确性核对：

- 切换标签 6 次，只建立了 1 个从未显示过的转录。切回后滚动位置不变（120 → 120），回到底部按钮仍在。
- 标签移到右侧拆分后，仍是原来那个视图，并显示在窗口中。
- 关闭 4 个标签页，转录控制器 12 → 8，均已释放。
- 隐藏方式的中间方案（不透明度为 0 并冻结尺寸）可以避免重建，但仍要参与 SwiftUI 布局，三标签时约 15 ms，因此没有采用。

## 会话列表滚动（2026-10-17）

用户反馈会话列表性能差，确认具体为滚动卡顿。

方法：开发版在临时 `VELUNE_HOME` 与 `HOME` 中后台启动，Claude Code 运行时指向合成 JSONL（12 个项目各 30 个会话，按项目分组，列表窗口 page 50／total 200，共 219 行）。临时进程内探针按 24pt 一步把侧栏列表上下往返滚动三遍（1362 步），每步滚动并绘制，统计步间耗时；用环境变量开关逐项去掉行修饰符与工具栏项做对照，并用 `sample` 采样主线程。探针与开关只在测量期间存在，已删除，不进入提交。

发现：

- 行内修饰符（`.help`、行与列表的上下文菜单、`itemProvider`、辅助功能、分组标题）全部去掉后仍为中位约 49ms，不是原因。
- 原因是 46bea6c 把会话窗口工具栏改成可自定义（`toolbar(id:)`）后，用于把右侧按钮推到末端的 `ToolbarItem(id: "trailing-space") { Spacer() }`。SwiftUI 把它变成系统 `NSToolbarFlexibleSpaceItem`，此后每次窗口布局（列表滚动、新行出现都会触发根视图布局）都在 `AppKitToolbarStrategy.updateLocations` 中把它删除再插入，每次还经 `_autoSaveConfiguration` 写一次 `NSUserDefaults`，并重建项目视图、重新解析各项图标。弹性空白后面没有项目、或改为非自定义工具栏时不发生。
- macOS 15 上未找到可自定义且右侧按钮靠末端、又不触发该问题的写法：把空白项改用系统标识、`.navigation`／`.primaryAction` 位置、`Spacer().frame(maxWidth:)`、`Color.clear`／`NSViewRepresentable` 空白、与非自定义项混排都无效或不能撑开；`.primaryAction` 靠左，`.secondaryAction`／`.status` 居中。

决定（用户 2026-10-17）：macOS 15 使用不可自定义的会话窗口工具栏；macOS 26 起保持可自定义，改用 `ToolbarSpacer(.flexible)`。分析、问题、资源库窗口没有弹性空白项，保持可自定义。

结果（每步耗时）：

| | 中位 | p90 | p99 | 最大 |
| --- | --- | --- | --- | --- |
| 改动前 | 58.7 ms | 185 ms | 485 ms | 798 ms |
| 改动后（macOS 15） | 1.9 ms | 2.6 ms | 4.7 ms | 11.4 ms |

改动后工具栏布局与原来一致：后退／前进在左，重新读取、大纲、拆分在右端，侧栏筛选与新建会话不变（项目坐标与截图已核对）。本机为 macOS 15，`ToolbarSpacer` 路径只经 macOS 26.2 SDK 编译，未在 macOS 26 上运行验证；那里是否同样不再反复重插，需在 macOS 26 上复核。
- 已安装 f47a5f7：签名严格校验通过，构建清单的 source_commit 指向该提交且 dirty 为 false，后台启动后没有新的崩溃报告。真实滚动是否流畅，由用户验收。
