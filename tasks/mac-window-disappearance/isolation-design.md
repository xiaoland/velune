# 开发与日常实例隔离方案（已采纳）

## 当前判断

这次事件暴露了三项独立的共享默认值：两种构建都叫Velune进程、拥有 `local.velune.prototype` 应用身份、未设环境变量时均打开 `~/.velune`。外部shell因此可以按名字选错目标，裸启动也能竞争日常核心锁。系统偏好与窗口恢复属于应用身份；只拆核心目录不够。已有按bundle路径正常退出工具可复用，无需建立进程守护器。

用户已明确同意方案落地。本文件保留方案依据；最终实现与验收归packet，日常开发操作的权威说明归 docs/development/environment.md。

## 建议契约

构建用途（development／daily）与编译优化（dev／release）正交。全部常规开发构建，包括release优化调试，产出开发用途；只有显式日常打包／重装入口产出日常用途。用途、稳定worktree标识、bundle ID及可执行文件名写入签名bundle元数据，应用与开发工具消费同一身份，不根据cwd或运行时环境猜测。

| 面 | 日常用途 | 开发用途 |
| --- | --- | --- |
| 系统应用身份 | 保留 `local.velune.prototype` | `local.velune.development.<worktree标识>` |
| 进程／显示名 | Velune | VeluneDev／Velune 开发版 |
| 核心状态 | 保留现有日常目录 | 独立的开发scope目录 |
| defaults／窗口恢复／通知 | 保持现有身份 | 随独立bundle ID隔离 |
| 日常链接协议 | 继续注册velune／agents | 不争用日常协议；链接测试定向投递到开发bundle |
| 原生Agent配置 | 现有用户配置 | 合成配置、独立managed HOME与原生目录 |

worktree标识取规范化工作树根路径的固定长度摘要，写入构建身份：同worktree重编译不变，另一个worktree不同。commit、branch及每次启动随机数不作为默认身份。工作树移动会成为新开发身份，旧开发数据保留，可显式转移，不自动碰日常目录。

### 应用入口拥有目录安全保证

默认开发状态位于 `~/.velune-dev/<scope>`（采用短路径适应Unix socket长度）；不依赖shell预先设置VELUNE_HOME。Finder双击、LaunchServices与裸执行得到同样的开发选择。

目录覆盖必须属于开发scope。开发启动器在新建私有fixture目录时写入用途／scope标记；应用核对其归属。开发版不能把任意已有、无开发归属的非空目录收编为开发目录，不为解除冲突删除lock或重置配置。明确指向日常目录及经symlink解析后指向日常目录均拒绝。需要临时HOME的既有验收入口改由同一准备函数创建／声明私有目录。

隔离准入必须早于Transport、遥测、DeviceHub、偏好及检查入口初始化。用途元数据缺失、矛盾或目录归属不符时，本次启动明确失败，不默认解释为日常、不进入15秒重试；开发检查参数也不能作为绕过准入的入口。日常入口同样不接受开发目录。

只换HOME不是账号隔离。原生CLI使用各自的agentDir／CODEX_HOME／CLAUDE_CONFIG_DIR等；Claude还可能访问同一登录用户Keychain。开发不复制日常配置或导入日常登录，合成验证沿用现有边界；真实账户联调仍须任务级明确授权。本次不引入容器或新的凭据框架。

### 工具拥有精确进程操作

SVC提供当前worktree的开发启动／状态／停止入口；复用现有AppKit正常退出能力。

- start通过LaunchServices打开准确开发bundle，默认后台，不裸启动普通GUI；已有符合身份的实例返回状态，不因“另一个实例”而终止其它Velune。
- status给出用途、scope、PID、出生时间、bundle／executable规范化路径、数据目录与构建来源。
- stop按明确的scope和bundle路径找候选，发送Quit前复核bundle身份、executable真实路径、PID及出生身份。取消、超时、歧义或身份变化均结束操作；不退回killall、pkill、SIGKILL或删除lock。
- 同worktree多Agent默认复用已声明的开发实例；需要独立UI验收时使用独立scope／fixture，不能借停止其它实例取得控制权。后端合成检验继续独立临时HOME，不引入通用调度器。
- 编译输出与运行中的bundle分开：开发启动器准备受管运行副本，构建不会原地修改已加载App的资源／dylib。副本只有对应进程结束后才更新或回收；不复制编译缓存。默认每个开发scope保留一个运行副本，避免无界积累。

通用Agent指引明确：普通GUI开发验证使用这些入口；既有程序化检查以私有合成目录和本次启动的准确子进程句柄运行；日常退出／重装仍需用户明确授权。任意同UID的外部shell仍能对日常PID发SIGKILL，应用不能拦截该信号；若要抵御任意命令，必须另设OS用户／更强执行隔离，不把这一昂贵边界伪装成改名能保证的事。

## 集成与过渡

1. 先引入单一构建身份元数据、应用启动准入和目录归属，再让构建／开发工具消费它；不在多个脚本散写一组profile判断。
2. 普通dev与优化开发入口统一为开发用途。新增显式日常打包用途，现有reinstall入口消费它。复用相同Rust／Swift编译缓存，不因用途复制或重编整套依赖。
3. 安装器改为读取bundle的真实可执行文件信息，去掉以 `/Contents/MacOS/Velune` 扫描所有候选的假设。验证源产物确为日常用途后才请求现有日常应用退出。
4. 日常迁移和启动共同消费同一明确状态目录选择，拒绝继承开发环境中的VELUNE_HOME；不能迁移目录A后通过不继承环境的LaunchServices启动到目录B。
5. 重建开发bundle并移除旧开发输出里的旧同名可执行入口，显式清理旧开发路径的LaunchServices注册。先确认该旧路径无在途实例；不退出或重装当前日常应用，不移动／删除／复制其配置与会话。旧版已污染的共享defaults不自动猜测恢复。
6. 已有dev-telemetry启动入口消费新身份和相同目录准备，不再拥有另一套Mac裸执行启动逻辑。遥测只是可选附件，不承担开发实例身份。

## 分层验收

- 目录／身份纯规则：普通与优化开发身份一致；同worktree稳定、A/B不同；缺失身份、日常目录、symlink别名、已有无归属数据均拒绝，拒绝发生在核心或日志写入前。
- 进程控制窄验：合成A/B实例，停止A只停止A；陈旧PID／出生时间变化拒绝。取消／超时无强杀回退。无需每次重跑其它产品路径。
- 一次Mac实际关键路径：当前日常实例全程保留；启动A/B开发实例并观测各自进程、锁、defaults／窗口元数据；无环境启动仍为开发；停止A后B和日常PID／出生时间／锁保持。全程合成数据，无鼠标键盘注入，不发送真实模型请求。
- 日常打包只验产物身份和安装准入，不实际重装日常应用。此次不扩展为四端全套构建／UI验收。

## 影响边界

涉及Mac构建／打包、启动上下文、开发进程工具、遥测启动接入和对应开发说明。没有必要改变会话领域、composer同步模型或核心持锁方式。日常身份与数据格式保持，因此不需要为现有日常数据新增自动迁移。隔离标记只声明新开发状态的归属，不是配置schema自动迁移。
