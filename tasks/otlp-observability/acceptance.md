# OTLP 验收设计

状态：2026-10-27。用户已授权实现与验收，并要求清理后重新启动验收。四端实现已装配；下列判据保持不变，已通过项与缺口归[验收记录](verification.md)。接收端、构建或自动化工具就绪均不能代替产品行为证据。

## 验收目标

主要消费者是 agent。成功标准是 agent 能从新鲜、有限、可关联的证据回答“哪个阶段失败、业务是否仍在执行、修复是否改善”，并能识别没有数据的原因。Grafana 页面出现曲线、SDK 返回成功或容器健康都不能单独证明这些目标。

每次验证直接使用已安装的 Velune，必要时覆盖更新构建，并使用合成设备关系、合成数据和独立测试配置；不要求额外安装产品副本或编写独立配对程序。每次运行记录构建版本、平台、run ID、参与实例、配置修订、生效状态、采样率、接收端及查询时间范围。接收端已有数据不能冒充本次运行结果。agent 查询权限与客户端上报配置分开；输出报告不包含认证值。

## 行为与判定

| 编号 | 条件与动作 | 观察与通过规则 |
| --- | --- | --- |
| A01 默认关闭 | 全新私有目录；分别从普通入口、Debug 构建和带冲突 `OTEL_*` 的环境启动，执行本地与远控操作 | 没有遥测配置、队列或出口；进程归属的 DNS／网络观测及可控接收器均无遥测请求。先用显式测试流量证明观测器能看见请求，避免把抓包失效误判为通过。本地问题详情仍可读取。 |
| A02 开发临时开启 | 开发入口连接就绪的 sfp7 接收端，启动未设置偏好的隔离客户端；退出后普通重启；另以明确关闭状态重试 | 第一次能查询新 run ID，状态显示临时来源；普通重启恢复原状态；明确关闭始终优先。接收端不可达或端口被占用时应用仍启动，明确显示未接入，不改投其他地址、不停止无关服务。 |
| A03 客户端归属 | 在同一客户端切换远端、打开多个窗口；在另一个客户端修改设置 | 设置和出口数量随本客户端生命周期保持稳定，不随窗口或远端增加；另一客户端不受影响。两套 SDK 报告同一 active revision 和实例身份，scope 可区分原生与 Rust。 |
| A04 配置切换与关闭 | 向可控接收器积压批次，然后关闭、换地址、换认证、重新开启；注入一侧 provider 准备失败、持久化失败和修订冲突 | 撤销出口以后，之前未发送的批次不再出网，也不进入新目的地；旧队列不会因重开复活。失败不产生半份配置或两套 SDK 分叉。接收器标记已接纳和在途请求，允许关闭前已经发出的数据稍后抵达，不误判为违规。 |
| A05 导出故障与生命周期 | 接收器持续不响应、拒绝认证、断网、队列满；应用正常退出、移动端切后台及强制结束 | 故障期间业务仍能完成，UI／业务线程不等待 exporter 的网络超时；队列和内存停止无界增长。导出状态、拒绝与丢弃可诊断且不泄密、不递归上报。正常退出仅有界 flush；移动端不额外保活，强制结束允许在途丢失。实际资源预算在隔离实验后固定，不能先凭空声称达到生产性能 SLO。 |
| A06 三信号与采样 | 在每端执行成功和受控失败操作，分别使用 100%、0% 及中间 trace 采样率 | 原生与 Rust 信号均能通过机器接口查询。计数和 histogram 与已知操作账本对应，不因 trace 抽样消失；一项语义只有一个 owner，不能重复统计。0% trace 下仍可诊断错误数和日志；日志引用未存储的 trace 是允许的缺口。 |
| A07 分布式因果 | 并发执行两次不同操作，经原生异步任务、FFI、QUIC、执行线程到受管网关；交换控制端和执行端开关 | 开启的两端呈现正确 parent／link，两个操作不串链。只开一端时业务和该端的局部观测正常，另一端不被 context 强制开启。长存活连接、reader 或前一轮执行不能成为后一轮的错误父节点。 |
| A08 业务结果与连接分离 | 受理后断开控制端；令结果回应丢失并重连查询；另测取消、重试、上游失败、后台工作 | 原 RequestId 可关联受理、执行和结果；回应丢失显示结果未知，不凭超时判业务失败或重复执行。控制端离开不结束执行 span；发送受理不计为轮次成功。每次网关尝试单独可见，native 直连／外部 Harness 的不可见部分明确标示。 |
| A09 一次性复制 | 目的端已有自己的开关，来源有保存配置和不同的临时开发覆盖；执行复制，随后来源修改或离线 | 仅保存的地址、认证和采样策略原子导入；不复制启用状态、修订、身份或开发覆盖；后续来源变化不影响目的端。回环地址或设备专属认证不被暗改，测试失败能指出需调整。导入持久化或并发修订失败保留原配置。 |
| A10 分享授权 | 使用仅控制授权的设备、无信任的手机、已获分享权限的设备及已撤销设备分别读取 | 旧控制授权不等于 `TelemetryProfileRead`。首次批准绑定具体来源、目的和权限，之后可一键复制；撤销后新受理的读取被拒绝。读取响应不进入普通 snapshot、业务结果账本、持久重试缓存或日志；撤销不声称收回已复制凭据。 |
| A11 隐私与无界字段 | 在正文、代码、路径、URL、设备名、token、stderr、错误链中放入不同的合成 canary；触发失败及配置分享 | 在接收器解码后的三信号、客户端遥测状态、诊断日志和配置摘要中搜索 canary，秘密与正文均不出现；本地授权查看的问题详情保留应有完整原因。指标标签仅使用批准维度，不包含请求／会话 ID 等无界字段。不能只检查界面或日志正文。 |
| A12 协议升级与不可信载荷 | 新旧端互连；发送过长、无效或非标准 trace carrier；升级已有合成配对存储 | 协议不兼容有明确结果，保留身份与原控制授权，不清空配对或静默提升权限。无效观测载荷不会绕过业务授权；有效业务请求不因观测信息损坏而串链。标准 propagator 和显式大小限制处理输入。 |
| A13 agent 判断缺口 | 暂停接收端、降低采样、关闭一端、使用过期状态快照、限定查询条数和保留窗口 | agent 能区分关闭、未生效、拒绝、积压、抽样和查询缺口；不把“未找到”报告成“没有错误”。报告列出时间范围、参与实例、采样／截断及外部不可见边界。 |
| A14 接收与存储 | 从实际 agent 机器经隧道写入三信号，再重建容器，查询旧数据并发送新数据 | 使用新 run ID 的正确父子链、关联日志、已知 counter／histogram 数值证明接收和查询。重建后旧、新数据都可查询，身份与访问边界不变化。资源、保留策略和长期观察的限制分别记录。此项已有[实验记录](deployment.md#实测结果)。 |

## 平台覆盖

验收对象是上述产品行为，测试框架名称不是证据等级。共享协议／配置边界可以由真实客户端协调器和真实通信自动驱动；原生入口仍需实际操作相应控件，并核对最终持久化、两侧 SDK 状态或导入结果。仅调用模型／服务不证明界面接线，读取控件、获得自动化权限或启动运行器也不构成产品通过。通过 AX API 触发的操作必须证明它确实进入了相应控件的事件和提交路径，不能把显示值变化当作配置保存。不要求为组合穷举重复完整 UI 回放，但仍需覆盖四端实际来源／目的角色和原生入口。

Mac、Windows、iPhone／iPad、Android 均需独立完成 A01–A06、A09–A11、A13。不能用共享 Rust 的单元测试替代原生 SDK、系统证书、前后台和设置持久化的实际观察。iOS 至少覆盖一台 iPhone 和一台 iPad 的布局／生命周期，模拟器结果不能代替真机可达性。

配置分享覆盖每个平台至少一次作为真实来源与一次作为真实目的端，并检查各平台的实际设置入口。已有 Mac→iPhone 与 Windows↔Android 路径，补 iPad→Mac 即可闭合四平台角色；不再为了穷举 16 个组合新增辅助程序。权限拒绝、撤销、原子导入及修订冲突复用公共协议／配置边界的真实通信检查，并在原生入口复验可见结果。未实际观察的组合不声称逐对实测通过；发现平台特有分支或真实组合故障时再针对性补验。手机在前台可提供配置分享，不承诺后台持续服务。

分布式执行按现有产品支持的控制／执行关系覆盖，至少包含 Android→Mac、iOS→Windows，以及 Mac／Windows 的控制与执行角色。两台手机间测试窄配置分享，不制造产品原本不支持的手机本地执行场景。并发与断线验证选择真实 FFI／QUIC 边界，不能把同线程直接调用当作跨端证据。

开发网络单独记录 Mac、Windows、Android ADB、iOS 模拟器与真机的路径。当前 sfp7 的 SSH 隧道只证明开发机可达；不表示真机已经可以访问。Android 使用已验证的反向端口转发，iOS 真机需要明确的受控入口。

## agent 实际诊断演练

准备三个已知根因的合成案例，但不把根因告诉执行诊断的 agent：执行准备失败、控制链路断开而执行仍在继续、一次网关失败后重试成功。只提供诊断编号／run ID、查询入口和本地无秘密状态。agent 应提出有证据的故障阶段与当前业务结果，不把传输结果混成执行结果，并能在修复后用同一操作账本比较错误数和延迟分布。

判定以独立的故障注入账本为准。计数缺失、错误因果、超出可见边界的肯定结论均判失败。查询必须限定时间和数量；不能靠读取合成正文中的答案过关。这个演练验证对 agent 是否有用，不能仅由埋点实现自己的断言替代。
