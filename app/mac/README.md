# Velune Mac app

本 unit 使用 SwiftUI／AppKit 的原生窗口、会话列表、聊天投影和设置界面。品牌只出现在图标与少量内容细节中。

app 通过生成的 UniFFI 接口消费 application 的完整用例，不解析 Pi RPC，不自行启动网关，也不承担跨包失败补偿。应用配置根为 `VELUNE_HOME`，默认 `~/.velune`；提供商 API key 由 application 私有配置保存，OAuth 保留原来源刷新。各 Harness 拥有真实会话持久化。

`svc run build-macos` 执行开发构建，输出至独立的 `target/macos-dev/Velune.app`，不安装日常应用。发布 profile 输出 `target/macos/Velune.app`；安装与重开只由 `svc run reinstall-macos` 执行。SVC Dev 中同样可操作 `macos-app` 的 `build`／`reinstall`。底层复用 [build-macos.sh](../../scripts/build-macos.sh) 和 [reinstall-macos.sh](../../scripts/reinstall-macos.sh)，本机签名身份在 `svc.local.json` 配置。Rust、UniFFI生成、Swift与资源按输入是否变化复用；dev使用Swift debug、限并行度2，release使用优化配置。真实登录、提供商调用和体验由用户验收；静态检查与隔离合成验证归 [开发说明](../../docs/development.md)。

运行时设置展示 family、精确版本类型与配置实例，当前提供 Pi 1.4.0、Codex 0.166、Claude Code 2.1、DeepSeek Harness 0.2.0-rc.2 与通用 ACP。同类型可保存多个实例，工作目录属于具体会话。App 只消费通用消息与类型化权限／回答交互，不解析 ACP 或 app-server envelope；选择、回答和取消通过生成接口交给 adapter。运行时要求外部 Node 22.19+ 的绝对路径；Pi、Codex 与 DSH CLI 均由用户外部安装并配置。添加实例后即可浏览会话，新建表单选择实例／模型，目录可选；Mac首次发送才准备运行时并创建原生会话，继续历史时自动准备。恢复 Codex／DSH 缺少提供商身份的模型选择须明确指定，不宣称恢复上次 Velune 路由。编辑实例时可在“运行环境”中选择 HOME：继承当前用户、指定目录，或由 Velune 管理。Velune 管理时“运行时目录”隐去，由 core 在该 HOME 中推出；已保存实例显示 core 解析出的位置，可在 Finder 中显示（首次使用时创建）。“运行位置”可选本机或 SSH：SSH 填本机 OpenSSH 程序、主机（名或 ~/.ssh/config 别名，须预先完成非交互认证与主机信任）、可选端口，以及类型描述声明 `remoteResources` 时必填的远端辅助目录；远端实例的路径字段是执行机器上的绝对路径，不提供本机选择面板、`~` 展开或可执行文件自动发现，远端 managed HOME 需远端根目录。保存经 `upsert_runtime_with_execution`，保留表单不编辑的其他设置；设置列表在类型后标注“SSH 主机”。Store 按实例读取已保存的运行位置。类型描述声明 `launchOptions` 时（当前为通用 ACP），编辑器另有“启动参数”（逐个传给入口，不经 shell）与“环境变量”，经 `upsert_acp_runtime` 一并保存；声明 `agentInfo` 时，已保存实例可“读取 Agent 信息”：启动一次 Agent，展示名称、版本、会话能力与其报告的登录方式（登录由 Agent 自身完成）。

构建前只需安装 runtime-support，huihua parser 依赖及许可证随 bundle 打包；不分发 Agent runtime 或完整 Pi SDK。具体步骤见 [开发说明](../../docs/development.md#原生运行时与历史读取)。构建产物不等于已安装或用户验收，最终状态以任务记录为准。

会话内容消费 Rust 的类型权威，Mac 只派生展示行与展开、滚动状态。用户内容在右侧气泡，assistant 正文及工具左对齐；客户端扩展通知同样在右侧，运行时状态在左侧，工具输出不按 LLM Markdown 解析。Markdown 由固定 SwiftPM 依赖 swift-markdown 解析，许可证随应用分发；不恢复手写 fence 解析。虚拟列表使用稳定行身份，打开／发送到底，阅读历史时暂停流式跟随。

Mac 最低支持macOS15，由根目录 [Package.swift](../../Package.swift) 定义独立 SwiftPM 产品，依赖固定 swift-markdown 0.9.0；[Package.resolved](../../Package.resolved) 锁传递依赖 swift-cmark。build-macos 先生成 UniFFI 模块，再以SwiftPM的Xcode后端构建本机架构产品，dev为debug并限制jobs为2，release为优化构建。应用与生成绑定目标各自启用warnings-as-errors，并打包`app/mac/Licenses`与解析锁文件。依赖保持各自声明的Swift语言模式；当前依赖没有资源bundle。Swift 包不依赖领域 Rust 包源码，只链接对应profile生成绑定与库。

新标签复用 DeviceStore 当前列表后直接读目标；不因打开标签先扫描所有运行时。显式 openWindow 请求以临时 seed 集合标记首次展示为普通窗口，展示后恢复全屏交互，系统恢复不消费这个临时意图；全屏源窗口的新开窗口沿用正常默认尺寸。列表拖放目标在异步读取 provider 前取消 ListDragWatch 的拖出后备动作，避免重复新窗口。

会话行与分组的 `NSItemProvider` 数据回调直接返回已捕获的不可变 payload。macOS 退出时会在主线程同步兑现未完成的拖放数据，回调必须独立于主线程运行循环完成。`--check-message-experience --experience-drag-provider-only` 用旧模式负对照和主线程限时等待覆盖这条约束，使用合成身份。

会话上下文菜单按运行时能力提供重命名和永久删除确认。重命名可在轮次或子 Agent 运行中通过原生元数据接口执行，不中断当前执行；删除仍须先停止该会话的工作。选中目标、待加载身份与已加载详情分别管理；加载时显示进度，暂停其它选择并隔离旧轮询，失败恢复原会话。操作交给生成绑定和运行时执行，不建立 Mac 标题覆盖存储。

侧栏浏览全部启用运行时的会话；“显示”菜单提供运行时／项目分组与显式筛选，组排序（最近活动／手动，分组时出现），会话排序（创建／更新时间，只排组内的会话）和方向，以及切换“显示已归档的会话”。分组、排序、总数上限与各组页数由 core 计算，侧栏只把返回的行放进 core 给出的组（`conversationGroups`，置顶组在前）。组排序“最近活动”时组按最近一次更新排列；“手动”时按 `groupOrder`（每种分组方式各一份），任何时间都不再移动组，之后新出现的组按键排在末尾，不插到前面把其他组挤下去。转为手动时把当前显示的顺序固定下来，先前排过的顺序保留；转回最近活动时顺序仍保存，再转为手动即恢复。拖动组标题，或右键“上移／下移／移到最前／移到最后”，即转为手动并移动（`groupSort` 与 `groupOrder` 一同保存）：拖动时原组变淡，指针在另一组（标题与其中的行）的上半部分时放到它前面，下半部分时放到它后面，两组之间的插入线标出落点；放回原处不画线，也不算被拒绝。移动后组立即以动画到新位置并短暂高亮，core 按新顺序返回的列表随后接替。搜索时不排序。组可折叠，折叠状态随浏览偏好保存（保存的结果即完整列表，不另外刷新配置；保存在途时侧栏不采用其他来源较早读到的列表，先发出的保存结果也让位于后发出的，否则先前折叠时的列表会盖住刚展开的组）；组内“加载更多”请求下一页，没有“显示全部”。项目组标题为项目名称或主文件夹名（同名时附上级文件夹），悬停显示主文件夹路径，双击或右键“编辑项目…”打开项目表单：名称（留空显示主文件夹名）、文件夹列表（＋添加、−移除、设为主文件夹，右键同样可用；主文件夹不可移除），以及只读列出的、按所属仓库自动归入的 Git worktree。会话行只有一行：会话标题与状态（行首未读圆点或上一轮失败的感叹号，行尾运行中指示），不显示日期、运行时与项目；悬停显示完整标题。未读会话行首有圆点并加粗，当前窗口正在显示的会话自动标为已读。行菜单提供置顶、标为已读／未读、移到项目（只改列表归属）、归档／取消归档（Codex 用原生归档，见 core）、“拷贝”子菜单中的会话 ID、Velune 链接与 xURL（仅有有效原生地址时显示）；应用注册 `velune` scheme，打开链接时在现有窗口打开会话。搜索在输入停顿后由 core 在最近一次列表中匹配标题、项目（含名称）与运行时名称。加载只限制普通行选择，原生菜单及管理提交保持可用，并显示等待或执行状态。分组、运行时／项目筛选、时间排序与折叠状态随应用配置保存，重启恢复；搜索文字、额外加载页与已归档视图仅属于本次运行。

会话列表的单击先选中，等待系统双击判定窗口结束后才打开；双击撤销该次待打开动作，只进入重命名。键盘选择即时打开；多选、拖拽与右键不会派发延迟导航，Option 单击仍在新标签页打开。列表选中独立于当前显示会话，同一会话的普通 snapshot 更新不覆盖正在重命名的另一行；更换焦点窗格或视图消失会取消待打开。

Mac 随包提供官方 xurl CLI（固定源码提交、Apache-2.0 许可证与构建记录），并注册 `agents` scheme。点击系统或正文中的 `agents://` 链接后自动定位并打开会话，不显示地址输入或查找表单。定位在接收链接的窗口所控制的设备上进行。只有多匹配、无匹配或读取失败时显示 `AgentURIView`；多个结果按标题、实例与目录供选择，局部失败进入“问题”并保留可选结果。复合会话继续使用 Velune 深链，原生子 Agent 仍按既有入口只读打开。

设置的“模型路由”页（`ModelRoutes.swift`）左侧列出路由（名称、策略与成员数，＋／−、双击或右键编辑），右侧是所选路由的现状：策略与会话保持的含义，按顺序列出各成员的提供商认证方式、账户尾号与登录状态、适用于该模型 ID 的额度窗口（已用比例、提供商上限、重置时间、观测是否过期），以及登录前或设有上限却缺少最新额度时路由不会使用它的提示；未登录成员行内可直接登录，双击或右键成员编辑其提供商。成员含订阅提供商时显示核心给出的订阅披露。编辑 sheet 设置名称、策略（智能／顺序／轮询／权重）、会话保持和成员：拖动排序、右键或 − 移除；＋ 菜单按提供商分组，其他协议或已加入的模型不可选；权重策略下每个成员有权重与所占比例。新路由默认智能策略并开启会话保持。路由经 `save_model_route`／`delete_model_route` 保存。

额度只读 core 观测（`provider_quota`／`refresh_provider_quota`，`ProviderQuota.swift`）：视图显示期间在请求队列上读取，不占用 `isLoading`；读取中或尚无结果时每 2 秒、否则每 30 秒再读，由 core 决定是否采样；未登录的提供商不读取。添加提供商先在同一 sheet 中选择 core `provider_templates()` 给出的模板（`ProviderTemplates.swift`，按订阅／API 分组，另有“从 Agent 运行时导入”），选中订阅时显示其披露，“继续”后以模板组合打开编辑器。订阅提供商的协议与地址以只读值呈现。OpenAI Platform 默认填入 Responses 与 `https://api.openai.com/v1`，Anthropic API 默认填入 Messages 与 `https://api.anthropic.com`，均可编辑协议／地址，默认不读取账户额度。已保存订阅的名称和连接锁定判定经共享 `providerSubscriptionTemplate` 取得，不由 Mac 按品牌或认证方式推断。Kimi Coding Plan 使用模板固定的 API key 认证，可保存、重开编辑与更换 Key；不提供 OAuth 登录。Codex／Claude Code 等交互式认证的新订阅提供商“保存并登录…”保存后留在编辑器并开始登录（Codex 登录 URL 自动在浏览器打开，Claude Code CLI 自行打开浏览器）。Claude Code 组合以本机 `claude` 可执行文件替代服务地址：自动填入发现的第一个路径，可从“已发现”菜单或“选择…”更换，须为绝对路径。已登录且认证带 `logout` 动作时显示“退出登录…”，确认后调用 `authentication_logout`。Claude Code 组合的“账户来源”选择在 Velune 中登录新账户、本机 Claude Code 登录，或本机 Claude Code 运行时的登录；改变来源后在保存时提交 `useClaudeCodeLogin`（改回新账户为 `clear`）。沿用的登录只显示状态、账户尾号与“检查登录状态”（`authentication_inspect` 后重读配置），没有登录、退出或“清除认证”。“从 Agent 运行时导入”列出 core `providerImportTypes` 中的运行时，含 Codex 与 Claude Code；没有服务地址的候选（Claude Code 登录）不显示地址行。订阅或报告额度的提供商有“额度与使用上限”页，按窗口选择已用比例上限，对所有路由和直接调用共同生效；只报告金额的提供商没有窗口，不显示上限。窗口按核心的节奏在重置前会用尽时以橙色给出预计用尽时间，金额（余额、OpenRouter Key 剩余额度）逐行显示。“历史…”打开额度历史（`QuotaHistory.swift`）：选择窗口或金额与 24 小时／7 天／30 天范围，按 96 个区间显示各区间最后一次观测，没有观测的区间留空；悬停查看观测时间与区间内的最低／最高，可确认后清除。直连 DeepSeek、Moonshot、OpenRouter 官方地址的 API 提供商在认证下方有“读取 … 账户额度”开关；地址不是官方地址时保存为不读取。本机核心时每 3 秒轮询 `quota_alerts`，以系统通知提醒达到上限、用尽或账户不可用。

设置窗口依次为“通用”“会话”“快捷键”“AI提供商”“模型路由”“Agent 运行时”，⌘, 打开时默认在“通用”。“通用”是分组 Form：用量显示、会话列表，macOS 15 另有详情与侧栏工具栏（见下）；“会话”放大纲（弹出面板、就地折叠、单独列出：停靠在窗口右侧）、关联 Agent、状态栏；“快捷键”是 `ShortcutSettingsSections`，按菜单分节。大纲列表打开时停在最末一条，会话运行中点按最末一条即前往会话末尾。用量显示有“额度”和“上下文”两个独立的占用／剩余选项：前者由 core 的 `usage_display`／`set_usage_display` 控制 `QuotaWindowRow` 和账户额度，后者由 `context_usage_display`／`set_context_usage_display` 控制状态栏上下文、圆环与详情；额度上限仍是已用比例，显示剩余时写作“保留 N%”（`UsageFormat`），上下文颜色仍按已用程度变化。每轮记录的“结束时上下文”是 token 计数，不随此切换。

所有可编辑列表采用原生双击主操作：提供商、运行时、模型模板、模型路由打开编辑，提供商内模型聚焦对应详情，会话打开原生标题重命名。单击选择与 ⌘／Shift 多选保持有效；只读目录或导入候选不伪造编辑操作。

“问题”是设备级 `DeviceStore` 的原生窗口，可从主窗口有问题时的状态入口、编辑／导入 sheet 标题行或菜单“问题…”打开（⌘⇧M）。操作失败保留结构化诊断，不在 composer／设置底部或会话列表重复展示；活动读取问题按来源合并，恢复时移除。记录在当前进程内最多保留100项，不作为第二套日志或持久化数据。

消息列表消费 Rust 的 `TranscriptTurn` 引用，保留用户问题与当前最后结果，其余工作消息可展开查看。详情右侧工具栏提供会话大纲，设置“大纲按钮”决定其行为：“弹出面板”在按钮处弹出原生 popover 列出用户消息；“就地折叠”使按钮成为开关，消息列表以行高插值动画缩起为只剩用户消息，点击其中一条或再次点击按钮即恢复完整列表，锚点消息在动画中保持屏幕位置，减少动态效果时直接切换。折叠是临时状态，切换会话或发送后恢复；工作过程等展开状态在折叠期间保留。跟随末尾时视口高度变化（底部面板展开、输入区增高）会重新定位到末尾。⌘F（“编辑 → 查找…”，可在快捷键设置中改）先交给焦点所在的工具窗口的查找（目前只有会话列表：侧栏聚焦其搜索框，块中弹出搜索框，否则聚焦其搜索框），其余位置回落到当前会话的消息查找（`TranscriptFind.swift`：面板顶部的查找栏，搜索真实消息及折叠工作过程的正文，查询时按需取得延迟文本；回车／⇧回车或上下按钮按匹配消息移动，自动展开命中的工作过程与内容块并高亮文字，Esc 关闭并清除高亮）。大纲、关联 Agent 日后可加入各自的查找。回到底部的向下箭头仍在消息列表内，右边距按当前滚动条样式让出滚动条宽度。展开状态按消息／turn 身份保存，权威历史替换时清理失效引用，不能将当前位置保存为固定数组下标。

问题窗口完整展示传入的本地错误原因、阶段与诊断编号；开发工具的真实数据读取限制不构成应用对用户诊断的过滤规则。窗口记录仍是当前进程内的有界问题集合，不是原始日志浏览器。

各会话窗口由窗口模型（`Workspace.swift`）组织。会话窗口不使用系统窗口 Tab（启动时关闭 `NSWindow.allowsAutomaticWindowTabbing`）：系统 Tab Bar 无法放进各个分屏，与分屏标签叠放又角色重复；多个工作区就是多个窗口。每台设备一个 `DeviceStore`（Transport/application、配置、会话列表与浏览偏好、认证、问题、草稿与保存的下一轮选择）；窗口的会话列表与每个会话标签页各一个 `ConversationStore`（列表的搜索与多选；标签页的转录、输入区、大纲与下一轮），设备状态从所属 `DeviceStore` 读取，不复制。编辑区是分屏树，叶子是面板（`Pane`），面板持有一组标签页（`ConversationTab`）与当前显示的一个。窗口内可向右（⌘D）或向下（⇧⌘D）拆分，分隔条拖动调整比例、双击恢复均分；拖动中比例只是该分屏视图的状态，松开才写入窗口布局（每一步都发布会让整个窗口的视图重新求值）。分隔条的拖动区是 `SplitSash.swift` 的 AppKit 视图，盖在所分隔的视图之上（8pt、系统调整尺寸指针，拖动在其中跟踪到松开）：SwiftUI 手势叠在转录的 AppKit 视图上时点按落到 AppKit 视图，只剩分隔线本身可拖。面板的标签栏仿照系统 Tab Bar（`Panes.swift`）：等分标签栏宽度（不放进 ScrollView：那样点按落到它的裁剪视图，到不了标签；标签多时变窄、标题截断）、标题居中、悬停时左端出现关闭按钮（否则显示运行或等待回应；指针在按钮上时其下有圆角底色，按下更深，在按钮外松开不关闭）、末端“＋”新建标签页（整个方格可点，悬停与按下时变深）、增删标签时宽度以动画调整（减少动态效果时直接切换）、按系统 Tab Bar 绘制（各标签不透明）：选中的标签与窗口同底色，其余稍暗并带顶部内阴影，标签之间与底边有分隔线；不加强调色激活条，拆分后未聚焦面板的标签文字按非活跃窗口变灰。标签栏始终显示，是拖动与右键菜单的把手。标签页由 AppKit 视图承载悬停（SwiftUI 的 hover 不经过 AppKit 视图）、关闭按钮的点按、点按（按下即选中）、双击就地重命名会话（未发送的新会话不可）、中键关闭、右键菜单（重命名、关闭、关闭其他；多标签时移到右侧／下方拆分，面板只有这一个标签时向右／向下拆分出新会话；移到新窗口）与拖动。拖动如系统标签：沿标签栏拖动时标签跟随指针在栏内滑动，其余标签以动画让位，松开即排到所在位置；指针离开本面板标签所占的栏（上下或左右超出 协作工具和原生 sub-agent 的调用下方显示“打开会话”链接，另一个 Agent 发来的消息在用户侧气泡顶部以链接标出来源会话（“来自 运行时 会话「标题」”）。“关联 Agent”工具（`LinkedAgents.swift`）把会话的父会话、原生子 Agent 与协作会话（核心快照的 `collaborators`，带方向与运行时）分组列出。这些链接、面板的双击与“打开父会话”按“设置 → 会话 → 关联 Agent”的打开方式打开：当前标签页（未在列表时先重读列表）、新标签页、浮层或新窗口，本窗口已有标签显示的会话改为切换过去；面板右键菜单可选任一方式。浮层是窗口的 sheet，内容为一个普通标签页（`TabContentView` 带自己的输入区），可原样转到标签页或会话窗口；浮层打开时 macOS 不接受退出，与其他 sheet 相同。原生 sub-agent 的会话不在侧栏列出；打开后底部以说明与“打开父会话”按钮代替输入区，因为它由启动它的会话继续。活动轮询发现未列出的运行中会话（例如 Agent 刚新建的）时重读会话列表。正文可在原生 NSTextView 内选择与复制；文本菜单首项“拷贝整条消息”复制该消息正文与通知的原文（不含推理和工具输出）；用户消息与每轮最后的回复下方另有同样内容的复制按钮（由 `TranscriptModel` 按轮次标出，工作过程中的消息与收尾消息的工作部分没有），指针在该行上时淡入（行的跟踪区域，含移动，以免滚到静止指针下的行不出现），位置在布局中预先留出。核心按 turn 报 `TranscriptTurn.canFork`（已完成的 turn 在可分叉运行时上即为真，未完成的 turn 为假），Mac 每轮收尾回复的复制按钮旁据此显示分叉按钮（`arrow.triangle.branch`）。运行中点击不打断当前 turn：请求挂起，底部提示条显示“已安排：当前 turn 结束后自动分叉”，turn 结束后自动执行并在新标签页打开（`openInNewTab(adopting:)`）。可编辑的用户消息行在复制旁有编辑按钮（铅笔），打开与右键菜单相同的编辑表单；编辑不限于空闲——“在新会话中继续”在运行中会等 turn 结束自动发送，“在原会话中继续”会先停止当前 turn（确认对话框明确标注）。仅 Mac 提供这些按钮入口。列表末尾保留固定留白，最后一条消息不贴住输入区。

消息容器是自有的翻转文档视图（NSScrollView 内），按需物化可见行与 overdraw 区域并复用纯 AppKit cell，不在行内承载 SwiftUI。未使用 NSTableView：它对未测行使用估计高度，并在任意 API 调用与布局中懒测量、自行重锚定，使高度在补偿之外落地。行几何是控制器高度列表的前缀和；每行布局由纯函数根据消息内容修订、局部展开状态与实际宽度计算，TextKit 1 测量与显示使用同一属性文本和容器配置，帧取整数，避免 layer 对齐改变已测宽度。可见带（视口上下各 0.75 屏）在显示前同步测量；其余行在后台队列按距阅读位置由近及远测量并分批提交。高度只在一次同步提交中变化，同时恢复视口顶部行及其行内偏移，阅读位置不随离屏行变化移动；`prepareContent(in:)` 为 responsive scrolling 预先物化。宽度连续变化时（拖动分隔条或窗口边缘、侧栏滑动）文字最多每 0.1 秒按新宽度重排一次，其间各行保持原布局，只按当前宽度重新居中（栏宽不变时与重排结果一致，文字随动画平移而不跳动）；宽度停下 0.15 秒后补一次重排并在后台测量其余行。输入区的单行／两行选择只在结果改变时更新视图状态，调整宽度不会每一步重新求值输入区。用户滚动离开底部即暂停跟随，滚回底部、点击回到底部或发送消息恢复。

共享应用状态仅在值变化时发布到工作区；无匹配的轮询问题清理及相同会话快照不触发重复界面应用。正常空闲轮询消费内存快照，点击／滚动不直接读取历史文件。轮询携带上次交付游标，core 未变化时不传快照，变化时只传变化消息及完整顺序；映射在后台请求队列完成，主线程按消息身份合并。超过 2KB 的推理与工具输出只随快照携带大小，展开对应 disclosure 时按消息读取并在原位替换占位；同一交付 stamp 的已读内容在后续合并中保留。

每个 Transport 操作标明效果（`OperationEffect`：只读、写入、改变配置；改变配置后重新读取列表）。各工作区的请求队列共用一个 Transport，退出时库在应用级队列上关闭：退出一开始，各队列中尚未开始的只读操作即被拒绝（`TransportError.quitting`，不记为问题），关闭只等正在进行的一个操作与此前排队的写入（如草稿、标记已读），而不是排在积压的列表、模型等读取之后；库拒绝关闭时恢复读取。

应用级 store 轮询 `conversation_activity`：侧栏对正在运行的会话显示小型进度指示，不区分 turn 由 Velune 还是其他客户端发起（是否在 Velune 之外不重要，重要的是正在运行），出现列表中没有的外部会话时重新读取列表；打开的会话随原生文件变化更新，外部发起的运行与自身运行使用同一底部状态行，输入资格由共享 input_access 决定（Velune 不能停止其他进程的 turn）。会话的右键菜单按活动提供运行操作，不改变列表选中与显示的会话：运行中“停止”（多选时“停止所选会话”），只剩子 Agent 时“停止子 Agent”，活动列为可恢复时“继续”，以及“发送消息…”。“继续”由显示该会话的标签页执行，没有时由一个不显示的标签页打开会话、等下一轮选择就绪后执行，与输入区的继续相同。“发送消息…”在窗口上的 sheet（`ComposerSheet.swift`）中显示该会话的输入区，草稿文字与会话详情共享，提交被核心受理（store 的 `acceptedSubmissions` 递增）后关闭。启动参数 `--check-list-actions` 仅供开发核对：对一个未显示的会话依次在 sheet 中发送、从列表停止、从列表继续，进度写到 stderr。

侧聊复用 `ConversationStore`、`ConversationTab` 与 `TabContentView`，消息、输入、审批、按需输出和增量轮询均走普通会话实现。`SideChat.swift` 保留打开参数、释放租约、列表后台读取请求与展示偏好；没有专用内容视图。侧聊交给现有 `PaneLayout` 作为相邻 editor（拥有普通标签栏），或交给普通 `LinkedConversationSheet`。列表右键入口固定先用 sheet，通过后台 store 读取目标的下一轮选择，不切换当前 editor；其他入口沿用“设置 → 会话 → 侧聊”的展示偏好。切换容器保留同一个 tab、草稿和阅读控制器。侧聊标签与只含侧聊的拆分不写入窗口恢复布局。界面只用“侧聊 · 原会话标题”区分。侧聊沿用打开时的模型等选择，只通过既有文本侧问入口发送；不显示附件入口，模型等选择为只读。关闭租约不受在途打开结果影响，关闭时迟到的结果仍会释放。启动参数 `--check-side-chat` 使用合成数据验证列表 sheet 保持当前 editor、共享发送与查找、editor 拆分、容器切换保留草稿、恢复布局、停止后继续、回答中关闭与父会话生命周期。

Velune 的 turn 结束（完成或失败，用户停止的不提示）与运行时请求等待确认时发送系统通知，正在前台查看的会话不提示；点击通知在最近使用的窗口打开该会话；Dock 标记等待确认的会话及后台期间结束的会话数，回到前台清除后者。通知是否显示由系统设置决定，应用内不另设开关。

变更审阅已实现但尚未纳入产品（2026-10-11 用户决定），入口由 `VeluneRootView.changeReviewEnabled` 关闭；启用后，详情工具栏的“变更”（⌥⌘D）打开原生 inspector，显示当前会话工作目录所在 git 仓库的未提交变更：仓库名与分支、变更文件（状态字母、目录、相对 HEAD 的增删行数），选中文件在下方显示按行着色的差异，可选择复制。双击文件以默认应用打开，菜单提供在访达中显示与拷贝路径。打开、切换会话、本会话 turn 结束时及手动刷新读取；只读，不提供暂存或提交。

ARK Coding Plan 沿既有订阅模板创建，连接页分为模型认证和独立额度查询认证。AK/SK 填写完整一对替换，空白保留；可单独清除，并在本次保存中明确确认查询来源与模型订阅的关联。额度页和路由成员显示未确认时的上限暂停原因；不会将该确认显示成服务器账户核验。

新会话的工作目录菜单直接消费 core 的 `workingDirectoryProjects`（按目标运行时返回的完整项目文件夹），按项目显示主文件夹及附加文件夹，不再从侧栏会话反推或截取 5 项。本机可“选择目录…”或“输入路径…”（支持 `~/`）；SSH 与远程设备仅输入执行机器的路径。已有选择可恢复默认，创建失败在 composer 就近说明并保留草稿和路径。

会话列表组菜单的“新建会话”调用窗口的 `createConversation(in:)`，与菜单和工具栏的 `createConversation()` 一样新开标签（当前标签已是未发送的新会话时原地改目标），草稿创建复用 `ConversationStore.createConversation(runtimeID:cwd:)`：运行时组指定实例，项目组取 `ConversationProject.primaryFolder`，原生项目另取 `nativeRuntimeId`；项目的不透明身份不当成路径。组显式指定的运行时同步到新标签的 composer，保证共享输入区的明确选择与新目标一致；正文和附件继续按既有草稿归属保留，首发前不创建原生会话。`--check-group-creation` 使用合成配置直接检查同一窗口动作的运行时、主目录和共享输入结果，不发送全局鼠标／键盘事件；配合 `--check-split-panes --check-dock-areas`，以后台隔离副本运行。

“会话 → 选择工作目录…”、命令面板与 `/cwd` 共用可搜索的目录候选及当前选择，命令可配置快捷键、默认不占用按键；仅未首发的新会话可用。原生目录面板与路径输入由窗口的 `WorkingDirectorySelection.swift` 共用呈现，不依赖 composer 是否挂载；异步确认时复核原会话和运行时，避免改到后来切换的目标。

## 安装 iPad 应用

在“设置 → 设备 → 安装到 iPad…”选择 Velune 源码目录、签名团队 ID 和已配对 iPad，点击“安装”。Mac 会调用所选目录的 `scripts/build-ios.sh`，构建当前源码并开发签名，再以 `devicectl` 覆盖安装，保留应用数据。目录与团队 ID 在本机记住；安装期间禁止重复执行与关闭面板。

需要完整 Xcode、已登录的 Apple 开发账号、仓库 Rust 工具链和 iOS target。首次用 USB 连接、解锁并信任 Mac，在 iPad 开启开发者模式；开发工具已配对的网络设备也可选择，实际可达性由构建与安装工具检查。安装前校验应用 ID、签名团队、配置文件有效期与设备授权，安装回执须匹配目标设备与 `app.velune.ios` 才显示成功。构建临时目录位于源码的 `target/IPadInstall.noindex`，结束后清理；不会卸载或自动打开 iPad 应用。

iPad 构建要求见 [iOS README](../ios/README.md#构建)。


## 本机遥测

遥测设置属于当前客户端，默认未配置且关闭；更换被控设备不改变本机出口。设置页支持 OTLP/gRPC 地址、认证、trace 采样、两侧生效状态和显式测试，以及独立授权的一次性配置复制。保存/复制保留本机开关；分享授权与控制授权分别核对和撤销。手机在前台可提供配置分享，不增加本地执行能力或后台保活，也不保证后台仍可读取。

使用官方原生 SDK 与 Rust SDK，共用实例身份与配置修订。原始会话、路径、认证和底层错误链不外传，本地问题详情保留。接收回执不等于后台查询已可见，未提供的 SDK 丢弃计数为未知。开发启动与隔离验收见[开发遥测](../../docs/development.md#开发遥测)，跨单元契约见[遥测装配](../../docs/design/telemetry.md)。


## 主动压缩上下文

“会话 → 压缩上下文”、命令面板和 `/compact` 调用核心的主动压缩操作；当前会话需要支持原生压缩，下一轮仍选中同一运行时，且核心允许操作。操作使用该运行时界面当前选择的模型。压缩状态作为独立系统消息呈现，停止按钮可取消；进行中禁用并发提交和队列操作，不重新计时上一轮，也不在结束后恢复暂停队列。

状态栏通过 `ComposerQuotaRequest` 捕获下一轮意图和界面修订，经唯一观察循环读取核心 `composer_quota`。切换选择或配置后立即停止展示旧结果，并拒绝迟到回复。视图不认识具体 Harness，也不持有完整提供商或运行时配置；原生历史限额也由核心返回，明确显示为“会话记录中的限额”。提供商编辑器仍直接查询提供商额度，以保持原有刷新、历史和上限编辑契约。

`ComposerModel` 只拥有一个 `InputID` 的正文、附件、编辑修订与原生撤销历史；切换发送目标不在模型内部换正文。`ComposerDrafts` 在窗口内按身份管理这些模型、导航关联和保留项：同 group 换 Tab 恢复另一份输入，跨 group 聚焦保留当前内容并换目标；布局移动延续同一模型。正文与附件只经 `ComposerInputClient` 的独立 CAS 保存和跨窗口同步，窗口快照保留导航与未同步编辑恢复依据，没有另一套 per-session 文本缓存或写入入口。发送 sheet 也引用该身份对应的模型，关闭 sheet 不再执行单独的草稿重载；提交失败捕获原模型和清空后的修订，后来的导航或编辑不会把失败正文写到别处。`ComposerContext` 配对输入、目标与核心解析的选择，菜单、隐藏后的命令、额度及提交共用它。标签跨窗口移动携带原编辑模型与撤销历史，共享工作区的输入仍归原窗口。侧聊输入由其 Tab 持有，sheet／拆分切换延续同一临时模型，关闭后不恢复；它不进入持久输入目录、保留项菜单或窗口输入快照。原生编辑挂接与程序替换保持幂等，初始化与消费输入原子发布；原生粘贴仍通过 `NSTextView.readablePasteboardTypes`／`readSelection` 接入 PNG／TIFF 与 Finder file URL。

工作过程只在 `TranscriptTurn.outcome == completed` 且不再运行时默认折叠。核心把完成的压缩、错误与重试归入工作过程；`RuntimeFailure` 的历史 disclosure 保留错误种类与原始详情。`RuntimeRecovery` 从交付消息派生当前恢复，`RuntimeRecoveryView` 在转录区底部显示实际错误、退避倒计时／尝试次数、原生重试及结束结果，并复用普通停止操作；不另建计时调度器、不改变 composer 高度、不重复活动进度。`--preview --preview-runtime-recovery` 提供 429 等待、原生过载重试与耗尽的合成状态。

`MessageEditorSheet` 复用核心的每条消息编辑资格，不因 composer 暂选其他运行时隐藏入口；重新发送目标明确显示为会话当前上下文的运行时。成功后才关闭编辑窗口，失败保留正文及附件；不能精确原地回退时只提供在新会话中继续并说明上下文参考语义。

锁定原因入口复用操作行；核心提交准入与本地 `draftEditable` 分开，外部控制不禁止草稿文本、粘贴和附件编辑。输入框最低一行，drawer 下限计入操作行及布局标题；低空间时附件／队列收进“输入详情”，展开按实际内容限高，不增加说明带。`--preview --preview-composer-access --check-dock-areas` 提供空闲／外部控制／运行的合成会话；另加 `--check-composer-minimum` 在独立预览中设置最小高度并开启该副本的系统窗口恢复，供关键路径截图与实际退出重启验证。`--check-composer-sharing` 只在预览中运行局部同步／消费／移动不留副本检查，不发运行时请求。

侧聊标题来自核心的“侧聊 · 来源标题”，选择器允许下一轮运行时／模型／推理强度／权限。`SendSideChat` 携带实际下一轮配置；切换配置由核心创建新的临时上下文并保留引用历史和已显示问答，原会话与原生持久会话文件不改写。

已保存的 OpenAI Platform／Anthropic API 提供商在“连接与认证”提供“用量与账单…”独立面板，配置组织查询 Key 和范围，按项展示本月 UTC 报表及新鲜度。查询配置单独保存，不中断模型请求；充值余额、费用和配置限额遵守 [组织账单约定](../../docs/prd/ai-providers.md#组织用量与账单)。

草稿附件的缩略图与名称是普通打开按钮，粘贴图片和选取文件都把已有 URL 交给 `NSWorkspace.open`，由 Launch Services 选择默认应用；移除按钮独立遵守草稿编辑资格。没有为粘贴图片另建预览器。会话与子 Agent 的名称由核心原生投影交付，标签不维护标题覆盖。


会话管理由 `DeviceStore.manageConversations` 接收并在设备队列串行执行，状态按会话显示；不复用浏览加载锁或单槽待办，不把结果绑定到发起 tab 的 generation。重命名受理即关闭表单，原生成功后广播名称给打开的视图。归档闲置的打开会话时 core 释放原生 writer、保留历史投影。列表组头与会话平铺，折叠由显式按钮处理，避免 SwiftUI 原生 disclosure Section 移除末项时的 tracking 生命周期。

`WindowWorkspaceJournal` 把同一 `SavedWindowLayout` 原子写到本机状态目录 `mac-window-workspaces/`，由模型的 editor 结构与完整输入变化触发，退出前 flush；系统 SceneStorage 仍可作为布局恢复来源。快照包含草稿身份、会话关联、未首发会话元数据和每份输入的修改时间；跨窗口合并按输入修改时间，不按整个窗口最后保存时间，空输入同样保留。找不到原窗口身份时恢复最近快照，包括已清空状态，不跳回更旧的非空工作空间。损坏的某一快照会进入问题记录，其余快照继续恢复。journal 记录 windowKind 与明确的本机／远端 windowDevice，默认回退只读取同一执行设备、同类窗口的快照，独立会话窗口不会覆盖主工作区恢复。旧快照缺少设备身份时保留原文件，仅允许凭显式 scene UUID 恢复，不猜作本机最新恢复点；失去原 scene 身份的记录需用户明确映射设备。未激活的新建 Tab 仍保留创建目标。独立会话窗口以默认内置 composer 开始，不继承主窗口抽屉；从远端窗口移出标签或打开独立窗口时保留执行设备，跨设备窗口拖放在移除源标签之前拒绝。宽 composer 两翼等宽留位，以整个编辑列为中心。

通知与定时任务结果经 `DeviceStore.showConversation` 复用已有 Tab 或请求既有 SwiftUI scene 入口；关闭所有会话窗口后仍保留开窗能力。通知抑制以当前 key 窗口的实际会话内容判断，Artifact 与设置窗口不沿用上一次会话焦点。

问题面板通过本机 telemetry binding 从既有 `logs/velune.*.jsonl` 读回历史。新增问题、恢复和显式清理写同一 rolling writer；恢复只标记时间，不删除历史，角标只计未恢复。旧日志未记录原始 detail 时明确说明，不编造详情；日志自身读写失败直接显示在问题面板，避免递归写入。具体保留与数据边界见[遥测装配](../../docs/design/telemetry.md#本地问题历史)。


## Artifact 与会话后续状态

`EditorTab` 是编辑区文稿的共同身份；`ConversationTab` 持有会话、composer 与阅读状态，`ArtifactTab` 只持有内容和查看选择。`Pane`、拖动源及窗口 handoff 不依赖 runtime store。`Artifacts.swift` 负责来源／源码快照、sheet 与按类型分发的 viewer；Mermaid 代码块在复制旁通过统一入口查看。Mermaid 11.12.0 与许可随 bundle 本地分发；源码经 WKWebView 参数传入，禁用图内导航和外部资源。已打开 Artifact 随窗口日志恢复，sheet 临时保留；没有会话目标时不能发送或停止背后的会话。

`ConversationManagementMenu` 同时服务列表和会话 Tab，确认在窗口层承载；`EditorTabActions` 处理所有文稿的关闭、分屏、移窗和布局。Tab 复用会话的未读／失败、运行与待答状态。`SendQueueView` 在各会话详情内，既不属于共享 composer，也不占输入区高度；只显示条数或当前等待／受阻原因。跨会话管理进度在窗口 toolbar 的 `ConversationOperationStatus`。

大纲导航先量出目标之前的可见带，再让目标用户气泡底部贴齐滚动视口底部，复制按钮不计入端点。自动命名在运行时设置中使用专门开关和模型 Picker，原生／生成标题从 snapshot 到达时立即同步列表与 Tab。产品规则见[Artifact](../../docs/prd/conversation-view.md#artifact)与[自动命名兜底](../../docs/prd/conversations.md#自动命名兜底)。


`OutgoingSubmissions` 拥有普通发送、排队和插入本轮的本地可见提交；点击即进入转录，受理后由权威队列或原生消息接替。application 的稳定 presentation identity 用于确认，重复轮询、原生 ID 确认和后台发送者不消费其它提交。

`MessageMetadata` 统一消息操作行的本地时间格式，用户／client／最终回复显示自身创建时间，时间与copy／edit／fork共用hover显隐；工作过程footer只提供复制，不显示时间。缺失原生时间不补造。

通用设置中的外观区分别控制 UI／消息／代码字号、紧凑程度与 composer 可用宽度比例。`AppearancePreferences` 原子保存本机 `mac-appearance.json`，原生测量读线程安全快照；字体变化清消息布局缓存并重测，composer 更新原对象排版以保留正文、选区和撤销记录。速度由模型目录变体表达，不增加独立的按轮维度。

`--check-message-experience` 使用 `/tmp` 下的合成 HOME 检查提交反馈和模型／journal 的保存；`--experience-reopen` 在新进程读回 editor 与外观；`--experience-visual-only` 只生成定向原生 PNG，`--experience-typography-only` 只检查原生编辑器更改字号的连续性。入口禁止激活，不创建可见窗口或注入全局输入。当前验证范围见[任务记录](../../tasks/messaging-and-workspace-polish/packet.md)。

系统通知使用通知专用的窗口路由：已打开的目标聚焦其原有Tab，否则在当前工作窗口新开Tab；保留此前Tab。原生通知回调才激活窗口，隐藏检查只验证模型路由。

新建工作区菜单为可原生选择的Codex166项目提供“整个项目（N个文件夹）”，其项目身份与完整根集合随每Tab创建目标保留；选择单目录或无工作区会清除整项目选择。选中项目后切换到不支持它的运行时会保留目标并明确阻止发送。

新增隐藏检查入口分别为 `--check-message-experience --experience-navigation-only`（通知、查找、hover时间及打开目录准入）、`--check-composer-controls`（快捷键、比例和选中提供商额度）及 `--check-composer-ownership --composer-check-content-target`（内容／目标规则）。均使用显式临时HOME、禁止激活，不注入系统输入；详见[本轮证据](../../tasks/post-dogfood-ux/packet.md)。


运行时编辑器允许编辑已有实例的 Adapter Type。实例身份、名称、HOME与SSH执行环境保留；表单按类型暂存专属字段、ACP启动参数和新会话默认选择，切回恢复当前编辑，保存只提交选中类型的数据。新类型不查询旧类型的Agent信息或模型目录；类型变更后不沿用旧类型LastChosen。没有类型升级关系，普通配置保存不重写历史来源。窄验入口为 `--check-message-experience --experience-runtime-editor-only`，使用显式 `VELUNE_EXPERIENCE_CHECK_HOME` 合成目录，无前台窗口和输入注入。

### 输入、目标与命令的运行期职责

ComposerDrafts 管理 InputID、正文、附件与编辑对象；窗口负责 Tab／group 导航和内容与目标的配对。读取已有模型不绑定编辑器，命令可用性读取当前投影。原生编辑器的实际焦点和编辑动作决定绑定；输入、光标及明确目标变化驱动补全，attach 本身只记录 Store。

ConversationStore 拥有目标准备请求、事实观察、配置刷新及迟到结果拒收，普通会话通过共享 `prepare_composer_target` 获取保存端实际记录与有效下一轮。ComposerContext、View、菜单和补全消费该投影并转发操作。原生模型目录到达后仍使用共享 resolver，不将观测到的默认值保存成手选配置。未手选项持续继承，选择某一项只固定该项；正文恢复和编辑独立于目标准备失败。

目标读取结果只合并对应记录，不确认其它待同步修改或重置 CAS 基线。Tab 的观察共同归一组 cancellables，移出标签和关闭整组共用释放入口。显式旧数据迁移见[迁移说明](../../docs/development/migrations.md#composer-未手选默认)。
