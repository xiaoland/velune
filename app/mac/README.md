# Velune Mac app

本文面向 Mac 端开发者，记录实现、构建与检查入口。产品操作见[用户指南](../../docs/usage.md)，代码 Agent 的进程与焦点约束见 [AGENTS.md](AGENTS.md)。

本 unit 使用 SwiftUI／AppKit 的原生窗口、会话列表、聊天投影和设置界面。品牌只出现在图标与少量内容细节中。

app 通过生成的 UniFFI 接口消费 application 的完整用例，不解析 Pi RPC，不自行启动网关，也不承担跨包失败补偿。日常应用配置默认为 `~/.velune`；开发应用由签名的 `MacExecutionContext` 强制使用独立scope目录，不能通过缺省环境或错误目录回退到日常实例。提供商 API key 由 application 私有配置保存，OAuth 保留原来源刷新。各 Harness 拥有真实会话持久化。

设备设置中的“本机连接 → 连接设置”按当前状态、连接方式和服务器组织，可选择公共中继、自定义服务器或不使用中继服务器；最后一项仍允许经可信设备中转。保存操作固定在底部，后台状态更新不覆盖草稿；其他服务器的访问资格与设施诊断在高级区域展开。已保存方式、应用结果和设施可达性分别显示，地址查找沿用当前配置。令牌不回显，以“令牌已保存”标记；留空保留，明确移除并保存后删除。网络切换由共享 Rust 服务持久化和应用，不改变设备身份与已配对记录。

## 开发与实现

`svc run build-macos` 输出 `target/macos-dev/Velune Dev.app`；`build-macos-release` 为优化的开发产物，输出 `target/macos-dev-release/Velune Dev.app`。日常产物只有 `package-macos`／`reinstall-macos` 显式准备到 `target/macos/Velune.app`。开发运行使用 `start-macos-dev`／`status-macos-dev`／`stop-macos-dev`；身份、私有状态、运行副本与准确进程控制归[开发实例](../../docs/development/environment.md#mac-开发实例)。构建不安装或退出日常应用；日常安装与迁移由重装入口处理。Rust、UniFFI生成、Swift与资源按输入复用，优化profile与运行用途分开，不为身份重复编译依赖。

运行时设置展示 family、精确版本类型与配置实例，兼容区间见[运行时兼容表](../../packages/agent-runtime/README.md#版本与原生控制)。同类型可保存多个实例，工作目录属于具体会话。App 只消费通用消息与类型化权限／回答交互，不解析 ACP 或 app-server envelope；选择、回答和取消通过生成接口交给 adapter。各类型的可执行文件与 Node 等依赖见[运行时安装要求](../../docs/development/runtimes.md)。添加实例后即可浏览会话，新建表单选择实例／模型，目录可选；Mac首次发送才准备运行时并创建原生会话，继续历史时自动准备。恢复 Codex／DSH 缺少提供商身份的模型选择须明确指定，不宣称恢复上次 Velune 路由。编辑实例时可在“运行环境”中选择 HOME：继承当前用户、指定目录，或由 Velune 管理。Velune 管理时“运行时目录”隐去，由 core 在该 HOME 中推出；已保存实例显示 core 解析出的位置，可在 Finder 中显示（首次使用时创建）。“运行位置”可选本机或 SSH：SSH 填本机 OpenSSH 程序、主机（名或 ~/.ssh/config 别名，须预先完成非交互认证与主机信任）、可选端口，以及类型描述声明 `remoteResources` 时必填的远端辅助目录；远端实例的路径字段是执行机器上的绝对路径，不提供本机选择面板、`~` 展开或可执行文件自动发现，远端 managed HOME 需远端根目录。保存经 `upsert_runtime_with_execution`，保留表单不编辑的其他设置；设置列表在类型后标注“SSH 主机”。Store 按实例读取已保存的运行位置。类型描述声明 `launchOptions` 时（当前为通用 ACP），编辑器另有“启动参数”（逐个传给入口，不经 shell）与“环境变量”，经 `upsert_acp_runtime` 一并保存；声明 `agentInfo` 时，已保存实例可“读取 Agent 信息”：启动一次 Agent，展示名称、版本、会话能力与其报告的登录方式（登录由 Agent 自身完成）。

构建前只需安装 runtime-support，huihua parser 依赖及许可证随 bundle 打包；不分发 Agent runtime 或完整 Pi SDK。具体步骤见 [开发说明](../../docs/development.md#原生运行时与历史读取)。构建产物不等于已安装或完成用户路径验收。

会话内容消费 Rust 的类型权威，Mac 只派生展示行与展开、滚动状态。用户内容在右侧气泡，assistant 正文及工具左对齐；客户端扩展通知同样在右侧，运行时状态在左侧，工具输出不按 LLM Markdown 解析。Markdown 由固定 SwiftPM 依赖 swift-markdown 解析，许可证随应用分发；不恢复手写 fence 解析。虚拟列表使用稳定行身份，打开／发送到底，阅读历史时暂停流式跟随。

Mac 最低支持macOS15，由根目录 [Package.swift](../../Package.swift) 定义独立 SwiftPM 产品，依赖固定 swift-markdown 0.9.0；[Package.resolved](../../Package.resolved) 锁传递依赖 swift-cmark。build-macos 先生成 UniFFI 模块，再以SwiftPM的Xcode后端构建本机架构产品，dev为debug并限制jobs为2，release为优化构建。应用与生成绑定目标各自启用warnings-as-errors，并打包`app/mac/Licenses`与解析锁文件。依赖保持各自声明的Swift语言模式；当前依赖没有资源bundle。Swift 包不依赖领域 Rust 包源码，只链接对应profile生成绑定与库。

[Checks](Checks/) 中的原生检查与入口由 `VELUNE_DEV_CHECKS` 控制，只编入 development 用途的 App，包含 `build-macos` 与 `build-macos-release`。日常包仍会在启动时拒绝开发检查和预览参数。

新标签复用 DeviceStore 当前列表后直接读目标；不因打开标签先扫描所有运行时。列表拖放目标在异步读取 provider 前取消 ListDragWatch 的拖出后备动作，避免重复新窗口。

会话行与分组的 `NSItemProvider` 数据回调直接返回已捕获的不可变 payload。macOS 退出时会在主线程同步兑现未完成的拖放数据，回调必须独立于主线程运行循环完成。`--check-message-experience --experience-drag-provider-only` 用旧模式负对照和主线程限时等待覆盖这条约束，使用合成身份。

会话导航分开记录选中、待加载与已加载的身份，读取在途时保留最后一次导航意图。切换失败时恢复原详情。重命名和删除经绑定交给运行时。 [会话管理](../../docs/prd/conversations.md#会话管理)

侧栏由 `AggregatedListModel` 合并各设备的会话分组。单设备视图使用该设备的浏览偏好，跨设备顺序保存到本机的 `mac-aggregated-list.json`。分组、排序和分页规则归[会话列表](../../docs/prd/conversations.md#会话列表)。

`ConversationStore.SearchRead` 按设备持有当前查询的结果、进行中状态和错误。聚合层只合并这些结果。浏览偏好保存期间，较早读取的列表不能覆盖新偏好。归档窗口使用独立客户端视图，技术边界见[浏览与执行准备](../../docs/product-tdd/conversations.md#浏览与执行准备)。

项目编辑的目标同时绑定项目键与所属设备。表单保留打开时的项目记录，存储前核对当前记录；远端使用新的代理取得提交版本。同一项目被其他窗口或设备修改时保留输入并提示核对，存储成功才关闭表单。远端添加文件夹输入执行设备上的绝对路径。

会话列表的单击先选中，等待系统双击判定窗口结束后才打开；双击撤销该次待打开动作，只进入重命名。键盘选择即时打开；多选、拖拽与右键不会派发延迟导航，Option 单击仍在新标签页打开。列表选中独立于当前显示会话，同一会话的普通 snapshot 更新不覆盖正在重命名的另一行；更换焦点窗格或视图消失会取消待打开。

Mac 随包提供官方 xurl CLI（固定源码提交、Apache-2.0 许可证与构建记录），并注册 `agents` scheme。点击系统或正文中的 `agents://` 链接后自动定位并打开会话，不显示地址输入或查找表单。定位在接收链接的窗口所控制的设备上进行。只有多匹配、无匹配或读取失败时显示 `AgentURIView`；多个结果按标题、实例与目录供选择，局部失败进入“问题”并保留可选结果。复合会话继续使用 Velune 深链，原生子 Agent 仍按既有入口只读打开。

设置的“模型路由”页（`ModelRoutes.swift`）左侧列出路由（名称、策略与成员数，＋／−、双击或右键编辑），右侧是所选路由的现状：策略与会话保持的含义，按顺序列出各成员的提供商认证方式、账户尾号与登录状态、适用于该模型 ID 的额度窗口（已用比例、提供商上限、重置时间、观测是否过期），以及登录前或设有上限却缺少最新额度时路由不会使用它的提示；未登录成员行内可直接登录，双击或右键成员编辑其提供商。成员含订阅提供商时显示核心给出的订阅披露。编辑 sheet 设置名称、策略（智能／顺序／轮询／权重）、会话保持和成员：拖动排序、右键或 − 移除；＋ 菜单按提供商分组，其他协议或已加入的模型不可选；权重策略下每个成员有权重与所占比例。新路由默认智能策略并开启会话保持。路由经 `save_model_route`／`delete_model_route` 保存。

额度只读 core 观测（`provider_quota`／`refresh_provider_quota`，`ProviderQuota.swift`）：视图显示期间在请求队列上读取，不占用 `isLoading`；读取中或尚无结果时每 2 秒、否则每 30 秒再读，由 core 决定是否采样；未登录的提供商不读取。添加提供商先在同一 sheet 中选择 core `provider_templates()` 给出的模板（`ProviderTemplates.swift`，按订阅／API 分组，另有“从 Agent 运行时导入”），选中订阅时显示其披露，“继续”后以模板组合打开编辑器。订阅提供商的协议与地址以只读值呈现。OpenAI Platform 默认填入 Responses 与 `https://api.openai.com/v1`，Anthropic API 默认填入 Messages 与 `https://api.anthropic.com`，均可编辑协议／地址，默认不读取账户额度。已保存订阅的名称和连接锁定判定经共享 `providerSubscriptionTemplate` 取得，不由 Mac 按品牌或认证方式推断。Kimi Coding Plan 使用模板固定的 API key 认证，可保存、重开编辑与更换 Key；不提供 OAuth 登录。Codex／Claude Code 等交互式认证的新订阅提供商“保存并登录…”保存后留在编辑器并开始登录（Codex 登录 URL 自动在浏览器打开，Claude Code CLI 自行打开浏览器）。Claude Code 组合以本机 `claude` 可执行文件替代服务地址：自动填入发现的第一个路径，可从“已发现”菜单或“选择…”更换，须为绝对路径。已登录且认证带 `logout` 动作时显示“退出登录…”，确认后调用 `authentication_logout`。Claude Code 组合的“账户来源”选择在 Velune 中登录新账户、本机 Claude Code 登录，或本机 Claude Code 运行时的登录；改变来源后在保存时提交 `useClaudeCodeLogin`（改回新账户为 `clear`）。沿用的登录只显示状态、账户尾号与“检查登录状态”（`authentication_inspect` 后重读配置），没有登录、退出或“清除认证”。“从 Agent 运行时导入”列出 core `providerImportTypes` 中的运行时，含 Codex 与 Claude Code；没有服务地址的候选（Claude Code 登录）不显示地址行。订阅或报告额度的提供商有“额度与使用上限”页，按窗口选择已用比例上限，对所有路由和直接调用共同生效；只报告金额的提供商没有窗口，不显示上限。窗口按核心的节奏在重置前会用尽时以橙色给出预计用尽时间，金额（余额、OpenRouter Key 剩余额度）逐行显示。“历史…”打开额度历史（`QuotaHistory.swift`）：选择窗口或金额与 24 小时／7 天／30 天范围，按 96 个区间显示各区间最后一次观测，没有观测的区间留空；悬停查看观测时间与区间内的最低／最高，可确认后清除。直连 DeepSeek、Moonshot、OpenRouter 官方地址的 API 提供商在认证下方有“读取 … 账户额度”开关；地址不是官方地址时保存为不读取。本机核心时每 3 秒轮询 `quota_alerts`，以系统通知提醒达到上限、用尽或账户不可用。

“通用”管理外观、用量显示和会话列表，macOS 26 以下也提供工具栏设置。“会话”管理消息编辑、大纲、侧聊、关联 Agent 和状态栏。“快捷键”按菜单分节。大纲列表打开时停在最末一条，会话运行中点按最末一条即前往会话末尾。用量显示有“额度”和“上下文”两个独立的占用／剩余选项：前者由 core 的 `usage_display`／`set_usage_display` 控制 `QuotaWindowRow` 和账户额度，后者由 `context_usage_display`／`set_context_usage_display` 控制状态栏上下文、圆环与详情；额度上限仍是已用比例，显示剩余时写作“保留 N%”（`UsageFormat`），上下文颜色仍按已用程度变化。每轮记录的“结束时上下文”是 token 计数，不随此切换。

所有可编辑列表采用原生双击主操作：提供商、运行时、模型模板、模型路由打开编辑，提供商内模型聚焦对应详情，会话打开原生标题重命名。单击选择与 ⌘／Shift 多选保持有效；只读目录或导入候选不伪造编辑操作。

“问题”是本机与所有已控设备合并的原生窗口（按设备标注，清除操作仍归属各设备的记录），可从主窗口有问题时的状态入口、编辑／导入 sheet 标题行或“窗口”菜单的“问题”打开（⌘⇧M）。操作失败保留结构化诊断，不在 composer／设置底部或会话列表重复展示；活动读取问题按来源合并，恢复时移除。记录在当前进程内最多保留100项，不作为第二套日志或持久化数据。

消息列表消费 Rust 的 `TranscriptTurn` 引用，保留用户问题与当前最后结果，其余工作消息可展开查看。详情右侧工具栏提供会话大纲，设置“大纲按钮”决定其行为：“弹出面板”在按钮处弹出原生 popover 列出用户消息；“就地折叠”使按钮成为开关，消息列表以行高插值动画缩起为只剩用户消息，点击其中一条或再次点击按钮即恢复完整列表，锚点消息在动画中保持屏幕位置，减少动态效果时直接切换。折叠是临时状态，切换会话或发送后恢复；工作过程等展开状态在折叠期间保留。跟随末尾时视口高度变化（底部面板展开、输入区增高）会重新定位到末尾。⌘F（“编辑 → 查找…”，可在快捷键设置中改）先交给焦点所在的工具窗口的查找（目前只有会话列表：侧栏聚焦其搜索框，块中弹出搜索框，否则聚焦其搜索框），其余位置回落到当前会话的消息查找（`TranscriptFind.swift`：面板顶部的查找栏，搜索真实消息及折叠工作过程的正文，查询时按需取得延迟文本；回车／⇧回车或上下按钮按匹配消息移动，自动展开命中的工作过程与内容块并高亮文字，Esc 关闭并清除高亮）。大纲、关联 Agent 日后可加入各自的查找。回到底部的向下箭头仍在消息列表内，右边距按当前滚动条样式让出滚动条宽度。展开状态按消息／turn 身份保存，权威历史替换时清理失效引用，不能将当前位置保存为固定数组下标。

问题窗口完整展示传入的本地错误原因、阶段与诊断编号；开发工具的真实数据读取限制不构成应用对用户诊断的过滤规则。窗口记录仍是当前进程内的有界问题集合，不是原始日志浏览器。

输入区的 `/` 命令与 `@` 文件列表（`ComposerCompletionPanel`）是一个无边框、不成为 key 的子窗口，放在输入框上沿之上 4 pt、与输入框同宽，盖住其上的内容而不撑高输入区（停靠在底部区域时也一样）；随窗口移动，窗口缩放或输入框变高时重新定位；输入框离开焦点或离开窗口（切换标签）时关闭。

各会话窗口由窗口模型（`Workspace.swift`）组织。会话窗口不使用系统窗口 Tab（启动时关闭 `NSWindow.allowsAutomaticWindowTabbing`）：系统 Tab Bar 无法放进各个分屏，与分屏标签叠放又角色重复；多个工作区就是多个窗口。一个工作区窗口聚合本机与所有已授权设备的会话（[PRD](../../docs/prd/remote-access.md)“聚合会话列表”、契约见[远控设计](../../docs/product-tdd/remote-access.md)）：每台设备仍是一个 `DeviceStore`（Transport/application、配置、会话列表与浏览偏好、认证、问题、草稿与保存的下一轮选择），`DeviceHub` 在服务启动后即对全部已授权设备建立并保持连接（`RemoteDevices.swift`）；窗口按设备持有 kept-input 目录（`drafts(for:)`），列表的合并模型 `AggregatedListModel`（`AggregatedList.swift`）把各设备的组按“设备 × 组”合并——组身份仍是各设备自己的分组键，多设备视图组标题带设备名，设备筛选、跨设备折叠与手动顺序保存在本机 `mac-aggregated-list.json`（schema 1），筛选到单台设备时该设备的既有界面与偏好原样生效。窗口的会话列表与每个会话标签页各一个 `ConversationStore`（列表的搜索与多选；标签页的转录、输入区、大纲与下一轮），每个标签页绑定其会话所属设备的 `DeviceStore`，选中会话即切换输入目标；设备状态从所属 `DeviceStore` 读取，不复制。编辑区是分屏树，叶子是面板（`Pane`），面板持有一组标签页（`ConversationTab`）与当前显示的一个。窗口内可向右（⌘D）或向下（⇧⌘D）拆分，编辑区网格是嵌套的原生 `NSSplitView`（`PaneGrid.swift`）：每组的面板是一个按组保留的 `NSHostingView`，拆分、合并、移动标签时只重排分栏并把仍在的面板视图移到新位置（先放入新排布再移走旧的，面板不离开窗口），转录与其中状态不重建；仅比例变化时不重排。分栏按布局比例排布（窗口调整大小时保持比例），细分隔线两侧各 4pt 可拖，拖动由 `NSSplitView` 跟踪，松开才写回比例（每一步都发布会让整个窗口的视图重新求值），双击恢复均分；相邻两组各至少 协作工具和原生 sub-agent 的调用下方显示“打开会话”链接，另一个 Agent 发来的消息在用户侧气泡顶部以链接标出来源会话（“来自 运行时 会话「标题」”）。“关联 Agent”工具（`LinkedAgents.swift`）把会话的父会话、原生子 Agent 与协作会话（核心快照的 `collaborators`，带方向与运行时）分组列出。这些链接、面板的双击与“打开父会话”按“设置 → 会话 → 关联 Agent”的打开方式打开：当前标签页（未在列表时先重读列表）、新标签页、浮层或新窗口，本窗口已有标签显示的会话改为切换过去；面板右键菜单可选任一方式。浮层是窗口的 sheet，内容为一个普通标签页（`TabContentView` 带自己的输入区），可原样转到标签页或会话窗口；浮层打开时 macOS 不接受退出，与其他 sheet 相同。原生 sub-agent 消息容器是自有的翻转文档视图（NSScrollView 内），按需物化可见行与 overdraw 区域并复用纯 AppKit cell，不在行内承载 SwiftUI。未使用 NSTableView：它对未测行使用估计高度，并在任意 API 调用与布局中懒测量、自行重锚定，使高度在补偿之外落地。行几何是控制器高度列表的前缀和；每行布局由纯函数根据消息内容修订、局部展开状态与实际宽度计算，TextKit 1 测量与显示使用同一属性文本和容器配置，帧取整数，避免 layer 对齐改变已测宽度。可见带（视口上下各 0.75 屏）在显示前同步测量；其余行在后台队列按距阅读位置由近及远测量并分批提交。高度只在一次同步提交中变化，同时恢复视口顶部行及其行内偏移，阅读位置不随离屏行变化移动；`prepareContent(in:)` 为 responsive scrolling 预先物化。宽度连续变化时（拖动分隔条或窗口边缘、侧栏滑动）文字最多每 0.1 秒按新宽度重排一次，其间各行保持原布局，只按当前宽度重新居中（栏宽不变时与重排结果一致，文字随动画平移而不跳动）；宽度停下 0.15 秒后补一次重排并在后台测量其余行。停靠区滑开（窗口的编辑列变宽）期间不重排，文字保持原布局居中，停下后重排一次；变窄时照常重排，否则文字会被裁掉。输入区的单行／两行选择只在结果改变时更新视图状态，调整宽度不会每一步重新求值输入区。用户滚动离开底部即暂停跟随，滚回底部、点击回到底部或发送消息恢复。

共享应用状态仅在值变化时发布到工作区；无匹配的轮询问题清理及相同会话快照不触发重复界面应用。正常空闲轮询消费内存快照，点击／滚动不直接读取历史文件。轮询携带上次交付游标，core 未变化时不传快照，变化时只传变化消息及完整顺序；映射在后台请求队列完成，主线程按消息身份合并。超过 2KB 的推理与工具输出只随快照携带大小，展开对应 disclosure 时按消息读取并在原位替换占位；同一交付 stamp 的已读内容在后续合并中保留。

每个 Transport 操作标明效果（`OperationEffect`：只读、写入、改变配置；改变配置后重新读取列表）。各工作区的请求队列共用一个 Transport，退出时库在应用级队列上关闭：退出一开始，各队列中尚未开始的只读操作即被拒绝（`TransportError.quitting`，不记为问题），关闭只等正在进行的一个操作与此前排队的写入（如草稿、标记已读），而不是排在积压的列表、模型等读取之后；库拒绝关闭时恢复读取。

应用级 store 轮询 `conversation_activity`：侧栏对正在运行的会话显示小型进度指示，不区分 turn 由 Velune 还是其他客户端发起（是否在 Velune 之外不重要，重要的是正在运行），出现列表中没有的外部会话时重新读取列表；打开的会话随原生文件变化更新，外部发起的运行与自身运行使用同一底部状态行，输入资格由共享 input_access 决定（Velune 不能停止其他进程的 turn）。会话的右键菜单按活动提供运行操作，不改变列表选中与显示的会话：运行中“停止”（多选时“停止所选会话”），只剩后台工作时“停止全部后台工作”，活动列为可恢复时“继续”，以及“发送消息…”。“继续”由显示该会话的标签页执行，没有时由一个不显示的标签页打开会话、等下一轮选择就绪后执行，与输入区的继续相同。“发送消息…”在窗口上的 sheet（`ComposerSheet.swift`）中显示该会话的输入区，草稿文字与会话详情共享，提交被核心受理（store 的 `acceptedSubmissions` 递增）后关闭。启动参数 `--check-list-actions` 仅供开发核对：对一个未显示的会话依次在 sheet 中发送、从列表停止、从列表继续，进度写到 stderr。

每台设备的活动、额度提醒和共享输入轮询，以及标签页的准备输入目标，失败后从 1.2 秒起倍增退避，最长 30 秒（`PollBackoff`）；读取成功、设备重新连接或目标事实变化时立即恢复，远控入口关闭或目标暂不可用时不再每秒重试数次。

`ReadRecovery.swift` 提供刷新图标和就地重试视图。读取方负责判断结果是否属于当前来源与范围，单独维护读取错误和写入错误。后台任务仅在工具可见时轮询，布局键用 `backgroundTasks`，旧布局缺少该键时使用内建弹出位置。`subAgents` 继续指关联 Agent。 [读取恢复复验](../../docs/development/validation.md#mac-读取恢复复验)

`ConversationStore` 的普通变更仍逐一执行，保留操作结束后才打开最后一个待选会话的行为。同会话的投影轮询、已显示消息的延迟内容读取、运行时回答和停止各自有独立准入，不等待普通变更的 ACK；轮询和回答各最多一个在途，内容读取每批最多 32 条、最多一个在途，待读 ID 按当前投影合并。完整投影与 delta 共用请求 scope 仲裁：同交付上下文、同 cursor generation 才比较 sequence；不可比较的 generation／上下文转换须匹配请求捕获的投影基线，否则保留当前视图并从逻辑 source 补读。内容缓存同时校验上下文、delivery generation 与 message stamp；同会话刷新只废弃旧响应，不丢弃唯一视口需求，导航或关闭则终止该视口的补读。轮询的 absent 也经捕获基线的 nil 仲裁，unchanged 才是无操作。业务受理收据先结算，附带的旧投影被拒绝不表示发送失败，也不会自动重发；首次创建使用独立的 created 阶段基线。创建对应的 InputID／执行选择由 operation 捕获的设备输入 facade 独立 promotion 一次，窗口事件只更新本地导航关联；即使窗口先关闭，创建事实和已创建后的失败草稿也不能恢复成一次新的创建。

`--check-conversation-requests` 在 SwiftUI App／delegate／scene 初始化前进入，不创建 NSWindow 或激活应用。入口使用私有 `VELUNE_HOME` 和本地合成 Codex peer，扣住 warm Send ACK 后检查 Store → Transport → Core 的轮询、延迟内容、回答及停止进展，并检查迟到投影、创建两阶段和回答 attempt 的隔离。按 [AGENTS.md](AGENTS.md) 的程序化入口规则运行开发可执行文件；该门禁不覆盖真实模型、系统键盘或视觉验收。

侧聊复用 `ConversationStore`、`ConversationTab` 与 `TabContentView`，消息、输入、审批、按需输出和增量轮询均走普通会话实现。`SideChat.swift` 保留打开参数、释放租约、列表后台读取请求与展示偏好；没有专用内容视图。侧聊交给现有 `PaneLayout` 作为相邻 editor（拥有普通标签栏），或交给普通 `LinkedConversationSheet`。列表右键入口固定先用 sheet，通过后台 store 读取目标的下一轮选择，不切换当前 editor；其他入口沿用“设置 → 会话 → 侧聊”的展示偏好。切换容器保留同一个 tab、草稿和阅读控制器。侧聊标签与只含侧聊的拆分不写入窗口恢复布局。界面只用“侧聊：原会话标题”区分。侧聊沿用打开时的模型等选择，只通过既有文本侧问入口发送；不显示附件入口，模型等选择为只读。关闭租约不受在途打开结果影响，关闭时迟到的结果仍会释放。启动参数 `--check-side-chat` 使用合成数据验证列表 sheet 保持当前 editor、共享发送与查找、editor 拆分、容器切换保留草稿、恢复布局、停止后继续、回答中关闭与父会话生命周期。

设备级活动轮询提供普通标签页的运行和等待状态，以及轮次完成事件。未选中标签页暂停读取正文，标签状态仍随设备活动更新。轮次完成时重新读取会话列表，更新原生未读状态与排序。Velune 执行的轮次完成或失败，以及运行时请求等待确认时，向系统提交通知。用户停止的轮次和正在前台查看的会话免打扰。通知可进入系统通知中心，点击后在最近使用的窗口打开对应会话。Dock 标记等待确认的会话及应用在后台期间结束的会话数，回到前台清除后者。通知是否显示由系统设置决定，应用内不另设开关。

变更审阅入口由 `VeluneRootView.changeReviewEnabled` 关闭。`ChangeReviewView` 按会话和工作目录读取列表，按文件和请求代际读取差异。失败保留同范围的文件列表或差异，并显示对应重试。

ARK Coding Plan 沿既有订阅模板创建，连接页分为模型认证和独立额度查询认证。AK/SK 填写完整一对替换，空白保留；可单独清除，并在本次保存中明确确认查询来源与模型订阅的关联。额度页和路由成员显示未确认时的上限暂停原因；不会将该确认显示成服务器账户核验。

新会话的工作目录菜单直接消费 core 的 `workingDirectoryProjects`（按目标运行时返回的完整项目文件夹），按项目显示主文件夹及附加文件夹，不再从侧栏会话反推或截取 5 项。本机可“选择目录…”或“输入路径…”（支持 `~/`）；SSH 与远程设备仅输入执行机器的路径。已有选择可恢复默认，创建失败在 composer 就近说明并保留草稿和路径。

会话列表组菜单的“新建会话”调用窗口的 `createConversation(in:)`，与菜单和工具栏的 `createConversation()` 一样新开标签（当前标签已是未发送的新会话时原地改目标），草稿创建复用 `ConversationStore.createConversation(runtimeID:cwd:)`：运行时组指定实例，项目组取 `ConversationProject.primaryFolder`，原生项目另取 `nativeRuntimeId`；项目的不透明身份不当成路径。组显式指定的运行时同步到新标签的 composer，保证共享输入区的明确选择与新目标一致；正文和附件继续按既有草稿归属保留，首发前不创建原生会话。`--check-group-creation` 使用合成配置直接检查同一窗口动作的运行时、主目录和共享输入结果，不发送全局鼠标／键盘事件；配合 `--check-split-panes --check-dock-areas`，以后台隔离副本运行。

“会话 → 选择工作目录…”、命令面板与 `/cwd` 共用可搜索的目录候选及当前选择，命令可配置快捷键、默认不占用按键；仅未首发的新会话可用。原生目录面板与路径输入由窗口的 `WorkingDirectorySelection.swift` 共用呈现，不依赖 composer 是否挂载；异步确认时复核原会话和运行时，避免改到后来切换的目标。

## 安装 iPad 应用

在“设置 → 设备 → 安装到 iPad…”选择 Velune 源码目录、签名团队 ID 和已配对 iPad，点击“安装”。Mac 会调用所选目录的 `scripts/build-ios.sh`，构建当前源码并开发签名，再以 `devicectl` 覆盖安装，保留应用数据。目录与团队 ID 在本机记住；安装期间禁止重复执行与关闭面板。

iPad 构建要求见 [iOS README](../ios/README.md#构建)。


## 本机遥测

遥测设置属于当前客户端，默认未配置且关闭；更换被控设备不改变本机出口。设置页支持 OTLP/gRPC 地址、认证、trace 采样、两侧生效状态和显式测试，以及独立授权的一次性配置复制。保存/复制保留本机开关；分享授权与控制授权分别核对和撤销。手机在前台可提供配置分享，不增加本地执行能力或后台保活，也不保证后台仍可读取。

使用官方原生 SDK 与 Rust SDK，共用实例身份与配置修订。原始会话、路径、认证和底层错误链不外传，本地问题详情保留。接收回执不等于后台查询已可见，未提供的 SDK 丢弃计数为未知。开发启动与隔离验收见[开发遥测](../../docs/development.md#开发遥测)，跨单元契约见[遥测装配](../../docs/product-tdd/telemetry.md)。


## 主动压缩上下文

“会话 → 压缩上下文”、命令面板和 `/compact` 调用核心的主动压缩操作；当前会话需要支持原生压缩，下一轮仍选中同一运行时，且核心允许操作。操作使用该运行时界面当前选择的模型。压缩状态作为独立系统消息呈现，停止按钮可取消；进行中禁用并发提交和队列操作，不重新计时上一轮，也不在结束后恢复暂停队列。

状态栏通过 `ComposerQuotaRequest` 捕获下一轮意图和界面修订，经唯一观察循环读取核心 `composer_quota`。切换选择或配置后立即停止展示旧结果，并拒绝迟到回复。视图不认识具体 Harness，也不持有完整提供商或运行时配置；原生历史限额也由核心返回，明确显示为“会话记录中的限额”。提供商编辑器仍直接查询提供商额度，以保持原有刷新、历史和上限编辑契约。

`ComposerModel` 只拥有一个 `InputID` 的正文、附件、编辑修订与原生撤销历史；切换发送目标不在模型内部换正文。`ComposerDrafts` 在窗口内按身份管理这些模型、导航关联和保留项：切换 Tab 或聚焦另一组时恢复目标 Tab 的输入，布局移动延续同一模型。正文与附件只经 `ComposerInputClient` 的独立 CAS 保存和跨窗口同步，窗口快照保留导航与未同步编辑恢复依据，没有另一套 per-session 文本缓存或写入入口。发送 sheet 也引用该身份对应的模型，关闭 sheet 不再执行单独的草稿重载；提交失败捕获原模型和清空后的修订，后来的导航或编辑不会把失败正文写到别处。`ComposerContext` 配对输入、目标与核心解析的选择，菜单、隐藏后的命令、额度及提交共用它。标签跨窗口移动携带原编辑模型与撤销历史，共享工作区的输入仍归原窗口。侧聊输入由其 Tab 持有，sheet／拆分切换延续同一临时模型，关闭后不恢复；它不进入持久输入目录、保留项菜单或窗口输入快照。原生编辑挂接与程序替换保持幂等，初始化与消费输入原子发布；原生粘贴仍通过 `NSTextView.readablePasteboardTypes`／`readSelection` 接入 PNG／TIFF 与 Finder file URL。

工作过程只在 `TranscriptTurn.outcome == completed` 且不再运行时默认折叠。核心把完成的压缩、错误与重试归入工作过程；`RuntimeFailure` 的历史 disclosure 保留错误种类与原始详情。`RuntimeRecovery` 从交付消息派生当前恢复，`RuntimeRecoveryView` 在转录区底部显示实际错误、退避倒计时／尝试次数、原生重试及结束结果，并复用普通停止操作；不另建计时调度器、不改变 composer 高度、不重复活动进度。`--preview --preview-runtime-recovery` 提供 429 等待、原生过载重试与耗尽的合成状态。

`MessageEditorSheet` 复用核心的每条消息编辑资格，不因 composer 暂选其他运行时隐藏入口；重新发送目标明确显示为会话当前上下文的运行时。成功后才关闭编辑窗口，失败保留正文及附件；不能精确原地回退时只提供在新会话中继续并说明上下文参考语义。

锁定原因入口复用操作行；核心提交准入与本地 `draftEditable` 分开，外部控制不禁止草稿文本、粘贴和附件编辑。输入框最低一行，drawer 下限计入操作行及布局标题；低空间时附件／队列收进“输入详情”，展开按实际内容限高，不增加说明带。`--preview --preview-composer-access --check-dock-areas` 提供空闲／外部控制／运行的合成会话；另加 `--check-composer-minimum` 在独立预览中设置最小高度并开启该副本的系统窗口恢复，供关键路径截图与实际退出重启验证。`--check-composer-sharing` 只在预览中运行局部同步／消费／移动不留副本检查，不发运行时请求。

侧聊标题来自核心的“侧聊：来源标题”，选择器允许下一轮运行时／模型／推理强度／权限。`SendSideChat` 携带实际下一轮配置；切换配置由核心创建新的临时上下文并保留引用历史和已显示问答，原会话与原生持久会话文件不改写。

已保存的 OpenAI Platform／Anthropic API 提供商在“连接与认证”提供“用量与账单…”独立面板，配置组织查询 Key 和范围，按项展示本月 UTC 报表及新鲜度。查询配置单独保存，不中断模型请求；充值余额、费用和配置限额遵守 [组织账单约定](../../docs/prd/ai-providers.md#组织用量与账单)。

草稿附件的缩略图与名称是普通打开按钮，粘贴图片和选取文件都把已有 URL 交给 `NSWorkspace.open`，由 Launch Services 选择默认应用；移除按钮独立遵守草稿编辑资格。没有为粘贴图片另建预览器。会话与子 Agent 的名称由核心原生投影交付，标签不维护标题覆盖。


会话管理由 `DeviceStore.manageConversations` 接收并在设备队列串行执行，状态按会话显示；不复用浏览加载锁或单槽待办，不把结果绑定到发起 tab 的 generation。重命名受理即关闭表单，原生成功后广播名称给打开的视图。归档闲置的打开会话时 core 释放原生 writer、保留历史投影。列表组头与会话平铺，折叠由显式按钮处理，避免 SwiftUI 原生 disclosure Section 移除末项时的 tracking 生命周期。

`WindowWorkspaceJournal` 把同一 `SavedWindowLayout` 原子写到本机状态目录 `mac-window-workspaces/`，由模型的 editor 结构与完整输入变化触发，退出前 flush。此处负责保存窗口内容，系统窗口恢复只记录窗口 UUID、种类与执行设备。旧格式转换和备份见[Mac 窗口恢复身份](../../docs/development/migrations.md#mac-窗口恢复身份)。快照包含草稿身份、会话关联、未首发会话元数据和每份输入的修改时间；跨窗口合并按输入修改时间，不按整个窗口最后保存时间，空输入同样保留。系统重开的窗口只读自己 UUID 对应的快照。自动打开的默认工作区可回退到同设备、同类窗口的最近快照，包括已清空状态。未激活的新建 Tab 仍保留创建目标。独立会话窗口以默认内置 composer 开始，不继承主窗口抽屉；从远端窗口移出标签或打开独立窗口时保留执行设备，跨设备窗口拖放在移除源标签之前拒绝。宽 composer 两翼等宽留位，以整个编辑列为中心。

通知与定时任务结果经 `DeviceStore.showConversation` 复用已有 Tab 或由 `WorkspaceWindows` 打开 AppKit 工作区。关闭所有会话窗口后仍可打开目标。通知抑制以当前 key 窗口的实际会话内容判断，Artifact 与设置窗口不沿用上一次会话焦点。

问题面板通过本机 telemetry binding 从既有 `logs/velune.*.jsonl` 读回历史。新增问题、恢复和显式清理写同一 rolling writer；恢复只标记时间，不删除历史，角标只计未恢复。旧日志未记录原始 detail 时明确说明，不编造详情；日志自身读写失败直接显示在问题面板，避免递归写入。具体保留与数据边界见[遥测装配](../../docs/product-tdd/telemetry.md#本地问题历史)。


## Artifact 与会话后续状态

### Artifact 编辑文稿

`EditorTab` 拥有编辑文稿的标签身份及激活／关闭／拖动契约；`ConversationTab` 持有会话、composer 与阅读状态，`ArtifactTab` 只持有内容和源码／图表选择。`Pane`、拖动源及窗口 handoff 不依赖 runtime store。窗口保留所属执行设备，交接和布局恢复不能把另一设备的会话身份交给当前 core。

Artifact 是携带内容类型、来源定位和源码快照的值；身份包含来源与内容摘要。`Artifacts.swift` 负责统一打开、sheet 与按类型分发的 viewer，Markdown 中的 Mermaid 代码块在复制旁调用该入口，不自行创建浏览器或窗口。同一执行设备的窗口间复用已有 `ArtifactTab`，sheet、标签和独立窗口间移动保留对象及源码／图表选择。已停靠内容随窗口布局日志恢复，临时 sheet 不另建持久存储。

Mermaid 11.12.0 与许可随 bundle 本地分发，使用固定版本和本地 WKWebView；源码经参数传入，禁用图内导航和外部资源。查看不取得会话控制权或执行生命周期；没有会话目标时不能发送或停止背后的会话。

### 会话后续状态

`ConversationManagementMenu` 同时服务列表和会话 Tab，确认在窗口层承载；`EditorTabActions` 处理所有文稿的关闭、分屏、移窗和布局。Tab 复用会话的未读／失败、运行与待答状态。`SendQueueView` 在各会话详情内，既不属于共享 composer，也不占输入区高度；只显示条数或当前等待／受阻原因。跨会话管理进度在窗口 toolbar 的 `ConversationOperationStatus`。

大纲导航先量出目标之前的可见带，再让目标用户气泡底部贴齐滚动视口底部，复制按钮不计入端点。自动命名在运行时设置中使用专门开关和模型 Picker，原生／生成标题从 snapshot 到达时立即同步列表与 Tab。产品规则见[Artifact](../../docs/prd/conversation-view.md#artifact)与[自动命名兜底](../../docs/prd/conversations.md#自动命名兜底)。


`OutgoingSubmissions` 在普通发送时立即呈现带「发送中」的消息，以运行时接收回执撤下标记，由原生投影接替暂态行。失败回退到提交时捕获的输入，受理为排队的消息转到对应的队列项。本机 Core 收到原生用户消息时按会话通知，可见会话沿用投影游标读取。`scripts/check-macos-composer.py` 的 `outgoing-submissions` 检查可见反馈、失败回退和队列，`late-send-echo` 检查运行时先确认、原生记录后到的接替。

`MessageMetadata` 统一消息操作行的本地时间格式，用户／client／最终回复显示自身创建时间，时间与copy／edit／fork共用hover显隐；工作过程footer只提供复制，不显示时间。缺失原生时间不补造。

通用设置中的外观区控制整体缩放、独立 UI／消息／代码字号、紧凑程度与 composer 可用宽度比例。缩放命令与设置共同读写 `AppearancePreferences`，它原子保存本机 `mac-appearance.json` 并向原生排版发布线程安全的只读快照。字号和间距由同一份值计算。外观变化后，消息布局重新测量，composer 在原对象上更新排版，保留正文、选区和撤销记录。转录 cell 的持久子视图（活动行、附件名、披露标题、代码块标签与按钮、本轮配置摘要）从行布局获取 NSAttributedString／NSFont，和布局缓存一起失效重建。速度由模型目录变体表达，不增加独立的按轮维度。

`--check-message-experience` 使用 `/tmp` 下的合成 HOME 检查提交反馈和模型／journal 的保存；`--experience-reopen` 在新进程读回 editor 与外观；`--experience-visual-only` 只生成定向原生 PNG，`--experience-typography-only` 检查原生编辑器更改字号的连续性，并核对复用 cell 上活动行／附件／代码块等持久标签的字体随外观恢复。`scripts/check-macos-composer.py appearance-zoom` 核对快捷键路由、缩放的保存和重载、排版快照与设置一致，以及宽窄窗口的渲染。入口禁止激活，不创建可见窗口或注入全局输入。

系统通知使用通知专用的窗口路由：已打开的目标聚焦其原有Tab，否则在当前工作窗口新开Tab；保留此前Tab。原生通知回调才激活窗口，隐藏检查只验证模型路由。

新建工作区菜单为可原生选择的Codex166项目提供“整个项目（N个文件夹）”，其项目身份与完整根集合随每Tab创建目标保留；选择单目录或无工作区会清除整项目选择。选中项目后切换到不支持它的运行时会保留目标并明确阻止发送。

检查入口分别为 `--check-message-experience --experience-navigation-only`（通知、查找、hover时间及打开目录准入）、`--check-composer-controls`（快捷键、比例和选中提供商额度）及 `--check-composer-ownership --composer-check-content-target`（内容／目标规则）。均使用显式临时HOME、禁止激活，不注入系统输入。


运行时编辑器允许编辑已有实例的 Adapter Type。实例身份、名称、HOME与SSH执行环境保留；表单按类型暂存专属字段、ACP启动参数和新会话默认选择，切回恢复当前编辑，保存只提交选中类型的数据。新类型不查询旧类型的Agent信息或模型目录；类型变更后不沿用旧类型LastChosen。没有类型升级关系，普通配置保存不重写历史来源。窄验入口为 `--check-message-experience --experience-runtime-editor-only`，使用显式 `VELUNE_EXPERIENCE_CHECK_HOME` 合成目录，无前台窗口和输入注入。

### 历史消息编辑

`MessageEditingSession` 持有独立的 `ConversationTab`、原生输入模型、历史基线及执行选择，初始选择来自所编辑消息的已知配置，不借用普通草稿。默认随窗口弹出，本机偏好可选浮动窗口；两种承载使用同一个 `MessageEditorView` 和真实 composer。编辑器右上角可随时切换承载，同一个会话与输入模型持续存在；关闭旧宿主不触发取消，异步附件和提交继续完成。取消不修改普通输入，提交失败保留编辑状态。原地与新会话的行为归[提交与恢复 PRD](../../docs/prd/composer-actions.md#编辑用户消息)。

原文件、路径图片和内嵌图片经内容接口异步保留到编辑会话的私有目录；保留完成前不允许提交，失败条目可重试或移除。移除、关闭或历史失效后，迟到读取不重新添加附件。提交时捕获当前正文、附件和运行时／模型／推理／权限，核心重新检查原历史基线及写入权。已删除的运行时明确禁发；只有实际受理成功才结束编辑，不自动重发结果未知的请求。

### 输入、目标与命令的运行期职责

ComposerDrafts 管理 InputID、正文、附件与编辑对象；窗口负责 Tab／group 导航和内容与目标的配对。读取已有模型不绑定编辑器，命令可用性读取当前投影。原生编辑器的实际焦点和编辑动作决定绑定；输入、光标及明确目标变化驱动补全，attach 本身只记录 Store。

ConversationStore 拥有目标准备请求、事实观察、配置刷新及迟到结果拒收，普通会话通过共享 `prepare_composer_target` 获取保存端实际记录与有效下一轮。ComposerContext、View、菜单和补全消费该投影并转发操作。原生模型目录到达后仍使用共享 resolver，不将观测到的默认值保存成手选配置。未手选项持续继承，选择某一项只固定该项；正文恢复和编辑独立于目标准备失败。

目标读取结果只合并对应记录，不确认其它待同步修改或重置 CAS 基线。Tab 的观察共同归一组 cancellables，移出标签和关闭整组共用释放入口。显式旧数据迁移见[迁移说明](../../docs/development/migrations.md#composer-未手选默认)。

### 系统环境通知与原生列表

Foundation 的日期、时区、时钟和区域设置通知按发布线程交付，不能用 `@MainActor` 类上的 Objective-C selector 推断回调已经在主线程。消息列表在订阅入口显式切到 main，订阅归跨挂载保留的 transcript controller，弱引用随其寿命取消。日期环境只使日期相关布局与可见行配置失效，保留正文渲染、字体、展开状态和阅读锚点；隐藏 Tab 在下一次呈现时重排。外观变化另行使字体与正文渲染缓存失效。全局滚动条偏好进入 SwiftUI 状态前也显式调度到 main；AppKit 自身的视图几何与窗口生命周期回调继续同步处理，不为它们增加异步布局时序。
