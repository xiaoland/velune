# Velune Mac app

本 unit 使用 SwiftUI／AppKit 的原生窗口、会话列表、聊天投影和设置界面。品牌只出现在图标与少量内容细节中。

app 通过生成的 UniFFI 接口消费 application 的完整用例，不解析 Pi RPC，不自行启动网关，也不承担跨包失败补偿。应用配置根为 `VELUNE_HOME`，默认 `~/.velune`；提供商 API key 由 application 私有配置保存，OAuth 保留原来源刷新。各 Harness 拥有真实会话持久化。

“设置 → 远程接入”显式启用本机执行端，复用所有窗口持有的同一个 `VeluneApplication`，不另建核心或后台 Host。入口由 `Transport` 持有，关闭设置或会话窗口不会停止它；“停止接入”关闭连接但不取消已接纳的任务和审批，退出应用仍遵守运行中工作确认。设备身份与信任列表由 SDK 保存在 `VELUNE_HOME/remote/identity.json` 与 `trusted-devices.json`，只在首次创建身份时记录本机名称；重启保留配对，接入每次启动后由用户重新启用。

连接设施可选“公共开发设施”（显式启用 iroh 的开发 relay／发现服务，自动争取直连，没有 Velune 正式服务承诺）或“仅直接连接”（不使用公共设施，连接取决于邀请中的地址）。系统网络变化和应用回到前台会通知 iroh 重新检查路径。最小入口不提供自部署地址编辑；底层 SDK 已支持自定义 relay／pkarr。用户生成 5 分钟、成功配对一次即失效的邀请，再显式拷贝给本人另一台设备；邀请不进入日志或持久化界面状态，离开该页即从界面内存清除。已配对列表可撤销设备并切断既有连接，错误进入共享“问题”窗口。连接邀请赋予完整业务访问，公开设备 ID 只用于辨认。

构建与本地安装入口为 [build-macos.sh](../../scripts/build-macos.sh)。真实登录、提供商调用和体验由用户验收；静态检查与隔离合成验证归 [开发说明](../../docs/development.md)。

运行时设置展示 family、精确版本类型与配置实例，当前提供 Pi 1.0.2、Codex 0.159.3 和 DeepSeek Harness 0.2.0-rc.2。同类型可保存多个实例，工作目录属于具体会话。App 只消费通用消息与类型化权限／回答交互，不解析 ACP 或 app-server envelope；选择、回答和取消通过生成接口交给 adapter。运行时要求外部 Node 22.19+ 的绝对路径；Pi、Codex 与 DSH CLI 均由用户外部安装并配置。添加实例后即可浏览会话，新建表单选择实例／模型，目录可选；Mac首次发送才准备运行时并创建原生会话，继续历史时自动准备。恢复 Codex／DSH 缺少提供商身份的模型选择须明确指定，不宣称恢复上次 Velune 路由。编辑实例时可在“运行环境”中选择 HOME：继承当前用户、指定目录，或由 Velune 管理。Velune 管理时“运行时目录”隐去，由 core 在该 HOME 中推出；已保存实例显示 core 解析出的位置，可在 Finder 中显示（首次使用时创建）。“运行位置”可选本机或 SSH：SSH 填本机 OpenSSH 程序、主机（名或 ~/.ssh/config 别名，须预先完成非交互认证与主机信任）、可选端口，以及类型描述声明 `remoteResources` 时必填的远端辅助目录；远端实例的路径字段是执行机器上的绝对路径，不提供本机选择面板、`~` 展开或可执行文件自动发现，远端 managed HOME 需远端根目录。保存经 `upsert_runtime_with_execution`，保留表单不编辑的其他设置；设置列表在类型后标注“SSH 主机”。Store 按实例读取已保存的运行位置。类型描述声明 `launchOptions` 时（当前为通用 ACP），编辑器另有“启动参数”（逐个传给入口，不经 shell）与“环境变量”，经 `upsert_acp_runtime` 一并保存；声明 `agentInfo` 时，已保存实例可“读取 Agent 信息”：启动一次 Agent，展示名称、版本、会话能力与其报告的登录方式（登录由 Agent 自身完成）。

构建前只需安装 runtime-support，huihua parser 依赖及许可证随 bundle 打包；不分发 Agent runtime 或完整 Pi SDK。具体步骤见 [开发说明](../../docs/development.md#原生运行时与历史读取)。构建产物不等于已安装或用户验收，最终状态以任务记录为准。

会话内容消费 Rust 的类型权威，Mac 只派生展示行与展开、滚动状态。用户内容在右侧气泡，assistant 正文及工具左对齐；系统通知居中，工具输出不按 LLM Markdown 解析。Markdown 由固定 SwiftPM 依赖 swift-markdown 解析，许可证随应用分发；不恢复手写 fence 解析。虚拟列表使用稳定行身份，打开／发送到底，阅读历史时暂停流式跟随。当前实施与验收见 [展示任务](../../tasks/conversation-presentation/packet.md)。

Mac 最低支持macOS15，由根目录 [Package.swift](../../Package.swift) 定义独立 SwiftPM 产品，依赖固定 swift-markdown 0.9.0；[Package.resolved](../../Package.resolved) 锁传递依赖 swift-cmark。build-macos 先生成 UniFFI 模块，再以SwiftPM的Xcode后端构建本机架构release产品，应用与生成绑定目标各自启用warnings-as-errors，并打包`app/mac/Licenses`与解析锁文件。依赖保持各自声明的Swift语言模式；当前依赖没有资源bundle。Swift 包不依赖领域 Rust 包源码，只链接对应生成绑定与库。

会话上下文菜单按运行时能力提供重命名和永久删除确认。选中目标、待加载身份与已加载详情分别管理；加载时显示进度，暂停其它选择并隔离旧轮询，失败恢复原会话。操作交给生成绑定和运行时执行，不建立 Mac 标题覆盖存储。隔离验收见 [会话管理任务](../../tasks/session-management/packet.md)。

侧栏浏览全部启用运行时的会话；“显示”菜单提供运行时／项目分组与显式筛选，创建／更新时间排序和方向，以及切换“显示已归档的会话”。分组、排序、总数上限与各组页数由 core 计算，侧栏只把返回的行放进 core 给出的组（`conversationGroups`，按最近活动排序，置顶组在前）。组可折叠，折叠状态随浏览偏好保存；组内“加载更多”请求下一页，没有“显示全部”。项目组标题为项目名称或主文件夹名（同名时附上级文件夹），悬停显示主文件夹路径，双击或右键“编辑项目…”打开项目表单：名称（留空显示主文件夹名）、文件夹列表（＋添加、−移除、设为主文件夹，右键同样可用；主文件夹不可移除），以及只读列出的、按所属仓库自动归入的 Git worktree。会话行只有一行：会话标题与状态（行首未读圆点或上一轮失败的感叹号，行尾运行中指示），不显示日期、运行时与项目；悬停显示完整标题。未读会话行首有圆点并加粗，当前窗口正在显示的会话自动标为已读。行菜单提供置顶、标为已读／未读、移到项目（只改列表归属）、归档／取消归档（Codex 用原生归档，见 core）、拷贝会话 ID 与拷贝 `velune://conversation?runtime=…&id=…` 链接；应用注册 `velune` scheme，打开链接时在现有窗口打开会话。搜索在输入停顿后由 core 在最近一次列表中匹配标题、项目（含名称）与运行时名称。加载只限制普通行选择，原生菜单及管理提交保持可用，并显示等待或执行状态。范围见 [统一浏览任务](../../tasks/conversation-browser/packet.md) 与 [会话列表管理任务](../../tasks/conversation-list-management/packet.md)。分组、运行时／项目筛选、时间排序与折叠状态随应用配置保存，重启恢复；搜索文字、额外加载页与已归档视图仅属于本次运行。

设置的“模型路由”页（`ModelRoutes.swift`）左侧列出路由（名称、策略与成员数，＋／−、双击或右键编辑），右侧是所选路由的现状：策略与会话保持的含义，按顺序列出各成员的提供商认证方式、账户尾号与登录状态、适用于该模型 ID 的额度窗口（已用比例、提供商上限、重置时间、观测是否过期），以及登录前或设有上限却缺少最新额度时路由不会使用它的提示；未登录成员行内可直接登录，双击或右键成员编辑其提供商。成员含订阅提供商时显示核心给出的订阅披露。编辑 sheet 设置名称、策略（智能／顺序／轮询／权重）、会话保持和成员：拖动排序、右键或 − 移除；＋ 菜单按提供商分组，其他协议或已加入的模型不可选；权重策略下每个成员有权重与所占比例。新路由默认智能策略并开启会话保持。路由经 `save_model_route`／`delete_model_route` 保存。

额度只读 core 观测（`provider_quota`／`refresh_provider_quota`，`ProviderQuota.swift`）：视图显示期间在请求队列上读取，不占用 `isLoading`；读取中或尚无结果时每 2 秒、否则每 30 秒再读，由 core 决定是否采样；未登录的提供商不读取。添加提供商先在同一 sheet 中选择 core `provider_templates()` 给出的模板（`ProviderTemplates.swift`，按订阅／API 分组，另有“从 Agent 运行时导入”），选中订阅时显示其披露，“继续”后以模板组合打开编辑器。订阅提供商的协议与地址以只读值呈现，不提供换用 API key 或其他订阅的入口；新订阅提供商“保存并登录…”保存后留在编辑器并开始登录（Codex 登录 URL 自动在浏览器打开，Claude Code CLI 自行打开浏览器）。Claude Code 组合以本机 `claude` 可执行文件替代服务地址：自动填入发现的第一个路径，可从“已发现”菜单或“选择…”更换，须为绝对路径。已登录且认证带 `logout` 动作时显示“退出登录…”，确认后调用 `authentication_logout`。订阅或报告额度的提供商有“额度与使用上限”页，按窗口选择已用比例上限，对所有路由和直接调用共同生效。

所有可编辑列表采用原生双击主操作：提供商、运行时、模型模板、模型路由打开编辑，提供商内模型聚焦对应详情，会话打开原生标题重命名。单击选择与 ⌘／Shift 多选保持有效；只读目录或导入候选不伪造编辑操作。

“问题”是共享 AppStore 的原生窗口，可从主窗口有问题时的状态入口、编辑／导入 sheet 标题行或菜单“问题…”打开（⌘⇧M）。操作失败保留结构化诊断，不在 composer／设置底部或会话列表重复展示；活动读取问题按来源合并，恢复时移除。记录在当前进程内最多保留100项，不作为第二套日志或持久化数据。具体验收和安装状态见 [问题展示任务](../../tasks/problems-surface/packet.md)。

消息列表消费 Rust 的 `TranscriptTurn` 引用，保留用户问题与当前最后结果，其余工作消息可展开查看。详情右侧工具栏提供会话大纲，设置“大纲按钮”决定其行为：“弹出面板”在按钮处弹出原生 popover 列出用户消息；“就地折叠”使按钮成为开关，消息列表以行高插值动画缩起为只剩用户消息，点击其中一条或再次点击按钮即恢复完整列表，锚点消息在动画中保持屏幕位置，减少动态效果时直接切换。折叠是临时状态，切换会话或发送后恢复；工作过程等展开状态在折叠期间保留。回到底部的向下箭头仍在消息列表内，右边距按当前滚动条样式让出滚动条宽度。展开状态按消息／turn 身份保存，权威历史替换时清理失效引用，不能将当前位置保存为固定数组下标。

问题窗口完整展示传入的本地错误原因、阶段与诊断编号；开发工具的真实数据读取限制不构成应用对用户诊断的过滤规则。窗口记录仍是当前进程内的有界问题集合，不是原始日志浏览器。

主窗口的下一轮运行时／模型选择位于输入区，与历史来源独立；侧栏工具栏保留浏览筛选，新建会话（⌘N，直接进入空会话与空输入区，不弹 sheet）归侧栏工具栏，大纲归详情右侧工具栏，分析不占主窗口工具栏。分析、问题与资源库窗口的工具栏以 `toolbar(id:)` 与逐项 `ToolbarItem(id:)` 声明为可自定义，因此系统工具栏菜单提供图标／文字显示模式与“自定工具栏…”，排列由系统按工具栏标识保存。会话窗口的工具栏从 macOS 26 起同样可自定义，侧栏与详情项目共用 `ConversationToolbar.id`，右侧按钮由 `ToolbarSpacer(.flexible)` 推到末端；macOS 15 上为不可自定义的普通工具栏，因为可自定义工具栏中充当弹性空白的 `Spacer()` 项会在每次窗口布局时被 SwiftUI 删除重插并写入 defaults，滚动会话列表每步由约 2ms 变为约 50ms（见[性能任务](../../tasks/mac-performance/packet.md)）。按条件出现的项目（子 Agent、保持在最前面、问题）仍只在适用时出现。从“显示 → 分析…”打开独立窗口，其概览、提供商与模型、请求页分别承载摘要、来源比较与明细。表格双击推进只读请求详情，不触发编辑。查询的最后成功范围与数据一起保存，刷新和失败不错误重标旧数据。分析验证归[体验整顿任务](../../tasks/mac-navigation-refinement/packet.md)，最新输入区与工具栏调整归[输入区任务](../../tasks/composer-pi-send/packet.md)。

消息列表消费 Rust 产出的有序展示项与稳定身份，原子更新行、工作范围与大纲。发送后，消息先作为列表末尾的本地行出现，下方标“发送中”，composer 随即清空；运行时接受后去掉标记，核心快照出现该轮的用户消息或这一轮结束时由其取代。发送失败时移除该行，正文与附件放回 composer（composer 已有新内容时不覆盖）。每个 turn 的工作过程行右端有一个 plain 信息图标，指针在该行上时其左侧展开运行时与模型，点按图标在 popover 中列出运行时、模型、推理强度与权限，以及该轮的 token 用量（输入、缓存读取／写入、输出与推理；推理未单独记录时注明）；没有工作过程的 turn 在用户消息后显示同样的不可展开行（有耗时则标“用时”）。运行时与权限名称由 App 按当前配置解析，解析不到时显示记录原文。assistant 正文经 swift-markdown 解析并映射为 TextKit 1 属性文本；围栏代码是独立布局元素，带圆角背景、语言标签与原生复制按钮。渲染结果按消息内容修订缓存，未变化轮询、离屏重入和 cell 复用不重新解析。工作过程、工具和推理使用行内 AppKit 原生 disclosure 按钮，开合只改变所在行。运行中的 turn（含其他客户端发起的）默认展开工作过程（用户可收起），结束后回到收起；工作过程内的思考块不自动展开，以核心给出的思考摘要为标题，摘要下还没有正文时只显示摘要文字、不带展开按钮，没有摘要（如只有加密签名）的思考块不显示；列表底部状态行为系统进度指示加当前工作：最新思考摘要、运行中的工具标题或“正在回复”，文字上有一道缓慢移过的高光（shimmer），系统“减少动态效果”时不动。用户消息的附件在气泡上方右对齐显示为标签：缩略图（ImageIO 后台生成并缓存，内容图片在行可见时按需读取）与文件名，图片在前、文件在后，按宽度换行；点按用系统默认应用打开，内容图片先写入临时目录。消息区域采用系统windowBackgroundColor不透明背景。Markdown链接交给系统注册的应用，相对文件以当前会话目录解析，失败由原生alert提供原文与复制。Agent 间协作没有专门的控件或面板：参与方都是普通会话，出现在会话列表并照常处理审批；Velune 协作工具和原生 sub-agent 的调用下方显示“打开会话”链接，另一个 Agent 发来的消息在用户侧气泡顶部以链接标出来源会话（“来自 运行时 会话「标题」”），二者都在当前窗口打开对应会话（未在列表时先重读列表）。原生 sub-agent 的会话不在侧栏列出；打开后底部以说明与“打开父会话”按钮代替输入区，因为它由启动它的会话继续。活动轮询发现未列出的运行中会话（例如 Agent 刚新建的）时重读会话列表。正文可在原生 NSTextView 内选择与复制；文本菜单首项“拷贝整条消息”复制该消息正文与通知的原文（不含推理和工具输出）。列表末尾保留固定留白，最后一条消息不贴住输入区。

消息容器是自有的翻转文档视图（NSScrollView 内），按需物化可见行与 overdraw 区域并复用纯 AppKit cell，不在行内承载 SwiftUI。未使用 NSTableView：它对未测行使用估计高度，并在任意 API 调用与布局中懒测量、自行重锚定，使高度在补偿之外落地。行几何是控制器高度列表的前缀和；每行布局由纯函数根据消息内容修订、局部展开状态与实际宽度计算，TextKit 1 测量与显示使用同一属性文本和容器配置，帧取整数，避免 layer 对齐改变已测宽度。可见带（视口上下各 0.75 屏）在显示前同步测量；其余行在后台队列按距阅读位置由近及远测量并分批提交。高度只在一次同步提交中变化，同时恢复视口顶部行及其行内偏移，阅读位置不随离屏行变化移动；`prepareContent(in:)` 为 responsive scrolling 预先物化。宽度连续变化时（拖动分隔条或窗口边缘、侧栏滑动）文字最多每 0.1 秒按新宽度重排一次，其间各行保持原布局，只按当前宽度重新居中（栏宽不变时与重排结果一致，文字随动画平移而不跳动）；宽度停下 0.15 秒后补一次重排并在后台测量其余行。输入区的单行／两行选择只在结果改变时更新视图状态，调整宽度不会每一步重新求值输入区。用户滚动离开底部即暂停跟随，滚回底部、点击回到底部或发送消息恢复。实施与验收状态见[会话阅读任务](../../tasks/mac-conversation-usability/packet.md)。

共享应用状态仅在值变化时发布到工作区；无匹配的轮询问题清理及相同会话快照不触发重复界面应用。正常空闲轮询消费内存快照，点击／滚动不直接读取历史文件。轮询携带上次交付游标，core 未变化时不传快照，变化时只传变化消息及完整顺序；映射在后台请求队列完成，主线程按消息身份合并。超过 2KB 的推理与工具输出只随快照携带大小，展开对应 disclosure 时按消息读取并在原位替换占位；同一交付 stamp 的已读内容在后续合并中保留。

应用级 store 轮询 `conversation_activity`：侧栏对正在运行的会话显示小型进度指示，不区分 turn 由 Velune 还是其他客户端发起（是否在 Velune 之外不重要，重要的是正在运行），出现列表中没有的外部会话时重新读取列表；打开的会话随原生文件变化更新，外部发起的运行与自身运行使用同一底部状态行，仍可发送（Velune 不能停止其他进程的 turn）。Velune 的 turn 结束（完成或失败，用户停止的不提示）与运行时请求等待确认时发送系统通知，正在前台查看的会话不提示；点击通知在最近使用的窗口打开该会话；Dock 标记等待确认的会话及后台期间结束的会话数，回到前台清除后者。通知是否显示由系统设置决定，应用内不另设开关。

变更审阅已实现但尚未纳入产品（2026-10-11 用户决定），入口由 `VeluneRootView.changeReviewEnabled` 关闭；启用后，详情工具栏的“变更”（⌥⌘D）打开原生 inspector，显示当前会话工作目录所在 git 仓库的未提交变更：仓库名与分支、变更文件（状态字母、目录、相对 HEAD 的增删行数），选中文件在下方显示按行着色的差异，可选择复制。双击文件以默认应用打开，菜单提供在访达中显示与拷贝路径。打开、切换会话、本会话 turn 结束时及手动刷新读取；只读，不提供暂存或提交。
