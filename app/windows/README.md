# Windows 完整端

Windows 的完整端：在本机运行 Agent、Harness 与网关，也能控制其他已配对的完整端。界面用 C#（.NET 10）与 WinUI 3（Windows App SDK 2.5，非打包、自包含），控件与主题都是 WinUI 自己的 Fluent 控件，随系统明暗、强调色、对比度与文字缩放；Windows 11 上窗口用 Mica 背景，Windows 10 上为纯色。C# 经 `uniffi-bindgen-cs` 生成的绑定以 P/Invoke 调用同目录的 `velune_bindings.dll`，与核心同进程，不启动常驻 Host 进程（见 [bindings](../../packages/bindings/README.md)）。

2026-10-21 起取代 MyGO 版（[S45](../../docs/sources.md#s45)）；进度与验证记录见 [任务](../../tasks/windows-winui/packet.md)。

## 界面

界面结构以 Mac 为基准（见 [界面与交互](../../DESIGN.md)），控件用 WinUI 的现成组件。

- **工作区窗口**（设计见 [Unit TDD](TDD.md)）：标题栏用 WinUI 的 TitleBar，显示 Velune 标志、设备切换（“本机”与已配对设备，另有“添加设备…”）与“新会话”（Ctrl+N），右侧是“布局”菜单、“更多”菜单（资源库…、分析…、问题…，菜单项注明在设置中设定的快捷键）与“设置”（Ctrl+,），左侧按钮收起或展开左侧区域。设备按窗口区分，切换后只换这个窗口的目标，本机与远端都通过同一个 `VeluneApplication` 访问。
  - 编辑区是分屏树，每个面板是一组 WinUI `TabView` 标签（＋新建，悬停显示关闭，可沿栏拖动排序，运行或等待处理时带图标）。标签的右键菜单：重命名、关闭、关闭其他、移到右侧／下方拆分（面板只有一个标签时向右／向下拆分出新会话）与“布局”。分隔条拖动调整，双击均分。一个会话在本窗口只有一个标签，再次打开即切换过去；标签记住先后打开的会话，标题栏返回与 Alt+←／→ 后退、前进。
  - 拖放：标签与列表中的会话可拖到任一同设备窗口的标签栏（插入到该处）、面板中间（加入该面板）或面板四分之一以内的边缘（在该侧拆出新面板），拖动提示写明落点；拖到所有窗口之外即成为会话窗口（大小取自来源面板，左上角在松开处），会话窗口里唯一的标签拖出时改为移动窗口。拖动只携带应用私有格式，应用之外不接受。标签移动时视图随之转移，草稿与阅读位置不变；本窗口已显示的会话被拖来时移动那个标签。分组标题可沿列表拖到另一组的位置，即转为手动组排序。
  - 会话窗口只显示编辑区（停靠区按最近的工具布局收起，可用“只显示编辑区”或各区开关恢复），关闭最后一个标签即关闭窗口，它对工具布局的改动不作为新窗口的起点。“新建窗口”（Ctrl+Shift+N）打开完整的工作区，列表行与标签菜单另有“在新窗口中打开”“移到新窗口”。关联会话的打开方式为新窗口时在会话窗口中打开。
  - 左、右、底三个停靠区放工具窗口：会话列表、会话大纲、输入区、关联 Agent。各工具可停靠在任一区、同区并排（多于一个时有标题条，含位置菜单与隐藏），大纲与关联 Agent 另可作为每个面板标签栏上的按钮（默认；关联 Agent 的按钮只在该标签的会话有关联会话时出现，点按弹出面板），输入区另可“在每个面板中”（默认）。区的边缘可拖动，双击恢复默认宽高；底区只放输入区时高度跟随输入区。显示空的区时带来它惯常的工具。“只显示编辑区”收起所有展开的区并可恢复。工具也可浮动或成为独立窗口：浮动是被所属窗口拥有的工具窗口（亚克力背景，始终在它之上、随它最小化、不在任务栏单列），独立窗口是普通窗口（Mica，有任务栏按钮，可放到别的屏幕）；两者标题栏右端有位置菜单，关闭即隐藏该工具（输入区回到各面板），所属窗口关闭时一并关闭。拖动浮动窗口松开时，指针在所属窗口左、右、底缘 80 px 内即停靠到该区；否则其边缘在所属窗口内外缘或另一贴边的浮动窗口边缘 14 px 内即贴边，贴边后随所属窗口移动、按最近的边保持距离。布局在标签与工具的菜单、标题栏的“布局”菜单与快捷键中调整，见 TDD 的快捷键表。
  - 工具布局（去掉“只显示编辑区”）作为新窗口的起点保存；各窗口的位置、大小、分屏、标签与会话在退出时保存，下次启动重新打开。都存于 `VELUNE_HOME/windows-layout.json`。会话列表按设备只读取一次，所有指向该设备的窗口共用。
  - 会话列表：按核心给出的分组，组标题是列表中的行（点按展开收起，状态存入该设备的列表偏好），每个会话一项，未读时带圆点，失败、等待处理或运行中时带图标；不列子 Agent。支持多选（Ctrl／Shift），只选中一个会话时在聚焦的标签中打开，中键在新标签页中打开；双击或 F2 就地编辑标题，Enter 保存，Esc 或焦点离开取消。
  - 列表上方是搜索框与“显示”菜单。搜索在停止输入后由核心 `search_conversations` 匹配，结果仍按分组显示，列表刷新时重新搜索（Ctrl+F 聚焦）。“显示”菜单：分组（不分组／按 Agent 运行时／按项目）、组排序（最近活动／手动，转为手动时固定当前顺序）、会话排序（更新或创建时间，最新或最早在前）、按 Agent 运行时与项目筛选、显示已归档的会话、重新读取（列表与已打开的会话），以及列表自己的位置。偏好写入该设备，写入期间读到的列表不显示，以免回退。
  - 会话的右键菜单作用于点按的会话，它在多选之中时作用于全部所选：在新标签页、右侧或下方拆分中打开，重命名，置顶，标为已读／未读，移到项目（另可回到工作目录所在的项目），归档／取消归档，拷贝会话 ID 与 `velune://` 链接，运行时允许时删除（确认后从运行时删除并关闭显示它的标签）。分组的右键菜单：项目分组可“编辑项目…”（名称、文件夹的增删与主文件夹，本机可浏览选取，远端填写路径；按仓库归入的 worktree 只读显示）；分组时可上移、下移、移到最前或最后，即转为手动组排序，置顶组始终在最前。
- **新会话**：直接打开一个空会话，第一条消息发送时才创建；运行时与工作目录在输入区的操作行选择。
- **会话**：标签显示会话标题，大纲按钮在面板的标签栏上（或大纲停靠为工具窗口，列出聚焦标签的用户消息）。转录按核心给出的条目排列（`transcript_items`、`transcript_turns`、`transcript_outline`），平台不自行分轮：用户消息在右，附件在气泡上方；LLM 正文限宽在左；系统与 Harness 状态通栏。每轮的工作过程（思考、工具与中间消息）收进一个 Expander，标题为“用时 …”，运行中默认展开、结束后收起，用户的选择按运行状态记住；结束消息中工作之后的部分留在外面作为回复。轮次右上角的信息按钮弹出本轮配置（运行时、模型、推理强度、权限）、token 用量、结束时上下文与用时；没有工作过程的轮次在工作过程的位置单独给出这一行。思考只显示核心给出的摘要，没有摘要的不显示。工具可打开它启动的子 Agent 会话，子 Agent 会话底部给出“打开父会话”而不是输入区；标题栏的返回按钮回到之前的会话。关联 Agent 面板分组列出聚焦标签会话的父会话、原生子 Agent（运行中、等待处理、失败或已结束）与经 Velune 协作的会话（运行时、谁联系了谁、状态）；双击按“通用”中的打开方式打开，右键菜单可选其他方式，已有标签页显示的会话改为切换过去。父会话的列表行在其子 Agent 仍运行或有待处理审批时一并显示运行中或等待。会话窗口的左区放关联 Agent 而不是会话列表。正文按 Markdown 渲染（Markdig 解析，WinUI 文本元素呈现，代码块等宽、可横向滚动），回复中途以流式呈现；链接中 http(s) 与邮件在浏览器打开，文件路径按会话工作目录解析后以默认应用打开，远端设备上的文件只说明所在设备。图片附件显示缩略图，点按以默认应用打开。发送后立即显示“正在发送”，运行中末尾一行显示当前在做的事（最近的工具、思考摘要或“正在回复”）。转录停在末尾时跟随新内容，向上滚动后不再跟随并出现“回到底部”按钮。大纲按“通用”中的设置弹出用户消息列表（打开时选中最末一条，运行中前往最末一条即回到末尾），或就地折叠为只剩用户消息、保持所在位置。审批与提问显示在输入框上方。Ctrl+Enter 发送，运行中可停止。
- **输入区操作行**：与 Mac 相同的下拉。
  - 第一个标题为“运行时 · 模型 · 推理强度”，含三个子菜单：运行时（附“Agent 运行时设置…”）；模型（首项为“沿用当前（…）”或“运行时默认”，其后是运行时自己的模型与“Velune 提供商”一节，附“重新读取模型”和“AI 提供商设置…”）；推理强度（仅当所选模型声明级别时出现）。
  - 运行时类型声明权限模式、或 ACP Agent 为会话提供选项时有第二个下拉：权限模式未选时沿用会话当前的模式；ACP 选项是单选子菜单（按 Agent 的分组）或开关，选中即经核心交给 Agent。
  - 尚未发送的会话还有工作目录菜单：本机可选择目录，远端设备输入其上的绝对路径，另列最近使用的五个目录。
  - 最左是“附加文件”：可多选，也可把文件拖到输入区或粘贴图片（剪贴板位图转为 PNG）。附件先上传到运行会话的设备（`upload_attachment`），显示为输入框上方的标签，可逐个移除；上传中不能发送。发送失败时附件回到输入区。
  - 操作行右侧、发送之前是状态栏：显示“通用”中选定的常驻项（上下文用量、本会话 token、工作目录与分支、账户额度、费用估算），只取运行时记录中已有的项，不推算；悬停说明，点按列出全部可用项。分支读自核心的 `working_changes`，每结束一轮读一次。
  - 草稿经核心按会话保存（输入停顿 0.6 秒后写入，关闭会话时写入未保存的部分），打开会话时恢复；尚未首发的会话不保存草稿。
  - 运行中发送按钮变为“加入队列”：消息进入核心的发送队列，显示在输入框上方，可就地编辑、上移下移与删除，运行时支持时可“插入本轮”；Ctrl+Shift+Enter 直接插入本轮，Esc 停止。队列因本轮停止、失败或首条未被接受而暂停时显示原因与“继续发送”；等待子 Agent 结束时显示原因，可“停止子 Agent”。上一轮停止或失败后出现“继续”，作为一条用户消息发出。
  - 用户消息的右键菜单有“拷贝”与“编辑…”（核心标为可编辑时）：最后一条在原处继续；更早的一条可在新会话中继续（随后打开新会话），或原地继续并舍弃之后的内容；只能新建会话时只提供前者。编辑只发出文字。
  - 下一轮可以换到另一个运行时，从当前会话的历史继续。选择按“会话 × 运行时”经核心保存；某运行时在此会话中还没有轮次与选择时，从该运行时上次的选择开始。
- **问题与通知**（[PRD](../../docs/prd/diagnostics.md)）：操作失败不在输入区、会话列表或设置页底部堆放，而记入应用级的“问题”：来源（操作与对象）、设备、时间、核心给出的原因与类别、代码、阶段、诊断编号，在独立的“问题”窗口中逐条查看、复制、移除或全部清除，只保存在本次运行的内存里，最多 100 条。反复失败的读取（会话列表、打开的会话、提供商额度）每个来源只记一条，下一次读取成功即移除；成功的操作不清除别的问题。有问题时工作区与设置窗口的标题栏出现带数量的“问题”按钮，Ctrl+Shift+M 打开窗口；新问题不弹窗抢焦点。字段校验、粘贴的邀请码有误、登录进度与导入结果仍在原处说明；读取不到的会话在会话中说明“详见问题”。
- **资源库**（[PRD](../../docs/prd/resource-library.md)）：从“更多 → 资源库…”或输入区运行时子菜单的“资源库…”（本机会话）打开独立、可缩放的窗口，只管理本机核心的资源库与用户范围。左侧 NavigationView 是四个类别（指令、技能、MCP 服务器、子 Agent）；中间是搜索框与该类别的资源（摘要写明启用于几个运行时、待同步与原生变化，未保存的带 ●），其下“运行时中的其他内容”列出各运行时不在资源库中的原生条目，底部是＋、−、复制与“从运行时导入…”；右侧是所选资源的编辑器与“启用于”。
  - 编辑器按类别：指令为整份正文；技能编辑 SKILL.md（其他文件随资源保留，此轮不编辑）；MCP 服务器选择本地命令或 HTTP，填命令、逐行参数、工作目录、环境变量或 URL、请求头与超时，变量与请求头的值用 PasswordBox 默认遮盖、可按住查看，“以 JSON 编辑”切到声明的原始 JSON（可粘贴单个服务器或含一个服务器的 `mcpServers`，未识别的字段列出不带入）；子 Agent 有描述、指令、模型（沿用父会话、原生模型 ID 或 Velune 模型）、推理强度、工具与资源库中的技能。名称规则与内容校验由核心在保存时检查，错误写在表单下方。
  - 修改即进入草稿：草稿在应用运行期间保留，关闭窗口不丢失；退出（关闭最后一个工作区窗口，含 Ctrl+Shift+W 与关闭会话窗口的最后一个标签）时若有未保存的修改先询问，可放弃并退出或打开资源库。“保存”经 `save_resource_template` 写入资源库并同步到已启用的运行时，窗口顶部 InfoBar 列出各运行时的结果与说明（无法表达的字段、写入失败另记入问题），并说明运行时何时加载；“还原”丢弃草稿。
  - “启用于”逐个列出运行时：勾选即 `apply_resource_template` 写入已保存的版本，遇到同名原生条目或另一份指令时先确认覆盖；取消勾选时选择删除原生内容或保留原生内容（`resolve_resource_binding` 的 Remove／Unmanage）；“全部启用”。各行说明已同步、待同步（运行时空闲后核心自动补写，可“立即同步”）、不支持的原因；原生被改或被删时“处理”菜单提供比较（`resource_drift`，逐文件并排显示原生与覆盖后的内容）、用资源库覆盖、用原生内容更新资源库（先列出无法带入的字段）与不再同步。
  - 原生条目只读显示为资源库的形式及无法带入的字段，唯一操作是“加入资源库…”（确认后 `adopt_runtime_resource`，继续启用于来源运行时）；“从运行时导入…”选一个运行时，多选其四类原生条目后一次加入，先列出无法带入的字段，结果说明未导入的项。设置中新增运行时（手动或快速导入）后，若资源库已有资源，运行时页提示可启用并可打开资源库。窗口回到前台时重新读取状态。
- **分析**（[PRD](../../docs/prd/analytics.md)）：从“更多 → 分析…”打开独立、可缩放的窗口（`analytics_query`，只读本机核心），概览、提供商与模型、请求三页由顶部 SelectorBar 切换，右侧是时间范围（今天、最近 7 天、最近 30 天，按本地日界分桶）与刷新。其下一行是报告所答的范围、时区与筛选及更新时间；读取新范围时、读取失败（保留上次结果，记入问题）或部分用量未能保存时以 InfoBar 说明，并可打开问题。概览：已报告的输入／输出 Token 与有效输出速率，各带“已报告／请求数”覆盖；请求数与各终态；多天范围有每日趋势（Token 用量的输入、输出柱，或有效输出速率的点，未报告的日子留空不补零，悬停读出当日数值）；“指标与数据来源说明”展开总量与速率的定义、只统计 Velune LLM 网关新请求的上游报告、没有费用记录、— 表示未知。提供商与模型：按提供商或模型列出请求、输入、输出与速率（悬停看覆盖），双击、Enter 或“查看请求…”把请求页筛选到该来源。请求：最近的请求（时间、提供商／模型 ID、结果、输出 Token），每次 100 条，“加载更多”至多 500 条；双击、Enter 或“显示详情…”打开只读详情（结果、协议、各类 Token、耗时与首输出延迟，推理与缓存用量、请求信息与指标说明可展开）。刷新就地重建：同一筛选下保留各页的选中与滚动位置。
  - Velune 的轮次结束（完成或失败，用户停止的不算）与会话出现新的待确认请求时，以 Windows 通知提示（App SDK 的 `AppNotificationManager`，未打包应用以“Velune”与应用图标注册），前台正在查看该会话时不提示；每个会话只保留最新一条，点按通知在最近使用的窗口中打开该会话（必要时切换设备，已有标签页时切换过去），通知启动 Velune 时同样打开。本机的会话始终提示，配对设备的会话在有窗口显示该设备时提示。通知是否显示由 Windows 设置决定，应用内不另设开关。Velune 在后台时有更多会话等待或结束，任务栏按钮闪烁直到回到前台；Windows 只为打包应用提供带数字的角标。
- **控制请求**：有设备请求控制本机时，主窗口弹出对话框，显示请求方名称和分组核对码。焦点落在核对码上，没有默认按钮，Esc 也不关闭，必须点击“允许”或“拒绝”。
- **设置**：只有一个设置窗口，再次打开时回到已开的窗口。左侧导航依次为通用、AI提供商、模型路由、Agent 运行时、设备；按 PRD，Mac 的“会话”与“快捷键”并入“通用”。列表页单击选择，双击、Enter 或“编辑…”编辑，右键菜单提供同样的操作，列表下方用＋／−增删，删除前确认（默认按钮为“取消”）。必填项留空时在字段下方提示；保存等操作失败时编辑保持打开，失败记入“问题”。对话框盖住了标题栏的入口，所以对话框内的保存、登录与导入失败另在对话框中说明。
  - **通用**：设置卡片，改动立即保存：用量显示（已用／剩余）、会话列表每次加载与总数上限、大纲按钮（弹出面板／就地折叠）、状态栏常驻项、关联会话的打开方式（当前标签页、新标签页、浮层、新窗口；浮层是带输入区的对话框，可转到标签页或新窗口），以及快捷键：按命令列出，点按后按下新组合即录制，Backspace 移除，Esc 取消；没有 Ctrl 或 Alt 的组合（F1–F12 除外）、已被其他命令或输入框、文字编辑与 Windows 占用的组合被拒绝并在该行说明，可逐项或全部恢复默认。只有改动存于 `VELUNE_HOME/windows-shortcuts.json`，所有窗口随即采用。
  - **AI提供商**：顶部在“提供商”与“模型模板”之间切换。提供商列表显示模型数、接口地址（Claude Code 为“Claude Code CLI”）与未登录状态。＋先选择核心 `provider_templates()` 给出的模板，按订阅、API 分组，另有“从 Agent 运行时导入…”；选中订阅时显示其披露。编辑不用对话框，而在页内打开，顶部的路径导航返回列表，有未保存的改动时先确认。编辑页按 Windows 设置的卡片分节：
    - **连接**：名称；订阅的协议与地址只读；Claude Code 以本机 `claude` 程序代替地址，自动填入 PATH 上发现的第一个，可从“已发现”或“选择…”更换。
    - **认证**：API key 可“显示”后查看和修改，留空保持不变。订阅显示账户与登录状态，操作按钮来自核心（登录、退出登录、检查登录状态）；新订阅提供商用“保存并登录…”。登录对话框按核心事件打开浏览器、显示验证码或回答提问，关闭即取消。Claude Code 的“账户来源”可选在 Velune 中登录新账户、本机 Claude Code 登录，或某个 Claude Code 运行时的登录；沿用的登录只检查状态，不登录也不退出。ARK Coding Plan 另有“额度查询认证”一节：AK/SK、本次关联确认与清除，与模型 key 一起原子保存。
    - **模型**：每个模型一个 Expander，收起时标题行仍显示模型 ID、上下文、输出与声明的推理强度；展开后编辑 model ID、昵称、上下文窗口、最大输出与推理强度（留空表示不声明）。“添加新模型”与“从模板中选取…”分开；后者是多选对话框，可搜索模型模板，并可显式读取公共模型目录（条目注明来源，只作参数起点）。模型的“存为模板…”打开预填的模板编辑。
    - **额度与使用上限**：订阅或报告额度的提供商在登录后列出核心观测的额度窗口（已用或剩余比例、重置时间、是否过期），每个窗口可设已用上限，用量显示为剩余时写作“至少保留”。编辑页显示期间读取核心观测：读取中或尚无结果时 2 秒、否则 30 秒再读，由核心决定是否采样。
    - **从 Agent 运行时导入**：来源是核心 `provider_import_types` 中类型的已配置运行时实例；读取后按提供商列出协议、地址、凭据状态与不可导入的原因，模型在 Expander 中逐个勾选，读取不默认选中；所选包含已导入的提供商时可选择替换。
    - **模型模板**：列表可增删与编辑（名称、建议的 model ID、昵称与参数）。模板只用于填写，填入的模型是独立副本。
  - **模型路由**：列出路由（名称、策略、成员数与会话保持），＋／−、双击或右键编辑；编辑在页内打开。名称、策略（智能、顺序、轮询、权重，各附含义）与会话保持之下按优先顺序列出成员：提供商与模型、认证与账户、适用于该 model ID 的额度窗口（已用或剩余、上限、重置时间、是否过期），以及路由此时不会使用它的原因（未登录、设有上限而缺少最新额度、已达上限、ARK 查询认证未确认）。未登录且核心给出登录动作的成员可就地登录，双击或右键“编辑提供商…”转到它的提供商。成员用上移、下移与移除调整；“添加成员”按提供商分组，其他协议或已加入的模型不可选；权重策略下每个成员有权重及所占比例。成员含订阅提供商时显示其披露。新路由默认智能策略并开启会话保持。路由与提供商模型一起出现在输入区的模型菜单中（核心的模型目录）。
  - **Agent 运行时**：列出本机的运行时实例（类型、是否停用）。＋按类型手动添加（路径字段可浏览），“快速导入…”在 PATH、npm／pnpm 与厂商安装位置中发现 Pi、Codex、Claude Code，只读取公开版本；编辑可改名称、启用与类型的配置项，其他设置保持不变；其下依次是可展开的几节（标题行带当前摘要）：“运行环境”选择 HOME（继承当前用户、指定目录或由 Velune 管理；由 Velune 管理时隐去“运行时目录”，由核心在该 HOME 中推出，已保存的实例显示核心解析的位置，可在资源管理器中显示，首次运行时创建）；ACP 类型的“启动参数”逐行填写参数与“名称=值”环境变量（不经 shell）；已保存的 ACP 实例可在“Agent 信息”中读取 Agent 的名称、版本、能力与登录方式；“新会话”选择会话尚未在此运行时上运行或选择时输入区从哪里开始：上次的选择、运行时默认，或指定的模型（读取该运行时的模型目录）、推理强度与权限。ACP 类型可手动添加。经 SSH 运行的实例在 Mac 上设置，Windows 上保持其运行位置不变。
  - **设备**：与 Mac 相同的两组，每项是一张设置卡片。“这台电脑”：允许其他设备控制的开关、设备名称、“添加控制设备…”（五分钟内有效、只能使用一次的邀请，以二维码与“复制邀请”给出，对方使用后或过期即收回），以及可以控制这台电脑的设备（撤销）。“控制其他设备”：已配对设备及其连接状态或核对码，“打开”在主窗口切换到该设备，配对中的可“取消”，右键菜单“移除此设备”；下方粘贴另一台设备的邀请并连接。

## 品牌

`assets/brand` 的标志包随构建复制到 `Assets\Brand`：标题栏用 small 光学母版，欢迎页用 medium，浅色主题用 graphite、深色用 dark 配色。exe 与窗口图标由 `scripts/render-windows-icon.ps1` 在构建时从同一标志包绘制：16–24 px 用 small、32–64 px 用 medium、256 px 用 large，均为 theme 配色、透明背景、无底板（Windows 图标不加底板，theme 色在浅色与深色任务栏上都可辨认），不改动路径几何。

## 构建与运行

需要 Rust（MSVC 目标）、Visual Studio Build Tools、.NET 10 SDK、Go 与 llvm-mingw（后两者用于 RelayKit），并先按 [开发说明](../../docs/development.md#windows-构建) 安装 runtime-support，然后执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
target\windows\Velune\Velune.exe
```

脚本输出 `target\windows\Velune`：先构建 `velune_bindings.dll`，再用固定提交的 `uniffi-bindgen-cs`（安装在 `target\tools`）从中生成 C# 绑定到 `target\bindings\cs`（生成物不入库），最后 `dotnet publish` 出自包含的 `Velune.exe`。输出目录包括 .NET 与 Windows App SDK 运行时、两个 DLL，以及 Harness 辅助脚本、`node_modules` 和第三方许可组成的 `resources`，约 230 MB；整个目录可以移动，但各部分必须放在一起，Windows 从 exe 所在目录解析 DLL 依赖。生成绑定后也可以只用 `dotnet build app\windows\Velune.csproj` 编译。

## 数据与 Harness

应用数据位于 `VELUNE_HOME`，缺省为 `%USERPROFILE%\.velune`；远控身份与状态在其中的 `remote` 目录，设备名取自 `COMPUTERNAME`。未处理的异常记录在 `%TEMP%\Velune\crash.log`：WinUI 结束进程时只留下 stowed exception 代码（0xC000027B）。

Harness 原生运行于 Windows，不经 WSL 或 SSH runtime。npm／pnpm 为每个命令生成 `.cmd`、`.ps1` 和无扩展名的 `sh` 脚本三种启动器。Pi 的安装解析只读取 `sh` 脚本里的目标路径，所以发现时使用这一个；Codex 与 Claude Code 直接启动二进制，优先 `.exe`，否则用 `.cmd`。Pi 需要 Node 的绝对路径，发现时取 PATH 上第一个 `node.exe`。PATH 之外，核心还列出厂商自己安装的位置：Codex 桌面应用（`%LOCALAPPDATA%\OpenAI\Codex\bin`）、OpenAI 独立安装器（Codex home 下的 `packages\standalone\releases`）、Claude 桌面应用（`%APPDATA%\Claude\claude-code`），以及 VS Code、VS Code Insiders 与 Cursor 中 Codex、Claude Code 扩展自带的可执行文件；隐藏的扩展暂存目录不算。是否可导入仍按适配器支持的版本判断。核心把子进程放在 kill-on-close 的 Job Object 中，应用退出（包括被强制结束）时，Harness 及其子进程随之结束。

首次冷启动时，Windows Defender 扫描可能使 Pi 的版本探测超过 15 秒而失败，重试即可。

## 已知限制

- 中文输入法、长转录与长列表的性能尚未在真机上验收。
- SSH 运行时依赖 OpenSSH ControlMaster 与 Unix socket，Windows 宿主不支持。
- MVP 推进中（顺序见任务的“MVP 差距与顺序”）：资源库与分析只作用于本机核心，远端设备的资源库在该设备上管理；技能此轮只编辑 SKILL.md。核心管理原生资源文件的一层（`agent-runtime` 的 `management/fs.rs`）只实现于 Unix 类平台，Windows 上启用、同步、比较、加入资源库与列出运行时中的其他内容都由核心以“当前平台不支持受限资源文件与 Unix 权限管理”拒绝，界面照实显示；资源库本身的新建、编辑与保存可用。系统通知已向 Windows 注册并发出，横幅的显示与点按打开尚未在真机上目视验收。布局系统按 [TDD](TDD.md) 全部实现，尚未在真机上逐项操作验收；Windows 尚未注册 `velune://`，拷贝的链接要在 Mac 上打开。额度窗口名称由 Windows 按核心的窗口 ID 拼出，核心尚未提供显示名。模型目录读取中或失败时，模型菜单只说明状态，不像 Mac 那样先列出可达的 managed 模型。
