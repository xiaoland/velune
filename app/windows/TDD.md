# Windows app Unit TDD：窗口与布局

本文是 Windows app 自有的布局设计：窗口、分屏标签组、停靠区与工具窗口，以及它们的保存与快捷键。产品行为见 [多窗口、标签与布局](../../docs/prd/workspace-layout.md)，分工见 [Product TDD](../../docs/product-tdd/index.md)（布局属平台 app 的呈现状态，不进核心、不经远控同步），结构名称以 [Mac README](../mac/README.md) 为基准。界面与构建见 [README](README.md)。

状态：2026-10-22 开发方起草并按下文“交付顺序”全部实施，win-ws 构建通过；尚未在真机上逐项操作验收。

## 模型

工具布局是纯数据（`Layout.cs` 的 `ToolLayout`），视图按它构建，改动经同一组操作写回再保存。编辑区的分屏树由持有视图的节点组成（`Editor.cs`），保存时转为同一文件中的数据，恢复时由数据重建。

- **工作区窗口**（`WorkspaceWindow`）：一个设备、一个编辑区与左／右／底三个停靠区，另有“保持在最前面”。设备按窗口区分：标题栏切换设备只换这个窗口的目标，各窗口可指向不同设备。
- **编辑区**：分屏树。节点是 `Split`（方向、子节点、各子节点比例）或 `Pane`；面板持有一组标签与选中的一个。窗口有一个聚焦面板，命令与停靠的工具跟随它。
- **标签**：一个会话（运行时 ID 与会话 ID）或未发送的新会话。标签持有它的 `ConversationView`，切换标签、在面板与窗口间移动时原对象随之转移，草稿、阅读位置与展开状态不丢。
- **停靠区**：`Left`、`Right`、`Bottom`，各有尺寸与“收起”。底区在编辑区下方、左右区之间。
- **工具窗口**：会话列表、会话大纲、输入区、关联 Agent。每个工具一份状态：位置、是否显示、区内比例、浮动或独立窗口的位置与大小。位置是停靠在某区、浮动、独立窗口；大纲与关联 Agent 另有“工具栏按钮”（大纲按设置弹出或就地折叠，关联 Agent 弹出面板且只在有关联会话时出现），输入区另有“在每个面板中”。工具可见＝显示且所在区未收起。显示一个空的区时带来惯常的工具（左列表、右大纲、底输入区）。“只显示编辑区”收起所有显示中的区，并记下哪些区要恢复。

默认：列表停靠左区，大纲与关联 Agent 为工具栏按钮，输入区在每个面板中，三个区中只有左区展开。

## WinUI 映射

- **标签栏**用 WinUI `TabView`：它是 Windows 的系统标签栏（Edge、终端、文件资源管理器都用它），自带拖动排序、跨 `TabView` 拖放与拖到窗口外（`TabDroppedOutside`）、末端“＋”和关闭按钮。不另画一套。按 PRD，标签栏始终显示，不加强调色激活条。拆分后未聚焦面板的选中标签不另作标记，聚焦靠输入焦点体现。
- **拖放**：标签与列表的会话都携带应用私有格式 `velune/conversation`（进程内由 `DragSource` 记录来源标签）。落在标签栏上插入，落在面板四分之一边缘拆出新面板，中间加入该面板。拖到所有窗口之外即为会话窗口；拖动不提供对应用外的操作，免得资源管理器接下数据。
- **分隔条**是自有的 `Sash`（一条带调整尺寸指针的 `Border`，按下后捕获指针）：WinUI 没有内置 GridSplitter，为此引入 Community Toolkit 不值得。拖动中只改网格的列宽或行高，松开才写入布局；双击恢复均分或默认尺寸。
- **停靠区**是窗口网格的列与行，不用 `NavigationView`：侧栏要能放到右区、底区或浮动，`NavigationView` 只能在左边，它的条目也不支持多选。区内多个工具沿区的方向排列，各有标题条（名称、位置菜单、隐藏）；区内只有一个工具时不显示标题条，位置在工具自身的右键菜单与列表的“显示”菜单里调整。
- **浮动**是被主窗口拥有的工具窗口（Win32 owner：始终在所属窗口之上、随它最小化、不在任务栏单列），相当于 Mac 的 utility 面板；与 Mac 不同，应用不活跃时不隐藏，这是 Windows 上被拥有窗口的惯例。**独立窗口**是普通顶层窗口，有任务栏按钮、可最大化、可放到另一块屏幕，所属窗口关闭时一并关闭。拖动浮动窗口松开时（窗口子类化接收 `WM_EXITSIZEMOVE`），在主窗口外缘或内缘、或已吸附的浮动窗口边缘 14 px 内即贴边，贴边后随主窗口移动；松开时指针在主窗口左、右、底缘 80 px 内即停靠到该区。
- **保持在最前面**用 `OverlappedPresenter.IsAlwaysOnTop`。
- **会话窗口**：只显示编辑区的工作区窗口（所有区收起），可恢复停靠区。它的左区是这个会话的关联 Agent，会话列表默认隐藏。
- **浮层**（关联会话的打开方式之一）用 `ContentDialog`：它是 WinUI 的模态 sheet，内容是一个普通标签（带自己的输入区），可转到标签或新窗口。
- **设置与设备**移到标题栏：设备切换与新会话在标题栏左侧内容区，设置在右侧，因为会话列表可能不在左区，甚至被隐藏。

## 共享与轮询

会话列表按设备轮询一次，由应用级的 `Listings` 持有并通知所有指向该设备的窗口；各窗口不各自轮询。列表的写入（偏好、整理）经它进行，它负责“写入期间读到的列表不显示”。会话由打开它的标签各自轮询；同一会话在两个标签中打开时，第二个标签切换到第一个而不是重复打开（本窗口内），跨窗口则各开一份。

## 保存与恢复

Windows 桌面应用没有系统级的窗口内容恢复，所以 Velune 自己在启动时恢复上次退出时的窗口，如浏览器与 VS Code。

- `VELUNE_HOME/windows-layout.json`，schema 1：工具布局（去掉“只显示编辑区”）与各窗口（设备、位置与大小、最大化、保持在最前面、只显示编辑区、分屏树、标签的会话、聚焦面板）。其他 schema 或读不出即用默认，下次改动时覆盖。
- 改动后稍候写入，退出前补写。没有自己布局的窗口（新建窗口、会话窗口）以最近一次的工具布局开始；会话窗口自己的改动不写回工具布局。
- 恢复时设备已不在配对中的窗口改为本机；会话已不存在的标签显示读取失败，由用户关闭，不自动丢弃。

## 快捷键

命令表（`Commands.cs`）列出 Velune 自己的命令、默认快捷键与说明；窗口的 `KeyboardAccelerators` 与菜单、提示文字都取自它。改动只记差异到 `VELUNE_HOME/windows-shortcuts.json`（schema 1，null 表示移除）；设置“通用”的“快捷键”一节按分组列出，点按后录制，Backspace 移除，冲突与无修饰键的组合被拒绝并在该行说明，可逐项或全部恢复默认。发送（Ctrl+Enter）与插入本轮（Ctrl+Shift+Enter）由输入框自身处理，不在表中。

默认值按 Windows 与 VS Code、Chrome 在 Windows 上的习惯，不照搬 Mac 的修饰键：

| 命令 | 默认 |
| --- | --- |
| 新建会话 | Ctrl+N |
| 新建标签页 | Ctrl+T |
| 新建窗口 | Ctrl+Shift+N |
| 关闭标签页 | Ctrl+W |
| 关闭窗口 | Ctrl+Shift+W |
| 向右／向下拆分 | Ctrl+\\、Ctrl+Shift+\\ |
| 上一个／下一个分屏 | Ctrl+[、Ctrl+] |
| 上一个／下一个标签页 | Ctrl+Shift+Tab、Ctrl+Tab |
| 后退／前进 | Alt+←、Alt+→ |
| 显示／隐藏左侧、右侧、底部区域 | Ctrl+B、Ctrl+Alt+B、Ctrl+J |
| 只显示编辑区 | Ctrl+Shift+E（Mac 的 ⇧⌘↩ 对应的 Ctrl+Shift+Enter 在输入框中是插入本轮） |
| 会话列表、大纲、转到输入区、关联 Agent | Ctrl+1、Ctrl+2、Ctrl+3、Ctrl+4 |
| 重命名 | F2 |
| 设置 | Ctrl+, |
| 问题 | Ctrl+Shift+M |
| 资源库、分析 | 无（Mac 也没有；可在设置中设定） |

## 会话列表工具

会话列表从 `NavigationView` 改为独立的 `ConversationList` 控件，可放在任一位置：

- 分组列表是一个 `ListView`，分组标题是列表中的行（可折叠、不可选中），因此保留虚拟化并支持 `Extended` 多选；整理操作对选中的全部会话执行（核心 `organize_conversations` 接受多条）。
- 分组标题可拖动排序（即转为手动组排序），会话行可拖到标签栏、面板或窗口外。
- 单击在聚焦面板的当前标签打开（本窗口已有标签显示则切换过去），Ctrl+单击或“在新标签页中打开”在其后新开；行菜单另有向右／向下拆分打开、在新窗口中打开。

## 交付顺序

每步在 win-ws 构建并提交：

1. 模型、保存与工作区窗口：标题栏（设备、新会话、设置），分屏树与 `TabView` 面板，标签的新建、关闭、切换、右键菜单的拆分与移动，三个停靠区与分隔条，会话列表、大纲、输入区作为工具窗口及其位置菜单，“只显示编辑区”。
2. 会话列表重建：分组 `ListView`、多选、分组拖动、打开方式。
3. 拖放：标签与会话拖到标签栏、面板边缘与窗口外；会话窗口；多个工作区窗口与启动时恢复。
4. 浮动与独立的工具窗口，贴边与拖回停靠。
5. 快捷键表与设置、保持在最前面、关联会话的打开方式（当前标签、新标签、浮层、新窗口）。
